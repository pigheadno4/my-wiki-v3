## Overview

This Adyen documentation overview introduces its in-person payments offering for merchants accepting payments at the point of sale with Adyen payment terminals and Terminal API. It points to terminal selection, network architecture, shopper experiences, and Customer Area management. The page describes product options and navigation; it does not establish a particular merchant's eligibility, terminal availability in a market, exact API or SDK version, or a completed payment.

## Key takeaways

- A merchant can use a standalone terminal solution when it does not need a fully featured API integration. For an integrated POS, the page centers Terminal API JSON messages and describes local-network or cloud communication choices. These are alternative integration paths; the overview does not specify request schemas or say that an SDK is required. See **An integration for your business**.
- The page describes Adyen payment terminals, global and local payment methods, configurable network architecture, and centrally managed terminals and transactions. The referenced support, method, and terminal-selection pages determine specifics; this overview alone does not establish availability for every region, merchant account, or terminal. See **In-person payments** and **An integration for your business**.
- Its shopper examples include local-currency payment, tax-free shopping, omnichannel recognition, customized terminal UI, on-screen input, and optional beacon-assisted terminal selection. These are described capabilities or linked integration routes, not automatic features of every POS setup. See **A unique experience for your customers**.
- The page says POS payments use the same platform as online payments and describes Customer Area or API management, transaction views, and reporting routes. This is platform positioning, not evidence that a specific online integration accepts terminal payments. See **One platform**.

## Detail locators

- **In-person payments** — broad capabilities, language, method, terminal, architecture, and Customer Area links; terminal software release-note route.
- **An integration for your business** — standalone option versus Terminal API integration, JSON messaging without libraries, local versus cloud network choices, and terminal selection.
- **A unique experience for your customers** — shopper-facing features and their linked setup pages.
- **One platform** — online/POS platform relationship, Customer Area or API management, transaction views, and automatic reporting/settlement-reconciliation navigation.
- **Next steps** — What we support and Get started routes for detailed implementation and eligibility checks.
