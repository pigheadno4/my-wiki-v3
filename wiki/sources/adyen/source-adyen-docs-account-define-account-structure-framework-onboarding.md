## Overview

This Adyen Docs guide (2021-09-03 last-modified metadata; captured 2026-09-15) explains an onboarding route for multiple legal entities owned by a common holding entity. In this framework, the **main contracting entity** is added as a company account and each **processing entity** as a merchant account. The holding entity is described as generally administrative or legal, rather than payment-processing, while affiliates process payments. This is a scoped account/onboarding model, not proof of a particular merchant of record, signed contract, regional eligibility, active account, or completed payout. See [[adyen-account-structure]] and [[adyen]].

## Key takeaways

- Adyen calls the common holding entity the main contracting entity and its affiliates processing entities; the word “generally” qualifies the statement that the holding entity does not commercially process payments. The page gives no region-specific topology or transfer-of-funds diagram. [Raw lines 23–29]
- To start the route, the page tells the applicant to get a test account, give an Adyen sales contact the legal-structure details, and use the test Customer Area. The main-contracting-entity application requests company, ownership/control, and contact information. The processing-entity application requests ecommerce or in-person type, company, payout account, ownership/control, and contacts. [Raw lines 31–57]
- Selecting **Send request** submits applications for review; Adyen then reviews and contacts the applicant. The page says the account only goes live after both the main contracting entity and first processing entity applications have been submitted **and approved** by Adyen. Submission, a review message, or the framework diagram is not activation or eligibility proof. [Raw lines 59–63]
