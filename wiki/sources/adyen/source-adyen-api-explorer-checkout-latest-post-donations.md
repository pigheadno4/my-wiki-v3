## Overview

This 2026-09-15-captured [[adyen]] Checkout API reference documents `POST /donations` on the listed v72 test server. It can use a donation token generated by `/payments` to make a separate donation. The `latest` URL does not establish the current API version. See [[adyen-giving]] for the online Giving flows and outcome webhook.

## Key takeaways

- The body schema marks `amount` (with `currency` and minor-unit `value`), `merchantAccount`, `reference`, and `returnUrl` required. The `donationToken` itself is marked optional because the page also shows a stored-payment-method example. When a donation token is provided, `donationOriginalPspReference` is required and must identify the transaction from which the token was generated. With a token, `paymentMethod` is derived from it and becomes optional; raw card donations by a PCI-compliant integration must explicitly provide payment-method details.
- `donationCampaignId` identifies a campaign returned by `/donationCampaigns`; `donationAccount` is a distinct account field. The request examples separately illustrate campaign, classic-account and stored-payment-method variants. They do not make all example fields universally required.
- The schema includes conditional 3D Secure and recurring fields. For example, `billingAddress` and `browserInfo` have conditional 3DS requirements; `shopperReference` is required for recurring payments. Consult the raw schema before implementing a particular route.
- The 200 response may include donation `status` (`completed`, `pending` or `refused`), a donation resource `id`, and a nested `payment` object with its own `pspReference`, action and result code. These are distinct from the original-payment reference. The examples show `completed` and `Authorised`, but do not prove a live donation or downstream settlement. The existing Giving route uses the merchant `DONATION` webhook for outcome.
- The page lists 400, 401, 403, 422 and 500 error responses. The token-specific 422 example reports an invalid `additionalData.donationAccount`; it is an example, not a general validation rule.
