## Overview

This collected JavaScript v3 guide documents the browser-side button setup for a closed-beta [[braintree-auth]] Connect flow. A platform page loads `braintree-oauth-connect.js` and gives it a `connect_url` generated by the platform server so a merchant can start the connection flow. This is merchant-to-platform OAuth connection UI, not payment-transaction authorization, and the page does not establish a successful connection, payment acceptance or current eligibility.

## Key takeaways

- The snapshot labels Braintree Auth closed beta and directs interested platforms to contact Braintree.
- The page tells the platform to load `braintree-oauth-connect.js`, instantiate `BraintreeOAuthConnect`, and pass a server-generated `connect_url`. The browser displays **Connect with Braintree** in a required container; generation of the Connect URL remains a server responsibility.
- The parameter table marks `connectUrl` and `container` required. It lists `onError` as an optional callback receiving an object with a `message` property and `environment` as optional, accepting `production` by default or `sandbox`. These are JavaScript v3 snapshot fields, not evidence of current configuration support or parity with other client variants.
- For a new-signup merchant who chooses **Finish Later**, the guide says Braintree redirects to the configured redirect URI with `error=access_denied` and `error_description=user%20denied%20access`; the platform can parse that response and keep the Connect button available for a later attempt. This is a deferral or denial return, not proof that OAuth authorization completed.

> [!warning] Snapshot and presentation boundary
> This 2026-09-16 snapshot documents a closed-beta JavaScript v3 Connect-button integration. It does not establish current availability, account eligibility, successful OAuth authorization, payment acceptance, or cross-variant parity. The raw page does not specify whether the merchant experience opens in a modal, a new window or another presentation surface, so no modal behavior should be inferred.
