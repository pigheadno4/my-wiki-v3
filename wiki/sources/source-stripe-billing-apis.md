## Summary

Overview of the 11 Billing API objects and how they relate. Core chain: Subscription → Invoice (each billing cycle) → PaymentIntent (collect payment). Introduces the Entitlements system (Feature, ProductFeature, Entitlement) and the two customer models (Account v2 recommended vs Customer v1).

## Billing Object Chain

`Subscription` → auto-generates `Invoice` each billing cycle → `Invoice` auto-creates `PaymentIntent` → `PaymentIntent` collects from stored `PaymentMethod`

## 11 API Objects

| Object | Role |
| --- | --- |
| Account (customer-configured) | Customer in Accounts v2 (recommended for most) |
| Customer | Customer in Customers API v1 |
| Product | Good or service; service products can include Features |
| Price | Unit price, currency, billing cycle |
| Subscription | Customer's recurring purchase of a Product |
| Invoice | Statement of amounts owed; auto-generated by Subscription |
| PaymentIntent | Payment collection; auto-created by Invoice |
| PaymentMethod | Customer's payment instruments |
| Feature | A function/ability customers can access |
| ProductFeature | Junction: associates a Feature with a Product |
| Entitlement | Auto-created when subscription starts; use to gate feature access |

## Entitlements Model

1. Create Features (`basic_features`, `extended_features`)
2. Create Products; associate Features via ProductFeatures
3. Customer subscribes → Stripe auto-creates one Entitlement per Feature in the subscribed Product
4. Check `customer.activeEntitlements` to gate access — no need to query subscriptions/products/features
