# Forward payment details

Forward stored payment details to use them with different payment service providers.

You can forward payment details that you stored with Adyen to a [PCI compliant](/get-started-with-adyen/adyen-glossary/#pci-compliance) third party, like a payment service provider (PSP). We support forwarding card details, and network tokens.

## Requirements

Before you begin, take into account the following requirements, limitations, and preparations.

| Requirement                                                               | Description                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| ------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Integration type**                                                      | An [online payments integration](/online-payments/build-your-integration/) that uses Checkout API v70 or later.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| **[API credential roles](/development-resources/api-credentials/roles/)** | Make sure that you have the following role(s):- **Checkout webservice role**
- **Merchant Recurring role**                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| **[Webhooks](/development-resources/webhooks)**                           | Subscribe to the [**Recurring tokens life cycle events** webhook](/development-resources/webhooks/webhook-types/#other-webhooks).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| **Limitations**                                                           | To forward network tokens, you must [create a token](/online-payments/tokenization/create-tokens) with Adyen for the same payment details. This is to ensure that Adyen can forward the payment details by falling back to the Adyen token in case we cannot find a network token.                                                                                                                                                                                                                                                                                                                                                                                        |
| **Setup steps**                                                           | Before you begin:- [Create tokens](/online-payments/tokenization/create-tokens) with Adyen.
- If you want to forward network tokens, [implement network tokenization](/online-payments/network-tokenization).
- Contact our [Support Team](https://ca-test.adyen.com/ca/ca/contactUs/support.shtml?form=other) to enable forwarding card details or network tokens.
- Make sure that your [live endpoint](/development-resources/live-endpoints) region matches your Adyen token vault storage region. If you are not sure about the region where your tokens are stored, contact our [Support Team](https://ca-test.adyen.com/ca/ca/contactUs/support.shtml?form=other). |

## How it works

1. You make a POST [/forward](https://docs.adyen.com/api-explorer/Checkout/latest/post/forward) request, including placeholders for the payment details you want to forward and the destination.
2. Adyen replaces the placeholders with the payment details and makes a request to the third party API on your behalf to forward the payment details.
3. Adyen receives a response from the third party.
4. You receive [a response from Adyen](#handle-the-result) that contains the third party response as a string.

![](/user/pages/docs/02.online-payments/20.tokenization/05.forward-payment-details/forward-api.svg?decoding=auto\&fetchpriority=auto)

You can forward [card details](#card-details) or [network tokens](#network-tokens).

## Forward card details

We support the following flows to forward card details:

* **Forward a token**: Forward the card details using a token, to share the stored payment details from the Adyen Vault with a third party.
* **Forward a token, with [CVC](/get-started-with-adyen/adyen-glossary#card-security-code-cvc-cvv-cid)**: Forward the card details using a token and the card CVC, to share the stored payment details from the Adyen Vault with a third party,
* **Forward non-tokenized card details**: Forward the card details (encrypted or unencrypted) directly to a third party to let the third party tokenize the card details. Optionally, you can choose to [tokenize](/get-started-with-adyen/adyen-glossary#tokenization) the card with Adyen using the same request.

To forward card details:

1. You make a [request to Adyen](#request-to-adyen-card) including the payment details that you want to forward to the third party.
2. [Adyen makes a request to the third party](#request-to-third-party-card) that contains the payment details.
3. [Third party responds to Adyen](#third-party-response-card), and we forward this response to you.

### Make a forward request to Adyen

### Adyen makes a request to the third party

We make a request to the third party on your behalf. To construct the endpoint URL, we use the [baseUrl](https://docs.adyen.com/api-explorer/Checkout/latest/post/forward#request-baseUrl) and [request.urlSuffix](https://docs.adyen.com/api-explorer/Checkout/latest/post/forward#request-request-urlSuffix) you provided in your forwarding request. The code sample below shows the request Adyen would make to the third party for forwarding a token, without CVC.

**Example request from Adyen to third party**

```bash
curl https://thirdparty.example.com/payments \
-H "Basic merchant:pass" \
-H 'content-type: application/json' \
-d '{
   "amount": {
      "value": 100,
      "currency": "USD"
   },
  "paymentMethod": {
     "creditCard": {
        "holderName": "S. Hopper",
        "number": "4111111111111111",
        "expiryMonth": "12",
        "expiryYear": "2025"
     }
  }
}'
```

### Third party responds to Adyen

We receive a response from the third party that contains the outcome of the [/forward](https://docs.adyen.com/api-explorer/Checkout/latest/post/forward) request. The response structure and content can differ depending on the third party.

**Example response from third party to Adyen**

```bash
{
  "data": {
     "tokenizeCreditCard": {
        "paymentMethod": {
           "id": "PAYMENT_METHOD_ID"
        }
     }
  }
}
```

## Forward network tokens

To forward stored network tokens:

1. You make a POST [/forward](https://docs.adyen.com/api-explorer/Checkout/latest/post/forward) request, including the `options.networkToken` parameter to [forward a network token](#request-to-adyen-network).
2. In your request, you specify [a fallback logic](#build-logic-for-adyen-token-fallback) to ensure that Adyen can forward the payment details using the token you created with Adyen instead of the network token in case it cannot be found.
3. [Adyen makes a request to the third party](#request-to-third-party-network) that contains the payment details.
4. [Third party responds to Adyen](#third-party-response-network), and we forward this response to you.

When building your logic for network tokens, keep in mind that you can not forward a network token together with card details that are not yet tokenized by Adyen.

### Build logic for Adyen token fallback

For requests that include network tokens, you must add a conditional statement in your [`/forward` request to Adyen](#request-to-adyen-network).

In your condition, you must build a logic that informs Adyen to check if the network token exists, and determine the fields to forward to the third party depending on the outcome. Your condition must introduce a fallback to forward the token you created for the same payment details with Adyen in case the network token cannot be found.

The following table indicates the fields that must be forwarded to third party depending on different availability scenarios.

|            | Network token                                                                               | `networkTxReference`                                                                        | Cryptogram                                                                                  | Fields to forward to the third party                                               |
| ---------- | ------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| Scenario 1 | ![-white\_check\_mark-](/user/data/smileys/emoji/white_check_mark.png "-white_check_mark-") | ![-white\_check\_mark-](/user/data/smileys/emoji/white_check_mark.png "-white_check_mark-") | ![-white\_check\_mark-](/user/data/smileys/emoji/white_check_mark.png "-white_check_mark-") | Forward the network token, `networkTxReference`, and the network token cryptogram. |
| Scenario 2 | ![-white\_check\_mark-](/user/data/smileys/emoji/white_check_mark.png "-white_check_mark-") | ![-x-](/user/data/smileys/emoji/x.png "-x-")                                                | ![-x-](/user/data/smileys/emoji/x.png "-x-")                                                | Forward the network token.                                                         |
| Scenario 3 | ![-x-](/user/data/smileys/emoji/x.png "-x-")                                                | ![-white\_check\_mark-](/user/data/smileys/emoji/white_check_mark.png "-white_check_mark-") | ![-x-](/user/data/smileys/emoji/x.png "-x-")                                                | Fallback to the Adyen token.                                                       |

```bash

-H 'x-api-key: ADYEN_API_KEY' \
-H 'content-type: application/json' \
-d '{
  "merchantAccount": "YOUR_MERCHANT_ACCOUNT",
  "shopperReference": "YOUR_SHOPPER_REFERENCE",
  "storedPaymentMethodId": "M5N7TQ4TG5PFWR50",
  "merchantReference": "YOUR_UNIQUE_REFERENCE",
  "baseUrl": "http://thirdparty.example.com",
   "options" : {
      "networkToken":{
         "useNetworkToken":true,
         "includeCryptogram":true
      }
   },
  "request": {
     "httpMethod": "post",
     "urlSuffix": "/payments",
     "credentials": "YOUR_CREDENTIALS_FOR_THE_THIRD_PARTY",
     "headers": {
        "Authorization": "Basic {​{credentials}}"
     },
     "body": "{
        "amount": {
           "value": 100,
           "currency": "USD"
        }
        {​{​#networkTxReference}},
            "reference": "{​{​networkTxReference}}"
        {​{/networkTxReference}}
        {​{​#networkTokenExists}},
            "networkToken": {
                "number": "{​{tokenNumber}}",
                "expiryMonth": "{​{tokenExpiryMonth}}",
                "expiryYear": "{​{tokenExpiryYear}}"
                {​{​#cryptogram}}",
                    "eci": "{​{ecommerceIndicator}}",
                    "cryptogram": "{​{cryptogram}}"
                {​{/cryptogram}}"
            }
        {​{/networkTokenExists}}
        {​{^networkTokenExists}},
            "paymentMethod": {
                "holderName": "{​{holderName}}",
                "number": "{​{number}}",
                "expiryMonth": "{​{expiryMonth}}",
                "expiryYear": "{​{expiryYear}}"
            }
        {​{/networkTokenExists}}
     }"
  }
}'
```

### Adyen makes a request to the third party

We make a request to the third party on your behalf. To construct the endpoint URL, we use the [baseUrl](https://docs.adyen.com/api-explorer/Checkout/latest/post/forward#request-baseUrl) and [request.urlSuffix](https://docs.adyen.com/api-explorer/Checkout/latest/post/forward#request-request-urlSuffix) you provided in your forwarding request.

We use the [condition](#conditional-placeholders) you set in the [/forward](https://docs.adyen.com/api-explorer/Checkout/latest/post/forward) field to determine which details to forward to the third party.

### Tab: Scenario 1

The network token, `networkTxReference`, and the cryptogram are found. Adyen forwards all details to the third party.

**Example request from Adyen to third party including all details**

```bash
curl https://thirdparty.example.com/payments \
-H "Basic merchant:pass" \
-H 'content-type: application/json' \
-d '{
   "amount": {
      "value": 100,
      "currency": "USD"
   },
   "reference": "5252520200034065",
   "networkToken" : {
      "expiryMonth" : "12",
      "expiryYear" : "2024",
      "number" : "4111111111111111",
      "eci":"02",
      "cryptogram":"123"
   }
}'
```

### Tab: Scenario 2

The network token is found, but a `networkTxReference` is not found. Adyen only forwards the network token to the third party.

**Example request from Adyen to third party including a network token**

```bash
curl https://thirdparty.example.com/payments \
-H "Basic merchant:pass" \
-H 'content-type: application/json' \
-d '{
   "amount": {
      "value": 100,
      "currency": "USD"
   },
   "networkToken" : {
      "expiryMonth" : "12",
      "expiryYear" : "2024",
      "number" : "4111111111111111",
   }
}'
```

### Tab: Scenario 3

A network token is not found. Adyen uses the card details that you stored with [Adyen tokenization](/online-payments/tokenization) to forward payment details to the third party.

**Example request from Adyen to third party including card details**

```bash
curl https://thirdparty.example.com/payments \
-H "Basic merchant:pass" \
-H 'content-type: application/json' \
-d '{
   "amount": {
      "value": 100,
      "currency": "USD"
   },
  "reference": "5252520200034065",
  "paymentMethod": {
     "holderName": "S. Hopper",
     "number": "4111111111111111",
     "expiryMonth": "12",
     "expiryYear": "2025"
  }
}'
```

### Third party responds to Adyen

We receive a response from the third party, that contains the outcome of the forward request. The response structure and content can differ, depending on the third party.

**Example response from third party to Adyen**

```bash
{
  "data": {
     "tokenizeCreditCard": {
        "paymentMethod": {
           "id": "PAYMENT_METHOD_ID"
        }
     }
  }
}
```

## Handle the result

You receive a response from Adyen that informs you of the outcome of your [/forward](https://docs.adyen.com/api-explorer/Checkout/latest/post/forward) request, for example:

**Example /forward response from Adyen**

```bash
{
   "storedPaymentMethodId": "M5N7TQ4TG5PFWR50",
   "pspReference": "XB7XNCQ8HXSKGK82",
   "merchantReference": "YOUR_REFERENCE"
   "response": {
     "status": 200,
     "headers": {
        "thirdparty-version": "2023-10-16"
     },
     "body": "{\"success\": \"ok\",\"data\": {\"tokenizeCreditCard\": {\"paymentMethod\": {\"id\": \"PAYMENT_METHOD_ID\"}}}}"
   }
}
```

The response contains:

* `pspReference`: Our unique identifier for the transaction.
* `merchantReference`: The unique reference for the transaction that you included in your request to forward payment details.
* `storedPaymentMethodId`: The unique identifier for the stored payment details that were forwarded. This is the Adyen identifier.\
  This field is not returned if you [forward non-tokenized card details](#card-details), and set `options.tokenize` to **false**.
* `response.status`: The [HTTP status code](/development-resources/response-handling/) Adyen received from the third party.
* `response.body`: The response that Adyen received from the third party. Adyen passes the response as a string without modifying it.

### Errors

If Adyen's request to share the token fails, you will receive a response with [HTTP status code](/development-resources/response-handling/) different from **2XX**. In this response, you get an [error code and message](/development-resources/error-codes/) that help you diagnose and resolve the error.

When you make a request to forward payment details, and an error occurs on the Adyen side, you will receive a response with [HTTP status code](/development-resources/response-handling#http-responses) different from **2XX**.

If an error occurs on the third party side, you can receive:

* **502**: Third party did not send a response to Adyen.
* **505**: Third party experienced a time-out.

Below is an example where the request fails, with status code **422** and error code [803](/development-resources/error-codes/#803-paymentdetail-not-found):

**Error details in API response**

```bash
{
    "status": 422,
    "errorCode": "803",
    "message": "PaymentDetail not found",
    "errorType": "validation"
}
```
