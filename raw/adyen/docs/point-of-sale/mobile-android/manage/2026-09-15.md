# Manage your Android Mobile solution

Learn how to enable and maintain your solution and keep the software up-to-date.

There are certain tasks that need to be done when going live with an Android Mobile solution, such as registering your Mobile SDK-enabled app with Adyen. Then, when your solution is live and distributed to your users, you need to ensure that all required software updates are carried out. Otherwise there is a risk of temporarily not being able to continue transacting.

## Upload your app to Google Play

Applies to:

Android Tap to Pay and Card reader.

Does not apply to:

Android Payments app.

When going live with an Android Mobile SDK-enabled app, consider uploading your app to Google Play. Uploading to Google Play is optional, but it is a convenient way to distribute the app to your stores.

For information and instructions, see the Android Studio documentation about [app signing](https://developer.android.com/studio/publish/app-signing).

Google will ask you to provide:

* **Information for [Google Play's Data safety section](#safety)**.
* **[Use of foreground service declaration](#declaration)**.

### Google Play's Data safety information

For the [Google Play's Data safety section](https://support.google.com/googleplay/android-developer/answer/10787469?hl=en#zippy=,optional-format-for-sdks,data-collection,data-sharing,data-types), use the following details on what data the SDK accesses:

* **Name of SDK:** Adyen IPPMOB Tap to Pay and NYC1 SDK

* **Security Practices:**

  * Provide the link to the Adyen privacy policy: <https://www.adyen.com/privacy-policy>
  * All data is encrypted in transit.
  * No data is shared with third parties.

* **Data Types accessed or collected:** see the following table.

  | Data Types accessed or collected | Category                 | Purpose           | Description                                                                                                             | Sharing                                                  |
  | -------------------------------- | ------------------------ | ----------------- | ----------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------- |
  | Precise Location                 | Location                 | App functionality | On devices with Android OS 11 or earlier, the SDK accesses the precise location for Bluetooth discovery and connection. | This data is not shared or transferred to third parties. |
  | App info                         | App info and performance | App functionality | The SDK collects the following info: App version, Device OS version, Connected peripherals.                             | This data is not shared or transferred to third parties. |

### Use of foreground service declaration

From Mobile SDK version 2.14.0 or later, you need to [declare any foreground service types ](https://support.google.com/googleplay/android-developer/answer/13392821?hl=en\&sjid=3362498663504981577-EU)that you use in a new declaration in Play Console under **Monitor and improve** > **App content**. Use the following text:

*The Adyen In-Person Payments SDK uses a foreground service with the `dataSync` type to synchronize payment transactions with Adyen's backend while the user's application is in the foreground. Transaction synchronization is financially critical — incomplete syncs can result in accepted transactions that are never settled, causing direct losses for the merchant. WorkManager is avoided to prevent dependency and configuration conflicts with the host application, and `shortService` is unsuitable because the number of pending offline transactions and poor network conditions can require well over three minutes to complete a full sync.*

## Register your app with Adyen

Applies to:

Android Tap to Pay and Card reader.

Does not apply to:

Android Payments app.

When going live with an Android Mobile SDK-enabled app that you built, you must register the app in your live Customer Area. To register, you upload the SHA-256 fingerprint of the app's signing certificate and the package name of the app. This is a security measure that enables Adyen to use the fingerprint of the app's signing certificate to detect if the integrity of the app has been compromised.

We block all live transactions if:

* The app has not been registered yet.
* We detect that a registered app has been tampered with.

It is possible to register multiple certificates that sign versions of the same app. For example, a developer-signed app version that developers use to test the live environment, and a Google Play-signed version.

To register your Android app with Adyen:

1. If you uploaded your app to Google Play, get the SHA-256 fingerprint of the app's signing certificate as follows:

   1. In the **Google Play Console**, go to **Setup** > **App signing** > **App signing key certificate**.
   2. Copy the **SHA-256 certificate fingerprint**.

2. If you did not upload your app to Google Play, use an OpenSSL command to get the SHA-256 fingerprint of your app's signing certificate:

   **.pem files**

   ```bash
   openssl x509 -in SIGNING_CERTIFICATE_OF_YOUR_APP.pem -noout -sha256 -fingerprint
   ```

   **.crt or .cer files**

   ```bash
   openssl x509 -inform der -in SIGNING_CERTIFICATE_OF_YOUR_APP -noout -sha256 -fingerprint
   ```

3. In your [live Customer Area](https://ca-live.adyen.com/), go to **Devices** > **Tap to Pay & card readers**.

4. In the **Registered Android apps** box, select **Register app**.

5. In the dialog:

   1. Enter the **Package name** of your app.
   2. Paste the **SHA-256 fingerprint** of your app's signing certificate.
   3. Select **Save**.

Your app is now added to the list of registered Mobile SDK-enabled Android apps.

You can unregister your app by deleting the SHA-256 fingerprint of the app's signing certificate from the Customer Area. It can take up to ten minutes for this to take the effect. Be careful: transactions with the unregistered app will be blocked.

When you delete the SHA-256 fingerprint from the Customer Area, you can no longer transact with the app that is linked to the deleted fingerprint.

## Keep the Mobile SDK up to date

Applies to:

Android Tap to Pay and Card reader.

Does not apply to:

Android Payments app.

To make sure that you can continue making payments, you need to regularly update the Mobile SDK. SDK versions [expire](#sdk-expiry) after 6 months and are [removed](#sdk-removal) after 18 months.

Make sure to [stay informed about Mobile SDK version changes](#stay-informed) and [add the new version to your project](/point-of-sale/mobile-android/build/tap-to-pay/). You can find the expiry and removal dates of a specific Mobile SDK for Android version in the [release notes](/point-of-sale/firmware-release-notes/).

### SDK expiry

As part of our security policy, each version of the Mobile SDK expires 6 months after release. When a version expires:

* Tap to Pay on Android transactions are blocked.
* Card reader PIN transactions are blocked.
* Card reader transactions without PIN are still possible.

### SDK removal

12 months after a Mobile SDK version expires, the version is removed. When a version is removed:

* All transactions are blocked. The SDK cannot be used anymore.
* The version is removed from GitHub.

Make sure to update to a supported Mobile SDK version before your current version is removed.

### SDK support policy

The Mobile SDK follows semantic versioning MAJOR.MINOR.PATCH:

* MAJOR: a major version increment indicates incompatible changes.
* MINOR: a minor version increment indicates added functionality that is backwards compatible.
* PATCH: a patch version increment indicates backwards-compatible bug fixes.

We do not support bug fixes to earlier MINOR or PATCH SDK versions. If you find bugs in an older MINOR or PATCH version, we recommend to update to the latest available SDK.

You can find the expiry date of a specific Mobile SDK for Android in the following ways:

* In your [Customer Area](https://ca-test.adyen.com/), go to **Devices** > **Tap to Pay & card readers** and select the **SDK & OS versions** tab.
* In your [Customer Area](https://ca-test.adyen.com/), go to **Devices** > **Device list**, and select the **Mobile devices** tab.
* Check the [release notes](/point-of-sale/firmware-release-notes) of that version.

Only Mobile SDK for Android versions 1.0.0 or later are visible in the Customer Area.

## Keep the Android Payments app up to date

Applies to:

Android Payments app.

Does not apply to:

Android Tap to Pay and Card reader.

To make sure that you can continue making payments using your Mobile solution, you need to regularly update the Android Payments app.

As part of our security policy, each version of the Android Payments app expires six months after the version was released. When a version of the Android Payments app has expired, you can no longer make transactions with Tap to Pay on Android. Only card reader transactions without PIN are possible.

Make sure to [stay informed about Android Payments app version changes](#stay-informed) and we recommend enabling the automatic updates in your mobile device.

You can find the expiry date of a specific Mobile SDK for Android version in the [release notes](/point-of-sale/firmware-release-notes/) of that version.

### SDK support policy

The Android Payments app follows semantic versioning MAJOR.MINOR.PATCH:

* MAJOR: a major version increment indicates incompatible changes.
* MINOR: a minor version increment indicates added functionality that is backwards compatible.
* PATCH: a patch version increment indicates backwards-compatible bug fixes.

We do not support bug fixes to earlier MINOR or PATCH Android Payments app versions. If you find bugs in an older MINOR or PATCH version, we recommend to update to the latest available Android Payments app.

## Keep the device OS up to date

Applies to:

All Android Mobile solutions.

To make sure that you can continue making payments using your Mobile solution, you need to regularly update the Android version on your mobile device.

If your mobile device is not running the minimum required Android version, all Mobile SDK transactions will be blocked. Make sure to check the [software requirements](/point-of-sale/mobile-android/requirements/#software) and subscribe to [system messages](#stay-informed) about required OS updates.

You can enforce a minimum OS version by following the [Android versioning guide](https://developer.android.com/studio/publish/).

You can find the OS version of your mobile devices in the following ways:

* In your [Customer Area](https://ca-test.adyen.com/), go to **Devices** > **Tap to Pay & card readers** and select the **SDK & OS versions** tab.
* In your [Customer Area](https://ca-test.adyen.com/), go to **Devices** > **Device list**, and select the **Mobile devices** tab.

## Keep the card reader up to date

Applies to:

Android Card reader.

Does not apply to:

Android Tap to Pay, Android Payments app.

The firmware of the card reader must be updated from time to time, to keep the reader secure.

You must check for new firmware updates regularly, and update your card readers to the latest version.

The Mobile SDK provides [built-in screens](/point-of-sale/mobile-android/understand/#updating-card-reader) to alert the user to firmware updates and to start the update. If you do not use the built-in UI, you must implement this functionality into your own custom UI.

## Keep the dock up to date

Applies to:

Android Card reader in combination with a dock.

Does not apply to:

Android Tap to Pay, Android Payments app.

The firmware of the dock must be updated from time to time, to keep the dock secure.

You must check for new firmware updates regularly, and update your docks to the latest version.

The Mobile SDK provides [built-in screens](/point-of-sale/mobile-android/understand/#updating-usb-dock) to alert the user to firmware updates and to start the update. If you do not use the built-in UI, you must implement this functionality into your own custom UI.

## Stay informed about version changes

Applies to:

All Android Mobile solutions.

To stay informed about version changes of the Mobile SDK for Android, the card reader, the Payments app, or the minimum required device OS, you need to subscribe to system messages.

1. In your [Customer Area](https://ca-test.adyen.com/), in the top navigation bar, select the **Notification center icon** **.
2. Select **Settings**.
3. Under **Developers and Integrations**, on the rows for **Mobile SDK releases** and **Mandatory updates** select how you want to be informed: by **Email** and/or in the **Notification center**.

Also keep an eye on the [release notes](/point-of-sale/firmware-release-notes/) for the expiry date of a specific SDK version or Payments app version .

## Change the language

Applies to:

All Android Mobile solutions.

![](/user/themes/adyen/images/illustrations/warning.svg) The Mobile SDK supports the following languages:

* English
* Dutch
* Finnish
* French
* Polish
* Portuguese
* Spanish
* German
* Danish
* Norwegian
* Italian
* Swedish

More languages will be added in future releases.

By default, the SDK uses the language of the operating system of the mobile device or the language of your POS application for the transaction flow and the UI for card reader operations. To change the default language, you have the following options:

* In the system settings of the mobile device, select the other language as the highest priority language. This changes the system language of the device.

* If only your POS application should be shown in the other language, in the system settings go to the app language settings, select your POS app, and select the other language.

If you select an operating system or app language that the SDK does not support, the SDK will use English.

### Primary, secondary, and card language

You can set a primary language and a secondary language [in the Customer Area](/point-of-sale/design-your-integration/determine-account-structure/configure-features#device) or [using the Management API](https://docs.adyen.com/api-explorer/Management/latest/patch/companies/\(companyId\)/terminalSettings#request-localization).\
If you set a secondary language, the transaction flow shows the "Present card" screen in the primary language with a button for the secondary language. Using that button, shoppers can switch to the secondary language before actually presenting their card.

For chip card payments, the SDK uses the language from the shopper's card. After the card is read, the SDK shows all following screens for the transaction in that language.

The language that the SDK shows in the transaction flow, follows this hierarchy:

1. Secondary language, if set and the shopper selects this language on the screen.
2. Card language, if the shopper uses a card that has a language tag.
3. Primary language, if set.
4. App language.
5. Operating system language.

If the secondary, card, or primary language is not supported, the SDK uses the app language. If the app language is not supported, the SDK will use English.

### Change the receipt language

The default language of the shopper receipt and the merchant receipt is English. To switch to a different supported language for either or both receipts, contact our [Support Team](https://ca-test.adyen.com/ca/ca/contactUs/support.shtml?form=other).
