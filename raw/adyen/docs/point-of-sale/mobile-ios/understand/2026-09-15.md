# Understand the iOS Mobile solutions

Learn about the concepts that the mobile transaction flow is based on.

This page explains various concepts that our Mobile solutions are based on. The focus is on how the Adyen Mobile SDK interacts with the Adyen payments platform and with your POS app.

## Communication session

When you integrate the Mobile SDK into your POS app, the SDK has to communicate in a secure way with the Adyen payments platform. To enable this, you must integrate a server-to-server POST [/auth/certificate](https://docs.adyen.com/api-explorer/softpos-configuration-api/latest/post/auth/certificate) request to establish a secure communication session. Your POS app needs to call your backend to trigger this request and get the session data.

The SDK uses the session data from the response to authenticate with our payments platform. Because the session expires after some time, the SDK checks regularly if it needs to establish a new session.

![Authentication flow](/user/pages/reuse/pos-mobile-sdk/communication-session/ipp-mobile-authentication-flow.svg?decoding=auto\&fetchpriority=auto)

## SDK transaction flow

If you use or build a Mobile solution where our iOS Mobile SDK is integrated into your POS app, transactions take place as follows:

1. Optional but recommended: your POS app calls a warm-up function to speed up initiating transactions.

2. Your POS app creates a Terminal API request that is serialized to JSON, or receives the Terminal API payment request from your backend.

   **Tip**\
   To help you create Terminal API requests, we provide a **TerminalAPIKit for iOS** on [GitHub](https://github.com/Adyen/adyen-terminal-api-ios). Installation and usage instructions are in the repository's README.

3. The POS app passes the Terminal API request to the Mobile SDK.

4. The SDK checks if the communication session is still valid, and if necessary establishes a new session.

5. The transaction starts on the mobile device.

6. The SDK passes the Terminal API response to your POS app.

![](/user/pages/reuse/pos-mobile-sdk/sdk-flow/ipp-mobile-sdk-flow-ios.svg?decoding=auto\&fetchpriority=auto)

## PIN transactions

It is possible to make PIN transactions in your Tap to Pay and card reader solution. Unlike traditional payment terminals with physical keypads, PIN entry on a mobile device requires specialized security measures to protect the shopper's data. To comply with [PCI MPoC compliance requirements](/point-of-sale/mobile-android/security/#pci-mpoc-compliance-requirements), the PIN entry pad is not always centered on the mobile device screen. Instead, it appears in a random position as shown in the following examples.

### PIN transaction with a card reader in the US

You need an NYC1 card reader with PIN support [for secure PIN transactions](/point-of-sale/mobile-ios/requirements#card-readers).

NYC1 card readers with PIN support require Mobile SDK version 3.8.0 or later.

In the US, not all NYC1 card readers support PIN. You can check if your card reader supports PIN transactions in the following ways:

* By checking the `connectedDevice.type` property. The results can be:

  * **nyc1** (card reader supports PIN)
  * **nyc1SCR** (card reader does not support PIN)

* In the [built-in UI](/point-of-sale/mobile-ios/understand#ui-for-card-reader-operations): If under **Device Info** the field **Model** is present, you have an NYC1-SCR card reader that does not support PIN. If the field **Model** is not present, you have an NYC1 that supports PIN.

| Device info for NYC1-SCR                                                                                              | Device info for NYC1                                                                                               |
| --------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| Card reader not suitable for PIN ![](/images/d/1/1/0/5/d1105f6e5ff5f48bc92a778b6366fc97030ef786-screen-enios-scr.png) | Card reader suitable for PIN ![](/images/9/2/e/d/e/92ede2aee7c09c1655fa5edb076939d1c09f950d-screen-enios-scrp.png) |

NYC1-SCR card readers will no longer be available for order after February 1, 2026.

If you want to disable PIN support on your NYC1 card reader, [refer to card reader requirements](/point-of-sale/mobile-ios/requirements#card-readers)

## UI for card reader operations

If your Mobile SDK solution uses NYC1 card readers as the payment interface, the people operating the readers need to:

* Connect their mobile device with the card reader through Bluetooth pairing.
* View an overview of card readers. For example, to switch to a different card reader.
* View details of the card reader they are using. For example, to check the battery charge level.
* Update the firmware of the card reader they are using.

The SDK allows you to build your own UI for those tasks, but also provides a built-in UI as shown in the following examples.

![The Pair reader screen shows nearby card readers.](/user/pages/docs/03.point-of-sale/56.mobile-ios/05.understand/screen-EN_ios_pair-reader2x.png)

![The Devices screen shows the connected card reader and previously paired readers.](/user/pages/docs/03.point-of-sale/56.mobile-ios/05.understand/screen-EN_ios_devices2x.png)

![The Device info screen shows the card reader details and an available firmware update.](/user/pages/docs/03.point-of-sale/56.mobile-ios/05.understand/screen-EN_ios_device-info2x.png)

The following sections provide some example built-in screens for specific tasks:

* [Bluetooth pairing](#bt-pairing)
* [Updating the card reader firmware](#updating-card-reader)

If your solution uses the NYC1 card reader in combination with the NYC1 dock, users also need to connect to the card reader through USB and update the dock firmware. See [UI for dock operations](#usb-dock).

### Bluetooth pairing

The built-in UI screens guide the reader through the process of connecting their mobile device to a card reader through Bluetooth.

![The Bluetooth pairing flow shows how to select a nearby NYC1 card reader.](/user/pages/docs/03.point-of-sale/56.mobile-ios/05.understand/ios_pairing-reader.gif?decoding=auto\&fetchpriority=auto)

### Updating the card reader firmware

The firmware of the card reader must be updated from time to time, to ensure secure transaction processing.

You must check for new firmware updates regularly, and update your card readers to the latest version.

Our built-in UI shows a red indicator when a new firmware version is available for the connected card reader, and has an **Update** button to start the firmware update. A firmware update can fail when the card reader does not have an active Bluetooth connection when the update requires it. In this case the built-in UI shows instructions on how to reset the reader before retrying the update.

![The firmware update flow shows how to install an available update on a card reader.](/user/pages/docs/03.point-of-sale/56.mobile-ios/05.understand/ios_reader-update.gif?decoding=auto\&fetchpriority=auto)

If you use your own custom UI, it is required that you [build logic into your POS app](/point-of-sale/mobile-ios/build/card-reader/?tab=build_a_custom_ui_1_2#updating-card-reader) to check for new card reader firmware updates and handle the firmware update flow correctly within your POS app.

## UI for dock operations

If your Mobile SDK solution uses NYC1 card readers as the payment interface in combination with NYC1 docks, the people operating the readers need to:

* Connect their mobile device with the card reader through the dock.
* Update the firmware of the dock they are using.

The SDK allows you to build your own UI for those tasks, but also provides a built-in UI.

The following sections provide some example built-in screens for specific tasks:

* [Connecting to a dock](#connecting-usb-dock)
* [Updating the dock firmware](#updating-usb-dock)

### Connecting to a dock

In addition to Bluetooth, card readers can be connected through USB. The user's mobile device is connected to a dock using a USB-C cable, and the card reader is placed in the dock. The SDK recognizes the situation, and presents built-in UI screens to inform the reader about the USB connection.

![The Devices screen shows a card reader connected to a dock.](/images/a/7/4/b/3/a74b328f17926ea35b7d65408d160039d2e10c31-screen-eniosdock2x.png)

Note that it is also possible to place the card reader in the dock but [connect the mobile device to the reader through Bluetooth](#bt-pairing). In that case the dock and the user's mobile device are *not* connected with a USB-C cable. This is a way to charge the card reader through the dock in a countertop setup.

### Updating the dock firmware

The firmware of the dock must be updated from time to time, to ensure secure transaction processing.

Our built-in UI shows a red indicator when a new firmware version is available for the connected dock, and has an **Update** button to start the firmware update.

![The firmware update flow shows how to install an available update on an NYC1 dock.](/user/pages/docs/03.point-of-sale/56.mobile-ios/05.understand/ios_dock-update.gif?decoding=auto\&fetchpriority=auto)

If you use your own custom UI, it is required that you [build logic into your POS app](/point-of-sale/mobile-ios/build/card-reader/?tab=build_a_custom_ui_1_2) to check for new dock firmware updates and handle the firmware update flow correctly within your POS app.
