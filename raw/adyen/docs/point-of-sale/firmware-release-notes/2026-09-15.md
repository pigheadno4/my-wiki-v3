# Release notes

Software updates for payment terminals and for Tap to Pay and card reader solutions.

You can find the release notes for the following categories:

* **Terminal software** release notes for the following payment terminals:

  * Verifone Engage: e280m, e285p, e285, M400, P400 Plus, UX300, UX410, V210, V240m Plus, V400c Plus, V400m
  * Android: AMS1, M450, P630, S1E, S1E Barcode, S1E2L, S1E4Pro, S1F2, SFO1, S1U2, S1F4Pro

  Because of the [transition to PCI PTS 6](https://help.adyen.com/guides/the-complete-guide-to-pci-6/what-are-the-key-timelines-and-milestones), the firmware version [1.120](/point-of-sale/firmware-release-notes#releaseNote=2025-08-12-terminal-software-1.120) is the last major update for the Verifone Engage terminals.

  For older payment terminals from the Verifone Verix (eVo terminals) and Verifone Engage ranges, see [Legacy release notes](/point-of-sale/legacy-release-notes).

  If you are on the manual update strategy, make sure that your terminals are [updated](/point-of-sale/release-updating) to one of the following [Long Term Support](/point-of-sale/release-updating#lts) versions: [v1.133](/point-of-sale/firmware-release-notes/#releaseNote=2026-08-07-terminal-software-1.133), [v1.130](/point-of-sale/firmware-release-notes/#releaseNote=2026-05-15-terminal-software-1.130), or [v1.126](/point-of-sale/firmware-release-notes/#releaseNote=2026-01-30-terminal-software-1.126) for Android terminals, and [v1.120](/point-of-sale/firmware-release-notes#releaseNote=2025-08-12-terminal-software-1.120) for Verifone Engage terminals. For the upcoming LTS versions, see the [Long Term Support](/point-of-sale/release-updating#lts) release schedule.

* **Android SDK on mobile** release notes for the Android [Tap to Pay](/point-of-sale/mobile-android/build/tap-to-pay/), [Card reader](/point-of-sale/mobile-android/build/card-reader) and [Android payments app](/point-of-sale/mobile-android/build/payments-app) integrations.

* **iOS SDK on mobile** release notes for the iOS [Tap to Pay](/point-of-sale/mobile-ios/build/tap-to-pay/) and [Card reader](/point-of-sale/mobile-ios/build/card-reader) integrations.

## 2026-09-01 — Android SDK on mobile — Version 2.20.0

*\<p>SDK expiry: 27 February, 2027. \<br> SDK removal: 27 February, 2028. \<br> \<a href="/point-of-sale/mobile-android/manage#keep-the-mobile-sdk-up-to-date">Learn more\</a>\</p>*

### Fixed

* We fixed an issue where shoppers could see untranslated screens because the SDK selected a language it does not support. The SDK now falls back to the app language if the secondary, card, or primary language is not supported, and only uses English if the app language is not supported either.
* We fixed an issue where the PIN entry screen showed incorrect PIN messages in English instead of in the [card language](/point-of-sale/mobile-android/manage#primary-secondary-and-card-language).
* We fixed an issue where the SDK could not find card readers if Bluetooth was turned off when your app started. Bluetooth scanning now recovers as soon as you turn Bluetooth back on, without restarting the app.

### Known Issues

* Apps that deliver the SDK as a dynamic feature module fail to build because a boolean resource referenced by the SDK's manifest is missing from the base module. As a workaround, declare `ippm_android_version_supported` in your base application module:

  * `false` in `res/values/bools.xml`
  * `true` in `res/values-v30/bools.xml`

  Both files are required, because the SDK's components are only supported on Android 11 or later.

### Updating

* The new **minimum iOS version** required to use all SDK functionality is now **version 18.4**, see section [here](/point-of-sale/mobile-ios/requirements#software).
* The SDK now requires a device passcode to be set in order to call any function on the SDK's [`PaymentService`](/point-of-sale/mobile-ios/build/tap-to-pay#enable-transactions). See [Setting a device passcode](/point-of-sale/mobile-ios/security#setting-a-device-passcode).

### New

* You can now set `ReceiptReprintFlag` to `false` in a [transaction status](/point-of-sale/basic-tapi-integration/verify-transaction-status) request to leave out receipt data from the response.

* The SDK now shows more detailed error messages in the UI when the NYC1 card reader connection fails.
* Online transaction calls now use a 30-second timeout. The initial transaction API call still uses a 10-second timeout, so the SDK can fall back to Store and Forward faster.
* The SDK now limits non-transaction requests to Adyen to protect against backend overload during attestation or threat scenarios.
* If session establishment repeatedly fails, the SDK now pauses new attempts for a period of time instead of retrying immediately.

### Fixed

* We fixed an issue where invalid or unsupported transaction types were incorrectly saved to the transaction status store.

### Improved: general

* We solved a network failover issue that occurred in situations where more that one connectivity interface is used.

* We improved the terminal's tender state messaging for Eftpos transactions, to make it easier to troubleshoot any issues with those transactions.
