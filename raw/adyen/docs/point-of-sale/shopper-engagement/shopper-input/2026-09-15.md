# Collect input

Learn how to use the payment terminal to collect input from your customers or staff.

In addition to making payments, Adyen's payment terminals can request input from your shopper or staff. This allows you to collect the shopper's email address for example, or perform a survey. The communication flow is between your POS app and the terminal, and does not involve the Adyen backend. You need to process the collected input with your own business logic.

After the user has provided input, you may want to show a waiting screen while your back-end system is processing the input. You can do this by [creating a session](/point-of-sale/shopper-engagement/create-session) that spans multiple requests.

## Requirements

Before you begin, take into account the following requirements, limitations, and preparations.

| **Requirement**      | **Description**                                                                  |
| -------------------- | -------------------------------------------------------------------------------- |
| **Integration type** | A [Terminal API integration](/point-of-sale/get-started) with payment terminals. |

## Input types

There are several types of input request:

* [Confirmation](/point-of-sale/shopper-engagement/shopper-input/confirmation): show some information and ask the user to confirm they agree.
* [Signature](/point-of-sale/shopper-engagement/shopper-input/signature): show some information and ask the user to confirm by supplying their signature.
* [Multiple choice—single answer](/point-of-sale/shopper-engagement/shopper-input/menu): show a multiple-choice question and let the user select one of the answers. You can use this for NPS surveys, order lists, and such.
* [Multiple choice—multiple answers](/point-of-sale/shopper-engagement/shopper-input/multi-menu): show a multiple-choice question and let the user select more than one of the answers.
* [Digit](/point-of-sale/shopper-engagement/shopper-input/digit): ask for numeric input, like a zip code. Another example is a pay-at-table flow where you ask your staff for the table number. This input accepts input of whole numbers.
* [Amount](/point-of-sale/shopper-engagement/shopper-input/amount): ask for an amount. This input request shows the currency and accepts input of a number with two decimals.
* [Phone number](/point-of-sale/shopper-engagement/shopper-input/phone-number): ask for a telephone number. The country code is prefilled based on the location of the terminal, but can be changed.
* [Rating](/point-of-sale/shopper-engagement/shopper-input/rating): show a question and let the user select a rating from 0 to 10.
* [Text](/point-of-sale/shopper-engagement/shopper-input/text): you'd typically use this to collect an email address.

For each input type, we provide predefined elements to show on the terminal display, and fields that you need to populate with your own text. The user enters a response with the terminal keypad or the on-screen keyboard and buttons.
