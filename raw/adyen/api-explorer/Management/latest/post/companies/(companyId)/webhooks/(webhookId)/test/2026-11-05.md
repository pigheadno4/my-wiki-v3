# POST /companies/{companyId}/webhooks/{webhookId}/test - Test a webhook

Sends sample notifications to test if the webhook is set up correctly.

We send sample notifications for maximum 20 of the merchant accounts that the webhook is configured for. If the webhook is configured for more than 20 merchant accounts, use the `merchantIds` array to specify a subset of the merchant accounts for which to send test notifications.

We send four test notifications for each event code you choose. They cover success and failure scenarios for the hard-coded currencies EUR and GBP, regardless of the currencies configured in the merchant accounts. For custom notifications, we only send the specified custom notification.

The response describes the result of the test. The `status` field tells you if the test was successful or not. You can use the other response fields to troubleshoot unsuccessful tests.

To make this request, your API credential must have the following [roles](https://docs.adyen.com/development-resources/api-credentials#api-permissions):

- Management API—Webhooks read and write

## Servers
- https://management-test.adyen.com/v3

## Parameters

### Path parameters
| Name | Type | Required | Description |
|------|------|----------|-------------|
| webhookId | string | Yes | Unique identifier of the webhook configuration. |
| companyId | string | Yes | The unique identifier of the company account. |


### Request body
| Name | Type | Required | Description |
|------|------|----------|-------------|
| merchantIds | array of string | No | List of `merchantId` values for which test webhooks will be sent. The list can have a maximum of 20 `merchantId` values.  If not specified, we send sample notifications to all the merchant accounts that the webhook is configured for. If this is more than 20 merchant accounts, use this list to specify a subset of the merchant accounts for which to send test notifications. |
| notification | object | No | Custom test notification object. Required when the [`types`](https://docs.adyen.com/api-explorer/#/ManagementService/v1/post/companies/%7BcompanyId%7D/webhooks/%7BwebhookId%7D/test__reqParam_types) list contains **CUSTOM**. |
|   - amount | object | No | The amount of the payment that the notification is about. Set the value in [minor units](https://docs.adyen.com/development-resources/currency-codes). |
|     - currency | string | Yes | The three-character [ISO currency code](https://docs.adyen.com/development-resources/currency-codes#currency-codes) of the amount. |
|     - value | integer | Yes | The numeric value of the amount, in [minor units](https://docs.adyen.com/development-resources/currency-codes#minor-units). |
|   - eventCode | string | No | The event that caused the notification to be sent.Currently supported values:  - **AUTHORISATION**  - **CANCELLATION**  - **REFUND**  - **CAPTURE**  - **REPORT_AVAILABLE**  - **CHARGEBACK**  - **REQUEST_FOR_INFORMATION**  - **NOTIFICATION_OF_CHARGEBACK**  - **NOTIFICATIONTEST**  - **ORDER_OPENED**  - **ORDER_CLOSED**  - **CHARGEBACK_REVERSED**  - **REFUNDED_REVERSED**  - **REFUND_WITH_DATA** |
|   - eventDate | string | No | The time of the event. Format: [ISO 8601](http://www.w3.org/TR/NOTE-datetime), YYYY-MM-DDThh:mm:ssTZD. |
|   - merchantReference | string | No | Your reference for the custom test notification. |
|   - paymentMethod | string | No | The payment method for the payment that the notification is about. Possible values:  - **amex**  - **visa**  - **mc**  - **maestro**  - **bcmc**  - **paypal**  - **sms**  - **bankTransfer_NL**  - **bankTransfer_DE**  - **bankTransfer_BE**  - **ideal**  - **elv**  - **sepadirectdebit** |
|   - reason | string | No | A description of what caused the notification. |
|   - success | boolean | No | The outcome of the event which the notification is about. Set to either **true** or **false**. |
| types | array of string | No | List of event codes for which to send test notifications. Only the webhook types below are supported.  Possible values if webhook `type`: **standard**:  - **AUTHORISATION**  - **CHARGEBACK_REVERSED**  - **ORDER_CLOSED**  - **ORDER_OPENED**  - **PAIDOUT_REVERSED**  - **PAYOUT_THIRDPARTY**  - **REFUNDED_REVERSED**  - **REFUND_WITH_DATA**  - **REPORT_AVAILABLE**  - **CUSTOM** - set your custom notification fields in the [`notification`](https://docs.adyen.com/api-explorer/#/ManagementService/v1/post/companies/%7BcompanyId%7D/webhooks/%7BwebhookId%7D/test__reqParam_notification) object.  Possible values if webhook `type`: **banktransfer-notification**:  - **PENDING**  Possible values if webhook `type`: **report-notification**:  - **REPORT_AVAILABLE**  Possible values if webhook `type`: **ideal-notification**:  - **AUTHORISATION**  Possible values if webhook `type`: **pending-notification**:  - **PENDING** |

## Request examples

### post-company-webhook-test
```json
{
  "merchantIds": [
    "YOUR_MERCHANT_ACCOUNT"
  ],
  "types": [
    "AUTHORISATION"
  ]
}
```

### post-company-webhook-test-custom
```json
{
  "notification": {
    "paymentMethod": "visa",
    "eventCode": "AUTHORISATION",
    "amount": {
      "currency": "EUR",
      "value": 2000
    },
    "reason": "Authorize visa payment",
    "success": true
  },
  "types": [
    "CUSTOM"
  ],
  "merchantIds": [
    "YOUR_MERCHANT_ACCOUNT_AU",
    "YOUR_MERCHANT_ACCOUNT_EU",
    "YOUR_MERCHANT_ACCOUNT_US"
  ]
}
```
## Responses

### 200 Success
The request has succeeded.

**Response body**
| Name | Type | Required | Description |
|------|------|----------|-------------|
| data | array of object | No | List with test results. Each test webhook we send has a list element with the result. |
|   - merchantId | string | No | Unique identifier of the merchant account that the notification is about. |
|   - output | string | No | A short, human-readable explanation of the test result.  Your server must respond with **HTTP 2xx* for the test webhook to be successful (`data.status`: **success**). Find out more about [accepting notifications](https://docs.adyen.com/development-resources/webhooks/#accept-webhooks)  You can use the value of this field together with the [`responseCode`](https://docs.adyen.com/api-explorer/#/ManagementService/v1/post/merchants/%7BmerchantId%7D/webhooks/%7Bid%7D/test__resParam_data-responseCode) value to troubleshoot unsuccessful test webhooks. |
|   - requestSent | string | No | The [body of the notification webhook](https://docs.adyen.com/development-resources/webhooks/understand-notifications#notification-structure) that was sent to your server. |
|   - responseCode | string | No | The HTTP response code for your server's response to the test webhook.  You can use the value of this field together with the the [`output`](https://docs.adyen.com/api-explorer/#/ManagementService/v1/post/merchants/%7BmerchantId%7D/webhooks/%7Bid%7D/test__resParam_data-output) field value to troubleshoot failed test webhooks. |
|   - responseTime | string | No | The time between sending the test webhook and receiving the response from your server. You can use it as an indication of how long your server takes to process a webhook notification. Measured in milliseconds, for example **304 ms**. |
|   - status | string | Yes | The status of the test request. Possible values are:  - **success**, `data.responseCode`: **2xx**.  - **failed**, in all other cases.  You can use the value of the [`output`](https://docs.adyen.com/api-explorer/#/ManagementService/v1/post/merchants/%7BmerchantId%7D/webhooks/%7Bid%7D/test__resParam_data-output) field together with the [`responseCode`](https://docs.adyen.com/api-explorer/#/ManagementService/v1/post/merchants/%7BmerchantId%7D/webhooks/%7Bid%7D/test__resParam_data-responseCode) value to troubleshoot failed test webhooks. |
