# POST /originKeys - Create originKey values for domains

This operation takes the origin domains and returns a JSON object containing the corresponding origin keys for the domains.

If you're still using origin key for your Web Drop-in or Components integration, we recommend [switching to client key](https://docs.adyen.com/development-resources/client-side-authentication/migrate-from-origin-key-to-client-key). This allows you to use a single key for all origins, add or remove origins without generating a new key, and detect the card type from the number entered in your payment form.

## Servers
- https://checkout-test.adyen.com/v72

## Parameters

### Header parameters
| Name | Type | Required | Description |
|------|------|----------|-------------|
| Idempotency-Key | string | No | A unique identifier for the message with a maximum of 64 characters (we recommend a UUID). |


### Request body
| Name | Type | Required | Description |
|------|------|----------|-------------|
| originDomains | array of string | Yes | The list of origin domains, for which origin keys are requested. |

## Request examples

### basic
```json
{
  "originDomains": [
    "https://www.your-domain1.com",
    "https://www.your-domain2.com",
    "https://www.your-domain3.com"
  ]
}
```

**Response body**
| Name | Type | Required | Description |
|------|------|----------|-------------|
| originKeys | object (string) | No | The list of origin keys for all requested domains. For each list item, the key is the domain and the value is the origin key. |
