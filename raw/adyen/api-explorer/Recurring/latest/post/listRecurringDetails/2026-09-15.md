# POST /listRecurringDetails - Get stored payment details

Lists the stored payment details for a shopper, if there are any available. The recurring detail ID can be used with a regular authorisation request to charge the shopper. A summary of the payment detail is returned for presentation to the shopper.

For more information, refer to [Retrieve stored details](https://docs.adyen.com/classic-integration/recurring-payments/retrieve-stored-details/).

## Servers
- https://pal-test.adyen.com/pal/servlet/Recurring/v68

## Parameters

### Request body
| Name | Type | Required | Description |
|------|------|----------|-------------|
| merchantAccount | string | Yes | The merchant account identifier you want to process the (transaction) request with. |
| recurring | object | No | A container for the type of a recurring contract to be retrieved.  The contract value needs to match the contract value submitted in the payment transaction used to create a recurring contract. However, if `ONECLICK,RECURRING` is the original contract definition in the initial payment, then `contract` should take either `ONECLICK` or `RECURRING`, depending on whether or not you want the shopper to enter their card's security code when they finalize their purchase. |
|   - contract | string | No | The type of recurring contract to be used. Possible values:  - `ONECLICK` – Payment details can be used to initiate a one-click payment, where the shopper enters the [card security code (CVC/CVV)](https://docs.adyen.com/payments-fundamentals/payment-glossary#card-security-code-cvc-cvv-cid).  - `RECURRING` – Payment details can be used without the card security code to initiate [card-not-present transactions](https://docs.adyen.com/payments-fundamentals/payment-glossary#card-not-present-cnp).  - `ONECLICK,RECURRING` – Payment details can be used regardless of whether the shopper is on your site or not.  - `PAYOUT` – Payment details can be used to [make a payout](https://docs.adyen.com/online-payments/online-payouts).  - `EXTERNAL` - Use this when you store payment details and send the raw card number or network token directly in your API request. |
|   - recurringDetailName | string | No | A descriptive name for this detail. |
|   - recurringExpiry | string | No | Date after which no further authorisations shall be performed. Only for 3D Secure 2. |
|   - recurringFrequency | string | No | Minimum number of days between authorisations. Only for 3D Secure 2. |
|   - tokenService | string | No | The name of the token service. |
| shopperReference | string | Yes | The reference you use to uniquely identify the shopper (e.g. user ID or account ID). |

## Request examples

### listAllRecurringDetails
```json
{
  "recurring": {
    "contract": "RECURRING"
  },
  "shopperReference": "YOUR_SHOPPER_REFERENCE",
  "merchantAccount": "YOUR_MERCHANT_ACCOUNT"
}
```
## Responses

### 200 Success
The request has succeeded.

**Response body**
| Name | Type | Required | Description |
|------|------|----------|-------------|
| creationDate | string | No | The date when the recurring details were created. |
| details | array of RecurringDetailWrapper | No | Payment details stored for recurring payments. |
|   - RecurringDetail | object | No |  |
|     - additionalData | object (string) | No | This field contains additional data, which may be returned in a particular response.  The additionalData object consists of entries, each of which includes the key and value. |
|     - alias | string | No | The alias of the credit card number.  Applies only to recurring contracts storing credit card details |
|     - aliasType | string | No | The alias type of the credit card number.  Applies only to recurring contracts storing credit card details. |
|     - bank | object | No | A container for bank account data. |
|     - billingAddress | object | No | The billing address. |
|     - card | object | No | A container for card data. |
|     - contractTypes | array of string | No | Types of recurring contracts. |
|     - creationDate | string | No | The date when the recurring details were created. |
|     - firstPspReference | string | No | The `pspReference` of the first recurring payment that created the recurring detail. |
|     - name | string | No | An optional descriptive name for this recurring detail. |
|     - networkTxReference | string | No | Returned in the response if you are not tokenizing with Adyen and are using the Merchant-initiated transactions (MIT) framework from Mastercard or Visa.  This contains either the Mastercard Trace ID or the Visa Transaction ID. |
|     - paymentMethodVariant | string | No | The  type or sub-brand of a payment method used, e.g. Visa Debit, Visa Corporate, etc. For more information, refer to [PaymentMethodVariant](https://docs.adyen.com/development-resources/paymentmethodvariant). |
|     - recurringDetailReference | string | Yes | The reference that uniquely identifies the recurring detail. |
|     - shopperName | object | No | The name of the shopper. |
|     - socialSecurityNumber | string | No | A shopper's social security number (only in countries where it is legal to collect). |
|     - tokenDetails | object | No |  |
|     - transactionLinkId | string | No | The unique identifier for the transaction link, used for Mastercard recurring transactions. |
|     - variant | string | Yes | The payment method, such as “mc", "visa", "ideal", "paypal". |
| lastKnownShopperEmail | string | No | The most recent email for this shopper (if available). |
| shopperReference | string | No | The reference you use to uniquely identify the shopper (e.g. user ID or account ID). |
