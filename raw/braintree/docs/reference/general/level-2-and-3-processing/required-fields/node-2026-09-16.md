### Interchange rates for Level 2 data

The values you pass in the required Level 2 fields determine whether you qualify for lower interchange rates or not. US merchants must pass abetween 0.1% and 22% for Visa transactions, and between 0.1% and 30% for Mastercard transactions.

## Level 3 data

To qualify for Level 3 processing on a given transaction, you must pass[Level 2 data](#level-2-data), along with specific additional Level 3 data and line items. In the US, Visa has introduced or mandated a quality check on Level 3 data (CEDP). Line items are similar to the details you would find on an itemized invoice.

### Amount validation

Each processor verifies that the total of the line-item amounts matches the root transaction amount. If there's a discrepancy, the transaction may be declined. For US Visa transactions (CEDP), to ensure these amounts match, it's advisable to sum the per-item tax, subtotal amounts, shipping tax, shipping amount, and subtract the discount amount to calculate the total transaction amount. In the EU and UK regions, transactions with a non-zero shipping amount may be rejected if the shipping tax amount is zero.

Transaction Amount = Sum of lineItem.total * + taxAmount + shippingAmount + shippingTaxAmount - discountAmount

* lineItem.total = (lineItem.quantity × lineItem.unitAmount) - lineItem.discountAmount

Here is an example for validating the amounts:

### Specifying level 2 and 3 data when submitting for settlement


**AVAILABILITY**
Level 2 and 3 processing via submit for settlement requires internal approval. Please [contact us](/braintree/help?issue=TransactionProcessingQuestion) if you’re interested in this functionality.

In some cases, transaction amounts, and by extension Level 2 and 3 parameters, are not finalized until the transaction is ready to be submitted for settlement. This functionality allows you to apply Level 2 and 3 parameters when submitting a transaction for settlement instead of specifying them in the transaction sale call.
**NOTE**
Level 2 and 3 data provided via submit for settlement will override all Level 2 and 3 data previously provided in a sale request. If you wish to pass Level 2 and 3 data, we recommend utilizing either [transaction.sale](/braintree/docs/reference/request/transaction/sale/ruby/node#tax_amount) or transaction.submit_for_settlement, but not both at the same time.


### Callbacks
```javascript
gateway.transaction.submitForSettlement(
    "theTransactionId",
    null,
    {
        purchaseOrderNumber: "12345",
        taxAmount: "5.00",
        taxExempt: false,
        shippingAmount: "1.00",
        shippingTaxAmount: "0.1",
        discountAmount: "0.00",
        shipsFromPostalCode: "60654",
        lineItems: [
            {
                name: "Product",
                kind: "debit",
                quantity: "10.0000",
                unitAmount: "9.5000",
                unitOfMeasure: "unit",
                totalAmount: "95.0000",
                taxAmount: "5.00",
                discountAmount: "0.00",
                productCode: "54321",
                commodityCode: "98765"
            }
        ]
    }, (err, result) => {
        if (result.success) {
            const settledTransaction = result.transaction;
        } else {
            console.log(result.message);
        }
    }
);
```

## Validation errors

A transaction result may contain[validation errors](/braintree/docs/reference/general/validation-errors/all#transaction-line-items)specifically for Level 3 fields or transaction line items, but only if the format or length of the value is outside expected bounds. This is to ensure the additional fields minimally interfere with the successful submission of transactions.

For a list of errors,[see the Validation Errors reference page](/braintree/docs/reference/general/validation-errors/all).
