# Merchant Account


## Result Object

A merchant account result may be successful or unsuccessful. Learn more about[result objects](/braintree/docs/reference/general/result-objects/ruby).
### Successful result

If the result was successful, the merchant account will have a

`pending`status. Within several minutes you should expect to receive a[confirmation webhook](/braintree/docs/guides/braintree-marketplace/confirmation).

The sub-merchant and its master merchant account will be provided on the result.

The sub-merchant status is pending at this point because (in production) we are taking the data provided, securely contacting a number of third-party services to verify the information, and making sure there are no red flags. This provides you with fraud protection while also satisfying our standard risk and underwriting process for new merchants. This means that a response will be delayed by just a minute or two (in production), so you will need to use[webhooks](/braintree/docs/guides/braintree-marketplace/confirmation)to listen for a response and confirm that the sub-merchant has successfully passed these checks.
### Node.js
```node
result.success; // true
result.merchantAccount.status; // "pending"
result.merchantAccount.id; // "blueLaddersStore"
result.merchantAccount.masterMerchantAccount.id; // "14laddersMarketplace"
result.merchantAccount.masterMerchantAccount.status; // "active"
```

### Unsuccessful result

Success will return false if[validations](/braintree/docs/reference/general/validation-errors/all#braintree-marketplace)prevent the merchant account from on-boarding. To simulate unsuccessful API calls in Sandbox, check out our[test values for merchant account creation](/braintree/docs/guides/braintree-marketplace/testing-go-live/node#sub-merchant-decline).
#### Validation errors

If any parameters are invalid, then the success call will return false and the[result object](/braintree/docs/reference/general/result-objects)will contain[validation errors](/braintree/docs/reference/general/validation-errors/all)indicating which parameters were invalid.
### Node.js
```node
result.success; // false
result.errors.deepErrors()
```

## Examples


### Statuses


#### Pending

The merchant account is in the process of verification with several third-party services. This is a transitory state. It will become active or suspended after verification.
#### Active

The merchant account has been approved. It can be used for processing transactions.
#### Suspended

The merchant account has been declined. It can't be used for processing transactions.
