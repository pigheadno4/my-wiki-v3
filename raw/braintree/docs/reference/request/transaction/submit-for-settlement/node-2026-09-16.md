# Transaction: Submit For Settlement

If you do not use the[`options.submit_for_settlement`](/braintree/docs/reference/request/transaction/sale/node#options-submit_for_settlement)option with, then you will have to explicitly submit the transaction for settlement. Refer to the[Transaction](/braintree/docs/reference/response/transaction)response object for more information.
### Node
```javascript
gateway.transaction.submitForSettlement("theTransactionId", (err, result) => {
  if (result.success) {
    const settledTransaction = result.transaction;
  } else {
    console.log(result.errors);
  }
});
```

## Examples


### Specifying settlement amount

If you want to settle for an amount that is different from the total authorization amount, you can specify the amount to settle. If you do not specify, the entire amount will be settled. You can only submit for settlement for an amount that is less than the total authorization amount one time. To submit more than once, you will need to use multiple partial settlements; this method is available for[PayPal](/braintree/docs/reference/request/transaction/submit-for-partial-settlement)and[Venmo](/braintree/docs/guides/venmo/submit-for-partial-settlement)transactions, and[some credit card transactions](/braintree/docs/guides/credit-cards/submit-for-partial-settlement)for select merchants.
#### Authorization adjustments

For eligible merchants,[authorization adjustments](/braintree/articles/control-panel/transactions/managing-authorizations#authorization-adjustments)occur automatically when you submit for settlement for an amount greater or less than the original authorized amount. Each adjustment attempt is recorded as an[adjustment detail](/braintree/docs/reference/response/transaction/dotnet#authorization-adjustments), which is returned on the[transaction response object](/braintree/docs/reference/response/transaction). Adjustment details allow you to determine decline responses and track the overall success rate of auth adjustments.

You can account for real-time decline responses in the form of[validation errors](/braintree/docs/reference/general/validation-errors/all#authorization-adjustment).

If you have questions regarding auth adjustment eligibility or functionality, please[contact us](/braintree/help?issue=TransactionProcessingQuestion)for details.
#### Availability

Authorization adjustments are available for select merchants and processors.[See our support articles for details.](/braintree/articles/control-panel/transactions/managing-authorizations)
### Callback
```javascript
gateway.transaction.submitForSettlement("theTransactionId", "35.00", (err, result) => { });
```

### Promise
```javascript
gateway.transaction.submitForSettlement("theTransactionId", "35.00")
  .then(result => { });
```

### Specifying Level 2 and 3 data


**AVAILABILITY**
Level 2 and 3 processing via submit for settlement requires internal approval. Please [contact us](/braintree/help?issue=TransactionProcessingQuestion) if you’re interested in this functionality. [See our Level 2 and 3 processing overview](/braintree/docs/reference/general/level-2-and-3-processing/overview) for more details.

In some cases, transaction amounts, and by extension Level 2 and 3 parameters, are not finalized until the transaction is ready to be submitted for settlement. This functionality allows you to apply Level 2 and 3 parameters when submitting a transaction for settlement instead of specifying them in the transaction sale call. Level 2 and 3 data provided via submit for settlement will override all Level 2 and 3 data previously provided in a sale request. If you wish to pass Level 2 and 3 data, we recommend utilizing either[transaction.sale](/braintree/docs/reference/request/transaction/sale/node#tax_amount)or transaction.submit_for_settlement, but not both at the same time.
#### Availability

Level 2 and 3 processing via submit for settlement requires internal approval. Please[contact us](/braintree/help?issue=TransactionProcessingQuestion)if you’re interested in this functionality.[See our Level 2 and 3 processing overview](/braintree/docs/reference/general/level-2-and-3-processing/overview)for more details.

gateway.transaction.submitForSettlement(

    taxAmount: "5.00",
    shippingAmount: "1.00",
    discountAmount: "0.00",
    shipsFromPostalCode: "60654",
    lineItems: [
      {
        name: "Product",
        kind: "debit",
        quantity: "10.0000",
        unitAmount: "9.5000",
        unitOfMeasure: "unit",
        totalAmount: "95.0000",
        taxAmount: "5.00",
        discountAmount: "0.00",
        productCode: "54321",
        commodityCode: "98765"
      }
    ]
  },
  (err, result) => {
    if (result.success) {
      const settledTransaction = result.transaction;
    } else {
      console.log(result.message);
    }
  }
);
```

### Shipping address information

In some cases, the shipping address information cannot be determined until the transaction is ready to be submitted for settlement. This functionality allows you to apply shipping address fields when submitting a transaction for settlement instead of specifying them in the transaction sale call. If shipping address parameters are applied via submit for settlement, they will override any corresponding shipping address parameters applied on the sale. We recommend using either transaction.sale or transaction.submit_for_settlement to send shipping address parameters, but not both at the same time. Shipping address includes the Level 3 fields[`shipping.postal_code`](#shipping-postal_code)and[`shipping.country_code_alpha3`](#shipping-country_code_alpha3).
#### Availability

Sending shipping address fields via submit for settlement requires internal approval. Please[contact us](/braintree/help?issue=TransactionProcessingQuestion)if you're interested in this functionality.
### Specifying order ID

You can pass additional information about a transaction by adding the[`order_id`](#order_id)when submitting the transaction for settlement. When adding an[`order_id`](#order_id)inRuby, you must also specify the amount to settle. If you want to settle the entire amount, pass.
### Callback

gateway.transaction.submitForSettlement("theTransactionId", null, {

  } else {
    console.log(result.message);
  }
});

```
