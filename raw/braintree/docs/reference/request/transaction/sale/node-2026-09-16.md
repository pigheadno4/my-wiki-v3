# Transaction: Sale

See also the[Transaction](/braintree/docs/reference/response/transaction)response object.

To create a transaction, you must include an[`amount`](#amount)and either a[`payment_method_nonce`](#payment_method_nonce), a[`payment_method_token`](#payment_method_token), or a[`customer_id`](#customer_id). Passing a`customer_id`is equivalent to passing the`payment_method_token`of the customer's default payment method.

Braintree offers products that manage risk and fraud related to each transaction. These products can only be leveraged if there is adequate data to support the capabilities. The required data can be easily added during the Braintree SDK or[Graph QL](/braintree/graphql/). integration, and must be done prior using risk products. For additional guidance go to[Premium Fraud Management Tools](/braintree/articles/guides/fraud-tools/premium/overview).

The following example creates a transaction using a[`payment_method_nonce`](#payment_method_nonce)from a client and instructs that it should be submitted for settlement immediately using[`options.submit_for_settlement`](#options-submit_for_settlement). You can see more[examples](#examples), including[using a vaulted payment method](#using-a-vaulted-payment-method), below the parameter reference.
### Node
```javascript
gateway.transaction.sale({
    amount: "10.00",
    paymentMethodNonce: nonceFromTheClient,
    deviceData: deviceDataFromTheClient,
    options: {
        submitForSettlement: true
    }
}, (err, result) => {
    if (result.success) {
        // See result.transaction for details
    } else {
        // Handle errors
    }
});
```

### Storing in your vault

When creating a transaction, you can also store the payment method in your vault.
#### Existing customer with new payment method

To associate this transaction's payment method with an existing customer, pass a[`customer_id`](#customer_id)along with[`options.store_in_vault`](#options-store_in_vault)or[`options.store_in_vault_on_success`](#options-store_in_vault_on_success)as`true`.
### Callback
```javascript
gateway.transaction.sale({
    amount: "10.00",
    paymentMethodNonce: nonceFromTheClient,
    customerId: "theCustomerId",
    options: {
        storeInVaultOnSuccess: true
    }
}, (err, result) => {
    // Handle result
});
```

### Promise
```javascript
gateway.transaction.sale({
    amount: "10.00",
    paymentMethodNonce: nonceFromTheClient,
    customerId: "theCustomerId",
    options: {
        storeInVaultOnSuccess: true
    }
}).then(result => {
    // Handle result
});
```

### Dynamic descriptors

Dynamic descriptors are typically composed of a name and phone number or URL. The name must include the business name, followed by a product name or identifier, separated by an asterisk (*). Depending on the type of transaction you're creating, the length/character limits may differ from those outlined above. For example, you can only specify up to 18 characters for dynamic descriptor names on Braintree Marketplace transactions. See below for details on[Venmo](#venmo),[PayPal](#paypal), and[Braintree Marketplace](#braintree-marketplace)dynamic descriptors.

Your processor may also restrict which descriptor values you can pass; certain processors allow you to pass URLs instead of phone numbers, while others accept only phone numbers or only names. If your processor supports URLs and you send both a phone number and URL, we will only pass the URL to the processor.[Contact us](/braintree/help?issue=updateDescriptor)for more information on your processor's specific requirements.
### Callback
```javascript
gateway.transaction.sale({
    amount: "10.00",
    paymentMethodNonce: nonceFromTheClient,
    descriptor: {
        name: "company*my production",
        phone: "3125551212",
        url: "company.com"
    }
}, (err, result) => {
    result.transaction.descriptor.name; // "company*my production"
    result.transaction.descriptor.phone; // "3125551212"
});
```

### Promise
```javascript
gateway.transaction.sale({
    amount: "10.00",
    paymentMethodNonce: nonceFromTheClient,
    descriptor: {
        name: "company<em>my production",
        phone: "3125551212",
        url: "<a href=\"http://company.com\">company.com</a>"
    }
}).then(result => {
    result.transaction.descriptor.name; // "company</em>my production"
    result.transaction.descriptor.phone; // "3125551212"
});
```

#### Venmo

Venmo only supports the dynamic descriptorname. The value can contain letters, numbers, spaces, and the characters+,-, and.. Any other character causes the entire dynamic descriptor name to be ignored — for example,O#1234would result in the full descriptor being sent without a dynamic descriptor name. The full descriptor sent to the processor is made up of three parts:
- The fixed prefixVENMO *(including two trailing spaces)
- TheBusiness Nameregistered in your Venmo application form
- The Dynamic Descriptor Name you submit through thedescriptor.namefield in yourtransaction.sale()ortransaction.submit_for_settlement()call

For example, if your Business Name isAStoreand you submitO-1234as the Dynamic Descriptor Name, the full descriptor isVENMO *AStore O-1234. When calling the API, submit only the dynamic portion (for example, O-1234) in thedescriptor.namefield. Do not include your Business Name or the VENMO * prefix — Venmo adds both automatically, and including them yourself will result in a duplicated or incorrect descriptor.
**NOTE**
The full descriptor is limited to 22 characters. If this limit is exceeded, the Business Name and Dynamic Descriptor Name portion will be truncated as needed. If you want to change the Business Name of the descriptor, you can edit your Venmo profile throughthe Venmo Processing page in the Control Panel. This will also update the name displayed to customers in the Venmo app during transaction processing.


#### PayPal

For PayPal transactions only, the dynamic descriptor is limited to a total of 22 characters and includes the following elements:


- The default prefix ofPAYPAL *
- Your PayPal hard descriptor*
- The product portion of yourname

These rules apply only when the payment method is PayPal. Card and other payment methods follow their own descriptor rules.

*Depending on your PayPal account setup, the PayPal hard descriptor may not be included in the dynamic descriptor. You can update the hard descriptor value from your[PayPal console](https://www.paypal.com/login).

The`name`must meet the following guidelines:


- Must include your registered Doing Business As (DBA) name, followed by an asterisk and a product description
- The DBA portion must be 3, 7 or 12 characters long - this portion will be dropped from your dynamic descriptor


**NOTE**
If the three parts of your dynamic descriptor combined exceed the 22 character limit, the `name` portion will automatically be truncated as needed.

The payment information displayed to a customer in their PayPal account overview does not contain the dynamic descriptor. The information displayed there is data the merchant has configured with PayPal directly, such as thebusiness name, email address, business contact details.
#### Braintree Marketplace

The only dynamic descriptor value we will pass for Braintree Marketplace transactions is the`name`you specify. We will not send any dynamic`phone`or`url`values to the processor, but we will pass the`phone`from the hard descriptor on your master merchant account.

The dynamic descriptor name can only contain the ASCII characters a-z, A-Z, the numbers 0-9, and the characters.-+and spaces (it can't contain special characters likeÑ,ü, andé). The maximum length is 18 characters; we will truncate any longer strings. The descriptor we pass to the processor will start with"BT *", followed by the`name`you specify.
- If the specified name is 12 characters or fewer, the descriptor we pass to the processor will end with a randomly generated 6-character string, such as123abc, which identifies the sub-merchant:
### 
```html
BT *MYDESCRIPTOR123abc
```

- If the specified name is 13 characters or greater, the descriptor we pass to the processor will not end with a randomly generated 6-character string:
### 
```html
BT *MYDESCRIPTORISLONG
```



**NOTE**
The sub-merchant can't access the 6-character string—we automatically append it to the descriptor name after you submit the transaction request. The string can't be changed, as it is required in order to identify each transaction we process for the sub-merchant.


### Hold a Braintree Marketplace transaction in escrow on creation

Upon creating a[Braintree Marketplace transaction](/braintree/docs/guides/braintree-marketplace/create), you can specify that its funds should be held in escrow. These funds can then be[released](/braintree/docs/reference/request/transaction/release-from-escrow)at your discretion. By default, funds are not held in escrow.
### Callback
```javascript
gateway.transaction.sale({
    amount: "100.00",
    merchantAccountId: "blue_ladders_store",
    paymentMethodNonce: nonceFromTheClient,
    options: {
        submitForSettlement: true,
        holdInEscrow: true,
    },
    serviceFeeAmount: "10.00"
}, (err, result) => {
});
```

### Promise
