# Transaction: Refund

You can[refund](/braintree/articles/control-panel/transactions/refunds-voids-credits#refunds)transactions that have a status of[settled](/braintree/docs/reference/general/statuses#settled)or[settling](/braintree/docs/reference/general/statuses#settling). If the transaction has not yet begun settlement, useinstead. If you do not specify an amount to refund, the entire transaction amount will be refunded.

Refer to the[Transaction](/braintree/docs/reference/response/transaction)response object for more information.
### Node
```javascript
gateway.transaction.refund("theTransactionId", (err, result) => {
});
```
If the transaction can't be found, it will return a[notFoundError](/braintree/docs/reference/general/exceptions/node#not-found-error).

If the refund fails, then the result will be unsuccessful and will include either[validation errors](/braintree/docs/reference/general/validation-errors/all)indicating which parameters were invalid, or a[processor settlement response code](/braintree/docs/reference/general/processor-responses/settlement-responses)indicating the type of settlement failure.
### Node
```javascript
result.success; // false
```

## Requirements


- Transaction status must be settled or settling.
- Refund amount can't be greater than remaining non-refunded amount of the original transaction.
- Transaction can't be refunded again after being completely refunded.
- Transactions[held in escrow](/braintree/docs/guides/braintree-marketplace/create/node#holding-funds-in-escrow)can only be refunded in full. Attempts to partially refund an escrow transaction will throw a[validation error](/braintree/docs/reference/general/validation-errors/all#braintree-marketplace).


## Examples


### Partial refunds

If you only want to refund a portion of the transaction, specify the amount to refund:
### Callback
```javascript
gateway.transaction.refund("theTransactionId", "50.00", (err, result) => {
    result.success; // true
    result.transaction.type; // "credit"
    result.transaction.amount; // "50.00"
});
gateway.transaction.refund("theTransactionId", "10.00", (err, result) => {
    result.success; // true
    result.transaction.type; // "credit"
    result.transaction.amount; // "10.00"
});
```

### Promise
```javascript
gateway.transaction.refund("theTransactionId", "50.00").then(result => {
    result.success; // true
    result.transaction.type; // "credit"
    result.transaction.amount; // "50.00"
});
gateway.transaction.refund("theTransactionId", "10.00").then(result => {
    result.success; // true
    result.transaction.type; // "credit"
    result.transaction.amount; // "10.00"
});
```
We support single and multiple partial refunds on a given transaction. You can continue to refund a transaction as many times as you like, as long as the sum of the refund amounts is less than the amount of the initial transaction.

If you have already partially refunded a transaction and you perform another refund without specifying the balance, we will refund the remaining non-refunded amount of the transaction.
**NOTE**
It's best practice to allow each partial refund call to complete successfully before creating any more for the same transaction. If a single transaction has too many simultaneous refund requests, some are likely to fail, returning an error from the gateway. A wait time of 5-10 seconds between partial refund attempts is strongly recommended to minimize errors.


### Refund processor declines

If using the most current SDK, and the processor declines the refund, the response will have the`processor_response_code`available. See the[transaction statuses page](/braintree/docs/reference/general/statuses#processor-declined)for additional information on the Processor Declined response. If using an older SDK version, and the processor declines the refund, you may receive a[validation error](/braintree/docs/reference/general/validation-errors/all#code-915200)in lieu of a processor response code.
### node
```node
result.success; // false
result.transaction.status; // "processor_declined"
result.transaction.processorResponseCode; // e.g. "2005"
result.transaction.processorResponseText; // e..g "Invalid Credit Card Number"
```

### Settlement failures

If the processor declines the capture for the refund transaction, the transaction object will have the`processor_settlement_response_code`available. See the[transaction statuses page](/braintree/docs/reference/general/statuses#settlement-declined)for additional information on theSettlement Declinedresponse.
### node
```node
result.success; // false
result.transaction.status; // "settlement_declined"
result.transaction.processorSettlementResponseCode; // e.g. "4001"
result.transaction.processorSettlementResponseText; // e..g "Settlement Declined"
```

### Issuing a credit


**IMPORTANT**
Credit transactions are **disabled** by default. If an attacker gets your API keys, they could transfer money out of your merchant account and put it on any credit card. If you need credit transactions to be enabled, [contact us](/braintree/help?issue=TransactionProcessingQuestion) .

You can use credit transactions to give a customer money. However, you should refund to an existing payment method whenever possible.

The only required parameters to create a credit transaction are the amount and the payment method token.
### Callback
```javascript
gateway.transaction.credit({
    paymentMethodToken: "aToken",
    amount: "100.00"
}, (err, result) => {
});
```

### Promise
```javascript
gateway.transaction.credit({
    paymentMethodToken: "aToken",
    amount: "100.00"
}).then(result => {
});
```
