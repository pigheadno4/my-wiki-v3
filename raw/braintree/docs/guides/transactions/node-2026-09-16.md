# Transactions


**NOTIFICATION**
 [Refer to the corresponding information for using GraphQL](/braintree/graphql/guides/transactions/) .

Transactions represent attempts to transfer money between you and your customers. You can:


- Get authorization to collect money from a customer by creating a[sale](/braintree/docs/reference/request/transaction/sale).
- Collect the money from an authorized sale by[submitting the transaction for settlement](#settlement).
- Undo a transaction before it settles by creating a[void](/braintree/docs/reference/request/transaction/void).
- Return previously collected money to a customer by creating a[refund](/braintree/docs/reference/request/transaction/refund).
- [Search for](/braintree/docs/reference/request/transaction/search)or[find](/braintree/docs/reference/request/transaction/search)transactions you've created.
- Take[more advanced actions](/braintree/docs/reference/request/transaction/cancel-release)depending on your setup.

## Settlement

To collect money, you'll need to submit the sale transaction for settlement. You can do this in two ways:


- When creating a transaction, use the[`options.submit_for_settlement`](/braintree/docs/reference/request/transaction/sale/node#options-submit_for_settlement)option:


### Callbacks
```javascript
gateway.transaction.sale({
    amount: "10.00",
    paymentMethodNonce: nonceFromTheClient,
    deviceData: deviceDataFromTheClient,
    options: {
        submitForSettlement: true
    }
}, (err, result) => {
    if (result.success) {
        // See result.transaction for details
    } else {
        // Handle errors
    }
});
```

### Promises
```javascript
gateway.transaction.sale({
    amount: "10.00",
    paymentMethodNonce: nonceFromTheClient,
    deviceData: deviceDataFromTheClient,
    options: {
        submitForSettlement: true
    }
}).then(result => {
    if (result.success) {
        // See result.transaction for details
    } else {
        // Handle errors
    }
});
```

- Use[Transaction: Submit For Settlement](/braintree/docs/reference/request/transaction/submit-for-settlement):


### Callbacks
```javascript
gateway.transaction.submitForSettlement("theTransactionId", (err, result) => {
    if (result.success) {
        const settledTransaction = result.transaction;
    } else {
        console.log(result.errors);
    }
});
```

### Promises
```javascript
gateway.transaction.submitForSettlement("theTransactionId").then(result => {
    if (result.success) {
        const settledTransaction = result.transaction;
    } else {
        console.log(result.errors);
    }
});
```
If the transaction can't be found, you'll receive a[notFoundError](/braintree/docs/reference/general/exceptions/node#not-found-error).

The transaction must be authorized to submit for settlement. Learn more about submitting authorized transactions for settlement in our[Managing Authorizations](/braintree/articles/control-panel/transactions/managing-authorizations)support article.
## Validations

If you provide invalid or malformed transaction details, the gateway returns[validation errors on the transaction](/braintree/docs/reference/general/validation-errors/all#transaction). You may also receive other types of validation errors on any additional information associated with the transaction, including the payment method, customer, and address.


**NOTE**
For certain account setups, we recommend that merchants collect and pass billing address information when storing payment methods or creating transactions. Passing billing address details (at least the postal code) can help increase the likelihood of a successful authorization. To learn more about your specific account setup, [contact us](/braintree/help/TransactionProcessingQuestion) .

Because transactions can have both a billing and a shipping address, you may get the same error code twice. Errors are scoped by parameter, so if you get an error such asStreet address is too long, verify whether the error is on the billing street address or the shipping street address. See the[validation errors overview](/braintree/docs/reference/general/validation-errors/overview)for more information.
## Disputes

Depending on your account setup, when a customer files a chargeback or other dispute with their bank or card network, you can retrieve those details from the[transaction response object](/braintree/docs/reference/response/transaction). Each transaction response object has a[`disputes`](/braintree/docs/reference/response/transaction/node#disputes)property that is an array of zero or more disputes.

You can also[search for disputed transactions by the dispute date](/braintree/docs/reference/request/transaction/search/node#dispute-date-range).

After you've located a disputed transaction, how you handle it depends on your banking partner.[Learn more about chargebacks and retrievals in our support articles.](/braintree/articles/risk-and-security/chargebacks-retrievals/overview)
