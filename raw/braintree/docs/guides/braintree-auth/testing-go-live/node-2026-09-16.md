# Testing and Go Live


**AVAILABILITY**
Braintree Auth is in closed beta. [Contact us](https://www.braintreepayments.com/products/braintree-auth#contact) to express interest.

Follow these steps to test your integration with Braintree Auth.
## OAuth sandbox testing


### Signup flow

You will want to do all of your Merchant Connect tests using the sandbox. To get started:


- Configure the server SDK to use thesandboxOAuthclient_idand aclient_secretyou were provided
- Set the[client-side](/braintree/docs/guides/braintree-auth/client-side)environment tosandbox

When you click the**Connect with Braintree**button in sandbox, we will present you with the signup form, just as we would in production. These fields can be[pre-populated](/braintree/docs/guides/braintree-auth/reference/node#signup-form-fields)or completed manually.
**NOTE**
No external credit checking or ID verification takes place while in the sandbox.

The signup fields will accept any dummy data with a few exceptions:
- **SSN**: Should be a dummy value but can't be sequential or all the same number
- **Phone numbers**: Must be a valid combination of area code + next 3 digits
- **Bank routing number**: Must be valid; use one from this[Chase](https://www.chase.com/personal/checking/routing-numbers)list

Once you have connected with one merchant in the sandbox, you can use that account's login information for future test flows without having to complete the form again.


### Redirect and authorization grant

We support several test authorization codes that allow you to test the OAuth redirect without having to go through the entire OAuth flow. These codes can be used to trigger predetermined responses in your sandbox and to retrieve an access token using thecreate_token_from_codemethod.

The following auth codes are supported:| Auth Code | Description |
| --- | --- |
| fake-valid-auth-code | A valid auth code that can be exchanged for an access token and a refresh token |
| fake-used-auth-code | An auth code that will be treated as a duplicate submission |
| fake-expired-auth-code | An auth code that will be treated as expired |

When usingfake-valid-auth-codeto obtain an access token, the returned token will be valid and can be used as any access token normally would. The only difference is that it will be able to take actions on behalf of your own merchant, rather than the merchant that authorized your application during the OAuth flow.
### Callback
```javascript
const gateway = new braintree.BraintreeGateway({
    clientId: "use_your_client_id",
    clientSecret: "use_your_client_secret"
});

gateway.oauth.createTokenFromCode({
    code: "fake-valid-auth-code"
}, (err, response) => {
    const accessToken = response.credentials.accessToken;
    const expiresAt = response.credentials.expiresAt;
    const refreshToken = response.credentials.refreshToken;
});
```

### Promise
```javascript
const gateway = new braintree.BraintreeGateway({
    clientId: "use_your_client_id",
    clientSecret: "use_your_client_secret"
});

gateway.oauth.createTokenFromCode({
    code: "fake-valid-auth-code"
}).then(response => {
    const accessToken = response.credentials.accessToken;
    const expiresAt = response.credentials.expiresAt;
    const refreshToken = response.credentials.refreshToken;
});
```
By default, the returned token will have theread_writescope, but you can change that by appending the desired scope(s) to the auth code:| Auth Code (with scopes) | Description |
| --- | --- |
| fake-valid-auth-code(read_only) | Obtain an access token withread_onlyscope |
| fake-valid-auth-code(read_write,shared_vault_transactions) | Obtain an access token withread_writeandshared_vault_transactionsscopes |

Passing a different scope will simulate a user connecting using a connect_url built with that scope.


## OAuth production testing

Once you are comfortable with the flow in the sandbox, you will want to do a test in production.


- Configure the server SDK to use theproductionOAuthclient_idand aclient_secretyou were provided.
- Set the[client-side](/braintree/docs/guides/braintree-auth/client-side)environment toproduction.

After clicking**Connect with Braintree**, if you already have a production Braintree merchant account you can choose the “Already have an account?” tab to log in and authorize. If you choose to link the Braintree production account where you created your OAuth application, the Connect flow will work; however, you may not be able to run a test transaction as that account may not have been underwritten for accepting payments. To run a test transaction you will need to create a new account via Connect and complete the form with accurate personal and business information.  If you need or want to sign up to complete the full Connect flow, then be aware that you will need to provide accurate ID and business information, and a credit check will be run on the business owner.
## Checkout integration

If you are enabling payments for your users, you must ensure your integration enables the full Braintree feature set. Below is a checklist of checkout integration items you'll need to implement.


### Client SDK

Integrate with our [Client SDKs](/braintree/docs/start/hello-client/) to create a payment form for your merchants.


### Premium Fraud Management Tools

Braintree's[Premium Fraud Management Tools for credit card transactions](/braintree/docs/guides/premium-fraud-management-tools/overview)are disabled by default for Braintree Auth.

If the connected merchant requires Premium Fraud Management Tools, you must[collect](/braintree/docs/guides/premium-fraud-management-tools/client-side)and[pass device data](/braintree/docs/guides/premium-fraud-management-tools/server-side)on their behalf. Be sure to also pass[options.skip_advanced_fraud_checking](/braintree/docs/reference/request/transaction/sale/node#options-skip_advanced_fraud_checking)falseto collect device data.
### PayPal

If you're accepting PayPal using the[Vault flow](/braintree/docs/guides/paypal/overview#vault-vs.-checkout), you must[collect and pass device data](/braintree/docs/guides/paypal/vault#collecting-device-data)for those transactions. Implement the data collector on the checkout and any page where a transaction could be completed using a Vault token (e.g. on your cart page).
### Transaction fields

When creating a transaction, ensure the following fields are always populated:


- [Channel ID / BN Code](/braintree/docs/reference/request/transaction/sale/node#channel): If you were assigned a PayPal BN code you can use this field and pass it for every transaction. This ensures every transaction is attributed to your platform.
- [Order ID](/braintree/docs/reference/response/transaction/node#order_id): This must be unique per transaction per merchant (the same IDs can be used for different merchants). This allows merchants to use our[duplicate transaction checking](/braintree/articles/control-panel/transactions/duplicate-checking)and[risk threshold rules](/braintree/articles/guides/fraud-tools/basic/risk-threshold-rules). Also, if you display this value in your dashboard, merchants can more easily match up transactions in the Control Panel and PayPal console.
- [Buyer/customer billing address](/braintree/docs/reference/request/transaction/sale/node#billing)(credit cards only): If the customer's billing address is collected during checkout, it should always be passed in the transaction sale call. The minimum field requirements are street address, postal code, and country code ([alpha-2 or 3](/braintree/docs/reference/general/countries)). This allows the merchant to use the[Address Verification System (AVS)](/braintree/articles/guides/fraud-tools/basic/avs-cvv-rules)in the Control Panel as well as[card verification](/braintree/articles/control-panel/vault/card-verification)(if the Vault is being used).
- [CVV](/braintree/docs/reference/request/transaction/sale/node#credit_card-cvv)(credit cards only): This should always be passed on single transaction requests if it is collected at checkout, as is recommended. This allows the merchant to set[CVV rules](/braintree/articles/guides/fraud-tools/basic/avs-cvv-rules)in the Control Panel as well as use[card verification](/braintree/articles/control-panel/vault/card-verification)(if the Vault is being used).
