# Shared Vault

**AVAILABILITY**
OAuth is in closed beta in production, and open beta in sandbox. [Contact us](https://www.braintreepayments.com/products/braintree-auth#contact) to express interest in the production beta release.

 The Shared Vault scope of OAuth allows you, as the platform owner, to store all credit cards and customer data in your own Braintree Vault. You can then use that data to create a transaction for a connected merchant. This Shared Vault model delivers a network benefit to all your connected merchants, helping boost checkout conversion.![shared,vault,diagram](https://www.paypalobjects.com/btdevdoc/braintree/img/developers/braintree-auth/partner-vault-diagram.png)


## Creating a Shared Vault transaction

The [shared_vault_transactions](/braintree/docs/guides/extend/oauth/reference#additional-oauth-scopes) right allows you to use tokens and IDs from your own Vault when creating a transaction for a connected merchant. The full list of parameters that can be used when creating a Shared Vault transaction can be found in the [transaction reference](/braintree/docs/reference/request/transaction/sale/node#shared_billing_address_id).

## Restrictions

Payment methods used to create Shared Vault transactions can never be updated by the connected merchant, and they can't be stored in the connected merchant's Vault or cloned via.     You cannot create a Shared Vault transaction using a [granted nonce](/braintree/docs/reference/xml-api/grant-api/overview) or a payment method created from a granted nonce.
