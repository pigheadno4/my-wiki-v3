# Create Subscriptions

To create a subscription, you only need a[stored`payment_method_token`](/braintree/docs/guides/payment-methods)and a[`plan_id`](/braintree/docs/guides/recurring-billing/plans). The subscription will be created using the price, trial duration (if any), billing details, and any add-ons or discounts specified within the plan's details.

A subscription can be created using either a payment method token or -[under certain conditions](/braintree/docs/reference/request/subscription/create/node#payment_method_nonce)- a payment method nonce.

The payment method must be vaulted before you can associate it with a subscription, so it's usually simplest to refer to the payment method using its[`payment_method_token`](/braintree/docs/reference/request/subscription/create/node#payment_method_token). Here's an example:
### Callbacks
```node
gateway.subscription.create({
    paymentMethodToken: "the_token",
    planId: "the_plan_id"
}, (err, result) => {
    // Handle response
});
```

### Promises
```node
gateway.subscription.create({
    paymentMethodToken: "the_token",
    planId: "the_plan_id"
}).then(result => {
    // Handle result
});
```
However, payment method tokens do not carry any 3D Secure data. If you use 3D Secure and need to apply 3DS to the first transaction of a new subscription, you must[create the subscription using a 3DS-enriched payment method nonce](/braintree/docs/reference/request/subscription/create/node#create-with-3d-secure-enriched-payment-method-nonce).
## Specifying merchant account

If you have multiple merchant accounts, you can pass the merchant account ID to specify which merchant account to use to process transactions for the subscription. If a merchant account ID is not passed, we'll use your default merchant account. If you would like to change which merchant account is default,[contact us](/braintree/help?issue=RecurringBillingQuestion).


**IMPORTANT**
The specified merchant account must be in the same currency as the subscription plan, or any attempted subscription transactions will trigger a [validation error](/braintree/docs/reference/general/validation-errors/all#code-91923) . If you want to use a merchant account with a different currency, you must create a new plan with the indicated currency.


### Callbacks
```node
gateway.subscription.create({
    paymentMethodToken: "theToken",
    planId: "silverPlanGbp",
    merchantAccountId: "gbpAccount"
}, (err, result) => {
    // Handle response
});
```

### Promises
```node
gateway.subscription.create({
    paymentMethodToken: "theToken",
    planId: "silverPlanGbp",
    merchantAccountId: "gbpAccount"
}).then(result => {
    // Handle result
});
```

## Overriding plan details

Certain plan attributes can be[overridden](/braintree/docs/reference/request/subscription/create/node#override-plan-details)when you pass the details you want to change along with the`payment_method_token`and`plan_id`.

You can override the following plan details:


- [Price](/braintree/docs/reference/request/subscription/create/node#price)
- [Trial duration and trial duration unit](/braintree/docs/reference/request/subscription/create/node#override-trial-details)
- [Start date](/braintree/docs/reference/request/subscription/create/node#set-start-date)
- [Number of billing cycles](/braintree/docs/reference/request/subscription/create/node#number_of_billing_cycles)
- [Add-on details](/braintree/docs/reference/request/subscription/create/node#add_ons)
- [Discount details](/braintree/docs/reference/request/subscription/create/node#discounts)


## Transaction flow

The transaction flow depends on when the subscription is set to start and whether it includes a trial period.

If there is no trial period and the subscription is set to bill immediately:


- We'll attempt to charge the customer and[submit the transaction for settlement](/braintree/docs/guides/transactions/node#settlement)right away
- If that transaction attempt is successful:
- The subscription will be created
- Its status will be[Active](/braintree/docs/guides/recurring-billing/overview#active)
- You'll receive a successful result that includes a[subscription object with its associated transaction details](/braintree/docs/reference/response/subscription/node#transactions)


- If that transaction attempt fails:
- No subscription will be created
- You'll receive an[error result](/braintree/docs/reference/response/transaction/node#unsuccessful-result)with information about why the transaction request failed



If there is no trial period and the subscription is set to bill in the future:


- The subscription will be created immediately, but its status will be[Pending](/braintree/docs/guides/recurring-billing/overview#pending)until the first billing date is reached
- On the first billing date, we'll attempt to charge the customer and submit the transaction for settlement
- If that transaction attempt is successful, the subscription status will change toActive
- If that transaction attempt fails, the subscription status will change to[Past Due](/braintree/docs/guides/recurring-billing/overview#past-due)

If the subscription has a trial period:


- The subscription will be created and its status will beActiveimmediately
- We'll attempt to charge the customer at the end of the trial period
- If that transaction attempt is successful, the subscription status will remainActive
- If that transaction attempt fails, the subscription status will change toPast Due


**NOTE**
Before setting up trial periods, be sure to read the risks and requirements in the [Trial Periods](/braintree/articles/guides/recurring-billing/trial-periods#risks-and-requirements) support article.

Check out this[diagram](/braintree/docs/guides/recurring-billing/overview#subscription-statuses)to see all of the possible transaction flows for subscriptions.
## Subscription days

Each subscription day runs from midnight to midnight in the time zone associated with your gateway account, regardless of the time of day the subscription was created. For example, a subscription created at 11pm in your Control Panel time zone will be in its second day at midnight.
## Email notifications

The gateway can[send emails](/braintree/articles/guides/recurring-billing/email-notifications)to customers based on recurring billing events. You'll need to[set up your DNS record](/braintree/articles/control-panel/transactions/email-receipts)to allow the gateway to send email from your domain, and then[contact us](/braintree/help?issue=RecurringBillingQuestion)to enable this feature.
