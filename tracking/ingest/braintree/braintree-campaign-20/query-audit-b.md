2. **What checks, rule settings and result boundaries does this page itself document? — PASS.** For new credit-card transactions or verifications, Braintree sends submitted address and CVV data to the issuer; **after issuer approval**, the issuer returns match codes for numeric address values and CVV. Enabled merchant rules can then gateway-reject the request and send a void request, which some banks may not recognize immediately—so AVS/CVV rule results are not authorization decisions. In the Control Panel, any enabled-rule violation can reject, AVS can require both postal-code and street-address violations, and rules can be scoped to all transactions or selected card types, amounts, or merchant accounts. Defaults cover first-time transactions, not recurring or vaulted-card transactions; pre-vault checking requires card verification, and CVV must be recollected because Braintree does not store it. The page also qualifies default US/no-country AVS scope, Global AVS false-rejection risk, numeric-only handling of alphanumeric postal codes, Maestro/CVV behavior, and selective API skip routes.
