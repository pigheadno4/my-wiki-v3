Q1. What does the PayMe Web Component guide cover, and what cannot be inferred?
A1. It describes desktop QR versus mobile app redirect for existing Web Components, with PayMe support from version 5.56.0 and Sessions/Advanced setups (raw lines 17–46). It does not establish current merchant eligibility, a live-enablement path, an observed QR/app return or a production authorized/captured/settled payment (raw lines 19–46, 226, 260–270). Q2. What version, field and sandbox qualifications matter?
A2. The v6 `PayMe` constructor and v5 `create('payme')` snippets are bounded by the 5.56.0 PayMe floor; the v6 import link points to Drop-in despite the Components guide (raw lines 28, 48–54, 228–258). Both API tables list `channel` and `lineItems` with blank Required cells, and `sku` is v70+; mobile curl and NodeJS examples disagree on `channel` (raw lines 56–84, 156–224). The sandbox maps amount endings to simulated Authorised, ten-minute-expiry OfferCancelled, and request-creation Error; it does not require the PayMe app (raw lines 260–270).
