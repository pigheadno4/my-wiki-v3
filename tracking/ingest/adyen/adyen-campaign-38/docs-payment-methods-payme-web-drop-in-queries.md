# Q1 — Purpose, scope, and inference limit

[[source-adyen-docs-payment-methods-payme-web-drop-in]] is Adyen's 2026-09-15 PayMe guide for an existing Web Drop-in integration, including desktop/laptop QR and mobile-browser PayMe-app routes (pinned raw raw/adyen/docs/payment-methods/payme/web-drop-in/2026-09-15.md:15–30). Its TEST request examples and sandbox amount-ending outcomes do not establish live eligibility, a real authorised payment, capture, or settlement (raw/adyen/docs/payment-methods/payme/web-drop-in/2026-09-15.md:88–226, 234–244). # Q2 — Central capability, prerequisites, warnings

PayMe support starts at Web Drop-in 5.56.0, and the page instructs implementation of both QR and mobile-app flows (raw/adyen/docs/payment-methods/payme/web-drop-in/2026-09-15.md:23–30). Sessions/Advanced each require the matching existing Web Drop-in integration and Customer Area PayMe addition (raw/adyen/docs/payment-methods/payme/web-drop-in/2026-09-15.md:32–48); v6 shows an explicit import (raw/adyen/docs/payment-methods/payme/web-drop-in/2026-09-15.md:50–56). The API tables list `channel` and bounded `lineItems` fields, with `sku` available from Checkout API v70+, but blank Required cells do not establish requiredness (raw/adyen/docs/payment-methods/payme/web-drop-in/2026-09-15.md:62–86). The mobile curl and Node examples disagree on `channel` (`Web` versus literal `Web/iOS/Android`; raw/adyen/docs/payment-methods/payme/web-drop-in/2026-09-15.md:178,215), and sample quantity is a string while the table calls it a number (raw/adyen/docs/payment-methods/payme/web-drop-in/2026-09-15.md:69,111). The PayMe sandbox needs no app and maps 30/81 to simulated `Authorised`, 77/90 to `OfferCancelled` after the stated default ten-minute expiry, and 40/44 to request-creation `Error` (raw/adyen/docs/payment-methods/payme/web-drop-in/2026-09-15.md:234–244).
