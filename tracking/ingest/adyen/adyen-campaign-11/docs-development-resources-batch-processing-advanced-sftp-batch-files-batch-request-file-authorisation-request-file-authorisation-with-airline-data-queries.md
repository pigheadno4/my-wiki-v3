# Fixed retrieval checks — airline-data batch sub-lines

## Q1 — What is this page for, what is its scope, and what should not be inferred?

This 2026-09-15 Adyen page documents airline-data `SL` sub-lines appended to card, IBAN or recurring-payment batch authorisation requests; its tables also refer to capture contexts. It is a field-position and conditional-sub-line reference, not a proof of accepted batch file, validated live data, authorisation/capture or final financial outcome. ## Q2 — What is the central record structure, prerequisites, and warning?

`Airline` has required record identity/sequence/type fields, with its remaining airline and ticket attributes marked optional; including airline data also requires at least one `AirlineLeg` and one `AirlinePassenger`. Their tables specify required positions and independent leg/passenger numbering; `MerchantOrderReference` is optional, though its own fields are required if included. See raw lines 32–45, 70–92, 117–135, and 164–175. Further airline field validation is delegated to the linked airline-data overview (raw lines 30, 76, 123). The full-file examples use Modification/CaptureWithExternalAuth, skip `SL` numbers, and include `DEVL` despite the common FH reference's TEST/LIVE table; treat them as illustrations rather than accepted formats. `PaymentDetails` example values do not define amount/exponent units (raw lines 53–68, 100–115, 147–162); preserve separate batch ACK and transaction-outcome checks through the concept route.
