Q1: What is this page for, what scope does it cover, and what must it not prove?
A: It is the parent `L` line-format reference for an Adyen SFTP RefundWithData *request* file. It describes metadata for corresponding `SL` records, not the child sub-line schema, ACK validation, refund success, or final funds credit. The field-5 ValidationError instruction points to a result structure from within the request page and should be treated as a context mismatch. Q2: What are the required parent fields, reference choices, and limits?
A: Required `L` positions 1–6 are `L`, sequential line number, `MerchantAccount`, merchant account name, `RefundWithData`, and merchant reference. The merchant reference may retain the original authorisation reference or be new for the modification; this is not identified as a PSP reference. Optional field 7 `EchoData` is returned as supplied, max 80 characters, and not used by Adyen. The page states one processing type and one sub-line but leaves that `SL` schema to the child.
