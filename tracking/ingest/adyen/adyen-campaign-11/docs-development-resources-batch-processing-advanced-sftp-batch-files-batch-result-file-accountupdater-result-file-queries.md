# Retrieval checks — Account Updater result file

## Q1. What is this page for, what is its scope, and what must a reader not infer?

This 2020-last-modified Adyen reference defines an Account Updater batch result file's encryption/PAN conditions and the `L` request-metadata and `SL` result record fields. The pinned snapshot was captured 2026-09-15. The encrypted-file rule requires all three conditions; an unencrypted file has no PAN (`raw/adyen/docs/development-resources/batch-processing/advanced-sftp-batch-files/batch-result-file/accountupdater-result-file/2026-09-15.md:14-28`). Validation/parsing errors use a separately linked file structure. The page does not show that stored merchant credentials were updated, that a customer granted new consent, or that a charge, authorization, capture, or settlement succeeded. The `TEST` example is illustrative (`raw/adyen/docs/development-resources/batch-processing/advanced-sftp-batch-files/batch-result-file/accountupdater-result-file/2026-09-15.md:135-154`).

## Q2. What central capability or process does it describe, with prerequisites and warnings?

The file correlates an `L` line (merchant account, request type, merchant reference, conditional line status/EchoData) with an `SL` result for scheduled batch, automatic/API, or real-time Account Updater (`raw/adyen/docs/development-resources/batch-processing/advanced-sftp-batch-files/batch-result-file/accountupdater-result-file/2026-09-15.md:30-77`). `Submitted` in `SL` means the record was sent to and processed by the scheme; `Not Submitted` means it was not, and this field is blank for real-time. `L` `Success` is a line status, not a positive card-change or payment result. `SL` action groups distinguish no change, closed account, PAN/expiry change, Visa-only `ContactCardAccountHolder` withholding updated details at customer request, and error; some groups are excluded for real-time (`raw/adyen/docs/development-resources/batch-processing/advanced-sftp-batch-files/batch-result-file/accountupdater-result-file/2026-09-15.md:78-123`). Field 4 is internally ambiguous for scheduled batch results: one rule describes a PSP reference based on `L` type, another a merchant reference for `AccountUpdaterResult` (`raw/adyen/docs/development-resources/batch-processing/advanced-sftp-batch-files/batch-result-file/accountupdater-result-file/2026-09-15.md:72`). Refusal-reason meaning differs between batch/automatic and real-time, while any new PAN depends on encrypted request, company AccountUpdater PGP key, and card number in the result (`raw/adyen/docs/development-resources/batch-processing/advanced-sftp-batch-files/batch-result-file/accountupdater-result-file/2026-09-15.md:124-133`). These are credential-update result states, not charge outcomes or fresh consent proof.
