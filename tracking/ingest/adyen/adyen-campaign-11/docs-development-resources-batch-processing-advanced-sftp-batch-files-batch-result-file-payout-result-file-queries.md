# Retrieval checks — payout result file

## Q1. What is this page for, what is its scope, and what must a reader not infer?

This Adyen SFTP reference defines a Payout result file's `L` line and `PayoutResult`/`StoreTokenResult` `SL` sub-lines; parsing/validation errors have another file structure (`raw/adyen/docs/development-resources/batch-processing/advanced-sftp-batch-files/batch-result-file/payout-result-file/2026-09-15.md:14-20`). It was last modified 2019-10-25 and captured 2026-09-15. It does not define an original-payment PSP reference, a destination account or amount field in these result tables, a final bank-credit event, or a guarantee that `Received` or `Success` means the recipient was paid.

## Q2. What central capability or process does it describe, with prerequisites and warnings?

The `L` table supplies merchant account/reference, `Payout` processing type, and literal `Received`, `Success`, or `Error` status (`raw/adyen/docs/development-resources/batch-processing/advanced-sftp-batch-files/batch-result-file/payout-result-file/2026-09-15.md:18-33`). `PayoutResult` field 4 is a PSP reference described as for “this modification,” field 5 a result code if available, and fields 6–7 a **stored-token** PSP reference/result code only if the payout request also executed `StoreToken` (`raw/adyen/docs/development-resources/batch-processing/advanced-sftp-batch-files/batch-result-file/payout-result-file/2026-09-15.md:37-49`). A separate `StoreTokenResult` sub-line has its own reference/result code (`raw/adyen/docs/development-resources/batch-processing/advanced-sftp-batch-files/batch-result-file/payout-result-file/2026-09-15.md:51-61`). The `TEST` example pairs payout `Received` with `[payout-submit-received]` and token `Success`; it also uses a `StoreToken` `L` type even though the table lists only `Payout` (`raw/adyen/docs/development-resources/batch-processing/advanced-sftp-batch-files/batch-result-file/payout-result-file/2026-09-15.md:63-72`). Preserve that table/example mismatch. The example demonstrates payout submission receipt and token-result fields, not final disbursement to a bank or card. No original-authorisation PSP field is identified here; do not swap the stored-token reference into that role.
