# Fixed retrieval checks — Modification request file

## Q1 — What is this page for, what is its scope, and what should not be inferred?

This 2026-09-15 Adyen page specifies the common `L` row in an SFTP Modification **request** file and says `SL` record count/types depend on the requested operation. It does not supply all operation-specific sub-line schemas, report `Received` or another result status, or prove capture/refund success. ## Q2 — What are the processing-type and reference fields, and what warnings apply?

The required `L` fields identify record, block-local line sequence, merchant account, and one of `AuthoriseReferral`, `Cancel`, `Capture`, `Refund`, or `CancelOrRefund` (raw lines 20–30). Optional field 6 is a merchant reference that may reuse the original payment authorisation merchant reference or take a new value for this modification; it is not itself a PSP reference. Optional field 7 is echoed, not processed by Adyen (lines 31–33). Follow an operation-specific sub-line page for its fields (lines 35–37), the Modification result-file source for status and PSP references, and the ValidationError result-file source if the result shows `ValidationError` (line 30). The request field-5 list includes `CancelOrRefund` (request raw line 30), while the linked Modification result-file field-5 list includes `CaptureOrRefund` (result raw line 31). The sources do not establish a mapping or returned label for a `CancelOrRefund` request; consult the result source and confirm the applicable mapping with Adyen. A submitted action label is not a final financial outcome; use the same concept→source→raw route.
