Q1: What is this page for, what does it cover, and what must it not establish?
A: A dated Adyen SFTP PayoutModification *result-file* schema for confirm/decline modification rows, with `L` metadata and `ModificationResult` `SL` details. It is not the original payout request, an ACK-validation file, or proof of final bank-side settlement. Validation-error rows use another structure. Q2: Which statuses, references, and warnings matter when interpreting a row?
A: `L` field 5 names `PayoutConfirm`/`PayoutDecline`; field 6 is merchant reference; field 7 is `Success`/`Error`/`Pending`, with Pending meaning postponed modification processing. `SL` field 4 is the modification PSP reference and field 5 is the **original payout** PSP reference; field 6 is a mapped reason/error when applicable. `ValidationError` switches to a separate file structure. The broad error-message list includes unrelated-sounding payment/refund/capture labels and should not be read as proof of those actions or final payout outcome.
