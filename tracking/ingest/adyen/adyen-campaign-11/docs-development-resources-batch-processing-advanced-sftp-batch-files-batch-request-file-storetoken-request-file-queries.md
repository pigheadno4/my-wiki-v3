## Q2. What central capability or process does it describe, with prerequisites and warnings?

The marked-required `L` fields are record type `L`, sequential line number, `MerchantAccount` account type, merchant-account name, lowercase `storeToken` processing type, and a merchant reference (`raw/adyen/docs/development-resources/batch-processing/advanced-sftp-batch-files/batch-request-file/storetoken-request-file/2026-09-15.md:20-28`). The merchant reference may reuse a value referring to the original payment authorisation or use a new value for the modification, but the table does not turn it into a PSP reference. Optional `EchoData` is returned unchanged, is unused by Adyen processing, and is capped at 80 characters (`raw/adyen/docs/development-resources/batch-processing/advanced-sftp-batch-files/batch-request-file/storetoken-request-file/2026-09-15.md:29`). A `ValidationError` in the table points to a different **result-file** shape (`raw/adyen/docs/development-resources/batch-processing/advanced-sftp-batch-files/batch-request-file/storetoken-request-file/2026-09-15.md:26`). This parent page leaves the sub-line fields to its child route, and no formatted line alone proves token creation or a successful payment/payout.
