Q1: What is this page for, what does it cover, and what must it not be taken to prove?
A: It is Adyen's dated advanced-SFTP batch *card Authorisation request* sub-line format reference: mandatory PaymentDetails/Card plus optional conditional record schemas, not an ACK, accepted transaction, authorization outcome, or current account eligibility. Q2: What are the central capability, prerequisites, positional fields, and warnings?
A: PGP encryption is required to submit these sub-lines; PaymentDetails and Card are mandatory, Card is SL 2, and SL counters increment. PaymentDetails positions 4–6 are amount/exponent/ISO currency, position 7 shopper reference becomes required for recurring use; blank optional positions retain delimiters. Card positions 4–8 contain PAN, MM/YYYY expiry, CVC (three digits for Visa/Mastercard/Discover, four for AmEx), and cardholder name. Optional Address, MerchantOrderReference, and ShopperInteraction have their own schemas; MOTO/recurring requires ShopperInteraction. The raw examples are illustrative: one joins FH/BH and another skips SL,5; neither establishes file acceptance or payment authorization.
