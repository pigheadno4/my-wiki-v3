# Retrieval checks — modification result file

## Q1. What is this page for, what is its scope, and what must a reader not infer?

This 2019-last-modified Adyen reference describes SFTP batch Modification result-file `L` and `SL` records and points parsing/validation errors to a separate file shape (`raw/adyen/docs/development-resources/batch-processing/advanced-sftp-batch-files/batch-result-file/modification-result-file/2026-09-15.md:14-20`). The snapshot was captured 2026-09-15. The opening describes a “successful modification” result file, but the same page defines `Error` and `Pending` statuses and shows two error rows (`raw/adyen/docs/development-resources/batch-processing/advanced-sftp-batch-files/batch-result-file/modification-result-file/2026-09-15.md:34-36,76-86`). Do not infer every row succeeded, that `Received` or `Authorised` are statuses in this file, that a payment was authorised, or that a capture/refund reached its final financial outcome.

## Q2. What central capability or process does it describe, with prerequisites and warnings?

The `L` line holds merchant account, one of `Cancel`, `Refund`, `Capture`, `CaptureOrRefund`, or `AuthoriseReferral`, an optional request-supplied merchant reference, `Success`/`Error`/`Pending` status, and optional echoed data. `Pending` means processing needs postponement; `ValidationError` uses another result-file structure (`raw/adyen/docs/development-resources/batch-processing/advanced-sftp-batch-files/batch-result-file/modification-result-file/2026-09-15.md:18-37`). The `SL` line's field 4 is the PSP reference for **this modification** and field 5 is the PSP reference for the **original payment authorisation**. Field 6 is a refusal/error reason when applicable, with possible messages listed in the raw (`raw/adyen/docs/development-resources/batch-processing/advanced-sftp-batch-files/batch-result-file/modification-result-file/2026-09-15.md:39-74`). The `TEST` sample has one Capture success plus Capture and Refund errors; its matching L merchant-reference and SL modification-PSP-reference strings do not make those field identities equivalent (`raw/adyen/docs/development-resources/batch-processing/advanced-sftp-batch-files/batch-result-file/modification-result-file/2026-09-15.md:76-89`). A reported error does not itself establish retry safety, and these row statuses do not replace later payment-modification outcome evidence.
