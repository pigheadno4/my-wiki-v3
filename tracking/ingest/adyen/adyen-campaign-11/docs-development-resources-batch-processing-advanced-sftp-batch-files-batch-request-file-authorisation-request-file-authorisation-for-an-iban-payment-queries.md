Q1: What is this page for, what does it cover, and what must it not be taken to prove?
A: A dated Adyen advanced-SFTP batch Authorisation request sub-line schema for IBAN bank-transfer/SEPA Direct Debit payments. It covers PaymentDetails, IBAN, and optional address/order-reference records. It does not establish file validation, payment authorization, debit settlement, or an individual financial result. Q2: What are the central fields, prerequisites, rejection rules, and example warning?
A: Mandatory PaymentDetails and IBAN sub-lines; IBAN is SL 2, SL counters increment, and empty optional fields retain commas. PaymentDetails fields 4–6 are amount, currency exponent and ISO currency; shopper reference at field 7 is required for recurring payments/contracts. IBAN fields 4–6 are owner name, two-letter country and IBAN; BIC at field 7 is optional. Owner name must be at least three alphanumeric characters and not only numbers (invalid format error 203); invalid country code rejects the transaction/request. Optional billing/delivery Address lines are separate; MerchantOrderReference is optional. Its example erroneously uses Card on this IBAN page, so prefer the IBAN field table.
