# Fixed-query probes — Adyen batch file naming and structure

## Q1 — purpose, scope, and non-inference

**Question:** What does Adyen's batch file naming and structure guide define, and what do valid names or ACKs not prove?

**Answer:** The captured reference defines filename patterns for advanced SFTP batch **request**, **result**, and **ACK** files and common CSV structure. A request uses `[Submission Platform]_[File Sequence Number]_[FileType].csv`; results add `_result` or `_result_enc`, and ACKs add `_ack`. It also requires an `FH` sequence matching the filename, a header/trailer and one file type per file. A valid name or ACK is a file/validation signal, not proof of PGP protection, every record's processing, payment authorization, payout completion or settlement. The naming page's error-only ACK wording is incomplete alongside the dedicated ACK page, which documents success and failure ACKs. Read [[source-adyen-docs-development-resources-batch-processing-advanced-sftp-batch-files-batch-file-naming-and-structure]] through [[adyen-batch-processing]] and [[source-adyen-docs-development-resources-batch-processing-advanced-sftp-batch-files-batch-acknowledgement-file]] for ACK status. Evidence: [[raw/adyen/docs/development-resources/batch-processing/advanced-sftp-batch-files/batch-file-naming-and-structure/2026-09-15|naming raw snapshot]] lines 18–24, 47–70 and 72–99; [[raw/adyen/docs/development-resources/batch-processing/advanced-sftp-batch-files/batch-acknowledgement-file/2026-09-15|ACK raw snapshot]] lines 18–25.

## Q2 — capability, prerequisites, and warnings

**Question:** How should submission-platform sequence numbers and file structure be handled, and what risks do duplicates or gaps create?

**Answer:** Each request filename must be unique. The sequence belongs to its submitting platform/server and increments **by one after each successful file submission**; the page says reused numbers and nonconsecutive gaps are rejected. The file header's sequence must match the filename. The `.csv` file has a header/trailer, exactly one allowed file type, UTF-8 encoding, no multiline fields, and delimiter placeholders for genuinely optional fields to keep the fixed column count for a transaction type. The page lists seven allowed file types. Its line-97 example calls FH field 9 optional, but the common request-file table marks FH field 9 **FileType required**; keep that field populated. Read [[source-adyen-docs-development-resources-batch-processing-advanced-sftp-batch-files-batch-request-file]] and its [[raw/adyen/docs/development-resources/batch-processing/advanced-sftp-batch-files/batch-request-file/2026-09-15|raw field table]] lines 46–56 for that conflict. A rejected file's next number should not be guessed from the filename alone: the ACK guide warns its `NextFileSubmissionNumber` after errors may be a guess and is always wrong when the header cannot be parsed. Do not resubmit blindly or read an ACK as a financial outcome.
