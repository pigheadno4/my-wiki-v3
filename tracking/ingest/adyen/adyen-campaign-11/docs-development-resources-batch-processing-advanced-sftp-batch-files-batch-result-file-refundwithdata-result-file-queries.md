# Retrieval checks — RefundWithData result file

## Q1. What is this page for, what is its scope, and what must a reader not infer?

This Adyen SFTP reference defines the `L` and `SL` records for a **RefundWithData result file** and routes parsing/validation errors to a different file shape (`raw/adyen/docs/development-resources/batch-processing/advanced-sftp-batch-files/batch-result-file/refundwithdata-result-file/2026-09-15.md:14-20`). It was last modified 2019-10-25 and captured 2026-09-15. The result table does not give an amount or currency field; those appear in a separate request guide. It does not prove the amount actually refunded, receipt by the shopper, settlement, or that retrying a failed-looking row is safe.

## Q2. What central capability or process does it describe, with prerequisites and warnings?

The `L` row gives merchant account, fixed `RefundWithData` type, merchant reference, and one of `Success`, `Authorised`, `Refused`, `Cancelled`, `Received`, or `Error`; the page does not explain a complete transition among those states (`raw/adyen/docs/development-resources/batch-processing/advanced-sftp-batch-files/batch-result-file/refundwithdata-result-file/2026-09-15.md:18-36`). The `SL` row contains `RefundWithDataResult`, the **original payment** PSP reference, an authorisation code only when the payment is authorised, a result code if available, and a refusal/error reason when applicable (`raw/adyen/docs/development-resources/batch-processing/advanced-sftp-batch-files/batch-result-file/refundwithdata-result-file/2026-09-15.md:38-48`). The `TEST` example's `L` and `SL` both show `Received`, with no authorisation code (`raw/adyen/docs/development-resources/batch-processing/advanced-sftp-batch-files/batch-result-file/refundwithdata-result-file/2026-09-15.md:50-59`). That example is not an `Authorised` result or proof of final refund. The result-file tables have no amount/exponent/currency fields; retrieve the separate RefundWithData request schema for those requested inputs. A file-row status remains distinct from the later financial refund outcome.
