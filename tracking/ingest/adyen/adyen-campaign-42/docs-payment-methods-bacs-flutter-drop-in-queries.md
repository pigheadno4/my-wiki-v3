## Q2. What are the central capability, prerequisites and warnings?

Sessions requires existing Flutter Drop-in Sessions, Checkout API **v68+**, Support addition in Customer Area and required `shopperEmail` on `/sessions`; no BACS-specific Drop-in config is needed (`:25-45,341-345`). Advanced requires an existing Flutter Drop-in Advanced flow and BACS addition; `/payments` requires `shopperEmail`, `type=directdebit_GB`, holder name, account number and bank routing number (`:414-445`). Its v72 TEST example does not state a new Advanced API minimum (`:449-472`). Initial `/payments` tokenization uses `shopperReference` and `storePaymentMethod: true`; the token arrives through `recurring.token.created` and subsequent `/payments` uses stored ID, shopper reference and `ContAuth` (`:347-400,820-873`). The guide strongly recommends explicit permission and notice before each recurring debit, but states notice is required when amount or collection date changes under the Direct Debit Guarantee (`:355-357,371-376`). Advanced prose requires `action.type: Direct` and links to a redirect anchor, while its displayed response has `voucher` and `Received`; this conflict must remain visible, with final outcome determined through webhooks (`:423,805-817,873`).
