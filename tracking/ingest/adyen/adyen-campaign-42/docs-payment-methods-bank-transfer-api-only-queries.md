## Q1 — What is this page for, and what cannot be inferred?

[[source-adyen-docs-payment-methods-bank-transfer-api-only]] is the API-only virtual-account Bank Transfer guide for an existing merchant-built checkout: it returns instructions that the shopper uses in their own bank environment (raw lines 15–19, 42–50, 71–111). It is not a bank redirect or merchant-initiated debit. Initial `resultCode: Received` is not funds receipt: the payment stays Open until funds arrive and the merchant confirms a matching `AUTHORISATION` webhook (raw lines 82–152). The related [[source-adyen-docs-payment-methods-bank-transfer|Bank Transfer overview]] likewise separates selection/account issuance from shopper transfer and funds webhook (overview raw lines 19–31). This 2026-09-15 snapshot and the TEST promotion flow do not prove current enablement or a live transfer (this raw lines 2, 11, 170–180).

## Q2 — What central capability, prerequisites, and warnings are stated?

The page requires an existing API-only integration, standard webhooks and Support activation; Support configures the shopper reference choice between short PSP reference and merchant request reference, which the source says cannot later change (raw lines 21–27, 80). `/paymentMethods` uses EUR and a supported European country, then `/payments` uses `bankTransfer_IBAN`, required country and an API-required `returnUrl` that is unused because the shopper is not redirected (raw lines 29–50). The action contains beneficiary, virtual IBAN/BIC, amount and reference to display with instructions; localized virtual accounts are DE/FR/NL, with NL default for other codes, and EUR beneficiary is Adyen NV (raw lines 49, 71–111). Funds arrival is confirmed by `AUTHORISATION` success after Open, not by `Received`; the sample webhook amount differs from the request, so it is not a reconciled payment trace (raw lines 57–59, 82–152). Subsequent tokenized EUR recurring payments use `sepadirectdebit`, a different debit method requiring separate mandate authority (raw lines 154–168). TEST settlement is simulated once daily, the test section misspells the webhook `AUTORISATION`, and live activation requires Support (raw lines 170–180).
