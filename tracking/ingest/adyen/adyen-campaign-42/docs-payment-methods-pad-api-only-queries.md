## Q1 — What is this source's purpose and scope, and what cannot be inferred?

## Q2 — What central capability, prerequisites and warnings should the answer retain?

The API-only guide calls for Notice of Change webhook subscription, Support setup and shopper mandate collection (pinned raw lines 23–38). Collect account number, branch ID, bank code and owner name, request available methods with CA/CAD, and send required `eft_directdebit_CA` bank fields in `/payments` (lines 40–60, 94–108). The primary curl examples omit a continuation after `-X POST`; the payment example also represents amount and `storePaymentMethod` as JSON strings although the surrounding prose calls for a true storage flag (lines 64–79, 110–146). Token response fields require creation parameters plus enabled Recurring details; a returned mandate ID does not replace collecting the shopper agreement (lines 148–157, 194–205). `Authorised` is bank-pending for up to five business days, with eventual settlement-report or chargeback evidence (lines 183–192). Test returns can be triggered by `chargeback:<reason>`; only codes 01 and 08 are marked retryable once within 30 days, while agreement/stop/revocation codes require other resolution (lines 222–253). Live PAD setup needs Support (lines 255–257).
