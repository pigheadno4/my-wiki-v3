Q1. What is this document's purpose and scope, and what must not be inferred?
A1. The 2026-09-15 Platforms catalog identifies webhook families, event types and broad structure for resource changes, requests and balance movements (raw lines 15–46). It is a navigation/meaning guide, not a delivered-event log, subscription proof, money-movement confirmation or bank receipt. Q2. What is the central capability, what prerequisites and consequential warnings apply?
A2. Use the webhook `type`, type-specific `data`, optional `data.status`, and environment to distinguish configuration objects, onboarding, payment-method requests, transfer requests/status, balance changes, negative-balance warnings and report readiness (raw lines 25–46, 80–197). Transfer `created` is a request, payout-schedule execution `succeeded` is initiation with a `transferId`, and negative-balance compensation warning is only a scheduled transfer; each needs later event-specific evidence for booking/finality (raw lines 98–111, 154–173, 183–189). Payment webhooks are deprecated in favor of transfer webhooks, the initial group list omits the later Balance section, and several managed-payout labels contain spacing anomalies, so check the linked schemas before using exact event IDs (raw lines 25–32, 100–111, 175–181, 199–210).
