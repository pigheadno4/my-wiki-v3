# Fixed retrieval checks — Platforms payout components

Q1. What do these components show, what limits their coverage, and what financial outcome is not proven?
- Expected: This 2026-09-15 Adyen for Platforms guide describes UI components for payout reporting: Payouts Overview lists automatic payouts for a selected balance account and period, with captured funds, aggregated adjustments and net payout; Payout Details adds breakdown and remaining balance. The components rely on the Balance Platform Payout Report and the guide states automatic-payout/default-settlement-delay scope, excluding manual, pass-through and sales-day T+0 payouts. The page calls net payout the final amount credited to the user's bank account, but a component value or completed label is not independent bank-statement or transfer-outcome proof. It is a view, not a payout initiation or execution API, and features may vary by library version.

Q2. Which access/session, filter, version and example-conflict details matter before embedding a view?
- Expected: A Platforms integration, Balance Platform API key for Session Authentication API, Adyen-assigned `Payouts Overview Component: View` role and generated Balance Platform Payout Report are prerequisites; check language, region and browser support. The platform server creates `/sessions` with `allowOrigin` (HTTPS only on live), `product: platform`, and policy resources for the account holder plus the View role. The client receives/refreshes the complete session object through `onSessionCreate`, then initializes and mounts the npm or CDN-SRI library. The overview period uses UTC+0 and defaults to last 30 days. Details is modal by default or separate; the Details table defines `id` as balance account ID and `date` as ISO payout date, while `onRecordSelection` yields balanceAccountId/date. A later sample uses `<SELECTED_PAYOUT_ID>` for `id`, and the standalone sample misses a comma after `id`; resolve those conflicts for the selected version rather than copying blindly. `availableTranslations` is deprecated; customization/localization fields are optional and version-sensitive. Authentication or rendering does not execute a payout.
