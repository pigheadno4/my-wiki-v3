## Q1 — identity and flow scope
Query: What does Boleto Bancário Web Drop-in require in Sessions versus Advanced?
Expected: Method-specific Web Drop-in add-on; Sessions requires Checkout API v68+, Customer Area addition, shopperName, billingAddress and CPF/CNPJ socialSecurityNumber; optional due-date field is deliverAt. Advanced requires voucher action handling plus paymentMethod.type boletobancario and the same shopper identity/address fields; optional due-date field is deliveryDate. Do not conflate the two field names or treat overview BR/BRL as evidence that any sample ran. The Advanced base link has a platform template placeholder. ## Q2 — voucher timing, instructions and paid state
Query: Does PresentToShopper mean the Boleto is paid, and how do due date/test/live steps work?
Expected: No. Boleto is offline; Advanced returns PresentToShopper with voucher action, PDF/barcode/expiry/amount fields. Default due date is five days; weekend/holiday can allow next-working-day payment. Custom shopperStatement should disallow amount mismatch and payment after due date; default Portuguese instructions await confirmation before order processing. The overview separately says unpaid offer remains open 15 days after due date before Offer cancelled. Test Customer Area can manually promote a pending offer to sale for reconciliation, not real payment; live requires separate Customer Area request.
