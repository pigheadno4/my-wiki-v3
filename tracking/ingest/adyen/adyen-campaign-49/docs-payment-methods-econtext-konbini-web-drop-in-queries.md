## Q2 — setup, optional fields and test conflict

**Query:** What setup and fields does the captured Japanese convenience-store Web Drop-in guide specify, and how should its 7-Eleven simulator instructions be read?

**Expected answer:** The guide lists Customer Area additions for eContext Convenience Stores (Lawson, Mini Stop, Family Mart, Seicomart), eContext PayEasy ATM, eContext PayEasy Online Banking, and eContext 7Eleven (pinned `raw/adyen/docs/payment-methods/econtext-konbini/web-drop-in/2026-09-15.md`, `## Requirements` lines 21–29). For Web Drop-in v6 it imports `Econtext`; no extra payment fields or required Drop-in-specific configuration are stated (lines 31–50). Optional `personalDetailsRequired: false` hides name/email/telephone, added in v5.2.0 and defaulting true (lines 52–79). The example has markup in a JavaScript comment and an unquoted mount selector (lines 62–90), so is not copy-ready. **Conflict:** line 95 says 7-Eleven voucher payments can only be tested live with Support for penny testing, while simulator step 3 offers a 7-Eleven choice (lines 111–115); the source does not establish test-environment 7-Eleven payment coverage. The simulator instructs waiting 15 minutes for a webhook; pending/expired vouchers appear in test Offers, paid vouchers in Payment list, and live acceptance requires a live Customer Area method request (lines 97–128). The method overview additionally states a 7-Eleven local-entity condition.
