# Fixed query answers — api-explorer-balanceplatform-webhooks-latest-post-balanceplatform-balanceaccount-recurringtopup-updated

Q1. The captured API Explorer `latest` page defines Adyen's incoming `balancePlatform.balanceAccount.recurringTopUp.updated` event after a recurring top-up configuration is successfully updated for a balance account, not a merchant operation. The required envelope fields are `data`, `environment`, and `type`; `data.accountId` and `data.webhookTopUpConfiguration` are required. Within the configuration, `id`, `counterparty`, `description`, `status`, `topUpAmount`, and `trigger` are required; fixed/target amount and schedule/threshold are described without nested required-property tables. Active enables pulling funds; inactive disables triggering. See [canonical reference](https://docs.adyen.com/api-explorer/balanceplatform-webhooks/latest/post/balancePlatform.balanceAccount.recurringTopUp.updated), raw lines 5–32, via [[source-adyen-api-explorer-balanceplatform-webhooks-latest-post-balanceplatform-balanceaccount-recurringtopup-updated]] and [[adyen-webhooks]].

Q2. The event establishes a successful configuration update, with the current configuration status in the payload; it does not establish a debit request, debit success, balance booking or bank receipt. Disabled reason/detail are conditional on inactive status; the inactive EUR example is illustrative (raw lines 22–29, 34–76). The page says 2xx accepts a webhook (lines 77–96), but does not itself specify delivery order, retries/deduplication, signatures, transfer reversal or finality. `latest` is the captured route label, not proof of a currently deployed version. [Canonical reference](https://docs.adyen.com/api-explorer/balanceplatform-webhooks/latest/post/balancePlatform.balanceAccount.recurringTopUp.updated); [[source-adyen-api-explorer-balanceplatform-webhooks-latest-post-balanceplatform-balanceaccount-recurringtopup-updated]].
