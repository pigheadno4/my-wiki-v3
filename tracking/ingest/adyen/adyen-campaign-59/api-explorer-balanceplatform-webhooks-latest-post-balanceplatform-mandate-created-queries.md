# Fixed query answers — api-explorer-balanceplatform-webhooks-latest-post-balanceplatform-mandate-created

Q1. Adyen's captured API Explorer `latest` page defines incoming `balancePlatform.mandate.created` after creation of a direct debit mandate, linked to the UK direct-debit guide. Required top-level fields are `data`, `environment` and `type`. `data.balancePlatform` and `data.mandate` are optional, as are every listed nested mandate identifier, counterparty, date, status and type. Status can be pending, approved or cancelled; the listed type is bacs. See [canonical reference](https://docs.adyen.com/api-explorer/balanceplatform-webhooks/latest/post/balancePlatform.mandate.created), raw lines 5–27, via [[source-adyen-api-explorer-balanceplatform-webhooks-latest-post-balanceplatform-mandate-created]] and [[adyen-business-accounts]].

Q2. Creation of the mandate resource does not prove approval, a direct-debit request, booked funds or bank receipt. The page supplies no example or state sequence and says any 2xx accepts the webhook (raw lines 29–37). It does not establish event ordering, retries/deduplication, signature verification, failure/reversal behavior or payment finality. `latest` is the captured route label, not current-version proof. [Canonical reference](https://docs.adyen.com/api-explorer/balanceplatform-webhooks/latest/post/balancePlatform.mandate.created); [[source-adyen-api-explorer-balanceplatform-webhooks-latest-post-balanceplatform-mandate-created]].
