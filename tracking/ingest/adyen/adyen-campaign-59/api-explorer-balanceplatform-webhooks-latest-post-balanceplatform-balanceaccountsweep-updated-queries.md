# Fixed retrieval answers: balancePlatform.balanceAccountSweep.updated

## Q1

The 2026-09-15 captured Balance Platform webhook reference says Adyen sends `balancePlatform.balanceAccountSweep.updated` when a sweep update succeeds. The body requires `data`, `environment` and `type`; `data.accountId`, `balancePlatform` and `sweep` are optional. Within a present sweep, `counterparty`, `currency`, sweep `id` and `schedule` are marked required. Counterparty requires one of balance-account, transfer-instrument or merchant-account identifiers, depending on direction. The optional sweep `type` defaults to push; status defaults to active and inactive disables triggering. The optional trigger threshold defaults to zero and is evaluated on the schedule: pull at or below it, push at or above it. See pinned raw lines 5–36, with test example at 40–70. ## Q2

This event establishes successful sweep-configuration update, not that a scheduled sweep fired or funds moved. The reference describes bank and internal categories, alternative sweep/target amount settings, currency matching, and ordered bank-transfer priority preferences. Its example is an inactive weekly EUR push sweep with zero target/trigger and another balance account as counterparty; example fields are not universal requirements. Any `2xx` accepts the webhook, which is a receipt acknowledgment rather than proof of transfer booking, payout or bank receipt. The captured page does not specify event ordering, retries, deduplication, signature verification or final transfer outcome, and `latest` is only its captured URL label. See pinned raw lines 18–33, 40–80.
