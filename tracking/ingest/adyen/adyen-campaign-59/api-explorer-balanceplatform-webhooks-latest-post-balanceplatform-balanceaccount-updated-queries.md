# Fixed retrieval answers: balancePlatform.balanceAccount.updated

## Q1

The 2026-09-15 captured Balance Platform webhook reference says Adyen sends `balancePlatform.balanceAccount.updated` after a successful balance-account update, linked to the separate Balance Platform PATCH endpoint. The body requires `data`, `environment` (`test` or `live`) and `type`; `data.balanceAccount` is optional, while its `accountHolderId` and balance-account `id` are marked required within that object. The balance-platform identifier and queued-event timestamp are optional. The example shows a test event with those IDs, EUR default currency, active status and Amsterdam time zone; it does not establish their universal presence. See pinned raw lines 5–30 and 34–50; route: [[source-adyen-api-explorer-balanceplatform-webhooks-latest-post-balanceplatform-balanceaccount-updated]], https://docs.adyen.com/api-explorer/balanceplatform-webhooks/latest/post/balancePlatform.balanceAccount.updated.

## Q2

The reference establishes a notification triggered by a successful balance-account update, not a payment, booking, settlement, payout or bank-receipt outcome. Its optional `balances` field is a list of amounts/currencies, not evidence that the example or every event contains a balance change. The field descriptions say default currency is immutable after creation and omission of existing metadata keys in an update deletes those keys; that is update behavior, not webhook-omission semantics. Any `2xx` accepts the webhook, which is only an acknowledgment. The captured reference does not specify delivery ordering, retries, deduplication, signature verification or event finality, and `latest` is merely the captured URL label. See pinned raw lines 17–30 and 52–60; route: [[source-adyen-api-explorer-balanceplatform-webhooks-latest-post-balanceplatform-balanceaccount-updated]], https://docs.adyen.com/api-explorer/balanceplatform-webhooks/latest/post/balancePlatform.balanceAccount.updated.
