# C59 fixed query answers — balance-account sweep created webhook

## Q1

The captured incoming Adyen Balance Platform POST event is `balancePlatform.balanceAccountSweep.created`, sent when a sweep is successfully created. It identifies a sweep configuration; `data.accountId`, `data.balancePlatform`, and `data.sweep` are optional in the request-body table, while outer `data`, `environment`, and `type` are required. If `sweep` is present, its nested rows require `counterparty`, `currency`, `id`, and `schedule`. The counterparty requires one of balance-account, transfer-instrument, or merchant-account identity, depending on direction. Optional `type` defaults to push; optional `status` defaults to active. Schedule and trigger threshold control when a push or pull may occur; `sweepAmount` and `targetAmount` are alternatives. The example shows an active weekly EUR push to another balance account in test. The `latest` path does not resolve a numbered API version. ## Q2

This event establishes successful sweep configuration creation, not that a scheduled threshold was met, that a push/pull transfer occurred, or that funds were booked or received. The example's active status and zero amounts are illustrative. The response table says any `2xx` accepts the webhook; it does not make acknowledgement financial proof. This pinned page states no delivery order, retry/deduplication, signature-verification, or transfer-finality guarantee; it also does not resolve `latest` to a numbered version.
