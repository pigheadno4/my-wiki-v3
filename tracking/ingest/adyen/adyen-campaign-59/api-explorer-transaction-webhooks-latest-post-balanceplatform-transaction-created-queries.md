# Fixed query answers — api-explorer-transaction-webhooks-latest-post-balanceplatform-transaction-created

Q1. The captured API Explorer `latest` reference defines Adyen's incoming `balancePlatform.transaction.created` event after a transfer is booked in a balance account. `data` and `environment` are required; top-level `type` is optional in the schema. Required `data` includes account-holder and balance-account objects, balance platform, amount with currency/minor-unit value, booking/value dates, transaction `id` and status. The transaction ID differs from optional related `transfer.id`. The status enum lists pending/booked, even though the introduction says after booking; examples show booked outgoing bank and incoming internal entries. See [canonical reference](https://docs.adyen.com/api-explorer/transaction-webhooks/latest/post/balancePlatform.transaction.created), raw lines 5–45 and 47–170, via [[source-adyen-api-explorer-transaction-webhooks-latest-post-balanceplatform-transaction-created]].

Q2. The event documents a balance-account ledger entry, not external-bank receipt or full transfer finality. The page's after-booking introduction conflicts with its pending status option, so do not derive a universal transition; the internal incoming example has a positive amount but a debit-oriented description (raw lines 7, 37, 89–126). A 2xx accepts the webhook (lines 171–179), without delivery order, retry/deduplication or signature semantics here. The `latest` route is captured, not current-version proof.
