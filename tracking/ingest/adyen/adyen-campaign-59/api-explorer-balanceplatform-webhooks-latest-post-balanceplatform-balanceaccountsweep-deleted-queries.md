# Fixed query answers — api-explorer-balanceplatform-webhooks-latest-post-balanceplatform-balanceaccountsweep-deleted

Q1. This captured API Explorer `latest` reference defines Adyen's incoming `balancePlatform.balanceAccountSweep.deleted` event after successful deletion of a sweep configuration. Required body fields are `data`, `environment` and `type`; `data.accountId`, `balancePlatform` and `sweep` are optional. If the sweep object is present, the table marks `counterparty`, `currency`, `id` and `schedule` required. The sweep can describe bank/internal category, push/pull direction, schedule and threshold, but those nested descriptions do not make deletion a transfer. See [canonical reference](https://docs.adyen.com/api-explorer/balanceplatform-webhooks/latest/post/balancePlatform.balanceAccountSweep.deleted), raw lines 5–36, via [[source-adyen-api-explorer-balanceplatform-webhooks-latest-post-balanceplatform-balanceaccountsweep-deleted]] and [[adyen-webhooks]].

Q2. The event establishes configuration deletion, not transfer execution, reversal, booked balance movement or bank receipt. The test example contains `status: active` within a deleted sweep; this is illustrative payload context, not proof it remains active (raw lines 38–71). A 2xx accepts the webhook (lines 72–80). The page itself does not specify delivery order, retry/deduplication, signature verification or financial finality; `latest` is a captured route label, not current-version proof.
