# C59 fixed query answers — recurring top-up deleted webhook

## Q1

The captured Adyen Balance Platform webhook POST reference says Adyen sends `balancePlatform.balanceAccount.recurringTopUp.deleted` when a recurring top-up is successfully deleted from a balance account. This is a configuration deletion event. Required request-body fields are `data`, `environment`, and `type`; required `data` children are `accountId` and `webhookTopUpConfiguration`. The latter requires `counterparty`, `description`, configuration `id`, `status`, `topUpAmount`, and `trigger`. The table makes `data.balancePlatform`, `creationDate`, `data.id`, `timestamp`, `mandate`, and `referenceForBeneficiary` optional. `accountId` and configuration `id` are distinct identities. The status descriptions are active/inactive; top-up amount can be fixed or target, and the trigger can be schedule or minimum balance threshold. The example shows `type` exactly as the event name and a test environment, but no numbered version is established by the `latest` route. ## Q2

The opening statement establishes successful deletion of the recurring-top-up configuration. It does not establish a completed debit, top-up transfer, booked balance credit or bank receipt. The deletion example still shows `status: active`; that example must not be read as a post-deletion state guarantee. The response section only specifies that any `2xx` accepts the webhook. This pinned event page does not state delivery order, retry/deduplication, signature verification, or finality guarantees; it also does not resolve `latest` to a numbered version.
