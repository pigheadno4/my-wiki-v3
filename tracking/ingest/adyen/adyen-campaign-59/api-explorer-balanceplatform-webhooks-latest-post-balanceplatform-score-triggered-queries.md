# C59 fixed query answers — Score signal triggered webhook

## Q1

The captured incoming Adyen Balance Platform POST event is `balancePlatform.score.triggered`. It is sent when a Score signal is triggered against an account holder for merchants opted in to Score. Outer `data`, `environment`, and `type` are required; all listed `data` children, including account-holder details, account-holder status, automated actions, platform ID, resource ID, risk score, signal names and source types, are optional. The example is a test event with `Active` account-holder status, score 67, six named signals, one signal source type and `bumpKYCTier` action. The linked Platforms Score guide identifies example `data.id` as a score calculation/recalculation ID, separate from `accountHolder.id`; the event page alone calls it an ID of the resource. The `latest` path does not resolve a numbered version. ## Q2

The event establishes that a signal was triggered under the stated Score opt-in scope. Its example does not establish confirmed fraud, a universal risk threshold, changed KYC status, payout blocking, payment or fund movement. The optional action and score fields are not guaranteed in every payload; the example action is not proof of an actual merchant-account outcome. Any `2xx` accepts the webhook, not a risk or financial result. This pinned event page gives no delivery order, retry/deduplication, signature-verification, or finality guarantee, and its `latest` route provides no numbered version.
