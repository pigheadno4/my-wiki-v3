# Fixed query answers — api-explorer-capital-webhooks-latest-post-balanceplatform-grants-created

Q1. The captured API Explorer `latest` page defines Adyen's incoming `balancePlatform.grants.created` event after a grant is created. Required top-level body fields are `balances` (currency, fee, principal, total), `grantAccountId`, `grantOfferId`, grant `id` and `status`; optional `counterparty` can identify holder, balance account or transfer instrument. Required `status.code` spans requested/review/approval, active, repayment and failure/cancellation labels; optional actions have required code and resolved fields per item. See [canonical reference](https://docs.adyen.com/api-explorer/capital-webhooks/latest/post/balancePlatform.grants.created), raw lines 5–30, via [[source-adyen-api-explorer-capital-webhooks-latest-post-balanceplatform-grants-created]] and [[adyen-capital]].

Q2. Grant creation and the listed principal/fee/total do not prove disbursement, balance-account booking, bank receipt or repayment. The page has no request example or transition sequence; 2xx accepts the notification (raw lines 32–40). It does not specify delivery order, retries/deduplication, signatures, reversal or financial finality. `latest` is the captured route label, not current-version proof. [Canonical reference](https://docs.adyen.com/api-explorer/capital-webhooks/latest/post/balancePlatform.grants.created); [[source-adyen-api-explorer-capital-webhooks-latest-post-balanceplatform-grants-created]].
