# Original query answers: api-explorer-management-latest-patch-companies-companyid-terminalsettings

- Q1: The 2026-11-05 Management API v3 reference documents `PATCH /companies/{companyId}/terminalSettings` on its listed TEST server. Required `companyId` identifies the company; terminal settings flow to company terminals unless merchant, store or terminal values override them. The API credential needs Terminal settings read and write, plus Advanced read and write for sensitive settings; live calls are rate-limited. Request body groups are optional, but changing a parameter requires its full containing object. Reset to the Adyen PSP inherited value uses that full object with the parameter empty or omitted; a wholly omitted object is not updated. The schema covers receipts, connectivity, DCC, gratuities, hardware, kiosk/localization, MOTO, Terminal API integration, offline payments, refunds, surcharge, Wi-Fi and other device settings. Conditional examples include store-and-forward maxAmount/maxPayments/supportedCardTypes configured or inherited; required children of supplied Wi-Fi profiles and surcharge configurations. The 200 response returns settings groups, largely optional; no per-device status field or propagation time is supplied. [[source-adyen-api-explorer-management-latest-patch-companies-companyid-terminalsettings]]; https://docs.adyen.com/api-explorer/Management/latest/patch/companies/(companyId)/terminalSettings; verified raw lines 5–196 and 289–454.
- Q2: A 200 response says the PATCH request succeeded and returns a settings representation. It does not establish that every terminal has applied settings, that a lower-level override was replaced, that a SIM can be changed at company scope, or that a Terminal API integration or payment is working. Credential roles gate the operation, with 401/403 authentication/permission errors; 400, 422 and 500 are also listed. The raw documents no idempotency key, deletion/reversal process, asynchronous approval/activation outcome or device propagation timing. First contactless-currency change needs Adyen contact and a compliance check; enabling DCC carries receipt/terms obligations, and unreferenced refunds carry stated fraud/duplicate liability. The TEST snapshot and examples do not prove current live account eligibility, compliance, authorizations, captures, settlement or bank receipt.
