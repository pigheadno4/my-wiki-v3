## Q1

The 2026-11-05 capture of the Management API `latest` GET reference describes reading one webhook configuration under `GET /companies/{companyId}/webhooks/{webhookId}`. It lists the TEST server `https://management-test.adyen.com/v3` and requires the caller's API credential to have `Management API—Webhooks read` or `Management API—Webhooks read and write`. Both path IDs are required strings: `companyId` names the company account, while `webhookId` names the webhook configuration; neither is the API credential ID. No query parameter or request body is specified. A `200` returns configuration with required `active`, `communicationFormat`, `type`, and `url`; `_links` is optional, but its `generateHmac`, `self`, and `testWebhook` children are marked required when that parent appears. Optional company and merchant links are scope-qualified. Optional fields include error and password flags, HMAC key check value, certificate acceptance, additional Standard-webhook settings and merchant-account filters. The three certificate-acceptance flags default to false; an unspecified encryption protocol is described as TLSv1.2, with HTTP allowed only on Test. The prose requires `filterMerchantAccounts` for `includeAccounts` or `excludeAccounts`, but not `allAccounts`; this is response-configuration conditionality, not another GET input.
