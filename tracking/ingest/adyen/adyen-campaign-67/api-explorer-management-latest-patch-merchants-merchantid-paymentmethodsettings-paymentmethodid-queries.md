## Q2

A `200` says the settings update request succeeded and may show configuration and status fields; `204` says it was processed without a body. Neither is a payment authorization, capture, settlement or bank receipt. `enabled` describes the method setting; `allowed` is a separate optional field Adyen sets true after merchant screening, and `verificationStatus` can still be pending, invalid or rejected. Associated-method entries can show additional changes and must not be ignored. Authentication and permission failures are `401` and `403`; the page also lists `400`, `422`, `429` and `500`. It states no idempotency, later propagation, reversal, asynchronous approval or payment-outcome contract. The introduction invokes request `type`, yet the request table omits a top-level `type` row and only the response table includes it; that mismatch does not justify inventing an input requirement. The pinned TEST snapshot does not prove current Live access, merchant eligibility or compliance.
