# Original campaign query answers — api-explorer-management-latest-get-companies-companyid-billingentities

## Q1

`GET /companies/{companyId}/billingEntities` is a captured Management API reference for listing billing entities of a company account and its merchant accounts. A billing entity is the legal entity Adyen charges for orders, and a separate terminal-product order must contain a billing-entity ID. The page lists the Test server `https://management-test.adyen.com/v3`; it says Live requests are subject to rate limits but provides no numeric limit or Live server URL. The caller's API credential needs either **Management API—Terminal ordering read** or **Management API—Terminal ordering read and write**. The required path `companyId` identifies the company account, and optional query `name` filters by billing-entity name; no request body is listed. `200` says the read succeeded. Its `data` array is optional in the schema; billing-entity items can contain optional `id`, `name`, `taxId`, `email`, and `address` (with optional city, company name, country, postal code, state/province, and two street lines). The item `id` is the reference used as `billingEntityId` in a later order. The sample's Company and MerchantAccount prefixes are example values, not a guaranteed ID grammar. See [[source-adyen-api-explorer-management-latest-get-companies-companyid-billingentities]] and [pinned API reference](https://docs.adyen.com/api-explorer/Management/latest/get/companies/(companyId)/billingEntities), raw lines 5–54 and 156–189.

## Q2

A `200` establishes a successful billing-entity lookup and may return the optional `data` array. It does not place a terminal order, bill it, verify the listed `taxId` or legal entity, approve or activate account capabilities, confirm terminal fulfillment, or show a payment, settlement, or bank receipt. Caller permission is bounded by the two stated terminal-ordering roles and documented 401/403 failures; 400, 422, and 500 cover other request/server errors. Live rate limiting is stated without figures in this capture. The GET page specifies no idempotency mechanism, lifecycle change, deletion or reversal, propagation delay, asynchronous review/approval, conflict rule, or Live URL. Its Test `/v3` server and 2026-11-05 example are snapshot evidence, not current account eligibility or a Live transaction result. See [[source-adyen-api-explorer-management-latest-get-companies-companyid-billingentities]] and [pinned API reference](https://docs.adyen.com/api-explorer/Management/latest/get/companies/(companyId)/billingEntities), raw lines 5–54, 57–154, and 156–189.
