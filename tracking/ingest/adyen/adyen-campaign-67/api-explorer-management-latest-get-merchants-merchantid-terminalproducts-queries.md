# Original query answers — api-explorer-management-latest-get-merchants-merchantid-terminalproducts

Q1. The 2026-11-05-captured Management API v3 TEST `GET /merchants/{merchantId}/terminalProducts` lists country-specific terminal packages and parts accessible to the named merchant account. The merchant-account `merchantId` path ID and ISO alpha-2 `country` query code are required. Optional `limit`, `offset`, and `terminalModelId` narrow or page the list; no default or numeric bound is specified. The caller needs Terminal ordering read or Terminal ordering read and write. A 200 response can include `data` with product identity, description, included items and price currency/value; 204 succeeds with no content. The listed server is TEST v3, with live requests subject to rate limits. [[source-adyen-api-explorer-management-latest-get-merchants-merchantid-terminalproducts]] — https://docs.adyen.com/api-explorer/Management/latest/get/merchants/(merchantId)/terminalProducts — verified raw lines 5–55.

Q2. A 200 reports request success and may include the optional `data` array of merchant-accessible products for the given country; 204 has no content. Neither response places an order or establishes stock, fulfillment, device delivery, boarding, configuration, or payment readiness. The example's EUR zero prices are illustrative. Authentication and role boundaries apply, and 400, 401, 403, 422, and 500 errors are listed. No idempotency, deletion/reversal, propagation, asynchronous approval or live order outcome is defined by this read endpoint. The dated capture cannot prove current eligibility, payment authorization, capture, settlement, or bank receipt.
