# C67 worker query answers: api-explorer-management-latest-post-merchants-merchantid-webhooks-webhookid-generatehmac

## Q1

The 2026-11-05 captured Management API `latest` page is for `POST /merchants/{merchantId}/webhooks/{webhookId}/generateHmac`: it generates an HMAC key for the webhook identified by the path, allowing integrity and origin checks on received notifications. Its only listed server is `https://management-test.adyen.com/v3`, so this snapshot provides a Test endpoint but no Live endpoint. The caller's API credential needs the “Management API—Webhooks read and write” role. Both path parameters are required; `merchantId` uniquely identifies the merchant account, and `webhookId` is the target webhook identifier ([[source-adyen-api-explorer-management-latest-post-merchants-merchantid-webhooks-webhookid-generatehmac]]; https://docs.adyen.com/api-explorer/Management/latest/post/merchants/(merchantId)/webhooks/(webhookId)/generateHmac; raw lines 5-22). The page has no request-body or query-parameter table, numeric limits, defaults, or idempotency header. On 200, the response body requires a string `hmacKey`; 204 denotes successful processing with no additional content. The example 200 key is illustrative ([[source-adyen-api-explorer-management-latest-post-merchants-merchantid-webhooks-webhookid-generatehmac]]; https://docs.adyen.com/api-explorer/Management/latest/post/merchants/(merchantId)/webhooks/(webhookId)/generateHmac; raw lines 24-36, 138-147).

## Q2

A 200 means the request succeeded and returns an HMAC key; a 204 means successful processing with no additional content, so the 204 does not supply a returned key. The page says creating an HMAC key starts HMAC-signed notifications, but neither success response establishes that any event was delivered, received, or cryptographically verified by the merchant. The separate [[source-adyen-docs-development-resources-webhooks-secure-webhooks-verify-hmac-signatures]] guide covers endpoint-specific keys, Test/Live separation and replacement-key propagation; those claims are from that guide, not this endpoint reference ([[source-adyen-api-explorer-management-latest-post-merchants-merchantid-webhooks-webhookid-generatehmac]]; https://docs.adyen.com/api-explorer/Management/latest/post/merchants/(merchantId)/webhooks/(webhookId)/generateHmac; raw lines 5-7, 24-36). The required credential role plus 401 authentication and 403 permission errors bound the caller; 400, 422 and 500 are also documented. This reference specifies no idempotency behavior, deletion/reversal, retry or rotation timing, asynchronous review/approval or activation status; do not infer those from the success code. Its `latest` URL and captured Test v3 server do not prove current eligibility or Live availability. HMAC key generation is a webhook-security configuration operation, not a payment authorization, capture, booking, settlement, bank receipt, or compliance result ([[source-adyen-api-explorer-management-latest-post-merchants-merchantid-webhooks-webhookid-generatehmac]]; https://docs.adyen.com/api-explorer/Management/latest/post/merchants/(merchantId)/webhooks/(webhookId)/generateHmac; raw lines 1-14, 39-136).
