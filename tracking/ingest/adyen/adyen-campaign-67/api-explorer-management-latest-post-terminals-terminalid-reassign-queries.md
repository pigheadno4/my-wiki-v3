# Original query answers — api-explorer-management-latest-post-terminals-terminalid-reassign

## Q1

The 2026-11-05 capture is the Management API v3 TEST reference for `POST /terminals/{terminalId}/reassign`. It reassigns the path-identified payment terminal to a company account, merchant account, merchant inventory, or store. The calling API credential needs `Management API—Assign Terminal`; the listed server is `https://management-test.adyen.com/v3`, and the page notes Live rate limits without stating figures. Required `terminalId` is the payment terminal ID. The body lists optional `companyId`, `merchantId`, `storeId`, and boolean `inventory` for destination identity. When assigning to a merchant account, prose requires `inventory` with `merchantId`: true sends the terminal to merchant inventory, which cannot process transactions; false assigns it directly to the merchant account, which the page says can process transactions. No default, numeric limit, or universal required body property is specified. HTTP 200 is the success status with no success resource/body schema; the actual response code determines request status. See [[source-adyen-api-explorer-management-latest-post-terminals-terminalid-reassign]], [captured endpoint](https://docs.adyen.com/api-explorer/Management/latest/post/terminals/(terminalId)/reassign), verified raw lines 5–53.

## Q2

A 200 response reports request success but supplies no terminal state or on-device confirmation. The inventory true/false distinction describes the assignment destination's transaction capability, not proof that a particular device is boarded, configured, reachable, or ready for payments. The endpoint lists 401 authentication and 403 permission failures, plus 400, 422, and 500 errors. It specifies no idempotency, reversal, asynchronous completion, review, or approval contract; the Live rate-limit statement gives no current limit or Live URL. The merchant/store examples do not define all valid body combinations or an inventory default. This dated `latest` capture cannot prove present account eligibility, successful physical assignment, compliance, payment authorization, capture, booking, settlement, or bank receipt.
