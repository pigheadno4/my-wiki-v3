# api-explorer-management-latest-get-merchants-merchantid-paymentmethodsettings-paymentmethodid-getapplepaydomains — original query answers

## Q1

The 2026-11-05-captured Management API `latest` reference describes `GET /merchants/{merchantId}/paymentMethodSettings/{paymentMethodId}/getApplePayDomains`, which reads Apple Pay domains registered for the merchant account and payment method named in the path. The listed environment is TEST at `https://management-test.adyen.com/v3`. The caller's API credential needs `Management API—Payment methods read`; this credential is distinct from the target merchant and payment-method IDs. Both `merchantId` and `paymentMethodId` are required string path parameters. No query, request body, defaults or limits are specified. A `200` has an optional `domains` array of strings described as merchant domains; a separate `204` success has no additional content, so it returns no domain list. ## Q2

A `200` establishes a successful read and may return the registered-domain list; because `domains` is optional, the schema does not promise that it appears in every `200`. A `204` says the request was successfully processed but gives no content or domain state. Neither success status registers or deletes a domain, validates a certificate, establishes Live Apple Pay enablement, proves a wallet session, or shows payment authorization or settlement. The reference states no idempotency, propagation, review, approval, activation, failure-reversal or domain-lifecycle rule. Authentication and the Payment methods read role gate access; documented failures are `400`, `401`, `403`, `422` and `500`. The source lists a TEST `/v3` server only; the `latest` URL and 2026-11-05 snapshot do not prove current eligibility, compliance or Live route availability.
