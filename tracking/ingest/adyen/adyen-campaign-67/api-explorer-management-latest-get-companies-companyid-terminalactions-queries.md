# C67 worker query answers: api-explorer-management-latest-get-companies-companyid-terminalactions

## Q1

The 2026-11-05 Management API `latest` snapshot documents `GET /companies/{companyId}/terminalActions` to list terminal actions scheduled for the identified company; it explicitly excludes actions scheduled by Adyen. It lists the Test v3 server `https://management-test.adyen.com/v3` and says Live requests face rate limits without specifying a number. The caller needs either “Management API—Terminal actions read” or “Management API—Terminal actions read and write.” The required `companyId` is the unique company-account ID ([[source-adyen-api-explorer-management-latest-get-companies-companyid-terminalactions]]; https://docs.adyen.com/api-explorer/Management/latest/get/companies/(companyId)/terminalActions; raw lines 5-24). Optional query filters are `type` (InstallAndroidApp, UninstallAndroidApp, InstallAndroidCertificate, UninstallAndroidCertificate) and `status` (pending, successful, failed, cancelled, tryLater); `pageSize` defaults to 20, maximum 100, and `pageNumber` selects a page with no stated default. A 200 response has an optional `data` array; each action's `actionType`, `config`, `confirmedAt`, `id`, `result`, `scheduledAt`, `status`, and `terminalId` are optional schema fields. No total count or pagination metadata is specified ([[source-adyen-api-explorer-management-latest-get-companies-companyid-terminalactions]]; https://docs.adyen.com/api-explorer/Management/latest/get/companies/(companyId)/terminalActions; raw lines 27-51).

## Q2

A 200 establishes that the list request succeeded and returns the documented action data if present. A reported action status is scoped to that action; the sample cancelled action is illustrative and does not define all actions or device state. The explicit Adyen-scheduled exclusion also means the list cannot be treated as a complete inventory of all actions for the company ([[source-adyen-api-explorer-management-latest-get-companies-companyid-terminalactions]]; https://docs.adyen.com/api-explorer/Management/latest/get/companies/(companyId)/terminalActions; raw lines 5-7, 35-51, 153-173). The required role and documented 401 authentication/403 permission errors bound access; 400, 422 and 500 are also possible. This read reference gives no idempotency, scheduling, cancellation, deletion, propagation timing, retry/reversal, asynchronous review/approval or device-activation contract. Its Live rate-limit sentence gives no numerical allowance, and the sole listed server is Test v3; the dated `latest` snapshot does not prove current Live endpoint details, eligibility, successful on-device application, or financial outcomes. Listing terminal actions is separate from payment authorization, capture, booking, settlement and bank receipt ([[source-adyen-api-explorer-management-latest-get-companies-companyid-terminalactions]]; https://docs.adyen.com/api-explorer/Management/latest/get/companies/(companyId)/terminalActions; raw lines 8-17, 54-151).
