# C67 job 32 — original query answers

## Q1

For `POST /companies/{companyId}/terminalOrders`, the captured Management API v3 reference creates an order for payment-terminal products for the named company account. Its listed server is `https://management-test.adyen.com/v3`, and the caller's API credential needs Management API—Terminal ordering read and write. Required path `companyId` identifies the company. The request table marks every body property optional: billing entity ID, merchant-defined order reference, an `items` array whose product `id`, `name`, `quantity` and `installments` are also optional in the table, order type, shipping location ID and tax ID. The Brazil note says `billingEntityId` need not be included for Brazil product orders. No default or numerical limit is given in this endpoint's request schema. A 200 can return optional order ID, processing `status`, date, items, billing and shipping entities, customer reference and carrier tracking URL; the example's `Placed` value is sample data. [[source-adyen-api-explorer-management-latest-post-companies-companyid-terminalorders]]; https://docs.adyen.com/api-explorer/Management/latest/post/companies/(companyId)/terminalOrders; verified raw lines 5–111, 213–264.

## Q2

A 200 means the request succeeded and may return an order representation; it does not prove shipment, receipt, device assignment, boarding or payment readiness. The raw expressly says Management API **test** requests do not create actual test-terminal orders and instead directs test-terminal sales orders to Customer Area. Live calls are subject to rate limits, but this pinned page lists only a test server and gives no live rate figure. The endpoint documents 400 request, 401 authentication, 403 permission, 422 validation and 500 processing errors. It specifies no idempotency key, cancellation/deletion or reversal mechanics, propagation timing, asynchronous review/approval, or delivery guarantee. The November 5 snapshot and sample `Placed` order cannot establish current live eligibility, compliance, an actual test order, payment authorization, booking, settlement or bank receipt. [[source-adyen-api-explorer-management-latest-post-companies-companyid-terminalorders]]; https://docs.adyen.com/api-explorer/Management/latest/post/companies/(companyId)/terminalOrders; verified raw lines 9–18, 66–111, 114–264.
