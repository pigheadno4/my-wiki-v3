## Q1

The 2026-11-05-captured Management API `latest` reference covers `POST /companies/{companyId}/terminalOrders/{orderId}/cancel`, a terminal-products-order cancellation. It lists the TEST server `https://management-test.adyen.com/v3`. The caller's API credential needs `Management API—Terminal ordering read and write`; `companyId` is the required company-account ID and `orderId` is the required order ID, distinct from the caller credential. The order must still be `Placed`. The POST has no request body, and no query parameters or defaults are documented. Live requests are rate limited, with no numeric rate given here. On `200`, the introduction says full order details return with status `Cancelled`. The schema marks top-level `status` and all other listed fields optional; these include order ID/reference/date, items, billing entity, shipping location and tracking URL, with nested address/contact fields. The example's `"Netherlands"` country values conflict with the schema's two-letter ISO country-code description. A `200` is the documented successful cancellation response, and the introduction describes the returned terminal-products order as `Cancelled`. That state concerns the order, not a payment cancellation, refund, shipment interception, inventory restoration or terminal boarding. The `Placed` prerequisite bounds when the operation can be used. The capture does not specify idempotency, an undo/reversal route, propagation timing, fulfillment effects or asynchronous review/approval/activation. Authentication and the terminal-ordering read/write role gate the call; listed failures are `400`, `401`, `403`, `422` and `500`. The page lists a TEST `/v3` server and a Live rate-limit warning, but no Live endpoint details or current rate value. Its `latest` label and dated snapshot do not prove present account eligibility, compliance, shipment result or financial outcome.
