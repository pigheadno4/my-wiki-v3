# Original query answers: api-explorer-management-latest-get-merchants-merchantid-shippinglocations

- Q1: This 2026-11-05 Management API v3 reference lists merchant-scoped shipping locations through `GET /merchants/{merchantId}/shippingLocations` on its listed TEST server. The API credential needs Terminal ordering read or read and write. Required `merchantId` identifies the merchant account; optional query `limit`, `offset`, and `name` control result count, skipped entries and name filtering, with no numeric bound or default specified. A 200 response's `data` array is optional; each location's `id`, unique `name`, address and contact are marked optional. The `id` is the `shippingLocationId` reference for creating a terminal-product order. Live requests are said to be rate-limited, without a figure in this raw. [[source-adyen-api-explorer-management-latest-get-merchants-merchantid-shippinglocations]]; https://docs.adyen.com/api-explorer/Management/latest/get/merchants/(merchantId)/shippingLocations; verified raw lines 5–60.
- Q2: A successful GET can return a configured merchant shipping-location readback; the page also lists 204 with no content. This is separate from creating, approving, shipping or delivering an order, assigning or boarding a device, and processing a payment. Role-gated API credentials are required; 401 and 403 cover authentication and permission failures, alongside 400, 422 and 500. The endpoint documents no idempotency key, deletion, propagation, asynchronous approval/activation, reversal or financial result. Its TEST server listing, live rate-limit note and sample address do not prove current live eligibility, compliance, terminal readiness or payment outcomes.
