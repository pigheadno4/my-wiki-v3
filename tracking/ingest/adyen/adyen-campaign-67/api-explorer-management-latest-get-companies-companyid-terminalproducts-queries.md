# Original query answers — api-explorer-management-latest-get-companies-companyid-terminalproducts

Q1. The 2026-11-05-captured Management API v3 TEST `GET /companies/{companyId}/terminalProducts` lists country-specific terminal packages and parts accessible to the company account. `companyId` is a required company-account path ID and `country` a required ISO alpha-2 query code. Optional `limit`, `offset` and `terminalModelId` filter or page results; no defaults or bounds are stated. The API credential needs Terminal ordering read or Terminal ordering read and write. A 200 response may contain `data` with product IDs, names, descriptions, included items and price currency/value. The listed TEST server is `https://management-test.adyen.com/v3`; live requests are rate limited. [[source-adyen-api-explorer-management-latest-get-companies-companyid-terminalproducts]] — https://docs.adyen.com/api-explorer/Management/latest/get/companies/(companyId)/terminalProducts — verified raw lines 5–51.

Q2. A 200 establishes success of this catalog read and describes products the company can order for the specified country. It does not place an order, show delivery, boarding, stock, installed configuration, or payment capability. The EU sample with zero prices is illustrative. Authentication and role restrictions apply; listed failures are 400, 401, 403, 422 and 500. This read endpoint states no idempotency, lifecycle/deletion, asynchronous approval, propagation or live availability result. The November snapshot and its live rate-limit note cannot prove current eligibility, fulfillment, payment authorization, capture, settlement, or bank receipt.
