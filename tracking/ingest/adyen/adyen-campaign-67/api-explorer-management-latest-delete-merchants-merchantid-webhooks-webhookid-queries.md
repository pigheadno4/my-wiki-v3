# api-explorer-management-latest-delete-merchants-merchantid-webhooks-webhookid — original query answers

## Q1

The 2026-11-05-captured Management API `latest` reference describes `DELETE /merchants/{merchantId}/webhooks/{webhookId}` as removal of the webhook configuration named in the path. Its listed environment is TEST at `https://management-test.adyen.com/v3`. The caller's API credential must have the `Management API—Webhooks read and write` role. `merchantId` is the required string ID of the merchant account and `webhookId` is the required string ID of the webhook configuration; these identify the target and are distinct from the caller's credential. No query or request body, defaults or limits are documented. `204` is the listed success status and no success response fields are specified; the page directs readers to use the actual HTTP response code for request status. The capture does not state whether removal propagates immediately, what happens to queued or in-flight notifications, or whether other webhook configurations remain. It gives no idempotency or reversal rule and no review, approval or activation workflow. The page lists only a TEST `/v3` server and no Live route; its `latest` label and dated snapshot do not prove present access. Removing configuration does not establish successful or failed webhook delivery, payment authorization, settlement, account eligibility or compliance.
