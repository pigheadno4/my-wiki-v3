# C67 job 42 — original query answers

## Q1

For `POST /merchants/{merchantId}/terminalOrders`, the captured Management API v3 reference creates a terminal-product order for the named **merchant account**, unlike the separate company-scoped route. Its only listed server is `https://management-test.adyen.com/v3`; the caller's credential needs Management API—Terminal ordering read and write. The required path `merchantId` is the merchant-account identifier. The request body table marks billing entity ID, merchant order reference, `items` (and its product ID, installment count, name and quantity), order type, shipping location ID and tax ID optional. It says a Brazil product order need not include `billingEntityId`; the merchant billing entity and accessory quantities in the example are not defaults. A 200 can return optional order ID, status, date, products, billing and shipping details, reference and tracking URL; 204 has no additional content. No numerical request limit or response-required property appears in this endpoint schema. [[source-adyen-api-explorer-management-latest-post-merchants-merchantid-terminalorders]]; https://docs.adyen.com/api-explorer/Management/latest/post/merchants/(merchantId)/terminalOrders; verified raw lines 5–115, 217–269.

## Q2

A 200 means the request succeeded and may return an order representation; a 204 means successful processing without content. Neither is shipment, delivery, assignment, boarding or payment-readiness proof. The raw expressly states that test-endpoint requests do **not** create actual orders for test terminals and directs those sales orders to Customer Area. Live requests face rate limits, while this snapshot lists only a test server and no rate figure. Its 400, 401, 403, 422 and 500 routes delimit request, authentication, permission, validation and server failures. This page specifies no idempotency key, cancellation/deletion or reversal flow, propagation timing, asynchronous review/approval, or carrier delivery guarantee. The example's `Placed` status and November 5 capture cannot establish current live eligibility, compliance, actual test-order creation, payment authorization, booking, settlement or bank receipt.
