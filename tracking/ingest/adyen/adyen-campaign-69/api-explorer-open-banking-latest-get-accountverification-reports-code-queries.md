# C69 worker query answers: api-explorer-open-banking-latest-get-accountverification-reports-code

## Q1

The 2026-11-07 Open Banking Gateway `latest` reference lists Test and Live `/obgateway/v1` servers for `GET /accountVerification/reports/{code}`. It retrieves an account verification report after a successful open banking connection; required path `code` comes from the `redirectUrl` callback query. This operation page states no request body, defaults, code-use limits, or named role. The separately captured [[source-adyen-api-explorer-open-banking-latest-overview]] says each Open Banking API request uses an API key in `X-API-Key`, requires **Role for OpenBanking account verification use case: EXTERNAL** on the credential, and directs Adyen contact for role setup (overview raw lines 15–32). The `200` schema requires report `id`, `country` of the third-party individual's registered bank account, and an `accounts` array. Account entries require an account ID, name, number, type, currency, identifiers object, and associated parties; regional identifier objects are optional. See [[source-adyen-api-explorer-open-banking-latest-get-accountverification-reports-code]] ([canonical reference](https://docs.adyen.com/api-explorer/open-banking/latest/get/accountVerification/reports/(code))); raw lines 5–50.

## Q2

A `200` retrieves identity and bank-account report data; it does not itself establish Business Account opening, ongoing eligibility, a payment or payout, booking, settlement, or bank receipt. The page lists `400` malformed request, `401` invalid credential or wrong permissions, `404` missing entity, `422` validation, `429` rate limit, and `500` server error. The operation does not name a role, while the family [[source-adyen-api-explorer-open-banking-latest-overview]] requires the `X-API-Key` API key and EXTERNAL account-verification role with Adyen-contact setup (overview raw lines 15–32). The operation states no report freshness, code lifetime/use count, idempotency, deletion/reversal, asynchronous approval/activation, or version-conflict rule. The ACH example repeats the same `accountId` for two different account numbers and banks despite the unique-ID schema description; do not infer a reliable one-to-one key from that example. The dated Test/Live endpoint listing does not prove current availability or financial outcome. See [[source-adyen-api-explorer-open-banking-latest-get-accountverification-reports-code]] ([canonical reference](https://docs.adyen.com/api-explorer/open-banking/latest/get/accountVerification/reports/(code))); raw lines 7–22, 24–50, 53–164, 166–224.
