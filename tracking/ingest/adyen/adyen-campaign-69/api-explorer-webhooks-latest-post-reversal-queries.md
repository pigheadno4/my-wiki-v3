# C69 api-explorer-webhooks-latest-post-reversal — original query answers

## Q1

The 2026-11-07 capture is Adyen Webhooks `latest` `POST /REVERSAL`, an inbound notification of a reversal-request result, rather than an operation for a merchant to submit one. The captured page names no numeric API version, caller credential, default, size limit, or request example. Its optional outer `live` string reports Live (`true`) or Test (`false`) origin when present; `notificationItems` and its item wrapper are also marked optional. Within an item, the table marks `amount`, `eventCode`, `eventDate`, `merchantAccountCode`, `merchantReference`, `pspReference`, and `success` required. `merchantAccountCode` is the transaction's merchant-account identifier; `merchantReference` is the merchant payment reference; `pspReference` is Adyen's unique transaction/request reference. Optional `originalReference` corresponds to the original payment request for a modification. Optional `additionalData`, `paymentMethod`, and `reason` are also listed. The prose says `modification.action` indicates cancellation of the original payment, refund of it, or cancellation of an authorised refund, but the table does not define that field's placement or values. The only listed response is `200 Success`, with event acceptance based on HTTP status. [[source-adyen-api-explorer-webhooks-latest-post-reversal]]; https://docs.adyen.com/api-explorer/Webhooks/latest/post/REVERSAL; pinned raw lines 5–7, 11–32.

## Q2

The `success` string describes the outcome of the notification's `eventCode`: `true` means the event executed successfully, `false` means it did not; optional `reason` gives a short refusal explanation when `success` is `false`. By contrast, the documented `200 Success`/HTTP status concerns receiver acceptance of a webhook event. It does not itself prove the reversal succeeded or that funds were settled or returned. This snapshot states no authentication or idempotency contract, lifecycle deletion or propagation timing, asynchronous review/approval/activation state, versioned server route, conflict resolution, or financial finality. The `latest` label and optional Live/Test origin flag do not prove current production availability or eligibility. The page documents reversal-result notification semantics only; it does not give an outbound reversal API contract.
