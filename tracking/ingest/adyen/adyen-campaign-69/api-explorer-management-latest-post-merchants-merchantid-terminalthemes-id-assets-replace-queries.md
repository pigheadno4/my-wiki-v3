# C69 merchant terminal-theme asset replacement — original query answers

## Q1

The 2026-11-07 Management API `latest` capture describes `POST /merchants/{merchantId}/terminalThemes/{id}/assets/replace`, which replaces an existing image or video asset of a theme owned by the merchant account. It lists the TEST `/v3` server and notes a Live rate limit; it does not list a Live base URL here. The API credential needs `Management API - Terminal themes read and write`. Required path values are the merchant-account `merchantId` and theme `id`; required query values `type` and `model` identify the existing asset combination. `logo` uses `All`; `idleScreen` and `shopperEngagementScreen` are limited to SFO1/M450, while the table lists the other supported screen types. The required multipart/form-data `file` part must declare a type/model-compatible Content-Type: SVG only for `logo`/`All`, MP4 or QuickTime only for SFO1/M450, JPEG/JPG or PNG for non-`All` models, and GIF except SFO1/M450. The size cap is 100 MB for SFO1/M450 or 10 MB for other models; generic or missing Content-Type triggers `422`. No default or idempotency rule is specified. `200` requires `type`, `model`, and a tokenized CDN `url` valid for 24 hours. ## Q2

A `200` result establishes that this replacement request returned asset metadata and a time-limited CDN link. Replacement is permitted only if the theme already contains the same `type`/`model` pair; otherwise the reference says the request fails and points to the separate asset-add endpoint. The credential role and model/media constraints still apply. The reference lists `400`, `401`, `403`, `404`, `422`, `429`, and `500`; its examples include a theme not found for the account, an absent type/model asset, a forbidden logo change, an oversize file, and a rate-limit response. Those examples do not exhaust failure conditions. The endpoint states no idempotency, asynchronous approval, device propagation, deletion, reversal, or version-conflict contract. A returned CDN URL does not prove the theme has been applied to a device, that a terminal is ready, that the merchant is currently Live-eligible, or that any payment was authorized, captured, settled, or received by a bank. This is a November 2026 documentation snapshot.
