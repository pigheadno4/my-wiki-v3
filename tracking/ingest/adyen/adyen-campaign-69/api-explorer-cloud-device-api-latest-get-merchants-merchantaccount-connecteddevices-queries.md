# C69 original query answers: api-explorer-cloud-device-api-latest-get-merchants-merchantaccount-connecteddevices

## Q1

For `GET /merchants/{merchantAccount}/connectedDevices`, the captured 2026-11-07 Cloud Device API v1 reference lists payment terminals or Mobile solution SDK installation IDs belonging to the specified merchant account that have an active cloud connection. It documents a test server at `device-api-test.adyen.com/v1` and regional live v1 servers for Australia, East Asia, Europe, and the United States; these are documented endpoints, not account-specific access proof. The caller's API credential requires the Cloud Device API role. `merchantAccount` is the required path parameter identifying the merchant account; optional query `store` is a store ID under that account and restricts the list. The 200 response schema marks `uniqueDeviceIds` optional; when present, it contains terminal IDs in model–serial format or Mobile SDK installation IDs. The raw specifies no default, page size, or other limit for this operation. See [[source-adyen-api-explorer-cloud-device-api-latest-get-merchants-merchantaccount-connecteddevices]] and [the captured API reference](https://docs.adyen.com/api-explorer/cloud-device-api/latest/get/merchants/(merchantAccount)/connectedDevices), raw lines 5–51.

## Q2

The documented 200 result is a read of device IDs with an active cloud connection for the requested merchant scope, optionally narrowed by store. It does not create or board devices, and connection presence alone does not establish payment authorization, capture, settlement, or continuing connectivity. The raw requires the Cloud Device API role and documents 401 Unauthorized and 403 Forbidden with optional error-body properties; its examples are sample payloads, not a guaranteed response shape. It states no idempotency key, lifecycle/deletion/propagation transition, asynchronous review or approval, reversal, or version-conflict rule for this GET. The November 2026 capture and `latest` path are snapshot evidence, not proof of current availability or merchant eligibility. See [[source-adyen-api-explorer-cloud-device-api-latest-get-merchants-merchantaccount-connecteddevices]] and [the captured API reference](https://docs.adyen.com/api-explorer/cloud-device-api/latest/get/merchants/(merchantAccount)/connectedDevices), raw lines 5–11, 43–89, and 91–133.
