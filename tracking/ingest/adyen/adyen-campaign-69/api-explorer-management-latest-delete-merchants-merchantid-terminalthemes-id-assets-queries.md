# C69 original query answers: api-explorer-management-latest-delete-merchants-merchantid-terminalthemes-id-assets

## Q1

The captured 2026-11-07 Management API `latest` reference for `DELETE /merchants/{merchantId}/terminalThemes/{id}/assets` documents a v3 **test** server and deletes one asset from a terminal theme owned by the merchant account in the path. The caller's API credential needs the Management API - Terminal themes read and write role. Required path values are merchant account `merchantId` and terminal-theme `id`; required query values `type` and `model` select the asset. For `logo`, `model` must be `All`; every other screen type needs one Android terminal model. `idleScreen` and `shopperEngagementScreen` are restricted to SFO1 or M450. The raw specifies no default, size limit, request body, or returned response fields; success is 204 Asset deleted. See [[source-adyen-api-explorer-management-latest-delete-merchants-merchantid-terminalthemes-id-assets]] and [the captured API reference](https://docs.adyen.com/api-explorer/Management/latest/delete/merchants/(merchantId)/terminalThemes/(id)/assets), raw lines 5–36.

## Q2

A 204 reports deletion of the identified theme asset, not deletion of the theme or proof of a changed on-device display. When `type=logo`, deletion is blocked if the theme owner cannot edit logos. The listed failure statuses are 401 Unauthorized, 403 Forbidden, 404 Not Found, 422 Unprocessable Entity, and 500 Internal Server Error; the example error bodies illustrate specific cases and do not guarantee identical details. The capture states no idempotency behavior, propagation delay, automatic apply/unapply, asynchronous review or approval, reversal, or version-conflict rule. It gives only a test server, so the snapshot does not prove live availability, merchant eligibility, terminal application, payment processing, or compliance.
