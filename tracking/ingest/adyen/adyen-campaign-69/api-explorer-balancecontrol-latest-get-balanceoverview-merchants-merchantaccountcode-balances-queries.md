# C69 original query answers: api-explorer-balancecontrol-latest-get-balanceoverview-merchants-merchantaccountcode-balances

## Q1

The 2026-11-07 Balance Control API `latest` reference documents v2 test and live servers for `GET /balanceOverview/merchants/{merchantAccountCode}/balances`. Its purpose is to view a specified merchant account's balances for a required `currency` query value; the required path `merchantAccountCode` is a merchant-account identifier, not a company account. This API page calls available funds settled and available for use, and pending balance unsettled; the separate [[source-adyen-docs-account-balances]] guide (raw lines 37–49) instead defines available funds as an adjustable aggregate including unsettled Pending, Next payout, Reserve and conditional Negative refund allowance. Do not equate API `availableFund` with that aggregate. The API page also names next payout (described for the next bank payout), reserve, and deposit (Adyen-withheld coverage). The 200 response table marks `merchantAccount` and all five amount objects optional; each present amount object has required three-character ISO `currency` and integer minor-unit `value` children. No default currency, pagination, or request limit is stated. See [[source-adyen-api-explorer-balancecontrol-latest-get-balanceoverview-merchants-merchantaccountcode-balances]] and [the captured API reference](https://docs.adyen.com/api-explorer/BalanceControl/latest/get/balanceOverview/merchants/(merchantAccountCode)/balances), raw lines 5–63.

## Q2

A 200 reports a balance overview, not a transfer, payout execution, bank receipt, or guarantee that funds remain available at a later time. The raw documents 401 authentication required, 403 insufficient permissions, and 422 validation error, with optional structured error properties and `invalidFields` item children required only if present. It supplies no role name, idempotency rule, deletion or propagation transition, asynchronous approval, reversal, or settlement confirmation for this read. Three material snapshot conflicts limit implementation inference: the API page's settled available-funds wording (raw lines 7–11) differs from the broader adjustable aggregate in [[source-adyen-docs-account-balances]] (guide raw lines 37–49), so this API's `availableFund` must not be treated as that aggregate; the merchant-scoped path and flat response table disagree with the 200 example's `merchantBalancesOverview` array containing two merchant accounts (raw lines 122–167); and this endpoint lists `/balance-control/api/v2` for live while the separately captured API overview's Going live paragraph gives `/api/v2` ([overview raw](https://docs.adyen.com/api-explorer/BalanceControl/latest/overview), 2026-09-15 raw lines 28–38). These captures do not establish equivalence of available-funds measures, the actual live envelope or base path, current account eligibility, or financial execution.
