## Q1

`DELETE /disputes/{disputeId}/attachments/{attachmentId}` removes an attachment from a raised Issuing dispute. This captured `transfers-api/latest` route uses the Raise disputes API v4 test and live bases `https://balanceplatform-api-test.adyen.com/btl/api/v4` and `https://balanceplatform-api-live.adyen.com/btl/api/v4`. Required path `disputeId` identifies the raised dispute; required `attachmentId` identifies its attachment. The page lists no query or body fields, defaults, numeric limits, or success response fields. `204` indicates successful removal. ## Q2

`204` establishes removal of the attachment from the raised dispute, while Adyen may keep the file for compliance. It does not establish complete file erasure, dispute submission or decision, reversal, payment recovery, or any financial outcome. The page lists `401` for missing authentication, `403` for insufficient permissions, and `422` for validation errors; optional top-level error fields do not guarantee a particular payload. It states no idempotency rule, deletion timing, asynchronous review/approval, account eligibility, or retry behavior. The 2026-11-07 capture supplies test and live v4 bases but is no proof of current account access.
