# C69 worker query answers: api-explorer-payments-app-latest-post-merchants-merchantid-generatepaymentsappboardingtoken

## Q1

The 2026-11-07 capture is a Payments App API `latest` merchant-level `POST /merchants/{merchantId}/generatePaymentsAppBoardingToken` reference on management `/v1` Test (`management-test.adyen.com`) and Live (`management-live.adyen.com`) servers. It creates a boarding token for the Payments App's `boardingRequestToken` under the merchant account identified by required path `merchantId`. The caller's API credential needs the Adyen Payments App role. The request body requires `boardingRequestToken`; `subMerchantData` is optional, and its table marks `displayName`, `id`, `mcc`, and `name` required within that object. The reference gives no defaults or limits. A `200` response contains required `boardingToken` and `installationId`, respectively the token allowing app boarding and the unique app-instance ID. See [[source-adyen-api-explorer-payments-app-latest-post-merchants-merchantid-generatepaymentsappboardingtoken]] ([canonical reference](https://docs.adyen.com/api-explorer/payments-app/latest/post/merchants/(merchantId)/generatePaymentsAppBoardingToken)); raw lines 5–56.
