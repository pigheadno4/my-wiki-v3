## Q1

`POST balancePlatform.balanceAccountSweepExecution.failed` is a captured incoming Balance Platform webhook sent by Adyen when a sweep execution fails. This operation page lists no outbound API server or endpoint version; the payload's required `environment` distinguishes `test` and `live`. The request table marks `data`, `environment` and `type` required, without a separate whole-body required flag. Nested balance-account, sweep-configuration, balance-platform, execution `id`, `result`, `resultDetails`, transfer ID and trigger time are optional fields. `resultDetails` may include a reason, reason code and disabled-configuration boolean. The common `result` enum includes succeeded, failed and skipped, while this event name denotes failure; the example shows failed with `missingCapabilities`. No defaults or limits are stated. `200` response body has optional `notificationResponse`; any `2xx` accepts the webhook. ## Q2

This event reports a failed sweep execution; its payload can identify the balance account, sweep configuration, execution and any transfer ID, but those are separate resources and the optional fields are not guaranteed. The example reason is illustrative. A receiver's `2xx` only accepts the webhook delivery; it does not turn the failure into a completed sweep, confirm a retry or reversal, establish transfer booking, or prove recipient-bank credit. The page gives no authentication, idempotency, retry, asynchronous recovery, review/approval or activation contract. A failed execution event is distinct from configuration deletion or a new successful execution. The November 2026 snapshot and `test`/`live` payload enum do not establish current eligibility, compliance, or financial outcome.
