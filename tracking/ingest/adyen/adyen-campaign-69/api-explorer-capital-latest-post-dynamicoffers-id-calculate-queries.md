# C69 worker query answers: api-explorer-capital-latest-post-dynamicoffers-id-calculate

## Q1

The 2026-11-07 Capital API `latest` v1 `POST /dynamicOffers/{id}/calculate` computes a preliminary offer for a selected financing amount. The captured TEST server is `https://balanceplatform-api-test.adyen.com/capital/v1`; LIVE is `https://balanceplatform-api-live.adyen.com/capital/v1`. The required path `id` identifies the dynamic offer, while required request-body `amount` has required ISO currency and integer minor-unit value. The page states 120 requests per minute in each environment, but no amount default/range or caller role. A 200 response requires account-holder ID, proposed payout amount, contract type (`loan` or `cashAdvance`), validity start/end, fee amount, and repayment basis points. APR, repayment term and threshold are optional; if term appears, estimated days is required, and maximum days applies only to loans. ## Q2

A 200 calculation returns informational preliminary terms only; the raw explicitly says they cannot be used to initiate a grant. It does not create a static grant offer, grant, approval, disbursement, repayment, bank receipt, or payment. The only listed error is 422 request validation with an optional problem-field schema. This reference does not specify role/authentication behavior, idempotency, deletion, propagation, approval workflow, asynchronous funding, reversal, or conflict/version rules. The `latest` TEST/LIVE server snapshot and calculated terms do not prove current account-holder eligibility or actual financing availability.
