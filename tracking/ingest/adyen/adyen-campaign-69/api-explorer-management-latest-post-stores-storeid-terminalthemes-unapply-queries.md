# C69 api-explorer-management-latest-post-stores-storeid-terminalthemes-unapply — original query answers

## Q1

The 2026-11-07 Management API `latest` capture documents `POST /stores/{storeId}/terminalThemes/unapply` on a listed TEST v3 server. An API credential with the stated `Management API - Terminal themes read and write` role resets the theme assignment for the store selected by required string path parameter `storeId`; no body, query input, default, or numerical limit appears. Android terminals under that store then use a custom theme applied at the next higher level (merchant account or company), or the default Adyen theme. A terminal with its own custom theme continues to use that theme. The theme resource remains unchanged and is not deleted. The endpoint returns `200 OK` even when the store has no custom theme applied; the illustrative response body is `{\"status\":\"success\"}`. ## Q2

A `200 OK` confirms the documented request response, including the no-custom-store-theme case. It does not distinguish a changed assignment from a no-op, delete the theme, override an individually themed terminal, report a terminal's observed display, or prove the change has propagated to hardware. The page lists 401 Unauthorized, 403 Forbidden, 404 Not Found, and 500 Internal Server Error; example 403 and 404 details concern account access or absence. This snapshot specifies no idempotency key, propagation time, asynchronous review/approval/activation state, reversal operation, Live route, or payment/financial result. The TEST v3 response alone does not establish current Live availability or device readiness.
