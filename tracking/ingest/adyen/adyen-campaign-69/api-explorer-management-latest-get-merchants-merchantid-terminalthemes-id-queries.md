# C69 api-explorer-management-latest-get-merchants-merchantid-terminalthemes-id — original query answers

## Q1

The 2026-11-07 Management API `latest` capture documents `GET /merchants/{merchantId}/terminalThemes/{id}` on the listed TEST v3 server. It reads the theme selected by two required string path IDs: `merchantId` is the merchant account and `id` is the terminal theme. The caller uses an API credential; the access prose names `Management API - Terminal themes read and write`, subject to the 403 example conflict below. No request body, query input, default, or rate/size limit is shown. The `200` response has required `id`, `name`, `mode` (`dark` or `light`), and `assets`; each asset has required terminal `model`, screen `type` (`logo`, `homeScreen`, `idleScreen`, `afterPaymentScreen`, `shopperEngagementScreen`), and CDN `url`. The URL has a `?token=` query parameter and is valid for 24 hours. A logo URL leads to the Adyen logo if the theme lacks logo-customization permission. The example illustrates one home-screen image and one default logo; it is not an asset-count guarantee. [[source-adyen-api-explorer-management-latest-get-merchants-merchantid-terminalthemes-id]]; https://docs.adyen.com/api-explorer/Management/latest/get/merchants/(merchantId)/terminalThemes/(id); pinned raw lines 5–39, 61–84.

## Q2

A `200` read returns theme metadata and added-asset URLs for the specified merchant account and theme. It does not show theme application to a terminal, on-device display, authorization to customize logos, payment readiness, or a financial outcome. The page lists 400 Bad Request, 401 Unauthorized, 403 Forbidden, 404 Not Found, and 500 Internal Server Error; its 404 example says no theme exists for the given ID and specified account. There is a material role conflict: access prose requires `Management API - Terminal themes read and write`, but the 403 example says `Missing required role: Management API - Terminal settings read and write`; this capture cannot settle the enforced role. This GET reference specifies no idempotency, mutation, deletion, propagation timing, asynchronous approval/activation, reversal, or Live endpoint. Its TEST v3 snapshot and 24-hour asset URLs do not prove current production eligibility or persistent access.
