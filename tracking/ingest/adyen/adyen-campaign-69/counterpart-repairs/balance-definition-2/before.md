# C69 company balances overview — original query answers

## Q1

The November 2026 `GET /balanceOverview/companies/{companyAccountCode}/balances` capture belongs to Balance Control API v2, not the Balance Platform balance-account API. It lists TEST and Live `/balance-control/api/v2` servers. The required path `companyAccountCode` identifies the company account, and required query `currency` selects a requested balances overview. The operation does not state a specific credential role, default, page limit, or response timing. The separately captured v2 overview recommends an API key in `X-API-Key` and a separate Live key. The endpoint describes per-merchant available funds (settled and available for use), pending balance (not settled), next payout (to be settled with the next payout), reserve, and deposit. The `200` body marks the `merchantBalancesOverview` array optional, and its merchant-account name and five amount objects optional; present amount objects require ISO `currency` and integer `value` in minor units. The example has two merchant accounts, mixed EUR/USD amounts, a negative pending value, and omitted categories; it does not settle how the required currency filter affects actual rows. ## Q2

`200` states that the lookup succeeded and may return per-merchant balance categories; it does not itself execute a transfer, payout, settlement, or bank deposit. The `nextPayout` definition is prospective, while `pendingBalance` explicitly describes unsettled funds and `availableFund` funds already settled and available for use. `401` means authentication is required, `403` insufficient permissions, and `422` a validation error; the error-envelope fields are optional. This operation gives no specific role, idempotency, lifecycle, reversal, asynchronous approval, propagation, or conflict/version-resolution rule. Its listed Live base includes `/balance-control/api/v2`, but the companion overview also gives a shorter `/api/v2` Live base in Going live prose; the snapshots do not resolve which path applies. A documented Live server, example figures, or successful status read does not prove current account access, a completed payout, reconciliation, or bank receipt.
