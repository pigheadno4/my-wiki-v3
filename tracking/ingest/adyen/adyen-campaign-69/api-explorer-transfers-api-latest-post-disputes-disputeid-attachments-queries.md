# C69 api-explorer-transfers-api-latest-post-disputes-disputeid-attachments — original query answers

## Q1

The 2026-11-07 `transfers-api` `latest` capture documents `POST /disputes/{disputeId}/attachments` under `/btl/api/v4`, with both Test and Live server bases. It adds receipts, correspondence, or other supporting information to an already raised Issuing dispute selected by required string path `disputeId`. The request-body table marks `attachmentType` (`receipt`, `correspondence`, `other`), Base64-encoded `content`, and `fileName` required. The filename must include a supported `jpeg`, `pdf`, or `tiff` extension. The description says Base64 line breaks, wrapping, and trailing newlines cause malformed input, subject to the wording conflict in Q2. It gives no file-size default or limit. `200` says the request succeeded and the only response-body field, `attachmentId`, is marked optional. The page specifies no named caller role beyond the 401 authentication and 403 permission responses. [[source-adyen-api-explorer-transfers-api-latest-post-disputes-disputeid-attachments]]; https://docs.adyen.com/api-explorer/transfers-api/latest/post/disputes/(disputeId)/attachments; pinned raw lines 5–40, 43–78.

## Q2

A `200` establishes success of this attachment request under the captured contract, while `attachmentId` remains optional in the response table. It does not establish that the dispute was submitted, reviewed, approved, won, or resulted in chargeback or fee reversal. The listed failures are 401 authentication required, 403 insufficient permissions, and 422 request validation error, with optional problem fields and required `message`, `name`, and `value` only inside an `invalidFields` item when that optional array is present. There is an unresolved encoding instruction: the `content` row demands Base64 without wrapping but also says not to use Java `Base64.NO_WRAP` or equivalent; a trailing newline is expressly malformed. This snapshot gives no idempotency, duplicate-upload, attachment deletion/retention, propagation, dispute-state transition, or financial outcome rule. Its Test/Live v4 URLs and `latest` label do not prove account eligibility or current behavior.
