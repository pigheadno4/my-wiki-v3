# C69 Cloud Device API GET device status — original query answers

## Q1

The captured `GET /merchants/{merchantAccount}/devices/{deviceId}/status` reference checks whether a specified payment terminal or IPP Mobile SDK installation ID has an active cloud connection. It is a Cloud Device API `/v1` endpoint with one TEST server and regional Live servers for Australia, East Asia, Europe, and the United States. The caller's API credential needs the Cloud Device API role. Both path values are required: `merchantAccount` is the merchant-account identifier; `deviceId` is a terminal model-and-serial ID for a terminal or an SDK installation ID in a Mobile solution. The reference gives no query or request-body fields, defaults, limits, or idempotency rule. Its `200` schema marks `deviceId` and `status` optional; `status` can be `ONLINE` or `OFFLINE` to indicate whether an active cloud connection exists. ## Q2

A `200` lookup is a successful status request. A returned `ONLINE` or `OFFLINE` value describes cloud connection state only; both response properties are optional in the schema, and the `ONLINE` example is not a guaranteed response shape. The API credential role is required, and the reference lists `401 Unauthorized` and `403 Forbidden` responses with optional error-envelope fields; `invalidFields` entries have required children only if that optional array is present. This GET reference does not state an idempotency rule, device activation/approval or deletion lifecycle, propagation timing, asynchronous result, retry or reversal behavior, or version-conflict contract. Thus the lookup does not prove account-specific Live eligibility, a successful Terminal API message, payment authorization/capture, settlement, or bank receipt. It is a 2026-11-07 documentation snapshot, not a current-account test.
