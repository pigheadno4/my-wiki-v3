# C69 original query answers: grant disbursement detail

## Q1

The 2026-11-07 capture documents Capital API `latest` on Balance Platform Test and Live `/capital/v1` servers for `GET /grants/{grantId}/disbursements/{disbursementId}`. It returns details of one disbursement. Required path IDs are the grant reference `grantId` and distinct disbursement `disbursementId`; no body, query inputs, defaults or limits are specified. The `200` schema requires recipient `accountHolderId` and `balanceAccountId`, `grantId`, disbursement `id`, `amount` in currency/minor units, `balances` with fee/principal/total, `fee.amount`, and `repayment.basisPoints` plus `updateDescription`. `fundsCollections` is optional, with optional collection-account identification and `UnscheduledRepayment`/`Revocation` type. ## Q2

A `200 Success` indicates the disbursement-detail GET succeeded and returns the described record. It does not itself show a bank transfer, bank receipt, settlement, actual collection, completed repayment or a current debt balance; the schema has no disbursement status field. `balances.total` is described as principal plus fee, and `repayment.basisPoints` is a configured percentage of incoming net volume, not evidence of collected funds. The page lists `404` entity not found and `422` validation errors, but no authentication role/header or idempotency rule, and no creation, deletion, propagation, asynchronous review/approval/activation, reversal, retry or version-conflict contract. The Test/Live v1 URL listing and 2026-11-07 capture do not establish present eligibility or a specific user's financial outcome.
