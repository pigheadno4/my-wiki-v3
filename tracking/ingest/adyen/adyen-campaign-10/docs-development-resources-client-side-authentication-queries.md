Q1. What does the client key do, and how is it different from an API key?
Expected: In this 2026-09-15 snapshot of a page last modified in 2021, the client key is a public key identifying an API credential for eligible client-side integrations. The guide names Web Drop-in/Components functions including secure card-input rendering and encryption, card-type detection, and some server-side barcode or QR rendering. It is not used for Adyen API requests; those require a separate API key. A credential has allowed origins and CORS controls expected client-side request origins. These statements do not prove merchant eligibility, a successful request, or payment execution. Q2. What version and environment constraints apply when generating and managing a client key?
Expected: Web Drop-in/Components support client key from 3.10.1 and earlier versions use origin keys; iOS/Android Drop-in/Components support it from 3.7.0 and earlier versions use client encryption public keys. From 4.0.0 the page says client key is the only client-side authentication route for these products. A key has test/live prefix; live needs a new key generated in live Customer Area. Allowed origins can include wildcards; test accepts HTTPS or HTTP in secure contexts such as localhost, while live requires HTTPS. The Customer Area path is Developers > API credentials > credential > Client settings > Authentication > Client key. Saved origins can change without key regeneration and take a few seconds to propagate; a newly generated key causes the old one to expire after 24 hours.
