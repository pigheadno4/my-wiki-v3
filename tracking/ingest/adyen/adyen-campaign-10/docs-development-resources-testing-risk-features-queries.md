Q2. Which Auto Rescue test scenarios and webhooks are described, and when is a payment link sent?
Expected: Enable Auto Rescue in test Customer Area for shopper-not-present payments such as subscription renewals. The page says test `/payments` `merchantReference` values `AutoRescueSuccessfulFirst`, `AutoRescueSuccessfulSecond`, `AutoRescueFailed`, and `AutoRescueFraud` simulate first-retry success, second-retry success, all retries failing, and fraud refusal with no retry. For triggered retries an `AUTHORISATION` webhook arrives per retry with a `success` field. Only if Pay by Link sending after failed rescue is enabled does the all-fail path produce an `AUTORESCUE` webhook carrying `paymentLink.url`; completing a separate link test payment then yields an `AUTHORISATION` webhook. These are documented fixture labels, not independently verified Checkout schema or live recovery proof. Raw lines 54–81; same canonical route.
