# Apple Pay API-only retrieval checks

Q1. What integration does this guide add Apple Pay to, and what are the channel prerequisites? It is an Advanced-flow API-only integration with a merchant-built form; Apple Pay must be added in Customer Area and the merchant must choose a certificate (pinned raw lines 15–32). Adyen's certificate is offered for web; mobile requires the merchant's Apple Developer account/certificate (line 30). `/paymentMethods` uses `channel: Web` for Safari or `iOS` in-app (lines 40–49). Q2. Can both decryption choices use the encoded `applePayToken` request, and does Apple authentication prove funds movement? No. The primary page's encoded framework `paymentData` to `paymentMethod.applePayToken` server `/payments` request is the **Adyen-managed decryption** path (pinned raw lines 133–164). The related [[raw/adyen/docs/payment-methods/apple-pay/api-only/apple-pay-token-decryption/2026-09-15|token-decryption guide]] requires a merchant-owned certificate, Apple Developer account, PCI compliance and API-only integration for self-decryption (related raw lines 693–702); its customer-initiated example sends decrypted `scheme` card details and applicable `mpiData`, not `applePayToken` (related raw lines 725–767), and it directs a duplicate `transactionId` check before crediting (related raw lines 710–717). Web merchant validation is separate and has a five-minute session limit (pinned raw lines 78–129). The sample `Authorised` response is not capture or settlement evidence (pinned raw lines 455–477).
