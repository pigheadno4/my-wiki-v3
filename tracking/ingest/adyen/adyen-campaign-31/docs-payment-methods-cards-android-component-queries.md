# Android Card Component retrieval checks

Q1. What is this guide for, and what must already exist? It adds cards to an Android Components v5.0.0-or-later integration with a chosen Sessions or Advanced server-side flow and cards added in Customer Area (pinned raw lines 15–39). Base card requests add no card-specific fields, while optional UI and tokenization features have their own conditions (lines 41–75, 379–393). Q2. Can the Advanced storage-switch example or test-card snippet establish live token creation and compliant card acceptance? No. The Advanced prose specifies `setShowStorePaymentField(true)` but the adjacent Kotlin snippet sets `false`, so the page conflicts about showing the option (pinned raw lines 1023–1051). Its `test_` card details are a test-only shortcut when the client is unfinished (line 2580); the guide separately calls for live card enablement, PCI DSS assessment and its stated SAQ A submission (lines 2582–2588). A token-created webhook and example request do not establish actual token creation or authorization/capture/settlement (lines 1446, 1495–1517).
