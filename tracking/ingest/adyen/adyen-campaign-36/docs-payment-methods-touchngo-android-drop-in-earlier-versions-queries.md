# Touch'n Go Android Drop-in earlier-versions retrieval questions

## Q1 — What is this page's purpose and scope, and what cannot be inferred?

It is an **earlier-versions** Android Drop-in Touch'n Go integration guide. Its malformed heading contains v4.x.x wording (raw lines 15–19), while the requirements explicitly specify an existing **Advanced flow** and Support-assisted addition in test Customer Area (lines 21–26; [[source-adyen-docs-payment-methods-touchngo-android-drop-in-earlier-versions]]). The introductory and See also Android links target Sessions guides (lines 19, 411), a source inconsistency; they do not establish a Sessions implementation from this guide. Neither the versioned examples nor displayed result examples establish a current SDK/API minimum or completed real authorization/capture/settlement. ## Q2 — What are the material display, redirect, result and environment conditions?

For method display, `/paymentMethods` includes **MY**, **MYR** and payment value (raw lines 28–36). Drop-in returns `paymentComponentData.paymentMethod`; the server sends it in `/payments` with a return URL capped at **1024 characters** and obtained from `RedirectComponent.getReturnUrl(context)` (lines 38–47). The prose says `returnURL` but request examples say `returnUrl` (lines 47, 65). The server passes response `action` to the client, then after app return posts `actionComponentData.details` to `/payments/details`; resultCode/pspReference are response data, and the shown RedirectShopper/Authorised responses are examples (lines 350–401). The page requires Support to add Touch'n Go in live Customer Area (lines 403–407); TEST listing, setup and example responses are not live outcome proof ([[source-adyen-docs-payment-methods-touchngo-android-drop-in-earlier-versions]]).
