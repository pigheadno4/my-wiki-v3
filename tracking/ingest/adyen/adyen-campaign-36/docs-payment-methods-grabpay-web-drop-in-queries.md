## Q2 — Central capability, prerequisites and warnings

Sessions and Advanced each require an existing Web Drop-in base integration and GrabPay Customer Area setup (raw lines 25–37). PayLater postpaid/installment payments need delivery address and item data, expressed as required `deliveryAddress` and `lineItems` in both `/sessions` and `/payments` tables; for Wallet the page only recommends providing them to ease future PayLater support (raw lines 39–57, 510–517). `/sessions` is the default for Web Drop-in v5.0.0+, whereas the `/payments` tab is for an additional use case or a pre-v5 integration (raw lines 50–52, 510–517). No GrabPay-specific Drop-in configuration is stated; test wallet credentials come from Support, simulator login uses a registered phone and OTP, and live acceptance needs a live Customer Area request (raw lines 811–824). The examples' 1000 order amount versus one quantity-1 line item of 400 is unexplained (raw lines 65–91, 525–554).
