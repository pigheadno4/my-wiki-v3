## Q1 — What is this page's purpose and scope, and what cannot be inferred?

It is a GrabPay add-on for an **existing Android Components** Sessions or Advanced integration, expressly targeting **v5.0.0** and linking earlier versions separately (raw lines 19–39; [[source-adyen-docs-payment-methods-grabpay-android-component]]). It is not a standalone integration or evidence of current merchant enablement, a completed transaction, app-return handling, capture or settlement. The page states no Checkout API minimum. ## Q2 — What are the version, request/configuration and TEST/live conditions?

The existing Sessions or Advanced Android Components flow must meet the stated **minimum v5.0.0**, with GrabPay added in Customer Area (raw lines 23–39). This page says no additional GrabPay fields for `/sessions` or `/payments`, nor additional GrabPay Component configuration (lines 41–67), but it does not distinguish **Wallet** from **PayLater**. The separately pinned GrabPay iOS Drop-in guide requires delivery address and item details for PayLater, so this broad Android wording does not settle PayLater request scope across integrations ([[source-adyen-docs-payment-methods-grabpay-ios-drop-in]]). TEST instructions use Support-provided test-wallet credentials and registered-phone/OTP simulator login, with status checked in Customer Area (lines 69–76); live acceptance requires a request in live Customer Area (line 78). These are setup/testing instructions, not successful-payment proof ([[source-adyen-docs-payment-methods-grabpay-android-component]]).
