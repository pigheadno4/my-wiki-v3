Q1. What does the Boost Wallet API-only guide cover, and what cannot be inferred?
A1. It is a historical add-on for an existing Advanced Web API-only integration: merchant-built form, MY/MYR `/paymentMethods` discovery (`molpay_boost` in an example), and an illustrated redirect response (raw lines 17–49, 327–338, 620–634). It does not establish current merchant eligibility, a working Boost TEST route, executable completeness of the omitted `paymentMethod` field in the example request, or an authorized/captured/settled transaction (raw lines 340–638). Q2. What prerequisites and material warnings does the guide give?
A2. It requires an existing API-only Web integration with redirect handling and Boost added in Customer Area (raw lines 23–29). The page says to include item information in the payment request but later says no extra parameters, while examples omit item information (raw lines 31–36, 340–618). It also shows TEST endpoint examples but expressly says there is no Boost test environment and describes penny testing in LIVE (raw lines 52–69, 624–638); this is a source contradiction, not a recommendation to run a live test.
