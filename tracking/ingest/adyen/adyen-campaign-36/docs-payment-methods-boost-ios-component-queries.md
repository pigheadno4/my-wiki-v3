Q1. What does the Boost Wallet iOS Component guide cover, and what cannot be inferred?
A1. It is a method-specific add-on for existing iOS Components integrations, split into Sessions and Advanced flows using `InstantPaymentComponent` and `molpay_boost` with redirect handling (raw lines 17–35, 50–69, 76–119). It does not prove current merchant eligibility, a working TEST environment, or an authorized/captured/settled payment; initiation and redirect are intermediate steps (raw lines 54–74, 98–123). Q2. What are the flow-specific prerequisites and warnings?
A2. Sessions requires iOS Components Sessions, Checkout API v68+, redirect handling, and Boost added in Customer Area; it needs no extra `/sessions` parameters or Boost configuration (raw lines 29–48). Advanced similarly specifies an iOS Components integration and redirect handling with no extra Boost configuration or `/payments` parameters, but its requirement links to a Drop-in URL despite the Components wording (raw lines 80–92, 115–119). Both flow sections say there is no Boost Wallet test environment and discuss LIVE penny testing, without authorizing a real transaction here (raw lines 72–74, 121–123).
