**Q2. What capability, prerequisites, and warnings matter?** Add GrabPay in Customer Area; choose `grabpay_XX` from `/paymentMethods` for MY/MYR, SG/SGD or PH/PHP. Wallet needs payment method, Component return URL, reference and amount; PayLater additionally needs address and item details, with PH excluded. Pass the redirect action to the Android Component, POST returned details server-side and treat Pending/Received as awaiting AUTHORISATION webhook; failure/timeout can appear through AUTHORISATION false or OFFER_CLOSED. TEST wallet credentials/simulator and live request are separate gates. Redirect-section link points to Sessions despite the stated Advanced prerequisite; examples mix Checkout v68/v72 without a stated minimum.
