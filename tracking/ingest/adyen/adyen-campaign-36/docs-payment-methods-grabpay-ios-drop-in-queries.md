# GrabPay iOS Drop-in retrieval questions

## Q1 — What is this page's purpose and scope, and what cannot be inferred?

It is an add-on guide for an **existing iOS Drop-in** Sessions or Advanced flow, with GrabPay added in Customer Area (raw lines 19–37; [[source-adyen-docs-payment-methods-grabpay-ios-drop-in]]). It does not establish a new standalone iOS integration, an iOS SDK minimum, current merchant enablement, or successful authorization/capture/settlement. Its `/sessions` and `/payments` routing prose invokes **Web Drop-in** versioning inside this iOS guide (lines 50–52, 510–512), so it cannot safely be presented as an iOS version rule. Route: [[index]] → [[adyen-index]] → [[adyen-online-payments]] → [[source-adyen-docs-payment-methods-grabpay-ios-drop-in]] → [[raw/adyen/docs/payment-methods/grabpay/ios-drop-in/2026-09-15]].

## Q2 — What are the material PayLater data, configuration and environment conditions?

For **PayLater** postpaid/installment payments, collect and send delivery address and purchased-item information as `deliveryAddress` and `lineItems` in the selected endpoint; for **Wallet**, including these is recommended future preparation rather than stated requiredness (raw lines 39–57, 510–517). Both Drop-in configuration tabs say no GrabPay-specific integration is required (lines 811–819), while base flow and Customer Area setup remain prerequisites (lines 21–37). The TEST route uses Support-provided test wallet credentials, registered phone/OTP simulator login and Customer Area payment-list check (lines 821–828); live acceptance requires a request in live Customer Area (line 830). TEST example code has blank currency/country/return URL placeholders, and the curl examples show v69 `/sessions` and v72 `/payments` rather than a general API minimum (lines 59–93, 519–555). A setup request, simulator login or test-status lookup is not live payment proof ([[source-adyen-docs-payment-methods-grabpay-ios-drop-in]]).
