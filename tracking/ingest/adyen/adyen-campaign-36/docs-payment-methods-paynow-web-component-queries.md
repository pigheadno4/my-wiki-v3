Q1. What does the PayNow Web Component guide cover, and what cannot be inferred?
A1. It is a method-specific add-on for existing Adyen Web Components integrations, split into Sessions and Advanced flows (raw lines 17–25, 99–107). It covers Component import/mount, QR-code-related configuration/action handling, and live enablement (raw lines 43–97, 109–151). It does not prove current eligibility, an actual QR scan or a successful authorized/captured/settled payment (raw lines 25–151). Q2. What are the central flow-specific prerequisites and warnings?
A2. Sessions requires an existing Web Components Sessions integration, Checkout API v68+, PayNow in Customer Area, and a required `countdownTime` in minutes after QR load; the shown value `5` is an example (raw lines 29–35, 61–70). Advanced requires an existing Advanced Web Components integration, `action.type: qrCode` handling and PayNow setup; it says no additional `/payments` parameters (raw lines 101–107, 137–141). Before live acceptance the guide requires Support to add PayNow in the live Customer Area, and it warns that test-environment bank transfers cannot be reversed and still deduct funds (raw lines 89–97, 143–151).
