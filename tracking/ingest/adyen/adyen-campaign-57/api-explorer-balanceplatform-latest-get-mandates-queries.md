# Fixed query check: GET /mandates

Canonical source: `wiki/sources/adyen/source-adyen-api-explorer-balanceplatform-latest-get-mandates.md` — https://docs.adyen.com/api-explorer/balanceplatform/latest/get/mandates

## Q1: For `balanceplatform/latest/get/mandates`, what purpose and object identities does this captured page establish, and which required/conditional fields, permissions, prerequisites or consequential constraints govern use?

The 2026-09-15 capture says `GET /mandates` lists direct debit mandates created for a Business Account (raw lines 5–7), and shows only the Balance Platform API v2 **test** base URL (line 10). `cursor`, `paymentInstrumentId` and `balanceAccountId` are optional query parameters (lines 14–19). The balance account is linked to the payment instrument; the instrument is linked to the mandate (lines 18–19). The `200` response requires `link` and `mandates` at top level; individual page-link objects appear when applicable (lines 26–40). A mandate item may include mandate `id`, linked balance-account and payment-instrument IDs, counterparty, timestamps, `pending`/`approved`/`cancelled` status and `bacs` type (lines 40–50). For a returned counterparty, `accountHolder` and `accountIdentification` are marked required, and identification's required fields vary with bank country and transfer currency (lines 42–44). These are response fields, not request requirements. The page identifies `403` insufficient permissions but no exact credential role (lines 72–73). The linked UK Bacs guide, separately at `wiki/sources/adyen/source-adyen-docs-business-accounts-accept-direct-debits-uk.md`, describes a dated limited-availability pilot and capability/approval flow; those prerequisites are not specified by this API Explorer page.

## Q2: What do the response/errors establish, and which lifecycle, deletion, verification/approval, propagation, asynchronous financial outcome, version/environment or missing-evidence boundaries prevent broader inference?

`200` says the list request succeeded and gives mandate records and pagination links (raw lines 21–50). It does not attest that a `pending` mandate later became `approved`, that a `cancelled` mandate was externally confirmed, or that a direct debit was collected. The status field is an optional response item with the three listed values (line 48); no transition timing or deletion operation is specified. Errors are `401` authentication required, `403` insufficient permissions, `422` request validation and `500` server processing failure, each with problem-body fields (lines 53–126). The captured server is test v2 (line 10); the `latest` URL does not verify a present live version, enabled product, account eligibility or actual financial outcome. The separate UK Bacs guide at `wiki/sources/adyen/source-adyen-docs-business-accounts-accept-direct-debits-uk.md` requires an external confirmation loop for mandate amendments/cancellations and describes a distinct later collection process. A list read alone proves neither.
