## Q1: For `Management/latest/get/stores`, what purpose and object identities does this captured page establish, and which required/conditional fields, permissions, prerequisites or consequential constraints govern use?

The 2026-09-15 reference describes a paged `GET /stores` list on Management API v3 **test** (raw lines 5–18). The credential needs either **Management API—Stores read** or **Management API—Stores read and write** role (lines 9–13). Optional query fields are merchant `merchantId`, store `reference`, `pageSize` (default 10, maximum 100) and `pageNumber` (lines 20–28). A result may identify the Adyen-generated store `id`, owning `merchantId`, reference/code, address, business-line IDs, shopper statements, split configuration and payment-facilitator sub-merchant data (lines 49–78). The response table contains conditional rules for address `stateOrProvince`, business lines, external references and nested sub-merchant fields, but these are descriptions of store fields, not required list-request parameters. A live rate-limit warning is present without numerical limit in this capture (line 15).

## Q2: What do the response/errors establish, and which lifecycle, deletion, verification/approval, propagation, asynchronous financial outcome, version/environment or missing-evidence boundaries prevent broader inference?

`200` marks the list read successful, with required `itemsTotal` and `pagesTotal` and optional top-level `_links`/`data`; next/prev links are conditional (raw lines 30–49, 79–80). Optional store `status` can be active (auto-assigned on creation), inactive (new terminal transactions blocked while outstanding captures remain possible) or closed (irreversible; terminals reassigned to merchant inventory) (line 73). These are status descriptions; the GET does not execute a transition or prove terminal boarding, payment-method activation or financial outcome. Errors include `400`, `401`, `403`, `422` and `500` (lines 83–180). The `200` example conflicts with the v3 server: its links point to v1 merchant-scoped store URLs, and `pagesTotal: 1` accompanies a last/next link to page 2 while showing two items with `pageSize=1` (lines 17–18, 189–251). Do not use that example to infer endpoint routing or consistent counts. The only shown base URL is test v3; `latest` does not prove current live version or merchant access.
