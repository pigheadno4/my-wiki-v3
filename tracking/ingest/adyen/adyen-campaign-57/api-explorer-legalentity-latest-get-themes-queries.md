# Fixed query check: GET /themes

Canonical source: `wiki/sources/adyen/source-adyen-api-explorer-legalentity-latest-get-themes.md` — https://docs.adyen.com/api-explorer/legalentity/latest/get/themes

## Q1: For `legalentity/latest/get/themes`, what purpose and object identities does this captured page establish, and which required/conditional fields, permissions, prerequisites or consequential constraints govern use?

The 2026-09-15 capture says `GET /themes` lists **hosted-onboarding page themes** on a Legal Entity Management API v4 **test** host (raw lines 5–18). It shows no query parameter or request body. A `200` response requires a `themes` array; theme records mark `id`, `createdAt` and `properties` required, with optional `description` and `updatedAt` (lines 20–35). `next`/`previous` are optional page strings, present only when a corresponding page exists (lines 28–30). The example light/dark properties, logos, images and links are illustrative values, not a complete schema or an applied theme (lines 102–143). Captured rate limits are 700 requests/5 seconds live, 200/5 seconds test, and 5 failed requests/10 seconds (lines 9–15). `403` denotes insufficient permissions, but this page names no credential role (lines 64–65). A separate Platforms guide at `wiki/sources/adyen/source-adyen-docs-platforms-onboard-users-customize-hosted-onboarding.md` gives theme creation/application prerequisites in its own scope; this list reference does not.

## Q2: What do the response/errors establish, and which lifecycle, deletion, verification/approval, propagation, asynchronous financial outcome, version/environment or missing-evidence boundaries prevent broader inference?

`200` means the theme-list request succeeded and can return theme records and optional page strings (raw lines 20–35). It does not create, update, apply or delete a theme, nor establish that a user saw a particular page, completed onboarding, passed legal-entity verification or gained a capability. Errors are `400`, `401`, `403`, `422` and `500` with optional generic error fields (lines 38–100). The error schema's `pspReference` is generically described as a payment PSP reference (lines 44–48); that field does not turn this theme read into payment evidence. The captured server is v4 test (lines 17–18); although the page gives a live rate limit, it provides no live base URL and no present live eligibility. Its `latest` URL does not certify current deployment. The examples show two presentation themes, not verification, approval, propagation, async financial outcome or funds movement.
