## Q1: For `legalentity/latest/post/businessLines`, what purpose and object identities does this captured page establish, and which required/conditional fields, permissions, prerequisites or consequential constraints govern use?

`POST /businessLines` creates a business line holding a user's industry/source-of-funds information for verification, associated with an existing `legalEntityId` (raw lines 5–11, 29–33). Request properties marked required are `industryCode`, `legalEntityId`, and `service`; service values are `paymentProcessing`, `issuing`, and `banking` (lines 26–33). `salesChannels` is conditionally required for payment processing; `sourceOfFunds` for banking/issuing, with `adyenProcessedFunds` required inside it and `type` required when that value is false (lines 31–35). Additional fund-type fields are conditional (lines 35–52). `webData`/exemption conditions are described without a universal requirement (lines 53–56). The 200-per-legal-entity maximum applies to payment-processing business lines, and captured live/test/failed-request limits are 700/200 per five seconds and five failures per ten seconds (lines 11–19). No named API role is stated; 401 and 403 remain possible (lines 186–209).
