## Q1: For `balanceplatform/latest/post/pins/change`, what purpose and object identities does this captured page establish, and which required/conditional fields, permissions, prerequisites or consequential constraints govern use?

`POST /pins/change` requests a PIN change for the specified card (raw lines 5–7). Its credential must have the Bank Issuing PIN Change Webservice role (lines 9–11). The request-body property table marks `encryptedKey`, `encryptedPinBlock`, `paymentInstrumentId`, and `token` required. The instrument ID identifies the card; `encryptedKey` is the symmetric session key encrypted with Adyen's public key; `token` is the 16-digit value used to generate the encrypted PIN block (lines 18–24). The table does not separately state whether the enclosing body object is required. The example is illustrative (lines 26–36). No accountHolder, balanceAccount, merchant, grant, or transfer ID is an input here.
