Q2. What central capability, prerequisites and warnings?

A2. Sessions requires existing Web Drop-in Sessions, Checkout API v68+, redirect handling and Customer Area addition; its `/sessions` table marks `shopperInteractionDevice` and `channel` required (raw lines 29-47). Advanced requires existing Web Drop-in Advanced, redirect handling and Customer Area addition; `/payments` marks `gopay_wallet` type, `browserInfo` and `channel` required (lines 376-406). The Advanced main-guide URL has an unresolved encoded platform template (line 380). The `Redirect` import is optional tree shaking (lines 75-85, 384-394). Initial token creation needs `storePaymentMethod: true`, a shopper reference of at least three characters and a recurring model; `recurring.token.created` arrives after settlement and supplies the stored ID (lines 89-108, 459-478). Later Subscription uses `ContAuth` and its stored ID, whereas CardOnFile requires a GoPay PIN challenge, redirect return and `/payments/details`; final status comes by `AUTHORISATION` webhook (lines 110-123, 327-360; repeated 480-492, 697-730). Testing directs merchants to Adyen Support, and live acceptance requires a separate live Customer Area request (lines 362-370, 732-740).
