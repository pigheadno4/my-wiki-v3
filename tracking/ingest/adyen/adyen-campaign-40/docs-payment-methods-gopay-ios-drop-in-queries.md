Q2. What central capability, prerequisites and warnings?

A2. Sessions requires existing iOS Drop-in Sessions, Checkout API v68+, Customer Area addition, and `shopperInteractionDevice` plus `channel` in `/sessions` (raw lines 29-45); no GoPay-specific configuration is stated (lines 73-77). Advanced requires existing iOS Drop-in Advanced, redirect handling, Customer Area addition, and `gopay_wallet` type, `browserInfo`, `channel` in `/payments` (lines 368-392). The primary Sessions `/sessions` and Advanced `/payments` curl examples are not copyable: each omits a continuation after `-X POST` and has unescaped inner double quotes inside a quoted `shopperInteractionDevice` or `browserInfo` value (raw lines 49-71 and 396-425). The initial token request needs `storePaymentMethod: true`, a shopper reference of at least three characters and a recurring model; `recurring.token.created` carries the stored ID after settlement (lines 81-100, repeated 445-464). Subscription later uses stored ID, shopper reference, `ContAuth`, and `Subscription` (lines 102-114), while CardOnFile requires GoPay PIN challenge, redirect return and `/payments/details` (lines 327-347). Final processed status is by `AUTHORISATION` webhook (lines 349-352; repeated 713-716). Blank subscription example values (lines 116-317, 480-681) are not usable defaults. Testing requires contacting Adyen Support, and live acceptance needs a separate live Customer Area request (lines 354-362; repeated 718-726).
