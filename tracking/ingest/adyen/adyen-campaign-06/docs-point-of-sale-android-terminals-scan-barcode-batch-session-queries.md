# Fixed answers: batch barcode scanning with Terminal API

## Query 1 — Can a POS app use Terminal API to scan several barcodes on an Android terminal, and does the Admin response contain their data?

**Answer:** In this dated guide, batch scanning is described for scanner-equipped **S1E Barcode, S1E2L, S1F2L, and S1U2** Android payment terminals with a Terminal API integration. The POS system sends an Admin request whose `ServiceIdentification` contains Base64-encoded session JSON: a unique `Session.Id`, `Type: Begin`, and the shown `ScanBarcode` operation with a scanner timeout of 0–300000 ms (300000 ms if `TimeoutMs` is omitted). The operator holds the scan button. The start `AdminResponse` reports whether the session started; each scan's content or failure comes separately in a `ScanBarcodeResult` **event notification**. Successful scan details include `data` and `symbology`, which the merchant's own POS-app logic must process.

**Prerequisites and warnings:** Configure event notifications and implement POS handling before relying on the flow. This method does not require Customer Area scan-button setup. The Admin request is scanner control, not a payment authorization, and a successful start response is not evidence of a scan or payment. The named hardware list is from a 2025-08-19 modification captured 2026-09-15; check present device, version, and account support separately.

## Query 2 — How does the batch scanner stop, and can I copy the sample ServiceID or V400m cancel response into production?

**Answer:** The scanner stops after its configured timeout; the guide shows a `ScanBarcodeResult` event with `status=Failure&reason=Timeout`. To stop it sooner, send a Terminal API Admin request containing Base64-encoded session JSON with the session reference and `Session.Type: End`; inspect the cancel `AdminResponse` for success. The stated `ServiceID` rule is **1–10 alphanumeric characters, unique within 48 hours for that terminal POIID**. The begin-request sample exceeds that length, and the cancel-response sample names V400m even though V400m is absent from the stated eligible scanner models. The failed-start response sample also contains malformed JSON and contradictory text. Do not treat these sample values as validated eligibility or a compliant request.

**Prerequisites and warnings:** Distinguish the Admin start/cancel response from per-scan event notifications; `AdditionalResponse` may be Base64 or URL encoded. A Timeout event is a scanner-session outcome, not a payment decline or payment status. Use the stated constraints and a current Terminal API contract to construct requests; this snapshot does not prove a live terminal's behavior.
