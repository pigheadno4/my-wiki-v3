# Fixed retrieval answers: docs-point-of-sale-android-terminals-deploy-apps-terminal-actions-api

1. **How can a merchant schedule an Android app install on Adyen payment terminals?** In Adyen's pinned 2026-09-15 guide, use a Management API credential with the listed terminal-action and terminal-settings roles, meet the app requirements, upload the app in Customer Area, and obtain its ready app ID from the company-level Android apps listing. Select Android terminal IDs via GET `/terminals`; POST one InstallAndroidApp action to `/terminals/scheduleActions` for up to 100 terminal IDs, with the app ID in `actionDetails`. A provided store ID must match assignment. This is scheduling, not confirmation of installation. Route: [[adyen-android-terminals]]. Evidence: [[source-adyen-docs-point-of-sale-android-terminals-deploy-apps-terminal-actions-api]]; [[raw/adyen/docs/point-of-sale/android-terminals/deploy-apps/terminal-actions-api/2026-09-15|raw §§ Requirements, Android terminal actions, 1–3]].

2. **Does `totalScheduled` mean the app has installed?** No. It counts terminals for which planning succeeded. The response also has `totalErrors` and per-terminal `TRAC` action IDs; GET `/companies/{companyId}/terminalActions/{actionId}` for an action you planned to inspect `pending`, `successful`, `failed`, or `cancelled` status. An invalid terminal ID prevents scheduling for the whole request, while validated IDs can still have individual scheduling errors. Timing depends on maintenance calls and WebSockets, and an open affected app closes when the action runs.
