**Q1: How does Management API terminal assignment differ from boarding and Terminal API payments?** This 2026-09-15 Adyen guide uses Management API to reassign a physical terminal from its initial inventory/account level to a store or qualifying merchant-account state. A store assignment or merchant assignment with `inventory: false` makes the device ready for a separate boarding step; only a boarded terminal is described as able to process transactions. Classic POS Terminal Management API support has stopped for this task. Terminal API is the distinct POS payment-message interface. **Q2: What identifiers, permissions, and outcome signal does automated reassignment require?** Obtain the target `storeId` through merchant-scoped `GET /merchants/{merchantId}/stores`; use credential-scoped `GET /terminals` for terminal `id` and current assignment. The `POST /terminals/{terminalId}/reassign` path identifies a device by model and serial; a merchant target requires the `inventory` field. An API key and operation-specific Management API roles are required: Stores read/read-and-write for store lookup, Terminal actions read for terminal details, and Assign Terminal for reassignment. HTTP 200/OK is asynchronous; `terminalAssignment.completed` is the delayed-assignment completion signal, while boarding and payment remain separate. The guide also points to live assignment rate limits.
