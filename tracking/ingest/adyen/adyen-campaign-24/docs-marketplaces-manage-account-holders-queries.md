# Retrieval checks — docs-marketplaces-manage-account-holders

Q1. What Marketplace account-holder resource and management routes does this guide cover?

A1. Route: [[index]] → [[adyen-index]] → [[adyen-platforms]] → [[source-adyen-docs-marketplaces-manage-account-holders]] → [[raw/adyen/docs/marketplaces/manage-account-holders/2026-09-15]]. The account holder represents a marketplace user and links legal entities, balance accounts and capability data; the guide uses the Configuration API (raw lines 19–21). Customer Area or GET `/accountHolders/{id}` views details; paginated list routes cover marketplace account holders and linked balance accounts (raw lines 25–73, 218–271). PATCH `/accountHolders/{id}` updates fields such as primary balance account, status and capabilities (raw lines 273–290, 483–489, 1016–1024, 1320–1326). This is the Marketplace Balance Platform resource, not Classic Account API.

Q2. What lifecycle, capability and evidence boundaries must be kept when suspending, closing or requesting a capability?

A2. Route: [[index]] → [[adyen-index]] → [[adyen-platforms]] → [[source-adyen-docs-marketplaces-manage-account-holders]] → [[raw/adyen/docs/marketplaces/manage-account-holders/2026-09-15]]. Account holders cannot be deleted; API suspension disables payout capabilities while linked balance accounts and payment instruments remain active (raw lines 23, 483–485). API reactivation requires current suspended state and cannot reverse Adyen-initiated suspension (raw lines 714–718). Permanent closure requires empty balance accounts, closing non-primary before primary, then the holder (raw lines 946–956). A capability request can return `requested=true`, `allowed=false`, `pending` (raw lines 988–1024, 1268–1290); enablement differs from Adyen allowance (raw lines 981–986, 1292–1326, 1569–1591). The disable-capability example requests `sendToTransferInstrument` but shows `receivePayments` in its response (raw lines 1330–1345, 1575–1591). KYC `rejected` is final in the displayed status table (raw lines 1641–1649). None of these example statuses proves verification approval, a payout or bank receipt.
