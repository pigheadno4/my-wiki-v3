# C61 fixed retrieval answers: Issuing Raise disputes API GET /disputes

Pinned raw: `raw/adyen/api-explorer/transfers-api/latest/get/disputes/2026-09-15.md`. Canonical source: [[source-adyen-api-explorer-transfers-api-latest-get-disputes]]; https://docs.adyen.com/api-explorer/transfers-api/latest/get/disputes. The companion [[source-adyen-api-explorer-transfers-api-latest-overview]] identifies the opaque `transfers-api` URL as **Issuing Raise disputes API v4**.

## Q1

This is a **caller-initiated GET read** returning raised disputes matching filters, not an incoming webhook or funds-transfer operation. The companion overview identifies Raise disputes API v4 for Issuing transactions made with Adyen-issued cards or fraud reports, and lists this `GET /disputes` route (companion raw lines 5–7, 49–61). The endpoint lists TEST `https://balanceplatform-api-test.adyen.com/btl/api/v4` and live `https://balanceplatform-api-live.adyen.com/btl/api/v4` bases. All six query fields are optional: `limit` (100 default, 500 maximum per page), `offset` (items skipped), ISO 8601 `createdSince`/`createdUntil` inclusive boundaries, `paymentInstrument` ID, and `status` with `draft`, `submitted`, `closed`, `won`, `chargeback`, `secondPresentment` values. The page calls pagination cursor based and says it returns next/previous links where applicable, but does not explain the relationship with `offset` (assigned raw lines 5–29). It provides no required query field, dispute item/reference ID schema, lifecycle transition, deletion, reversal or timing rule beyond the created-time filters. [[source-adyen-api-explorer-transfers-api-latest-get-disputes]]

## Q2

The endpoint's 200 section says only that the request succeeded; it gives **no success response-body schema or example**, so it does not establish list-item IDs, cursor syntax, or a particular dispute state or chargeback result (assigned raw lines 31–35). It documents 401 for authentication required, 403 for insufficient permissions and 422 for request validation error. Their problem-body top-level fields are optional; `invalidFields` is optional, with `message`, `name`, and `value` required inside each present item (assigned raw lines 37–91). The companion overview separately describes API-key or basic authentication and an additional credential role supplied by Adyen (companion raw lines 9–27). A successful list read is not a dispute decision, chargeback, or financial movement, and the page does not state delivery, order, retry, deduplication or signature rules. Its captured `transfers-api` URL must not be read as the distinct funds-movement Transfers API; the companion catalog is Raise disputes API v4 (companion raw lines 5–7, 49–61).
