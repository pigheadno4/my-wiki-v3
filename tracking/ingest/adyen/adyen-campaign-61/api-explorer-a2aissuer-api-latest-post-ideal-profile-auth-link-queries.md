## Q1

A2A Issuer API v1 `POST /ideal/profile/auth-link` generates a short-lived redirect URL for managing an already registered iDEAL profile associated with the request's required `accountHolderId`. The test/live hosts use `/a2aissuer-api/v1`. A 200 response defines optional `redirectUrl`; if it appears, nested `href` is required. The page gives no URL lifetime duration or profile-management completion rule. Its 422 examples include `1069_008` for no registered profile, `29_001` for missing/invalid request data, and `30_012` for account holder not found; it also documents 400 malformed-request and 500 server-error schemas/examples. [[source-adyen-api-explorer-a2aissuer-api-latest-post-ideal-profile-auth-link]] (https://docs.adyen.com/api-explorer/a2aissuer-api/latest/post/ideal/profile/auth-link), raw lines 5–41, 44–191.

## Q2

HTTP 200 reports success of the management-link request, while the schema does not require `redirectUrl` to be present. The example includes one URL but cannot turn the optional parent into a guaranteed field. Link creation is separate from the user's redirect, profile management, iDEAL authentication, payment authorization, and funds movement; none of those outcomes is established here. The endpoint does not specify delivery/order/retry/deduplication, signature, reversal, or deletion rules. Its 400/422/500 examples demonstrate possible failures rather than an exhaustive error inventory.
