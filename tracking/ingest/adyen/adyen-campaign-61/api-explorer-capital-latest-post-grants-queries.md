# Fixed query check — api-explorer-capital-latest-post-grants

- Q1: Capital API v1 `POST /grants` requests a grant on behalf of an account holder (raw lines 5–15). `grantAccountId` and `grantOfferId` are required; optional destination balance account or transfer instrument has stated holder/legal-entity ownership conditions (lines 19–26). The 200 response requires grant reference `id`, grant-account/offer IDs, balances and status; status code has several lifecycle values rather than guaranteed `Active` (lines 28–52). A 422 is request validation error (lines 55–71). See [[source-adyen-api-explorer-capital-latest-post-grants]] and https://docs.adyen.com/api-explorer/capital/latest/post/grants.
- Q2: HTTP 200 means the request succeeded, with a grant status in its body; it does not establish offer acceptance, actual disbursement, repayment or bank receipt (raw lines 28–52). The endpoint gives no request/response examples, timing, webhook delivery/order/retry/deduplication or signature contract (lines 1–71). See [[source-adyen-api-explorer-capital-latest-post-grants]] and https://docs.adyen.com/api-explorer/capital/latest/post/grants.
