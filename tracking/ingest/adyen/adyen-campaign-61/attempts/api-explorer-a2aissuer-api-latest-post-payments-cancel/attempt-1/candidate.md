## Overview

Captured A2A Issuer API v1 `POST /payments/cancel` reference. It takes a payment `token` and returns a user-redirection URL. The separate [A2A API overview](https://docs.adyen.com/api-explorer/a2aissuer-api/latest/overview) scopes this issuer-facing API to direct payments through Adyen for users with an Adyen Business Account; this is not a merchant Checkout cancellation route. [[adyen]] [[adyen-business-accounts]]

The endpoint says “Cancels the payment.” The separately captured [[source-adyen-docs-business-accounts-send-funds-ideal-integration|iDEAL Business Accounts integration guide]] narrows the flow: the payment must still be pending, unexpired and unconfirmed, and it is considered canceled when the returned `links.cancel.href` is opened. A `200` response or returned link alone should therefore not be treated as proof that the user completed the cancellation path.

## Key takeaways

- The required body field `token` identifies the payment and is generated by Adyen in the payment-details response. The captured v1 servers are `balanceplatform-api-test.adyen.com/a2aissuer-api/v1` and `balanceplatform-api-live.adyen.com/a2aissuer-api/v1`; live operation for a particular account is not established by this reference. See raw lines 9–30.
- The `200` response requires a `links` object. Its `cancel` and `success` objects are individually optional; each object's `href` is required when that object is present. The success example includes `links.cancel.href` only. Do not read the `success` link's schema presence as a successful payment in this cancellation response. See raw lines 32–45 and 103–116.
- The reference lists `400` malformed/format errors, `422` validation errors and `500` server errors. Its `422` examples include an invalid payment token (`1069_003`), an expired payment (`1069_004`), a payment in a final state (`1069_005`), and validation failure (`29_001`). These examples do not establish retry behavior or cancellation success. See raw lines 47–102 and 118–218.
- Error response properties such as `detail`, `errorCode`, `requestId` and `invalidFields` are optional at the parent level. The `invalidFields` entries mark `message`, `name` and `value` required when an entry appears. See raw lines 50–101.
