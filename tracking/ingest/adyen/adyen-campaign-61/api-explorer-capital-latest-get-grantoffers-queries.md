## Q1

Capital API v1 `GET /grantOffers` reads available static financing offers for the required query `accountHolderId`, including static offers created after the user selected a financing amount from dynamic offers. Its test/live hosts use `/capital/v1`. A 200 response requires `grantOffers` and each listed offer's `accountHolderId`; amount, contract type (`loan` or `cashAdvance`), validity dates, fee, offer `id`, and repayment are optional. If optional amount appears, currency and minor-unit value are required within it; optional fee requires its nested amount, and optional repayment requires `basisPoints`, the percentage of incoming net volume deducted for repayment. Optional fee APR is expressed in basis points. The page provides no worked offer response, acceptance step, disbursement timing, or grant lifecycle rule. [[source-adyen-api-explorer-capital-latest-get-grantoffers]] (https://docs.adyen.com/api-explorer/capital/latest/get/grantOffers), raw lines 5–47.

## Q2

HTTP 200 means this read request succeeded and returns an offer list; it does not accept an offer, create a grant, release funds, or prove repayment. The 404 response is for an entity not found and 422 for request validation error; both use optional problem fields, with required item fields only inside an optional `invalidFields` array. The endpoint establishes no delivery/retry/deduplication, signature, payout, bank receipt, reversal or debt-completion rule, and its snapshot does not establish current user eligibility. [[source-adyen-api-explorer-capital-latest-get-grantoffers]] (https://docs.adyen.com/api-explorer/capital/latest/get/grantOffers), raw lines 24–85.
