# C61 fixed retrieval answers: BENEFICIARY_SETUP

## Q1

The captured `Notification/latest` page describes an **incoming Adyen** `POST /BENEFICIARY_SETUP` notification when a Classic benefactor/beneficiary relationship is created (raw lines 5–7). It is an event delivered to the receiver, not the merchant's Setup Beneficiary API call. Optional `content` fields name the source benefactor account and holder by `sourceAccountCode`/`sourceAccountHolderCode`, the destination beneficiary account and holder by `destinationAccountCode`/`destinationAccountHolderCode`, and a `merchantReference`. `pspReference` identifies the originating request. Required top-level event fields are `eventDate`, `eventType`, `executingUserKey`, `live`, and `pspReference`; `content` and `error` are optional. `content.invalidFields` lists fields causing Setup Beneficiary failure, and an empty list means the setup request succeeded; optional `error` carries failed-request information. The table describes optional `transferDate` as the date of setup and funds transfer. The response table's optional `notificationResponse` can be set to `[accepted]` (raw lines 9–32, 69–77). No limit, deletion, reversal, or timing rule beyond the event/transfer date field descriptions is stated here. [[source-adyen-api-explorer-notification-latest-post-beneficiary-setup]]

## Q2

The documented 200 `notificationResponse: [accepted]` acknowledges **receipt of the notification**, not success of the underlying Setup Beneficiary request or a particular funds movement (raw lines 69–77). The heading and lead say when Adyen sends the event, but `invalidFields` distinguishes failed from succeeded setup; the illustrative JSON has a nonempty `invalidFields` array and an `error` object (raw lines 17, 34–68). `transferDate` is optional, and its example value is not live transfer proof (raw line 24 and lines 65–67). This page does not state delivery order, retry, deduplication, signature, or financial-finality rules, and the `latest` URL is a captured route, not evidence of current availability. The separate Fund API request contract must be consulted for request acceptance and processing. [[source-adyen-api-explorer-notification-latest-post-beneficiary-setup]]
