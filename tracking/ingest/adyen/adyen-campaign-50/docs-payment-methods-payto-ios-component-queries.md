## Q1 — purpose, scope and payment boundary

**Query:** What does the captured PayTo iOS Component add to an existing integration, and what do a bank agreement or Pending/await response establish?

**Expected answer:** The page at `https://docs.adyen.com/payment-methods/payto/ios-component` is a 2026-09-15-captured method add-on for existing iOS Components Sessions and Advanced flows, with Checkout API v70+, one-off and subscription agreement setup, Component initialization, and bank/webhook handling. The bank notifies the shopper to authorize or decline an agreement; `Pending`/`await`, agreement acceptance and a token do not prove an authorized payment. `AUTHORISATION` on an accepted agreement can still report authorized or rejected. The method overview separately supports AU/AUD method context and merchant setup; this child page does not show current merchant entitlement or a successful live payment. ## Q2 — flow differences, mandate and warning checks

**Query:** How do the Sessions and Advanced PayTo iOS Component paths handle first and subsequent subscription payments, and which source caveats prevent a copy-ready recipe?

**Expected answer:** Sessions `/sessions` separates one-time from subscription setup/first payment. A one-time request requires shopper first/last name and describes an adhoc exact one-count mandate with one-day default end; subscription setup/first payment requires name, stored-method consent flag, Subscription/Ecommerce and mandate frequency, end date, amount, rule and remarks. `mandate.count` is conditionally needed for non-adhoc frequency even though its table cell is optional. Sessions says subsequent payments use Advanced or API-only, despite showing a stored-method Component initialization tab. Advanced requires `payto`, shopper account identifier, name and `await` handling for initial payments, then storedPaymentMethodId and `ContAuth` within agreement conditions for subsequent payments. `RECURRING_CONTRACT` token references differ across sections from `recurring.token.created.data.storedPaymentMethodId`; verify mapping. The Advanced base link points to Drop-in and its action anchor says redirect while action type is await. The Sessions subscription example omits table-required `storePaymentMethod: true`; several JSON/curl examples omit commas or line continuations. These are captured examples, not validated executable code or a live result.
