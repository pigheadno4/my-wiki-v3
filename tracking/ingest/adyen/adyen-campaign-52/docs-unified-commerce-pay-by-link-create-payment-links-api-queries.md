# Fixed queries — Pay by Link through the API

## Q1 — create, send and result boundary

**Query:** How does the captured Pay by Link API guide create and send a link, and which evidence determines payment outcome?

**Expected answer:** https://docs.adyen.com/unified-commerce/pay-by-link/create-payment-links/api is a 2026-09-15-captured guide. After terms, API key, webhook processing and merchant-account method setup (full pinned raw/adyen/docs/unified-commerce/pay-by-link/create-payment-links/api/2026-09-15.md, ## Requirements lines 42–84), POST /paymentLinks supplies merchantAccount, reference and minor-unit amount; omitted shopperLocale/description/expiresAt yield browser-locale language, no description and a 24-hour expiry (## Step 1 lines 93–103). The response gives id, url and expiresAt; send/redirect the shopper to the Adyen-hosted URL, with iframe embedding barred from 2025-11-01 (raw lines 386–418). Await AUTHORISATION webhook and use paymentLinkId, pspReference and success for transaction result; manual capture is additional only when enabled (lines 420–447). GET /paymentLinks/{linkId} gives active, completed, expired or paymentPending link status, not final success from link creation or an unfinished asynchronous flow (lines 476–505). Customer Area list is EU-created-link scoped and details retained three months (lines 424–432). ## Q2 — reusable, token, method data and expiry qualifications

**Query:** What changes for reusable or tokenizing links, method-specific data and forced expiry, and what must not be inferred?

**Expected answer:** Set reusable=true on POST for a reusable fixed-amount link (pinned raw/adyen/docs/unified-commerce/pay-by-link/create-payment-links/api/2026-09-15.md, ## Create a reusable payment link lines 509–535). For card storage, choose CardOnFile, Subscription or UnscheduledCardOnFile according to later use, seek consent, use a unique non-PII shopperReference of at least three characters, and askForConsent or already-consented enabled mode; zero-value preauthorization is described for subscription/unscheduled setup (raw lines 798–824, 1426–1449, 1751–1771). Retrieve stored details and make later /payments requests separately after shopper completion (lines 1747–1749, 2072–2074). BNPL method-specific lineItems/shopper/address fields are tabulated (lines 2076–2092); API v67+ requiredShopperFields can ask the shopper on the hosted page, or the merchant can supply collected details (lines 2556–2565). PATCH status=expired forces expiry and sets expiresAt to current date/time (lines 3644–3648, 3839–3858), not a refund or reversal. This page's 24-hour default does not restate the related overview's 70-day maximum/five-failure rule; consult wiki/sources/adyen/source-adyen-docs-unified-commerce-pay-by-link-create-payment-links.md and the supported-method source for their BNPL channel conflict. The examples do not prove consent, account enablement, token creation, live link issuance or payment success.
