## Q2 — Central capability, prerequisites and warnings

Start with an existing Web Drop-in integration and add Trustly in test Customer Area (primary raw `:19-26`). The v6 import is conditional; the page says ordinary Trustly requests need no extra fields, points to `/sessions` as the v5.0.0-or-later Drop-in default and `/payments` for additional use cases, and requires no Trustly-specific Drop-in configuration (primary raw `:28-45`). TEST uses Trustly's ID-format fixture and test Customer Area status checks; live acceptance requires a request in live Customer Area (primary raw `:47-53`). None of these steps proves bank funds arrived; the overview's `AUTHORISATION`/funding warning and chargeback path remain relevant (overview raw `raw/adyen/docs/payment-methods/trustly/2026-09-15.md:38-53`).
