# Q2 — Central capability, prerequisites and warnings

Route: `wiki/index.md` → `wiki/adyen-index.md` → `wiki/concepts/adyen-android-sdk.md` → `wiki/sources/adyen/source-adyen-docs-payment-methods-twint-android-component.md`. Stored-payment retrieval also routes via `wiki/concepts/adyen-tokenization.md`, and online-method retrieval via `wiki/concepts/adyen-online-payments.md`.

Sessions needs an existing Components integration, Checkout API v68+ and Customer Area TWINT setup, but no extra ordinary `/sessions` parameters. Advanced needs an existing Components integration, TWINT setup and `redirect` or `sdk` action handling, but no extra ordinary `/payments` parameters (raw `adyen/docs/payment-methods/twint/android-component/2026-09-15.md:25-41,194-202,310-314`). For recurring use, `/payments` token creation includes `storePaymentMethod: true` and a shopper reference; a `recurring.token.created` webhook gives stored ID, and later `ContAuth` payments use `Subscription` or `UnscheduledCardOnFile` (raw lines 147-186,316-355). The later Sessions display subsection spells `storedPaymentMethodMode` in `/sessions`; verify that field against the API schema. Advanced maps the shopper's storage choice through `data.storePaymentMethod` and requests stored methods with shopper reference (raw lines 386-423). Storage UI defaults visible but is not consent by itself (raw lines 72-76,233-237). Test status is checked in Customer Area; live acceptance requires a live Customer Area request (raw lines 188-192,357-361).
