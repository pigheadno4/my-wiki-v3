## Q2 — Central capability, prerequisites and warnings

Sessions and Advanced each require an existing matching Web Components flow and adding Trustly in Customer Area (primary raw `:21-37`). The guide says no extra Trustly fields for the ordinary `/sessions` or `/payments` route (primary raw `:47-52`). Web Components v6 imports and mounts `Trustly`; v5.x.x or earlier uses `checkout.create('trustly')`. The v6 import link is labeled for a Component but points to `integration=Drop-in`, so its target is not an exact Components route (primary raw `:39-45`, `:54-84`). TEST supplies an ID-format fixture and Customer Area status lookup; accepting live payments needs a request in live Customer Area (primary raw `:86-92`). Do not equate authorization with received funds: the approved Trustly overview describes delayed/cancelled bank transfers and a chargeback path (overview raw `raw/adyen/docs/payment-methods/trustly/2026-09-15.md:38-53`).
