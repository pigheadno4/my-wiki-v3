Q1. What does the PayCo Android Component guide cover, and what cannot be inferred?
A1. It is a PayCo-specific add-on to existing Android Components integrations for Sessions and Advanced flows, each with redirect handling and `InstantPaymentComponent` examples using `kcp_payco` (raw lines 17–36, 75–126, 134–234). It does not establish a concrete SDK version from `YOUR_VERSION`, current merchant eligibility, live enablement or a completed authorized/captured/settled payment (raw lines 52–65, 128–132, 154–165, 236–240). Q2. What prerequisites and method-object differences does it state?
A2. Sessions requires Checkout API v68+, Android Components Sessions, redirect handling and PayCo in Customer Area; its examples get `kcp_payco` from `checkoutSession` (raw lines 29–36, 83–125). Advanced requires an Android Components Advanced integration and redirect handling, then selects `kcp_payco` from the `/paymentMethods` response (raw lines 136–142, 183–227). Both show Compose/non-Compose paths, no extra PayCo configuration or request parameters, and no specific PayCo test credentials; the guide directs testing questions to Support (raw lines 40–71, 128–132, 144–177, 230–240).
