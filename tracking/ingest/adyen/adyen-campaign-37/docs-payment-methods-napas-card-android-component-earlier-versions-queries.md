Q2. What are the central capability, prerequisites and warnings? Add Napas card in Customer Area, query `/paymentMethods` with VN/VND and an amount, then the merchant server submits `/payments` with the page's stated `momo_atm` and Component-derived return URL (`raw/adyen/docs/payment-methods/napas-card/android-component/earlier-versions/2026-09-15.md:26-54`). Pass the redirect action to Android, then submit `actionComponentData.details` from the return to server `/payments/details` (`raw/adyen/docs/payment-methods/napas-card/android-component/earlier-versions/2026-09-15.md:157-198`). The Redirect Component link points to a Sessions-flow Android Components guide (`raw/adyen/docs/payment-methods/napas-card/android-component/earlier-versions/2026-09-15.md:177`), despite this page's Advanced-flow requirement (`raw/adyen/docs/payment-methods/napas-card/android-component/earlier-versions/2026-09-15.md:30`); do not infer Sessions support from the link. The curl body is syntactically JSON but has a literal hinted property rather than the ordinary `paymentMethod` `/payments` field (`raw/adyen/docs/payment-methods/napas-card/android-component/earlier-versions/2026-09-15.md:69-70`); its `/payments` and `/payments/details` curl examples use v68 and v72 respectively (`raw/adyen/docs/payment-methods/napas-card/android-component/earlier-versions/2026-09-15.md:59`, `raw/adyen/docs/payment-methods/napas-card/android-component/earlier-versions/2026-09-15.md:186`), which does not establish general version compatibility. `Pending`/`Received` are not final and require AUTHORISATION; an incomplete offer may yield `OFFER_CLOSED` (`raw/adyen/docs/payment-methods/napas-card/android-component/earlier-versions/2026-09-15.md:210-229`).
