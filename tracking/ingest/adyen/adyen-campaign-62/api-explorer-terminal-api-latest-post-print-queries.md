# api-explorer-terminal-api-latest-post-print: fixed query answers

## Q1

The captured 2026-09-15 API Explorer page is a Terminal API `POST /print` Print Request/Response body reference: the request conveys print data and how to process it. It lists test cloud Device API `/v1/merchants/{merchantAccount}/devices/{deviceId}/sync` and `/async` transport URLs, whose path supplies merchant account and device ID, and a local-terminal-IP placeholder. The page itself gives no complete Terminal API message envelope, protocol version, `POIID`, sale ID, session ID, or production endpoint; `latest` is a documentation label and the Device API `v1` path does not version the Print message schema. The request-body table requires `PrintOutput.DocumentQualifier`, `ResponseMode`, and `OutputContent.OutputFormat`. `OutputText` is mandatory only for Text, `OutputXHTML` only for XHTML, and `OutputBarcode` only for barcode output; the table disallows each in other formats. The optional `IntegratedPrintFlag` changes response timing: integrated printing responds immediately even with `PrintEnd`. The optional `RequiredSignatureFlag` concerns a physical customer signature on a cardholder payment receipt. The page lists no payload-wide size, retry, reversal, timeout, or deprecation rule. ## Q2

The `200 Success` section describes a Print Response result, which may be absent if a response is not required. When present, the response-body table requires `DocumentQualifier` and `Response.Result`; `Result` can be `Success`, `Failure`, or `Partial`. The `Response` description makes `ErrorCondition` absent or unused for Success and present in other cases, with optional `AdditionalResponse` for processing/logging detail. An HTTP 200 heading is not proof of a successful print, and an immediate response under `IntegratedPrintFlag` does not prove printing has ended. Print processing is separate from payment authorization, capture, reconciliation, settlement, and bank receipt, even if the document qualifier names a receipt. This page lists test cloud sync/async paths and a local address placeholder but no authentication/security method, message-header correlation or idempotency rule, async callback/status workflow, or absent-result recovery. It also supplies no explicit Terminal API protocol version or deprecation statement. [Canonical source: [[source-adyen-api-explorer-terminal-api-latest-post-print]]](https://docs.adyen.com/api-explorer/terminal-api/latest/post/print); pinned raw lines 10–19, 26–51.
