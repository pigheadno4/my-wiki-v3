# Fixed query answers — api-explorer-terminal-api-latest-post-storedvalue

## Q1

The captured `terminal-api/latest/post/storedvalue` page defines `POST /storedvalue`, a Terminal API StoredValue Request for processing stored-value transactions. It lists `Reserve`, `Activate`, `Load`, `Unload`, `Reverse`, and `Duplicate`. `latest` and `/v1/` cloud test route text appear, but no numbered Terminal API schema version is given. The page names no caller or session ID; cloud routes identify `{merchantAccount}` and `{deviceId}` and offer `/sync` and `/async`, with a local terminal IP form also listed. Request `SaleData` and `StoredValueData` are required. The sale transaction identity requires `TransactionID` and `TimeStamp`; each stored-value item requires a transaction type. `StoredValueAccountID` is optional, but if included its account type, entry mode, identification type, and stored-value ID are required. Original POI reference, item amount, and currency are optional in the table. The response has a separate POI transaction identity; result may be `Success`, `Failure`, or `Partial`, with `ErrorCondition` required for non-success. Optional stored-value results are described for successful/partial loaded or activated entries; current balance is optional if relevant and known. No timing limit or full reverse lifecycle is stated. ## Q2

The `200 Success` section describes a response body, not guaranteed stored-value success: `Response.Result` includes `Failure` and `Partial`, and non-success requires `ErrorCondition`. Required response `SaleData` and `POIData.POITransactionID` distinguish sale and POI transaction identities. `StoredValueResult` is optional and, for successful or partial load/activation, has one entry per requested item loaded or activated; optional `CurrentBalance` does not guarantee a balance. The page does not establish when a command is merely accepted versus completed, an asynchronous callback result, authentication/security, a complete correlation header, a deprecation rule, or financial authorization, capture, settlement, or bank receipt. `POIReconciliationID` is optional if result is successful and does not prove financial settlement. `Reverse` is a stored-value transaction enum here, without a separate reversal outcome guarantee.
