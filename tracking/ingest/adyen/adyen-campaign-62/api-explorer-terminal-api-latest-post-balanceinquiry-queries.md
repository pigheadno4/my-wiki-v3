# C62 fixed-query answers: Terminal API POST /balanceinquiry

Canonical source: [[source-adyen-api-explorer-terminal-api-latest-post-balanceinquiry]] — https://docs.adyen.com/api-explorer/terminal-api/latest/post/balanceinquiry

## Q1

The captured `POST /balanceinquiry` page describes a request for information about an account and a response that can identify a payment, loyalty, or stored-value account and convey its balance. It is the Terminal API API Explorer `latest` page, captured 2026-09-15; the shown cloud **test** servers use Device API `/v1/merchants/{merchantAccount}/devices/{deviceId}/sync` and `/async`, and the local option is `<local-terminal-IP-address>`. Thus the URLs identify merchant and device routing, while the page's request body names neither a caller identity nor a MessageHeader, SaleID, ServiceID, POIID, Nexo protocol version, or session ID. `latest` alone does not identify a protocol version or live endpoint. Raw lines 5–19 and 21–46.

Both top-level request objects, `PaymentAccountReq` and `LoyaltyAccountReq`, are marked optional. Within an included `CardAcquisitionReference`, `TransactionID` and `TimeStamp` are required; within included `PaymentInstrumentData`, `PaymentInstrumentType` is required; within included `LoyaltyAccountID`, `EntryMode`, `IdentificationType`, and `LoyaltyID` are required. These are conditional child properties, not required request-body parents. The timestamp is described as transaction/event time and a uniqueness aid; the page gives no retention period, deadline, retry interval, default, size limit, reversal procedure, or lifecycle transition. Raw lines 23–46. Response failure conditions are enumerated, including `InProgress`, but no handling sequence is specified. Raw lines 57–60.

## Q2

The page's `200 Success` response section defines a required `Response` with required `Result`, whose values include `Success`, `Failure`, and `Partial`; therefore the HTTP section title alone is not a successful balance finding. `ErrorCondition` is absent or unused for a successful result and must be present otherwise, with `AdditionalResponse` optional. `PaymentAccountStatus` is optional; it contains optional `CurrentBalance` and `Currency`, so even a successful processing result does not guarantee both fields in this schema. Its description references `BalanceInquiryRequest. PaymentAccount` although the request table calls its object `PaymentAccountReq`; the snapshot does not resolve that naming difference. Optional acquirer and print/display receipt structures do not establish financial settlement or bank receipt. Raw lines 48–87.

The cloud async URL establishes a listed transport, not the timing or finality of an asynchronous result. The page gives no response MessageHeader or correlation procedure beyond optional `CardAcquisitionReference.TransactionID` and `TimeStamp` fields, no authentication recipe, and no full security contract; `ProtectedCardData` is described only as sensitive card data protected by CMS. It has no version/deprecation statement beyond the `latest` URL and captured `/v1` cloud path, and no payment authorization, capture, reconciliation, settlement, reversal, or later spendability evidence. `Failure`, `Partial`, and error enums should be read as request-processing outcomes for this inquiry, not as authorization outcomes. Raw lines 10–19, 28–34, 39–41, and 48–87. See [[source-adyen-api-explorer-terminal-api-latest-post-balanceinquiry]] (https://docs.adyen.com/api-explorer/terminal-api/latest/post/balanceinquiry).
