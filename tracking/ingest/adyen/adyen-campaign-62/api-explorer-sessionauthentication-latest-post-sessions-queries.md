# api-explorer-sessionauthentication-latest-post-sessions: fixed query answers

## Q1

This 2026-09-15 Session Authentication API `POST /sessions` snapshot creates a token required for Adyen for Platforms Onboarding or Platform Experience **UI components**. Test and Live server bases end in `/authe/api/v1`; `latest` is the documentation route, while the listed server paths identify the captured v1 API. The component front end uses the session data for component-related server calls. The request-body table requires `allowOrigin` (component URL), `policy` (allowed resources/roles), and `product` (`onboarding` or `platform`). In live, `allowOrigin` must be SSL protected and start with `https://`. `policy.resources`, `policy.roles`, and resource `type` are each marked No in the table, but the prose requires the relevant type and unique identifier when describing a resource: Onboarding uses the legal entity with a contractual platform relationship (the individual's legal entity for a sole proprietor); Platform Experience uses the account holder associated with the displayed balance account. The examples show `legalEntityId` and `accountHolderId`, though the schema table has no rows for those ID keys. No device, terminal, payment session, token expiry, renewal, cancellation/reversal, or timing rule appears. [Canonical source: [[source-adyen-api-explorer-sessionauthentication-latest-post-sessions]]](https://docs.adyen.com/api-explorer/sessionauthentication/latest/post/sessions); pinned raw lines 5–73.

## Q2

HTTP `200 Success` describes a successfully created component session token. The response table lists session `id` and `token` as optional properties, although both 200 examples contain them; the introduction says the response contains encrypted session data. That token and session identity enable component integration, not payment authorization, capture, completed onboarding/verification, transfer, payout, settlement, or bank receipt. The page documents `400` bad request, `401` unauthorized, and `403` forbidden; the 403 example denies access to all token-policy resources. Error `requestId` is optional; the 400 example's `invalidFields` item omits `value` despite the table marking it required within an item. This operation page provides no authentication header/credential-role instructions, idempotency or other success correlation key, async outcome or webhook contract, token lifetime/revocation, deprecation, or component-version compatibility. The Checkout API's same-named `POST /sessions` is a different payment-session family; see [[source-adyen-api-explorer-checkout-latest-post-sessions]].
