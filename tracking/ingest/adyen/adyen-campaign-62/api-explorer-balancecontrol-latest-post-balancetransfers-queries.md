# api-explorer-balancecontrol-latest-post-balancetransfers: fixed query answers

## Q1

The 2026-09-15 API Explorer capture describes Balance Control API `POST /balanceTransfers` for transferring balances between **merchant accounts**. This operation page's Test and Live Servers list uses `/balance-control/api/v2`. The separate [[source-adyen-api-explorer-balancecontrol-latest-overview|Balance Control API v2 overview]] gives a conflicting live base in its Going live paragraph, `https://balance-control-live.adyen.com/api/v2`, while its Servers list agrees with this operation page at `https://balance-control-live.adyen.com/balance-control/api/v2`. Neither captured page resolves which live URL to use. The page's `latest` label does not identify a BalanceControlV1 or Balance Platform transfer contract. The request supplies `fromMerchant` and `toMerchant` merchant-account identifiers, with no terminal, device, or session identity. Success requires both merchant accounts under the same company account and legal entity, adequate source funds, and a shared processing currency. The request requires `amount.currency` as a three-character ISO code, integer `amount.value` in minor units, `fromMerchant`, `toMerchant`, and `type` from tax/fee/terminalSale/credit/debit/adjustment; optional `reference` has an 80-character maximum. Multiple requests for the same merchant-account pair must be sent sequentially because parallel requests may not be processed. The page documents 401 Unauthorized and 422 validation errors but no reversal, retry/idempotency, expiry, or settlement timing rule. [Canonical source: [[source-adyen-api-explorer-balancecontrol-latest-post-balancetransfers]]](https://docs.adyen.com/api-explorer/BalanceControl/latest/post/balanceTransfers); operation raw lines 5–35, 64–99; overview raw lines 28–38.

## Q2

The 200 section says the request succeeded and returns required `createdAt` (described as the date the transfer was performed) and a 16-character `pspReference`; the response example caption instead says “balance transfer created.” This page therefore documents a successful transfer response and its identity, but no independently stated ledger/booking stage, reconciliation record, downstream payout, or bank receipt. The 401/422 schemas provide optional `requestId` and conditional `invalidFields` error detail; client `reference`, error `requestId`, and success `pspReference` should be kept distinct. The page does not state an authentication method or credential role, asynchronous callback/outcome path, retry/idempotency key, reversal route, deprecation rule, or current account eligibility. The operation page's `/balance-control/api/v2` Servers list establishes the captured Balance Control API v2 family/version, not a version shared with BalanceControlV1 or Balance Platform Transfers. Its listed live path conflicts with the Going live paragraph of [[source-adyen-api-explorer-balancecontrol-latest-overview|the v2 overview]], which omits `/balance-control`; that overview's own Servers list agrees with this operation page, so these snapshots do not settle the live base. The overview separately describes API-key guidance, but this operation page does not.
