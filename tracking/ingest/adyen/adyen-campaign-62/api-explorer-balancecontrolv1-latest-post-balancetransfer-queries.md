# C62 fixed-query answers: Balance Control v1 POST /balanceTransfer

## Q1

The 2026-09-15 reference at https://docs.adyen.com/api-explorer/BalanceControlv1/latest/post/balanceTransfer describes Balance Control **v1** `POST /balanceTransfer` as starting a balance-transfer request between **merchant accounts**, on the listed TEST server `https://pal-test.adyen.com/pal/servlet/BalanceControl/v1`. The page does not name a caller role or credential and has no device or session identity. `fromMerchant` and `toMerchant` identify source and destination merchant accounts; those accounts must be under the same company account and legal entity and share at least one processing currency, and the source must have sufficient funds. The body requires `amount.currency` (three-character ISO code) and integer `amount.value` in minor units, both merchant IDs, and a `type` from `tax`, `fee`, `terminalSale`, `credit`, `debit`, and `adjustment`. Optional `reference` has an 80-character maximum and is generated uniquely by Adyen if omitted; optional `description` has a recommended 140-character maximum because it may be truncated. Repeated requests for the same merchant pair must be sequential because parallel requests may not be processed. The page provides no reversal operation, retry/idempotency rule, or completion timing. [[source-adyen-api-explorer-balancecontrolv1-latest-post-balancetransfer]] (raw lines 5–32).

## Q2

The same contract's `200 Success` text says **the request succeeded**, and the response requires a `createdAt` date for when the transfer was **requested**, a 16-character `pspReference`, amount, merchant IDs, type, and `status`. That status can be `transferred`, `failed`, `error`, or `notEnoughBalance`; HTTP 200, request creation time, and the reference do not by themselves establish a successful movement of funds. The example shows `transferred`, but the schema explicitly permits failure states. The page describes no authentication/security role, idempotency or correlation guarantee beyond returned/request references, asynchronous notification or polling outcome, version migration/deprecation, settlement or payout process, or bank receipt. It is Balance Control **v1** merchant-account movement, not evidence for Balance Control v2 or Adyen for Platforms balance-account transfers. https://docs.adyen.com/api-explorer/BalanceControlv1/latest/post/balanceTransfer; [[source-adyen-api-explorer-balancecontrolv1-latest-post-balancetransfer]] (raw lines 17–18, 25–32, 49–89).
