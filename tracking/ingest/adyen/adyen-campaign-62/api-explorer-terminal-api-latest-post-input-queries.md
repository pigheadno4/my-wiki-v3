# C62 fixed query answers: api-explorer-terminal-api-latest-post-input

## Q1

The captured **Terminal API v1 POST /input** page defines an `InputRequest` that tells an input device what to display and how to process a cashier/customer input command; it can also carry a `DisplayOutput` operation. Its test cloud routes address `{merchantAccount}` and `{deviceId}` through `/sync` or `/async`, and it lists a local-terminal-IP route. The request-body table requires `InputData`, then `Device`, `InfoQualify` and `InputCommand` within it; it marks `DisplayOutput` optional, with required nested Device/InfoQualify/OutputContent and required `OutputFormat` when present. Text, XHTML and barcode output payloads are format-conditional, and menu entries are for an input command. Optional `MaxInputTime` is in seconds, with optional length bounds and other flags but no numeric defaults/ranges; `ImmediateResponseFlag` can request an early response. The 200 response schema requires `InputResult`; its Result is Success, Failure or Partial, with `ErrorCondition` required for non-Success. The table gives no separate reversal rule. ## Q2

An HTTP **200 Success** section identifies the response schema, but the nested InputResult or optional OutputResult still carries the processing result; it can say Success, Failure or Partial. `ImmediateResponseFlag` specifically permits a response before the input command completes, so receipt of that response alone does not prove final user input. `InputResult.Input` is optional and its confirmation, key, text, digit, password and menu fields depend on what was entered; a successful input operation alone establishes no payment authorization, capture, reconciliation, settlement, bank receipt or valid consent. The page lists cloud and local routes and an optional card-input event flag, but does not define authentication headers, nexo header/correlation fields, asynchronous notification payload or eventual outcome rules; those cannot be inferred from its `/async` URL. This is the captured Terminal API v1 operation, not an assertion about another version or current account/device availability.
