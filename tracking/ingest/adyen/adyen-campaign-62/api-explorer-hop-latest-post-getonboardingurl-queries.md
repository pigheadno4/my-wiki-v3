# C62 fixed query answers: api-explorer-hop-latest-post-getonboardingurl

## Q1

The captured `Hop/latest/post/getOnboardingUrl` page is a Classic Hosted Onboarding Page **Hop/v6** test-server contract at `https://cal-test.adyen.com/cal/services/Hop/v6`. A platform calls POST /getOnboardingUrl for an existing Classic **account holder**, identified by required `accountHolderCode`, to obtain an Adyen-hosted page link for that holder; no terminal/device identity or separate session ID is defined here. Optional `collectInformation` limits KYC collection (all applicable checks by default; individual flags default true, with PCI questionnaire partner-platform-only), while `showPages` controls page visibility (checks overview and welcome default false, most others true). Optional `returnUrl` has a 500-character maximum and receives the holder on completion or session timeout; without it, the platform default applies. Locale and edit/OAuth callback fields are optional. The 200 response fields, including `redirectUrl`, `resultCode` and request-identifying `pspReference`, are all marked optional; the returned URL is one-use and this contract says use it within **30 seconds**. A separate Classic HOP guide says **15 seconds** and describes a 30-minute session, so the timing claims conflict. The operation lists 400, 401, 403, 422 and 500 failures and no reversal. ## Q2

A successful **URL issuance request** and returned `redirectUrl` let the platform redirect a holder to HOP; they do not prove the holder used the URL, began or completed a session, passed KYC, became eligible for payments/payouts, or received funds. The optional `pspReference` identifies this request for correlation, not a payment or onboarding completion; optional `resultCode` and `invalidFields` require inspection instead of assuming every HTTP 200 is a finished onboarding result. The page says 401 means authentication is required and 403 means insufficient permissions, but does not identify a credential scheme or role. It contains no webhook/result-event contract, so later verification and financial outcomes require separate evidence. The URL's one-use 30-second statement conflicts with the separate guide's 15-second instruction; neither should be silently generalized. The path says `latest` but its listed server is Hop/v6 test, and this capture does not establish current live availability or behavior in newer Platforms APIs.
