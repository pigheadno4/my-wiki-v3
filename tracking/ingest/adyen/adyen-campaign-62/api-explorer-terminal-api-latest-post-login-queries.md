## Q1

The captured `terminal-api/latest/post/login` page defines the Login Request/Response for a Sale-to-POI session, explicitly the period between Login and the following Logout. The Sale System provides its date/time and Sale software information to the POI System; the response can give POI System date/time, software and component status. The page lists test cloud Device API sync/async `/v1/merchants/{merchantAccount}/devices/{deviceId}` URLs and a local-terminal-IP placeholder. Its `latest` route and cloud `/v1` path do not specify a numbered Terminal API message version. The body requires `DateTime`, `SaleSoftware` (manufacturer ID, application name, software version and certification code) and `OperatorLanguage`. Optional `SaleTerminalData` applies when a Sale Terminal participates and can include `TotalsGroupID`; `OperatorID` and `ShiftNumber` are optional attribution fields. Optional `TrainingModeFlag` marks the *entire session* for test/training rather than real transactions; token, customer-order and POI-serial options have their listed conditions. No request-field length limit, session timeout, Logout schema, payment reversal or financial lifecycle is specified on this page. Raw lines 5–40. ## Q2

HTTP 200 carries a Login Response body, whose required `Response.Result` may be `Success`, `Failure`, or `Partial`; HTTP acceptance is therefore distinct from a successful Login. The text requires `ErrorCondition` for results other than Success despite its generally optional table marker. `POISystemData` is table-optional and described as returned on Success; its optional `POIStatus.GlobalStatus` (when `POIStatus` is present) can be OK, Busy, Maintenance or Unreachable, so Login result and component readiness must be read separately. Optional token-request status applies if the POI manages tokens. This page identifies operator/group/shift labels but supplies no operator-credential or authentication exchange, payment authorization/capture, terminal totals, reconciliation result, settlement or bank receipt; the separate POS login/logout guide explicitly says Login does not authenticate the operator. The async test URL alone does not define callback/final-outcome delivery, and this page supplies no live cloud URL, error HTTP-response schema, explicit message version or deprecation statement.
