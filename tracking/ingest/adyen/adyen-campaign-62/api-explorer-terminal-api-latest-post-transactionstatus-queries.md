# Fixed query answers — api-explorer-terminal-api-latest-post-transactionstatus

## Q1

The captured [`POST /transactionstatus`](https://docs.adyen.com/api-explorer/terminal-api/latest/post/transactionstatus) is a Terminal API **latest** request for information on the last or current Payment, Loyalty or Reversal transaction. It lists cloud **test** sync/async device URLs parameterized by `merchantAccount` and `deviceId`, plus a local terminal IP address. The page gives no numeric protocol version, caller authentication or session identifier. Request `MessageReference` and each listed child are marked optional; it identifies a previous message header for a missing-response status inquiry. The shared field description mentions abort, but this endpoint does not establish an abort action. `SaleID` and `POIID` default to their MessageHeader values. Optional `ReceiptReprintFlag` and `DocumentQualifier` address receipt printing. There is no numeric field limit, retry timing rule or reversal outcome rule here. ## Q2

The [response contract](https://docs.adyen.com/api-explorer/terminal-api/latest/post/transactionstatus) documents a `200 Success` status-message response with required `Response.Result` (`Success`, `Failure`, `Partial`). Non-success processing requires `ErrorCondition`; `AdditionalResponse` is optional POI logging detail. A successful completed status inquiry can include optional `RepeatedMessageResponse`, with a header and a body selecting among original response categories, but this page does not expand those transaction response schemas. Thus status-request processing success alone does not establish original payment authorization, reversal success, capture, settlement or bank receipt. `MessageReference` can correlate the prior message, while cloud async is only a listed transport endpoint here; no callback delivery, security scheme, deprecation or version transition is specified.
