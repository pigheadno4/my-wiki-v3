Q1. What does this React Native Apple Pay Component guide require for setup and requests?
A1. It is an Advanced-flow React Native Components add-on requiring the merchant's own Apple Pay certificate and method addition in Customer Area. Client `AdyenCheckout` configuration adds `applepay.merchantID` and `merchantName`; the guide says no Apple Pay-specific additional fields are needed in `/payments`. It gives a test `countryCode: NL`/`EUR 1000` example, not a universal support rule. LIVE also requires API Clientside Encryption Payments role and the live Apple merchant identifier setup. Q2. What optional and recurring details limit implementation and outcome claims?
A2. `supportedCountries` is an issuer-country card filter, `allowOnboarding` defaults false, and the last `summaryItems` value must match server `/payments` amount. Recurring requires `recurringPaymentRequest` plus later shopper-token flow; its table lists `paymentDescription`, `regularBilling`, `managementURL` required, but its example uses `description` and omits a comma. Sandbox lookup, client launch and wallet display do not prove consent capture, live authorization, capture or settlement. Raw lines 64–79, 81–106, 110–147, 149–161.
