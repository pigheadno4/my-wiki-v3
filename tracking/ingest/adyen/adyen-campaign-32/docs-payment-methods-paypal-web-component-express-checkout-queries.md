# PayPal Express Checkout Web Component retrieval checks

Q1. What must exist, and how do Sessions and Advanced identify an Express order update? The guide requires an implemented PayPal Web Component and Web v5.59.0+ (pinned raw lines 19–23). Sessions creates `/sessions`, retains `sessionId`, and uses it with current `paymentData` for `/paypal/updateOrder` (lines 27–40, 73–102). Advanced uses a server `/payments` call from `onSubmit`, stores `pspReference`, and uses it plus latest `paymentData` for updates (lines 962–990). Each successful update returns replacement `paymentData` (837–849, 1725–1737). Q2. Can a Sessions merchant add a review page or use zero-value/`intent: tokenize` token setup, and do the snippets prove completion? Sessions cannot add the extra review page; only Advanced configures `userAction: 'continue'` and defers `/payments/details` until shopper Pay on its review page (pinned raw lines 1880–1939). Zero-value authorization cannot create an Express token, and `intent: "tokenize"` makes tokenization fail; explicit future-charge permission is a strong recommendation (1960–1971). The two details curl bodies are malformed JSON (1863–1877, 1943–1957), other test SDK examples differ in currency/import versions, and lightbox completion or callback is not capture/settlement evidence.
