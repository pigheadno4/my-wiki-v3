Q1. What does this dated API-only guide require to send a Google Pay payment through Adyen?
A1. Add Google Pay in Customer Area, have an existing Checkout API v67+ integration, and integrate Google's Web or Android API using PAYMENT_GATEWAY with `gateway: adyen` and the merchant/company account name as `gatewayMerchantId`. Obtain `PaymentData.token` from Google and send it from the merchant server as `googlePayToken` with `paymentMethod.type: googlepay` to `/payments`; `browserInfo` and `returnUrl` relate to 3DS. Q2. What boundaries prevent treating token, TEST, or response examples as a live successful payment?
A2. This gateway-token page provides no merchant-decryption/key or PCI-level procedure. A returned 3DS `redirect` or `threeDS2` action requires continuation; result codes can be Authorised, Error or Refused, and neither a token nor action is capture/settlement proof. TEST card paths and an illustrated v68/curl snippet are examples; LIVE additionally calls for the API Clientside Encryption Payments role, Google MID association, Google production-deploy steps and a shopper logged into Google with a valid method. The curl has hint annotations in field names, Go version/path labels disagree, and the prose broadly says redirect on any action despite naming `threeDS2`.
