# Fixed query audit: api-explorer-account-latest-post-updateaccountholderstate

- Q1: For `Account/latest/post/updateAccountHolderState`, what purpose and object identities does this captured page establish, and which required/conditional fields, permissions, prerequisites or consequential constraints govern use?
  - Answer: On Account API v6 TEST, `POST /updateAccountHolderState` enables or disables one holder's `Processing` or `Payout` state (raw lines 5–10). `accountHolderCode`, boolean `disable`, and `stateType` are required; `reason` is conditionally required when disabling (lines 14–20). The sample disables payout state (lines 22–32). Authentication/permission errors are 401/403, but the page names no role (lines 124–147).
