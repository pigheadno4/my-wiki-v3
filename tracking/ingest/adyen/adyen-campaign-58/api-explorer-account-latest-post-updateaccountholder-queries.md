# api-explorer-account-latest-post-updateaccountholder — fixed retrieval checks

- Q1: For `Account/latest/post/updateAccountHolder`, what purpose and object identities does this captured page establish, and which required/conditional fields, permissions, prerequisites or consequential constraints govern use?
  - Answer: Captured Classic Account API v6 TEST `POST /updateAccountHolder` updates an account holder identified by required `accountHolderCode`: details/processing tier, with bank account and shareholder additions. Either `accountHolderDetails` or `processingTier` is conditionally required; tier cannot be lowered. Omitted detail parameters remain unchanged except sent `metadata`, which replaces the entire object. Updating address, full phone, bank-account detail, or shareholder contact calls for all fields needed for validation. New bank/shareholder entries omit their UUID/code; a bank UUID uncorrelated with an existing bank account causes update failure. The table gives further conditional nested rules and points to separate required-information guidance for bank fields. 401/403 are listed. See [[source-adyen-api-explorer-account-latest-post-updateaccountholder]] (https://docs.adyen.com/api-explorer/Account/latest/post/updateAccountHolder); raw lines 5–25, 32–139, 601–637.
- Q2: What do the response/errors establish, and which lifecycle, deletion, verification/approval, propagation, asynchronous financial outcome, version/environment or missing-evidence boundaries prevent broader inference?
  - Answer: 200 is labeled request succeeded, but optional `invalidFields` can identify validation failures when the account holder has not been updated; HTTP 200 alone does not prove the requested update took effect. 202 means accepted for processing but incomplete. Response schema can also include request reference, account-holder status and KYC check results. Payout `allowPayout` aggregates conditions; `disabled: false` alone is insufficient. 400, 401, 403, 422, and 500 are listed. The Active/allowPayout sample and TEST endpoint are not live eligibility, completed KYC, payment or payout proof. The page gives no propagation deadline or idempotency contract. See [[source-adyen-api-explorer-account-latest-post-updateaccountholder]] (https://docs.adyen.com/api-explorer/Account/latest/post/updateAccountHolder); raw lines 27–28, 269–598, 601–663, 665–926.
