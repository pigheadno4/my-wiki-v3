- Q1: For `Fund/latest/post/refundNotPaidOutTransfers`, what purpose and object identities does this captured page establish, and which required/conditional fields, permissions, prerequisites or consequential constraints govern use?
  - Answer: Fund API v6 TEST `POST /refundNotPaidOutTransfers` targets all transactions of one account since its most recent payout, not selected individual payments (raw lines 5–10). It refunds only each payment's portion allocated to that account; commission, fees and other accounts' portions remain where split (line 7). Both `accountCode` and its owner's `accountHolderCode` are required (lines 14–18); no amount or selected-transaction list is shown. 401/403 indicate authentication/permission gates, but no named role appears (lines 78–101).
