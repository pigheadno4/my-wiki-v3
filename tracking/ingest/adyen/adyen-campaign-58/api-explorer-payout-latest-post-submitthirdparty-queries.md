- Q1: For `Payout/latest/post/submitThirdParty`, what purpose and object identities does this captured page establish, and which required/conditional fields, permissions, prerequisites or consequential constraints govern use?
  - Answer: Deprecated Payout API v68 TEST `POST /submitThirdParty` submits a payout using details previously stored via `/storeDetail` (raw lines 5–28). New integrations are directed to Transfers API; existing users to an Adyen contact (7–21). Required request properties include amount/currency/minor-unit value, merchant account, recurring, merchant reference, selected stored-detail reference, shopper email/reference (32–56). Nested `recurring.contract` is table-optional but explicitly must be `PAYOUT`; selected detail can be `LATEST` (44–51). Date of birth is mandatory for natural persons; other identity fields have update conditions (39–55). The page lists 401/403 but no named role (88–113).
