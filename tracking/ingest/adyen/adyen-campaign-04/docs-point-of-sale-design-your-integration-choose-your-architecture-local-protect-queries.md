2. **Central capability, prerequisites, warnings?** With Adyen's root certificate installed and a shared key configured (raw `## Requirements`, lines 26–31), the POS app validates the terminal chain and Common Name each connection (`## Validate the terminal certificate`, lines 33–63), encrypts outgoing full Terminal API messages and decrypts/authenticates incoming messages (`## Encrypt communications`, lines 65–358). The protocol derives secret key material, uses a nonce, `NexoBlob`, and a trailer identifying key ID/version and crypto version 1; a receiver checks HMAC and inner/outer header. Cached derived material must be stored securely (line 90). The full PHP sample warns that almost all validation is missing (line 764), so it cannot be treated as production-secure. Troubleshooting ties crypto errors to shared-key mismatch and SSL errors to root installation (lines 1273–1317).
