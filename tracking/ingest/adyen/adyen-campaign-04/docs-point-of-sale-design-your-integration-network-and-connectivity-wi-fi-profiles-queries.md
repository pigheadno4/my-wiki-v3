# Wi-Fi profiles: fixed retrieval checks

1. **What is this guide for, and what should it not establish?** It is Adyen's payment-terminal Wi-Fi profile setup guide for a Wi-Fi-capable terminal in a Terminal API or standalone POS solution. Local profiles cover Personal networks; remote profiles configured through Customer Area or Management API also cover Enterprise EAP-PEAP/EAP-TLS, then load as terminal configuration. It does not prove a particular merchant's eligibility, currently deployed network behavior, payment success, or the current behavior of separately versioned GitHub libraries. Locate `## Requirements` (raw lines 27-46), `## Wi-Fi network and profile types` (48-92), and `## Load profiles on the terminal` (1832-1863). The raw frontmatter's `last_modified` is 2020-10-28 (line 11), while this pinned snapshot is 2026-09-15 (line 2); API examples name their own older library versions under `## Set up Wi-Fi profiles using API calls`.

2. **How are remote profiles configured and loaded, and what needs care?** Customer Area provides PSK/PEAP/TLS setup, with EAP-TLS Customer Area creation available on demand; Management API GET/PATCH `/terminalSettings` at company, merchant, store or terminal level needs `Management API—Terminal Advanced settings read and write`. For first use, give the terminal temporary internet connectivity so boarding can fetch the profile; later changes arrive through maintenance or **Config > Update**. Before removal, check inherited higher-level settings; certificate expiry and unsuitable crypto can stop Enterprise Wi-Fi connectivity. Same-SSID profile nodes support staged credential/certificate transitions.
