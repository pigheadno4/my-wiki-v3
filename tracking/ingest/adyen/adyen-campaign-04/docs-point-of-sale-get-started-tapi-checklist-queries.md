# Adyen C04 — Terminal API checklist fixed answers

1. **Purpose/scope; what not to infer.** This 2026-09-15 snapshot is a merchant checklist for building a Terminal API POS integration with Adyen-provided terminals in a test environment before going live (`raw/adyen/docs/point-of-sale/get-started/tapi-checklist/2026-09-15.md:15-25`). It maps test-account structure, architecture/feature scope, test terminals, configuration, testing, and live application (`:37-233`). It does not prove a specific merchant's approval, payment-method or acquirer enablement, current library version, or live payment execution; linked detail pages are navigation until read.

2. **Central capability/prerequisites/warnings and route.** A test account and planned company/merchant/store structure precede the Terminal API build; live structure is set up again (`:34-47`). Choose local or cloud, consulting Adyen before building cloud; standalone is separate, while mobile requires Terminal API plus its relevant POS Mobile SDK (`:67-77`). E2EE is the stated default and P2PE needs Adyen notice/different terminal software (`:81`). Enable Terminal API and configured payment methods/features on test terminals; some features need Support (`:113-121`). The default test API credential exists; extra test credentials are optional, while additional or separated POS/ecommerce credentials are recommended for live (`:139-153`). Test success/failure paths, simulated acquirer responses, configured methods, and reconciliation (`:185-221`). Then apply for a live account and sign a contract before live use (`:231-233`).
