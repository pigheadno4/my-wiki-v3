# Fixed retrieval checks — Adyen POS payment methods

1. **What is this page for, and what does it not establish?** It is a 2026-09-15 snapshot of an Adyen Terminal API point-of-sale payment-method overview. It maps listed card schemes, NFC/QR wallets, one-time code and gift/prepaid methods to country/region, refund and chargeback columns. A table entry does not establish current merchant enablement, a particular terminal or mobile-solution capability, supported currencies, or a successful transaction. The `# Payment methods` requirement table and `## Payment methods in Mobile solutions` establish the scope; each method family has its own table in [[raw/adyen/docs/point-of-sale/what-we-support/payment-methods/2026-09-15|pinned raw]].

2. **What are central capability and consequential qualifications, and how do I find them?** Terminal API integrators can use the snapshot to locate candidate in-person payment methods, but must inspect scheme, region, terminal/card-entry, wallet-flow and refund constraints for the exact method. Brazil and Mexico require referenced refunds; specified local schemes decline swipe or manual entry; listed QR wallets differ on merchant-presented-only flow, and IRIS needs Greek-bank onboarding with Adyen as gateway and bank-handled refunds/cancellations. Mobile solutions cover fewer methods. The page gives no currency matrix and its listing does not itself enable a method for an account. See `## Credit and debit cards`, `### Card entry methods`, `## NFC wallets`, `## QR code wallets` > `#### Supported flows`/`#### Refunds`/`#### Local onboarding`, `## Prepaid and gift cards`, and `## Payment methods in Mobile solutions`.
