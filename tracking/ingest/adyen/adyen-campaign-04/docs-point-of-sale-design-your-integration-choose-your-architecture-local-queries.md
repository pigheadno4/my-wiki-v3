# Adyen C04 — local architecture fixed answers

1. **Purpose/scope; what not to infer.** The 2026-09-15 *Building a local integration* guide applies to a merchant POS using Terminal API and Adyen terminals over local communications (`raw/adyen/docs/point-of-sale/design-your-integration/choose-your-architecture/local/2026-09-15.md:15-30`). It assumes the local-versus-cloud choice has been made (`:19-23`) and covers the local setup through recovery (`:35-46`). Its examples do not establish cloud flow, current SDK behavior, merchant eligibility, or a completed live transaction; the page's Node v16.2.0 and other language examples are version-labeled (`:308-542`).

2. **Central capability/prerequisites/warnings and route.** The POS calls the terminal's LAN IP, the terminal routes the shopper-completed transaction to Adyen, and the POS receives a synchronous response (`:35`, `:675-679`). Network prerequisites include DNS-name allowlisting rather than hard-coded IPs, TCP 443 to the internet, TCP 8443 on LAN, and proper TLS (`:48-70`). An API library is optional (`:74-83`). Test building does not enforce local protection, but live processing requires certificate validation and shared-key encryption (`:87-95`, `:634-642`). Shared-key API setup needs a Management API role, while Customer Area setup needs a merchant POS management role (`:28-31`); the API response can include the passphrase (`:551-552`). Use HTTPS timeout >120 seconds and, after 150 seconds with no response or a timeout response, request transaction status to reduce duplicate actions (`:679`, `:690-697`).
