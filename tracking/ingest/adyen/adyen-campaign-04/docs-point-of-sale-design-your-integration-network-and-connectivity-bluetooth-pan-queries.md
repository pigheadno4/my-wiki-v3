# Bluetooth PAN and tethering: fixed retrieval checks

1. **What is this guide for, and what should not be inferred?** It is a dated Adyen Terminal API guide to a direct Bluetooth PAN between an Android/iOS mobile POS and a payment terminal, with a separate internet leg from terminal to Adyen for online authorization. Requirements say terminal software 1.60+ and only e280/e285p, but later setup names e285; the discrepancy is unresolved. The source does not specify a cloud Terminal API architecture, mobile permission contract, Bluetooth cryptographic guarantee or current terminal/carrier eligibility. Locate `## Requirements` (raw lines 26-34), `## Concepts and setups` (36-47), and source dates (2, 10).

2. **How do pairing and internet sharing work, and what needs verification?** Pair both Bluetooth devices after matching their codes. For a terminal internet path, the guide uses e280 Wi-Fi or e285 Wi-Fi with optional terminal 2G/3G fallback. With tethering, Android can share Wi-Fi or cellular; iOS shares cellular. Keep hotspot active, verify terminal IP address, run the PSP connection test, then make a test payment; these checks have different purposes. Regional 3G availability and model/software scope matter. Locate raw lines 32-47, `## Bluetooth PAN using the terminal for internet access` (49-85) and `## Bluetooth tethering using the mobile device for internet access` (87-133).
