2. **What central capability, prerequisites, and warnings should a reader retrieve?** Enable Terminal API in the test Customer Area before test use and repeat the steps in live when switching environments (raw lines 26–35). Requests use `SaletoPOIRequest` with a header and category-specific body, and the header table gives IDs and constraints (lines 37–90). Local POS-to-terminal requests return synchronously; cloud requests go through an Adyen endpoint and can return synchronously or asynchronously (lines 92–102). In asynchronous cloud mode the immediate `ok` is not a payment result; the header and result body arrive by event notification (lines 104–116). For locally communicated approved offline payments, the tender reference exists before the PSP reference is generated on reconnection and platform processing (lines 145–171).
