# Adyen C04 — V400m Bluetooth base station fixed answers

1. **Purpose/scope; what not to infer.** The 2026-09-15 Adyen page troubleshoots one topology: a V400m terminal uses Bluetooth to reach a compatible base station, which has an Ethernet uplink; the terminal can use it docked or undocked (`raw/adyen/docs/point-of-sale/design-your-integration/network-and-connectivity/bt-base-station/2026-09-15.md:15-33`). It applies to a Terminal API integration with that hardware (`:28-33`). It does not establish other terminal-model support, whether Terminal API messages use local or cloud transport, software-version compatibility, or payment success. The linked V400m manual carries detailed setup outside this snapshot (`:21-24`, `:121-122`).

2. **Central capability/prerequisites/warnings and route.** Pair the terminal to the base, match serial numbers, and change the base's default credentials before live transactions (`:21-24`, `:61-66`). A steady white LED signals that the base finished booting; use its Ethernet port rather than Serial (`:42-53`). *No devices* calls for discovery, terminal Wi-Fi/Bluetooth checks, then restarts (`:68-79`). *Connection error* means Bluetooth pairing worked but network access failed, so check DHCP, Ethernet and base restart (`:81-93`); a missing Bluetooth IP also directs a PSP connection diagnostic (`:95-108`). Default addresses are dynamic, with static assignment possible if the network requires it (`:108`).
