# Fixed retrieval checks — Adyen Terminal API POIID

1. **What is this source for, and what should the identifier not be mistaken for?** The 2026-09-15 Adyen guide explains how to get the physical terminal's unique ID for `Terminal API MessageHeader.POIID`. It combines device model and serial number, with a dash separator and dashes removed from the serial part. The model prefix or example `P400‑123456789` is not a software/SDK version, a merchant account, a current live-connection guarantee or a payment outcome. See `# Get the terminal ID` and `## Get the serial number from the terminal` in [[raw/adyen/docs/point-of-sale/design-your-integration/terminal-api/get-the-terminal-id/2026-09-15|pinned raw]].

2. **How is POIID obtained in cloud versus local integrations, and where is the route?** Device back or **Settings > Device info**, and Customer Area **Devices > Device list > Terminals**, provide serial numbers for model-plus-serial construction. A cloud integration can POST `/connectedTerminals` with a merchant account and optional belonging store; response `uniqueTerminalIds` covers live-cloud-connected terminals in that scope, not all merchant inventory. A local integration can issue the documented placeholder-POIID diagnosis request, which fails while returning the actual terminal `POIID` in `DiagnosisResponse.MessageHeader`. The Android `Settings.Global.DEVICE_NAME` route applies only when the app is installed on the Android terminal. See `## Make an API call`, `## Use a diagnosis request`, and `## Use an Android function`.
