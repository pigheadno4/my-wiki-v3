1. **Which notifications are covered, and how do they differ from terminal messages?** This page covers Adyen payments-platform webhooks to a merchant backend: Standard transaction webhooks and terminal-management webhooks for assignment, boarding, orders, or settings. They are asynchronous platform events. They are not terminal-generated EventNotification/DisplayRequest messages or an immediate Terminal API response; the latter has a separate transaction-status path if missing. Locators: raw lines 15–23, 36–53, 131–143. Route through Adyen Webhooks to this source/raw, with the Terminal API concept for the separate terminal message boundary.

2. **What configuration, acknowledgment, and field limits apply?** Standard webhooks select event codes and optional additional-data settings; some identifiers are enabled under Developers > Additional data, which also affects API responses. Terminal-management webhooks have a different payload structure and, per this guide, need only Customer Area server/security setup beyond the general webhook route. Verify HMAC and acknowledge with a successful HTTP status such as 202. The example `live: false` AUTHORISATION body does not establish all fields or outcomes for other events/environments.
