# Configure features: fixed retrieval checks

1. **What is this guide for, and what should not be inferred?** It is a Customer Area POS Device settings map for Adyen terminals in Terminal API or standalone solutions, with a link to API-call configuration. It establishes setting scope, navigation, inheritance and feature prerequisites in the pinned Adyen guide; it does not prove a merchant account has a feature enabled, that a POS app supports it, or that a separately versioned GitHub SDK implements the webpage's options. Locate `## Requirements` (raw lines 25-33), `## Inheritance of settings` (35-72), `## Find and edit settings` (90-98) and `## Payment features category` (150-175). The snapshot is dated 2026-09-15 and the source frontmatter says last modified 2026-05-19 (raw lines 2 and 11).

2. **How do feature settings flow, and what are the main configuration cautions?** Company → merchant account → store → terminal settings inherit downward, with lower-level values replacing inherited ones; Adyen PSP settings are above company but cannot be merchant-defined. Customer Area viewing requires a POS standard or Terminal View role; editing requires Terminal Management Admin. Changes reach a terminal at its next reboot-hour configuration update, or through the linked manual update. Cloud Terminal API needs both **Enable Terminal API** and **Enable WebSockets**, while local needs **Enable Terminal API**; feature use still depends on POS app compatibility. Some payment features require Support and/or limits. The renamed/removed table describes Customer Area Device settings placement, not blanket removal of an underlying capability. Locate raw lines 31-50, 74-76, 150-188 and 190-253.
