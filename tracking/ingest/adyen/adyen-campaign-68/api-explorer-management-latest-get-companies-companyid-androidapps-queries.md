It returns apps uploaded to Adyen for the company account named by required path `companyId`. A caller needs one of Android files read, Android files read and write, Terminal actions read, or Terminal actions read and write on its API credential. Live requests are subject to a rate-limit notice without a figure. Optional query parameters are app `versionCode` and unique `packageName`, `pageSize` (default 20, maximum 100), and `pageNumber`; no request body is listed. `200` has optional `data` array; if an app object is present, `id` and `status` are required, with optional description, error code/details and terminal models, label, package name, and version fields. ## Q2

[[source-adyen-api-explorer-management-latest-get-companies-companyid-androidapps]] ([canonical URL](https://docs.adyen.com/api-explorer/Management/latest/get/companies/(companyId)/androidApps)) documents a `200` successful list read, with optional `data`, not an upload or terminal action. `processing` means signing/conversion is underway; `error` signals a problem, `invalid` an APK problem, `ready` signed/converted, and `archived` no longer available. Installation or removal on Android payment terminals is through separate terminal actions, so an uploaded or `ready` entry is not proof of installation, device activation, app approval for every model, or payment execution. `401` is authentication required, `403` insufficient permission, with `400`, `422`, and `500` also documented. This GET has no idempotency key, deletion/reversal operation, propagation or asynchronous deployment result, financial state, or Live-eligibility evidence.
