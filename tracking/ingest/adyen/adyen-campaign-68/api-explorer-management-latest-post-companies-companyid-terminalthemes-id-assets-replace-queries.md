# api-explorer-management-latest-post-companies-companyid-terminalthemes-id-assets-replace

## Q1

The 2026-11-07 Management API `latest` reference lists the v3 TEST server for `POST /companies/{companyId}/terminalThemes/{id}/assets/replace`, replacing an existing image/video asset in a company-owned theme. Required path fields identify company account and theme; required query `type` and `model` identify the asset pair. The pair must already exist; otherwise use the separate asset-creation endpoint. The credential needs Terminal themes read and write. The body is multipart/form-data with one required `file` part declaring supported Content-Type. SVG is logo+All only; JPEG/PNG exclude All; MP4/QuickTime are SFO1/M450 only; GIF excludes SFO1/M450. Model All is for logo only; idle and shopper-engagement screens are SFO1/M450 only. Maximum is 100 MB for SFO1/M450, 10 MB otherwise. A `200` returns required model, type and tokenized CDN URL valid 24 hours. No defaults are stated. ## Q2

A `200` establishes a returned replacement asset representation and short-lived CDN URL; it does not prove any terminal has downloaded, applied or displayed the asset, nor a payment outcome. Missing matching asset pair fails, with a 404 example directing asset creation; another 404 example covers a theme absent for the company. A 403 example denies logo modification for that theme. Unsupported or missing Content-Type is explicitly rejected with 422, and the source lists 400, 401, 403, 404, 422, 429 rate-limit and 500 errors. It specifies no idempotency, rollback, asynchronous review/activation, downstream deployment timing, or financial state. The TEST snapshot does not establish current Live eligibility.
