# api-explorer-management-latest-get-stores-storeid-terminallogos

## Q1

The 2026-11-07-captured Management API `latest` reference describes `GET /stores/{storeId}/terminalLogos` as reading a logo configured for one terminal model at the identified store. It lists the v3 TEST server `https://management-test.adyen.com/v3`; Live requests have a rate-limit notice, without a Live server URL in this raw. The API credential needs Terminal settings read or read and write. The required path `storeId` is the unique store identifier, and the required query `model` chooses a model from the captured list. No request body or default is listed. A `200` has an optional `data` string containing a Base64-encoded image; decode it for the image file. The store/model logo applies to that model's terminals at the store unless an individual terminal has a different logo. ## Q2

A `200` establishes a successful read of the described store/model logo response, with `data` optional; the example's populated `data` does not make it guaranteed. It does not show that a particular device displays the logo, that a merchant can access Live, or that a payment occurred. The credential-role gate and Live rate-limit notice are at raw lines 11–17. The captured failures are `400` request problem, `401` authentication required, `403` insufficient permissions, `422` validation error, and `500` server processing failure (lines 46–143). This GET reference specifies no idempotency, update/deletion, asynchronous review, approval, activation, reversal, or financial outcome; those processes cannot be inferred from the read response. Its dated snapshot and single listed TEST server do not establish current account eligibility or support for every listed model.
