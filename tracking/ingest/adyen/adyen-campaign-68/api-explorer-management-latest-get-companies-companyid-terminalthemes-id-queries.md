# api-explorer-management-latest-get-companies-companyid-terminalthemes-id

## Q1

The 2026-11-07-captured Management API `latest` reference lists the v3 TEST server for `GET /companies/{companyId}/terminalThemes/{id}`, which reads the specified theme's metadata and CDN URLs for its added assets. Both path fields are required: `companyId` identifies the company account and `id` the terminal theme. The operation prose requires the Management API - Terminal themes read and write credential role. No query or body fields, defaults or endpoint rate limits are listed. A `200` requires `id`, `name`, `mode` (`dark` or `light`), and an `assets` array; each listed asset requires model, screen type, and tokenized CDN URL valid for 24 hours. If the theme lacks permission to customize terminal logos, its logo URL leads to Adyen's logo. The 403 example instead names a Terminal settings read and write role, an unresolved source conflict. A `200` establishes theme metadata and asset URL readback in this captured reference. It does not establish that a terminal has downloaded, applied or displayed the theme; the asset URLs expire after 24 hours, and logo permission may route to the Adyen logo. Errors listed are `400` Bad Request, `401` Unauthorized, `403` Forbidden, `404` Not Found and `500` Internal Server Error, with illustrative bodies at raw lines 86–147. The 403 role detail conflicts with the operation's stated role, so the example cannot settle authorization. This GET reference gives no idempotency, change/deletion, asynchronous approval, activation, payment, booking or settlement contract. The dated TEST snapshot does not prove Live eligibility or current theme/device state.
