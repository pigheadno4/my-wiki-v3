# C68 terminal settings GET query answers

## Q1

`GET /terminals/{terminalId}/terminalSettings` is the captured Management API `latest` v3 TEST-server read of settings configured for the terminal identified by the required path `terminalId`. The API credential needs Terminal settings read or read-and-write; sensitive settings require the additional Advanced read-and-write role. There is no query parameter or request body in this reference. A successful `200` response has optional settings groups, including receipts, connectivity, DCC, gratuities, hardware, localization, MOTO, Terminal API URLs/encryption, offline processing, payment, refunds, standalone, store-and-forward, surcharge, timeouts, and Wi-Fi. Defaults and limits are field-specific: for example, reset/restart hours default to 6:00 AM terminal local time and permit 0–23, while store-and-forward `maxAmount`, `maxPayments`, and `supportedCardTypes` must be configured locally or inherited. Optional parent objects do not become required because some nested properties are marked required. See [[source-adyen-api-explorer-management-latest-get-terminals-terminalid-terminalsettings]] and [captured API reference](https://docs.adyen.com/api-explorer/Management/latest/get/terminals/(terminalId)/terminalSettings), lines 5–56 and 89–196.

## Q2

A `200` establishes a successful settings read, not that the terminal is online, has applied all settings, completed boarding or activation, or processed a payment. The returned groups are optional. Even `simcardStatus: ACTIVATED` may require cellular connectivity to be enabled on the terminal. The schema says contact Adyen before a first contactless-currency change for a compliance check; it also warns of merchant liability for fraudulent or duplicate unreferenced refunds. Those descriptions do not prove compliance, refund execution, or financial outcome. The GET reference describes no mutation, idempotency key, deletion, conflict/version check, propagation timing, asynchronous approval, or reversal workflow. It lists `400`, `401`, `403`, `422`, and `500` failures; live requests have rate limits, while the displayed server is test v3. This 2026-11-07 documentation snapshot cannot establish current account eligibility or device state. See [[source-adyen-api-explorer-management-latest-get-terminals-terminalid-terminalsettings]] and [captured API reference](https://docs.adyen.com/api-explorer/Management/latest/get/terminals/(terminalId)/terminalSettings), lines 7–34, 41–47, 103–105, 130–145, 199–296, and 298–427.
