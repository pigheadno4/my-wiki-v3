# C68 company Android-app GET query answers

## Q1

`GET /companies/{companyId}/androidApps/{id}` is the captured Management API `latest` v3 TEST-server read of an Android app already uploaded to Adyen. Required path `companyId` identifies the company account; required `id` identifies the app. The caller's API credential needs Android files read or read-and-write. The reference lists no query parameter, request body, defaults, or pagination/size limit; it warns of live rate limits. A `200` requires app `id` and `status`; description, label, package name, version code/name, and error details are optional. Status values distinguish processing, error, invalid APK, ready after signing/conversion, and archived/unavailable. Error codes and model-specific errors may be reported. See [[source-adyen-api-explorer-management-latest-get-companies-companyid-androidapps-id]] and [captured API reference](https://docs.adyen.com/api-explorer/Management/latest/get/companies/(companyId)/androidApps/(id)), lines 5–47.

## Q2

A `200` establishes a successful app-detail read, not a deployment action. `ready` means the uploaded app has been signed and converted; installation or uninstallation on terminals is performed through separate terminal actions. `processing` is not ready, `error` and `invalid` describe failures, and `archived` is no longer available. The GET reference gives no idempotency or mutation semantics, install timing, approval, activation, rollback, device state, or payment outcome. It lists `400`, `401`, `403`, `422`, and `500` failures; live calls have rate limits, while its displayed server is test v3. This captured documentation cannot prove current account eligibility, app compatibility with a particular terminal, successful install, or financial processing. See [[source-adyen-api-explorer-management-latest-get-companies-companyid-androidapps-id]] and [captured API reference](https://docs.adyen.com/api-explorer/Management/latest/get/companies/(companyId)/androidApps/(id)), lines 7–19, 29–47, and 50–147.
