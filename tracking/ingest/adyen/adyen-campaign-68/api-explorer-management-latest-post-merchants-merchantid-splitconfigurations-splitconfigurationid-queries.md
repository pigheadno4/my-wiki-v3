# api-explorer-management-latest-post-merchants-merchantid-splitconfigurations-splitconfigurationid — actual query answers

## Q1

`POST /merchants/{merchantId}/splitConfigurations/{splitConfigurationId}` is a Management API `latest` reference captured 2026-11-07 with TEST `https://management-test.adyen.com/v3` server. It creates a rule in the identified split configuration profile for the identified merchant account, requiring an API credential with Management API - SplitConfiguration read and write. The path requires both IDs. The body requires `currency` (table: three-character ISO code), `fundingSource`, `paymentMethod`, `shopperInteraction`, and `splitLogic`; within that object `commission` is required, though its amount and percentage children are optional. `cardUsageType` defaults to `ANY`; `cardRegion` is optional. Commission fixed amounts are in minor units and percentages in basis points. Optional DCC allocation is pilot-limited. A 200 returns profile `description` and `rules`, with optional rule, logic and profile IDs; 204 contains no content. The response example's `currency: ANY` conflicts with the ISO-code table, so acceptance of `ANY` is unresolved. ## Q2

A 200 reports successful rule creation and a split-configuration representation; a 204 reports success without content. Neither establishes that the profile is associated with a store, selected for a transaction, or that fees, commissions, refunds, chargebacks, capture, settlement or payout were booked. The raw describes a `paymentFee` fallback when no transaction fee type is included, but that conditional configuration behavior is not a transaction result. The credential role and 401/403 failures qualify access; 400/422/500 cover request/server failure. This capture states no idempotency mechanism, deletion/reversal process, approval or activation status, or propagation timing. It lists TEST v3 only, and the November snapshot does not prove current Live eligibility. The ISO-code versus `ANY` example conflict also prevents treating the sample as a validated input contract.
