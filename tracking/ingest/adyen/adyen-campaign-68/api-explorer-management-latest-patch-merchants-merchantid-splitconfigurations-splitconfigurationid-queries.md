# C68 split-configuration description PATCH query answers

## Q1

`PATCH /merchants/{merchantId}/splitConfigurations/{splitConfigurationId}` is the captured Management API `latest` v3 TEST-server endpoint to change a split configuration profile's description under a merchant account. Required path `merchantId` identifies the merchant account and `splitConfigurationId` identifies the profile; required JSON body `description` supplies its new text. The credential needs `Management API - SplitConfiguration read and write`. No query parameter, request default, or description-length limit is stated. `200` requires response `description` and `rules`, with optional `splitConfigurationId`; the rules contain response-only conditions and split-logic detail. `204` has no body. The response schema says `rules[].currency` is a three-character ISO code, but the example uses `ANY`; that inconsistency does not change this endpoint's description-only request scope. ## Q2

A `200` means the description-update request succeeded and returns a profile representation; `204` means successful processing without content. Neither establishes that the profile is linked to a store, a rule matched, or any payment was authorized, captured, booked, settled, or paid out. Rule and split-logic fields appear in the response, not the request, so this PATCH does not edit them. The reference lists `400`, `401`, `403`, `422`, and `500` failures, and specifies no idempotency key, version/conflict guard, asynchronous review, activation step, or reversal behavior. The displayed server is test v3; this 2026-11-07 snapshot does not prove live eligibility or financial outcomes. The response example's `ANY` currency conflicts with the schema's ISO-code wording, so validation or returned values cannot be inferred from that example alone.
