# C68 store-reference terminal-logo GET query answers

## Q1

The 2026-11-07 capture of Adyen Management API `latest` documents `GET /merchants/{merchantId}/stores/{reference}/terminalLogos` to retrieve the logo configured for a specified payment-terminal model at the store identified in the path. It lists the Test server `https://management-test.adyen.com/v3`; Live requests have rate limits. The caller's API credential needs either `Management API—Terminal settings read` or `Management API—Terminal settings read and write`. Required inputs are the merchant-account `merchantId`, the store's human-readable `reference`, and query parameter `model`, whose allowed values are enumerated in the raw. The page documents no request body, conditional input or default. A `200` schema has optional `data`, a Base64-encoded image string; decode it to get the image file. It also documents `204` success with no additional content. The store logo applies to terminals of that model under the store unless an individual terminal has a different logo. See [[source-adyen-api-explorer-management-latest-get-merchants-merchantid-stores-reference-terminallogos]] and [the captured operation](https://docs.adyen.com/api-explorer/Management/latest/get/merchants/(merchantId)/stores/(reference)/terminalLogos), raw lines 5–17, 19–48.

## Q2

A `200` response can return the configured store/model logo as optional Base64 `data`; a `204` response has no additional content. The read does not update a logo, establish what a terminal currently displays, or prove terminal boarding, payment readiness, eligibility, compliance, or any financial outcome. The documented credential roles are required; the raw also lists `400` request problem, `401` authentication required, `403` insufficient permissions, `422` validation error and `500` server error. Its Live rate-limit notice qualifies operating conditions, while the visible server is Test v3 and this is a 2026-11-07 documentation snapshot rather than evidence of current Live access. No idempotency, mutation lifecycle, deletion, propagation time, asynchronous review, approval, activation or reversal behavior is specified for this GET operation. The individual-terminal override means store-level configuration alone cannot prove the effective logo on a particular device. See [[source-adyen-api-explorer-management-latest-get-merchants-merchantid-stores-reference-terminallogos]] and [the captured operation](https://docs.adyen.com/api-explorer/Management/latest/get/merchants/(merchantId)/stores/(reference)/terminalLogos), raw lines 7–20, 36–48, 51–148.
