# C68 merchant split-rule DELETE query answers

## Q1

The 2026-11-07 Adyen Management API `latest` capture documents `DELETE /merchants/{merchantId}/splitConfigurations/{splitConfigurationId}/rules/{ruleId}` to delete the specified rule within a merchant split configuration. The listed server is `https://management-test.adyen.com/v3`; the API credential must have `Management API - SplitConfiguration read and write`. All three path parameters are required: the unique merchant-account ID, unique split-configuration ID and the rule ID. The operation documents no query parameter, request body, conditional input, default or limit for the DELETE request. A `200` success schema represents a split configuration with required `description` and `rules`; its `splitConfigurationId` and each nested `ruleId` are optional response fields. The rules' currency, funding source, payment method, shopper interaction and split logic fields describe returned configuration, not request inputs. `204` success has no additional content. See [[source-adyen-api-explorer-management-latest-delete-merchants-merchantid-splitconfigurations-splitconfigurationid-rules-ruleid]] and [the captured operation](https://docs.adyen.com/api-explorer/Management/latest/delete/merchants/(merchantId)/splitConfigurations/(splitConfigurationId)/rules/(ruleId)), raw lines 5–65.

## Q2

The DELETE operation is specified to remove the rule in the path, rather than the split-configuration profile itself. `200` indicates success and documents a configuration-shaped response; `204` indicates processing succeeded without additional content. Those responses do not establish which rule will match a later payment, that any transaction was split, or that capture, refund, fee booking, settlement or payout occurred. The role requirement and documented `400` request problem, `401` authentication, `403` permission, `422` validation and `500` server errors bound execution. The reference gives no idempotency key, undo/reversal flow, asynchronous approval or activation state, propagation guarantee, or current Live account eligibility. The listed endpoint is Test v3 in a 2026-11-07 documentation snapshot. Its returned `dcc` split-logic field is marked pilot and not available to all platforms; its fee-allocation default text pertains to a configured rule, not proof that this DELETE booked fees. See [[source-adyen-api-explorer-management-latest-delete-merchants-merchantid-splitconfigurations-splitconfigurationid-rules-ruleid]] and [the captured operation](https://docs.adyen.com/api-explorer/Management/latest/delete/merchants/(merchantId)/splitConfigurations/(splitConfigurationId)/rules/(ruleId)), raw lines 7–14, 25–65, 68–165.
