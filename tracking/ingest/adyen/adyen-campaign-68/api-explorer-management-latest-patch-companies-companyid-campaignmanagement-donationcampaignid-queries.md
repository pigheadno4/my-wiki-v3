# C68 company donation-campaign PATCH query answers

## Q1

The 2026-11-07 Adyen Management API `latest` capture describes `PATCH /companies/{companyId}/campaignManagement/{donationCampaignId}` for changing properties of a donation campaign under a company account. It lists the Test `/v3` server and requires the caller's API credential to have `Management API—Campaign Management read and write`. `companyId` identifies the company account and `donationCampaignId` uniquely identifies the campaign; both path fields are required. The request body lists optional `accountHolderIds` (array or null), `inPerson` object, `name` string and `online` object, without nested request fields or documented defaults. Adding account holders incompatible with the nonprofit produces a validation error. `200` returns a campaign representation with required Adyen-generated `id`, `name`, `nonprofitCause` and `status`; optional fields include account-holder IDs, activation/end timestamps and channel settings. The response describes fixed-donation amounts in minor units with one to three amounts, but those details are in the response schema, not additional documented PATCH-body requirements. See [[source-adyen-api-explorer-management-latest-patch-companies-companyid-campaignmanagement-donationcampaignid]] and [the captured operation](https://docs.adyen.com/api-explorer/Management/latest/patch/companies/(companyId)/campaignManagement/(donationCampaignId)), raw lines 5–79.

## Q2

A successful `200` response is a campaign-properties update/readback; this PATCH cannot change campaign status. Activation or ending requires the separate POST status route named by the reference. The returned `status`, `activatedAt` or `endedAt` fields do not prove that this PATCH caused a lifecycle transition. The operation does not establish nonprofit/account-holder compatibility beyond the validation rule, current campaign eligibility, a donation attempt or outcome, webhook delivery, settlement or receipt by a nonprofit bank. It documents `400` request problem, `401` authentication, `403` permission, `422` validation, `500` server and `503` account-level temporary campaign-management unavailability; the `503` text explicitly says donations themselves are unaffected. No idempotency key, deletion, reversal or propagation guarantee is specified. The Test v3 server and 2026-11-07 capture are documentation, not proof of present Live availability. See [[source-adyen-api-explorer-management-latest-patch-companies-companyid-campaignmanagement-donationcampaignid]] and [the captured operation](https://docs.adyen.com/api-explorer/Management/latest/patch/companies/(companyId)/campaignManagement/(donationCampaignId)), raw lines 7–18, 39–79, 82–193.
