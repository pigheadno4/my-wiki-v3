# C68 original-query answers: api-explorer-management-latest-get-companies-companyid-androidcertificates

## Q1

The 2026-11-07 Management API `latest` reference describes `GET /companies/{companyId}/androidCertificates`, “Get a list of Android certificates,” on the shown TEST v3 server `https://management-test.adyen.com/v3`. Required path `companyId` is the unique company-account identifier. The API credential must hold **one of** Android files read, Android files read and write, Terminal actions read, or Terminal actions read and write. There is no request body; optional query parameters are `certificateName`, `pageSize` (20 by default, maximum 100), and `pageNumber`. A `200` response may include `data`, an array of uploaded certificate objects; each included object's `id` is required, while `description`, `extension`, `name`, `notBefore`, `notAfter`, and `status` are optional. The raw specifies no status enum or default for the other filters. ## Q2

The `200` GET confirms a successful list request, not a new upload or a terminal action. Listed certificates were uploaded to Adyen and can be installed or uninstalled through separate terminal actions; the example's `ready` status, certificate dates, and IDs do not prove installation, app deployment, current device eligibility, or payments. Optional `data` must not be treated as guaranteed. Live endpoint requests have rate limits, with no numeric threshold in this raw. `401` requires authentication; `403` signals insufficient permissions; `400` covers request reading/understanding problems, `422` validation errors, and `500` server failure. This read gives no idempotency, deletion, reversal, approval/activation, asynchronous completion, or version/conflict contract. The dated TEST snapshot does not prove a company's current Live inventory or valid terminal state.
