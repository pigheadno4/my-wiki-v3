# api-explorer-management-latest-post-companies-companyid-terminalthemes-id-assets

Q1: The captured Management API v3 TEST POST adds an image or video asset to terminal theme `id` under company `companyId`, both required path IDs. Required `type` and `model` query parameters choose the screen element and Android model. The body is multipart/form-data with one required `file` part and a supported Content-Type. SVG is limited to logo/All; videos to SFO1/M450; JPEG/PNG exclude All; GIF excludes SFO1/M450. Logo uses All, and idle/shopper-engagement screens are SFO1/M450 only. Maximum size is 100 MB for SFO1/M450 and 10 MB otherwise. The credential needs Management API - Terminal themes read and write; the endpoint is rate limited. The TEST server is `https://management-test.adyen.com/v3`. A `201` returns required `model`, `type` and tokenized CDN `url`, valid 24 hours. [[source-adyen-api-explorer-management-latest-post-companies-companyid-terminalthemes-id-assets]] (https://docs.adyen.com/api-explorer/Management/latest/post/companies/(companyId)/terminalThemes/(id)/assets); raw lines 5–63.

Q2: `201` establishes asset creation and a temporary CDN URL, not that the theme has been applied or rendered on a device. An existing asset with the same type/model causes this add request to fail and requires the separate replace endpoint; a generic or absent file Content-Type yields `422`. The reference documents 400, 401, 403, 404, 422, 429 and 500 responses, with examples including duplicate, oversized file and rate limit. It states no idempotency, rollback, asynchronous approval, propagation or device activation guarantee. The TEST snapshot does not prove current eligibility or payment execution.
