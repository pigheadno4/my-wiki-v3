# api-explorer-management-latest-post-merchants-merchantid-splitconfigurations

## Q1

The 2026-11-07 Management API `latest` reference describes `POST /merchants/{merchantId}/splitConfigurations` on the listed v3 TEST server as creating a profile under the merchant account identified by required `merchantId`. The credential needs Management API - SplitConfiguration read and write. A profile can automatically split transactions between the platform liable balance account and a user's balance account **after** association with a store in that merchant account. The body requires `description` and `rules`; each rule requires `currency`, `fundingSource`, `paymentMethod`, `shopperInteraction`, and `splitLogic`, whose `commission` is marked required. `cardRegion` and `cardUsageType` are optional; the latter defaults to `ANY` in the API table, while the 2026-09-15 automatic-split overview calls card usage type a pilot unavailable to some platforms. The split logic supports fee, chargeback, refund, tip, remainder and commission instructions; `dcc` is pilot. If no transaction-fee type is included, the reference says Adyen adds `paymentFee` to the payment request to book all transaction fees to the liable account. A `200` returns a profile representation, with `splitConfigurationId`, `ruleId` and `splitLogicId` optional in its table; `204` has no body. The `currency` tables require a three-character ISO code but both examples use `ANY`; the 2026-09-15 creation guide also explicitly instructs `ANY` for any currency. Current API acceptance remains unresolved. ## Q2

A successful response establishes the profile-creation request was processed; a `200` may return its representation and `204` explicitly returns no content. Creation alone does not show the separate store association needed for automatic splitting, a matching transaction, funds booked, settlement, payout or bank receipt. This raw has no idempotency, rule priority, deletion, reversal, review or activation contract; those must not be inferred. The stated failures are `400` request problem, `401` authentication required, `403` insufficient permissions, `422` validation error and `500` server processing failure. The `dcc` pilot limitation and the `currency` table/example conflict further bound interpretation. The snapshot's TEST server does not establish Live access or current eligibility.
