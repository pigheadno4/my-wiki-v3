## Q2 — What differs between iPhone and Android prerequisites and security?

iPhone requires Windows InStoreHub with CPOS, Mobile POS v5.1.766+, Retail Y2 v18+, and linked iPhone/iOS hardware/software rules. Without InStoreHub receipt printing is unavailable, requiring fiscal review; contact a Cegid representative to learn about activating the extension for the Cegid Retail account (additional costs apply), while Adyen account enablement is separate and testing uses iPhone Developer Mode (raw lines 40–73). Android Live Store instead uses the standalone Adyen Payments app, with version requirements from Cegid, linked device rules, and separate Test/Live apps (lines 75–120). Its setup calls for API credential/key, client key, Adyen Payments App role, encryption settings, Merchant Account ID and conditional Store ID, then Support enablement for Tap to Pay and short responses (lines 122–138). Mandatory PCI-related device checks can cancel the transaction before PIN; Android Developer Options must be off, and the other passcode/accessibility/screen/camera/overlay rules are in raw lines 140–153. CPOS setup plus only the chosen iPhone or Android enablement path is required; do not transfer iPhone testing Developer Mode to Android. Use the concept→source→raw route; linked platform requirements own exact device/market rules.
