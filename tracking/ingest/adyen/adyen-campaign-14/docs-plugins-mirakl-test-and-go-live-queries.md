This Mirakl connector guide is a **test-to-live checklist**: first run seller/KYC, payment, capture, refund, invoice/payout and operational checks in test, then use separately configured live pilot sellers for real payout verification (raw `raw/adyen/docs/plugins/mirakl/test-and-go-live/2026-09-15.md:15-90`). ## Q2. What is the central capability, prerequisites, and material warnings?

The test checklist calls for Mirakl seller sync, successful and failed Hosted Onboarding KYC scenarios, `/payments` with split data **excluding commissions**, and `applicationInfo` visibility (raw lines 25–33). It asks for full/partial captures, unique references per partial capture to retain reconciliation granularity, partial/full refunds and chargebacks; refunds must use an original-split balance account and the same unique reference (lines 35–52). It then checks seller invoices in Mirakl/Customer Area, Paid labeling after payout and operator emails (lines 54–62). After satisfactory test results, an Adyen contact can configure live; prerequisites include Mirakl Operator API key roles, live KYC Status/Payment Confirmation and pilot sellers (lines 64–72). The connector manages seller-payment blocking and unsuspends new KYC-verified shops by default unless the operator requests disabling either control (lines 74–77). Real payouts cannot be tested in test, so Adyen recommends testing with a small number of live pilot sellers to verify bank arrival (lines 79–90); this is not a mandatory launch gate, and the page does not show that bank receipt occurred. An invoice status alone is not that proof.
