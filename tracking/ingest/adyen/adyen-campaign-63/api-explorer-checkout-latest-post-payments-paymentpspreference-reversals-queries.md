# Fixed-query answers — api-explorer-checkout-latest-post-payments-paymentpspreference-reversals

## Q1

For `POST /payments/{paymentPspReference}/reversals`, the 2026-11-02 captured Checkout API reference presents the v72 **test** server `https://checkout-test.adyen.com/v72` and a full-amount reversal of an existing payment: it refunds one already captured and cancels one not yet captured. The path requires the **original payment** `pspReference`; the body requires `merchantAccount`. The optional body `reference` is limited to 80 characters and `applicationInfo` is optional; the optional `Idempotency-Key` header is limited to 64 characters, with a UUID recommended. No request amount or default is stated. The endpoint itself excludes multiple partial captures; the separately linked 2026-09-15 reversal guide also excludes payment-request or Adyen for Platforms capture-request split data and directs separate cancel or refund after checking capture state ([guide](https://docs.adyen.com/online-payments/reversal), pinned guide raw lines 35–36). A 201 response requires the merchant account, original `paymentPspReference`, a **distinct** 16-character reversal-request `pspReference`, and `status: received`; merchant `reference` is optional. ## Q2

A 201 `status: received` establishes receipt of the reversal request and a new request reference; it does **not** establish that cancellation or refund succeeded or that funds reached any party. The endpoint says to obtain the outcome asynchronously from `CANCEL_OR_REFUND`. Its full-payment reversal must not be used for a payment with multiple partial captures. Separately, the linked 2026-09-15 reversal guide excludes payments whose payment request or Adyen for Platforms capture request includes split data; it directs checking capture state and using the separate cancel or refund route ([guide](https://docs.adyen.com/online-payments/reversal), pinned guide raw lines 35–36). This additional selection restriction is guide context, not a field in the 2026-11-02 endpoint schema. The captured reference lists 401 authentication-required and 403 insufficient-permission errors, alongside 400 request-understanding, 422 validation and 500 server-processing errors. The optional idempotency header is described as a unique message identifier, but this page supplies no retry guarantee or key lifetime. It states no deletion, propagation delay, or terminal financial finality contract. The single v72 test-server snapshot cannot establish current or live-account availability.
