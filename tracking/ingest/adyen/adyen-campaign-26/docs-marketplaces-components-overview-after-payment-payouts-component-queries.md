# C26 Q1–Q2: Marketplace payout components

**Q1. What do these components show, and what must the platform configure first?**
Follow [[index]] → [[adyen-index]] → [[adyen-platform-components]] → [[source-adyen-docs-marketplaces-components-overview-after-payment-payouts-component]] → [[raw/adyen/docs/marketplaces/components-overview/after-payment/payouts-component/2026-09-15]]. The Marketplace-path guide embeds Payouts Overview and Payout Details reporting UI: completed automatic-payout records for a balance account and period, captured funds, adjustments, net payout and, in details, remaining balance (raw lines 27-36, 60-68, 114-118). It requires Adyen for Platforms, a Balance Platform API key with Adyen-assigned **Payouts Overview Component: View** role, generation of the Balance Platform Payout report, and checks for language, region and browser support (raw lines 44-56). A platform server creates a scoped Session Authentication `POST /sessions` token for the account holder, role, `product: platform` and allowed origin; the front end uses `onSessionCreate` to obtain/refresh that session (raw lines 147-197, 251-262, 319-348).

**Q2. What are the report coverage, timing and payout-proof boundaries?**
At the same route, this report-backed UI is designed for automatic payouts with default settlement delay and excludes manual payouts, pass-through payouts and sales-day payout T+0 (raw lines 52-56). Amounts are in the chosen balance account's currency; the time filter is UTC+0 and defaults to Last 30 days (raw lines 68, 99-112). Payout Details can appear as an embedded modal or separately with account `id` and ISO `date` (raw lines 114-118, 278-286, 362-391). Raw line 66 describes net payout as the amount credited to a user's bank, but displaying a report value or completed label is not independent bank-receipt evidence. The guide cautions that features differ by library version (raw lines 36-38), and its standalone Details JavaScript example lacks a comma between `id` and `date` (raw lines 362-366); do not copy it verbatim as validated code. The library defaults to test, with live configured separately, and live `allowOrigin` supports HTTPS only (raw lines 157, 259-262).
