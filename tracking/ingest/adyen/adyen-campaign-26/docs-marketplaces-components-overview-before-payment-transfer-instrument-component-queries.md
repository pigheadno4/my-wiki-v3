# Q1 — Purpose and prerequisites

Configuration and Management components collect and manage bank-account transfer instruments in Marketplace API-only onboarding, but other onboarding work still needs separate API calls (raw lines 23–35, 57–75). Compatible legal entities must have been created under LEM API v3/v4; prerequisites include Adyen for Platforms, a LEM API key for Session Authentication API, supported language/browser conditions and preceding onboarding/verification guidance (raw lines 23, 43–53). The server issues a `POST /sessions` token scoped to `product=onboarding`, the bank-account-owning contractual legal entity and configuration/management roles; live `allowOrigin` requires HTTPS (raw lines 98–113). # Q2 — Scope and outcome boundary

Configuration offers permission-based instant verification or document upload, while Management displays status/errors and user add/delete flows (raw lines 57–75). The configuration property `openBankingPartnerConfigId` is marked required for US/CA; optional cross-border and account-format settings are conditional, not proof of route eligibility (raw lines 180–190). A `complete` event means submission/UI task completion, and Management events reflect user actions; the example completed payload has null verification fields (raw lines 562–603). Thus a component callback does not establish verified instrument, enabled payout capability, executed payout or bank receipt.
