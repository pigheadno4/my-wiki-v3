# Retrieval checks — docs-marketplaces-reports-and-fees-balance-platform-accounting-report

Q1. What does this report cover and how can it be generated? Answer: The daily report tracks balance changes across liable and user balance accounts, schedulable or manual for a day; an Interactive Report can be manually generated for a range and filtered by account holder, balance account and Category/Type/Status. It supports daily reconciliation of payment, internal-transfer, payout balance-entry and fee activity, while API/webhooks are recommended for current individual payment status. The selected Booking Date window is 00:00 to next-day 00:00 CET; inactive accounts with no transactions are omitted. Raw lines 19–40, 216–220, 228–230.

Q2. What is the booking/evidence boundary and sample conflict? Answer: Transfer Id groups pending received/authorized/refused events; Transaction Id marks booked debit/credit, and Value Date can differ from Booking Date. A booked bank-transfer report row is account movement, not bank-receipt proof. Chargeback prose says EUR 60 but rows show EUR 10.97; top-up sample rows reuse a bank-payout Transfer Id and show Balance (PC) +100 while remaining received with no Transaction Id, so do not use that sample to infer completed top-up or a universal join. Raw lines 50–57, 200–210, 391–404, 425–435.
