# C20 transfer-request retrieval checks

## Q1 — What is this page for and what must be in place?

Route: `wiki/index.md` → `wiki/adyen-index.md` (Business Accounts source catalog and `[[adyen-business-accounts]]` concept) → `wiki/concepts/adyen-business-accounts.md` → candidate `wiki/sources/adyen/source-adyen-docs-business-accounts-send-funds-make-transfer-request.md` → `raw/adyen/docs/business-accounts/send-funds/make-transfer-request/2026-09-15.md`.

The captured guide is for initiating a third-party **bank account** transfer from a Business Account source balance account, not for opening an account or issuing a card. The API credential needs Transfers API roles, the user must have `sendToThirdParty` allowed and enabled, transfer and transaction webhook subscriptions are listed, and Adyen says to enable transfers on the source balance account via its contact (raw lines 21–38). Route lookup and bank-account validation are recommended (lines 36–48). The request is POST `/transfers`, with amount/currency, source `balanceAccountId`, bank category, counterparty bank account/holder details and priority; cross-border address is additionally required (lines 160–174). A transfer-request ID is not the recipient bank account ID.

## Q2 — What can fail or remain uncertain, and what conflicts or boundaries matter?

The validation examples show HTTP 200 for valid details and illustrative 422 `33_01` invalid-field responses (raw lines 95–158). The capture limits sending to third-party bank accounts, with wallets/cards described only as future support (line 30). Request field requirements depend on bank identification type and cross-border condition (lines 19, 169–170); use the linked send-funds type/route guidance for supported corridors and values. A successful transfer request returns HTTP 200 and an `id`; actual status follows outgoing bank-transfer webhooks (line 1559), so submission is not settlement or bank receipt. The optional review path states one additional approval and team approval before continued processing (lines 1563–1571, 2114–2120), but several sentences in that section have missing nouns; the approval guide must resolve the details. SDK examples show idempotency keys (e.g. lines 1676, 2048) but this page gives no complete replay guarantee. The dated TEST examples and the separate 2023-modified Business Accounts overview in the concept are historical snapshots, not present availability or account eligibility.
