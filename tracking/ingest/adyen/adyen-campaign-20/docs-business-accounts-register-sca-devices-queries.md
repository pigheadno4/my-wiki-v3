# Retrieval checks — Register SCA devices

## Q1 — What are the prerequisites and steps to register a Business Account SCA device?

Answer: The 2022-modified guide says to confirm device OS or browser SCA support, install the Authentication SDK, use an API credential with Bank SCA Webservice Role, and obtain extra configuration from Adyen Support (pinned raw lines 30–39). The client checks availability and sends `sdkOutput` to the server (lines 41–129); the server POSTs `/registeredDevices` with the Business Account `paymentInstrumentId` and that output, receiving `sdkInput` and device ID (lines 131–145, 374–390). After user 2FA, the SDK registers with `sdkInput` and sends a new `sdkOutput` back to the server (lines 392–449). The server PATCHes the device ID and checks `success: true` (lines 451–461, 690–692). ## Q2 — Does a registered device authorize a transfer or prove user consent, and what device boundaries matter?

Answer: Registration binds the device ID to the specified payment instrument only after the final response is checked (pinned raw lines 690–692). The page then says the user can begin authenticating for future operations (line 692), and links separate transfer and transaction-history SCA flows (lines 696–716); it supplies no transfer authorization, settlement, bank receipt or standalone consent artifact. It says each device is registered separately and cannot be registered more than once, though more payment instruments may later be associated through the separate management flow (lines 133–135, 694). The introduction names iOS/Android, but the procedure also has a WebAuthn browser tab and `SCA_UNAVAILABLE` outcome (lines 15–17, 105–129).
