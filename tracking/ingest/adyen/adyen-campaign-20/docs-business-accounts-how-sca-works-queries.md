## Q1 — What does the captured Business Accounts SCA API overview require and how does the challenge exchange work?

The page says it is an overview, not a use-case-specific example guide (raw line 19). It names third-party transfers, transaction-history consultation and transfer-limit creation as procedures that can require SCA (lines 21–29). Requirements include a Platforms integration with Business Accounts, a web-service credential with endpoint-dependent roles, the Authentication SDK, and additional Adyen configuration for the device-eligibility feature (lines 31–39, 77–83). The client checks eligibility and sends `sdkOutput` to the server; the first request carries it in `WWW-Authenticate`, and a successful initiation returns HTTP 401 with new input for the SDK challenge (lines 49–68, 175–199). After challenge completion, the server submits new `sdkOutput` with the same realm and receives endpoint-dependent HTTP 2xx on success (lines 70–73, 258–270). No. The guide's `Authenticate your user` section explicitly describes device registration and shows SDK `register(...)` calls after a 2FA step (raw lines 201–256). HTTP 2xx is the endpoint-dependent successful *API response* after finalization (lines 258–270); the page gives no transfer-booking or beneficiary-receipt evidence. The captured 2022-modified guide also does not establish current legal SCA obligations.
