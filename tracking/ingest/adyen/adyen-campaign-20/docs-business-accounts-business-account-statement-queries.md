# Retrieval checks — Business Account statements

## Q1 — What is the statement for, and what must a platform set up?

Answer: The CAMT.053 file summarizes a business account's financial activity over a period for balance reconciliation and user transaction reporting (raw lines 15–21). The platform needs an Adyen for Platforms integration supporting Business Accounts, a balance-platform Report user API key with Merchant Report Download role, a webhook receiver subscribed to `balancePlatform.report.created`, and Adyen-contact feature enablement/settings (raw lines 23–45). On readiness, the webhook supplies `balanceAccount`, `fileName` and `downloadUrl`; an authenticated GET downloads the file (raw lines 47–90). ## Q2 — Does the statement prove opening, financial activity, or compliance; what boundaries or conflicts matter?

Answer: This page describes statement generation and XML interpretation, not evidence that a particular account opened, holds funds, completed a transfer, or delivered an approved user-facing statement. The related compliance source separately requires platform-created user-facing statements and template review (source `wiki/sources/adyen/source-adyen-docs-platforms-compliance-financial-products-account-statements.md`, overview/key takeaways). Issuing card transactions appear only when the card and Business Account are linked to the same balance account (raw lines 21, 452–454). The optional summarized daily file groups entries by BAI code, so it cannot be treated as one row per transaction (raw lines 473–486). The settings table says `Summary` is included by default (raw line 43), while the later standard-versus-summarized comparison says standard `TxsSummry` is included when configured (raw line 484); preserve both wordings and check the account's actual configuration.
