# C20 brand-specific industry-code retrieval checks

## Q1 — What is this reference for, and when should the platform contact Adyen?

Route: `wiki/index.md` → `wiki/adyen-index.md` (`[[adyen-business-accounts]]`) → `wiki/concepts/adyen-business-accounts.md` → candidate `wiki/sources/adyen/source-adyen-docs-business-accounts-verification-requirements-reference-additional-products-brand-specific-industry-codes.md` → `raw/adyen/docs/business-accounts/verification-requirements/reference-additional-products/brand-specific-industry-codes/2026-09-15.md`.

Adyen says some brands have unique MCCs and assigns brand-specific ICs to capture them; the platform should select an IC that matches the user's brand and business activity (raw lines 15–19). The page directs the platform to its Adyen contact or Support if approval for an industry code is needed **before onboarding users**, or if it wants to offer Business Accounts to users in **new industries** outside a prior approval process (21–24). These conditions do not themselves confer approval, account eligibility or an opened account.

## Q2 — Which specific brand codes are accepted, and what does this snapshot prove?

The raw says “We only accept the following values for brand-specific industry codes” at line 26, but no code values or table follow: only a separator and a See also link to a separate general industry-codes list appear through line 32. This snapshot cannot answer which brand-specific code is accepted or map any brand to an IC/MCC. The linked general list is a separate, unread navigation target, not proof of brand-specific acceptance. The Business Accounts and Platforms captures have the same substantive short body, but their canonical and See also paths differ. Neither proves onboarding approval, actual MCC assignment, account opening or current eligibility.
