# Fixed locator-backed retrieval checks

1. **Purpose and scope; what should not be inferred?** This Adyen Docs page is for Terminal API Manual Key Entry as a fallback when a terminal cannot read the shopper card's chip or magnetic stripe; the shopper enters card number/expiry and signs on the terminal (raw 15–25, 27–45). The standalone path is only a link here (19–21). Virtual JCB credit cards are excluded and routed to MOTO (34). MKE is distinct from remote, staff-keyed MOTO; the page gives no general software-version, region matrix, API-role or PCI-questionnaire rule. 2. **Enablement, liability, amount, request/CVM, and warning?** MKE has no liability shift and puts fraud-chargeback liability on the merchant (raw 25). Support must enable it and Customer Area must have an MKE max amount; no universal value is given (35–36, 47–55). The POS Terminal API payment sets `PaymentTransaction.TransactionConditions.ForceEntryMode=Keyed`, with amount and currency in the worked example (57–105). Terminal shopper entry/signature is described (40–45); the response identifies `SignatureCapture`, `CapturedSignature`, `EntryMode=Keyed`, and `posEntryMode=MKE` (149–155). These example fields are not merchant enablement or payment proof. Route: `wiki/index.md` → `wiki/adyen-index.md` → `wiki/concepts/adyen-terminal-api.md` → proposed source → pinned raw.
