1. **What is this page's role and how is SaleToAcquirerData represented?** It is a non-exhaustive sample collection for the POS or Mobile Terminal API payment request's `PaymentRequest.SaleData.SaleToAcquirerData`. Its tabs show a JSON object to Base64 encode and a key-value representation; the parent add-data guide supplies full encoding and `AdditionalResponse` format rules. Sample categories include application/platform/device versions, metadata, shopper/recurring fields, store, tender options, and additional data. App version strings in the payload are example application metadata, not a pinned API/SDK version. Locators: raw lines 15–33, 35–64, 97–119; parent source [[source-adyen-docs-point-of-sale-add-data]]. Route through Terminal API concept to this source/raw.

2. **Can sample paths and actions be copied as a required payment contract?** No. JSON places split and tax-free names under `additionalData`, while the key-value sample puts `split.*` and `taxfree.indicator` at the top level; `surchargeFee` appears only in the JSON tab. The page does not mark these sample fields as generally required, nor does an example `authorisationType=PreAuth`, `tenderOption=ReceiptHandler,AskGratuity`, `manualCapture=false`, or split amount prove account eligibility or a payment/capture/settlement result. Select desired additional response data and verify exact field-specific requirements in the linked detailed guides. Locators: raw lines 24–29, 64–93, 118–145, 148–152.
