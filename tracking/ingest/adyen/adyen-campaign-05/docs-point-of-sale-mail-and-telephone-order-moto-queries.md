It also names a standalone solution (27, 48–55). Terminal use does not make the card present, and the page is not an online Checkout API integration or proof of merchant enablement. 2. **Prerequisites, fraud/AVS, request/response, and warning?** Complete PCI DSS SAQ B-IP for the commercial contract; enable MOTO through Customer Area for select merchants or Support, with optional maximum amount, AVS settings and capture delay; Platforms store/business-line setup is conditional (raw lines 21–32, 57–81). MOTO has no liability shift and merchant fraud-chargeback liability (34–38). AVS is optional, scheme/region qualified, unavailable on Android or legacy terminals, and a mismatch may still be authorized (28–29, 40–55). The Terminal API tender option goes in `SaleToAcquirerData`; the terminal prompts staff for card/CVC and AVS address if enabled, while response shows keyed/MKE and optional AVS result fields (83–96, 171–179). Review an authorized but inconclusive AVS transaction before capture; cancelling a MOTO authorization changes status to `SentForRefund` (225–229).
