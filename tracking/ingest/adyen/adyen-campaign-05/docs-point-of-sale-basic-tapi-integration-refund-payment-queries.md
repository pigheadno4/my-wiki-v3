# Fixed retrieval checks — Adyen POS refund overview

Catalog route pending coordinator promotion: `wiki/index.md` → `wiki/adyen-index.md` → `wiki/concepts/adyen-terminal-api.md` → proposed `wiki/sources/adyen/source-adyen-docs-point-of-sale-basic-tapi-integration-refund-payment.md` → `raw/adyen/docs/point-of-sale/basic-tapi-integration/refund-payment/2026-09-15.md`.

1. **Which POS refund request applies, and how does this differ from Checkout refunds or cancellation?** After an approved POS payment, a referenced Terminal API refund is a `ReversalRequest` linked by tender and/or PSP reference; an unreferenced refund is a terminal `PaymentRequest` with `PaymentType: Refund` for a presented card. Customer Area is another route for infrequent POS refunds. This overview does not specify Checkout API captured-payment refunds or an unreferenced-cancellation request; the latter is a linked page for cancellation before completion. Locators: raw lines 19–33 and 95–111. Route through the Terminal API concept to this source/raw; the online `adyen-refunds` concept has separate API/lifecycle scope.

2. **When is a refund outcome known, and what eligibility constraints matter?** Referenced refunds always process asynchronously: Terminal API receipt is not final, webhooks carry the processing result, and shopper funds may take up to 40 business days. Unreferenced processing may be synchronous or asynchronous by scheme and country/region; a synchronous `acquirerResponseCode` indicates approval. BankAxept needs an additional contract and the original-purchase store; Dankort and Interac allow only unreferenced refunds in this guide. Some single-messaging debit routes require unreferenced refunds, so retain `paymentMethodVariant` for routing and `fundingSource` for card type. An issuer refund-authorization decline does not necessarily stop Adyen's processing attempt. Locators: raw lines 35–49, 51–93. Detailed partial, split, and refund-webhook mechanics belong to linked pages, which remain navigation here.
