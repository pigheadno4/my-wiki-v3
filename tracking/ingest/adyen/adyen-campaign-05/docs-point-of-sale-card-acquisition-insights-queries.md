# POS shopper insights: fixed retrieval checks

1. **What is the purpose and scope of this guide?** It frames merchant analysis of payment identifiers with purchase data to ask about shopper origin, repeat purchases and optional online/POS overlap. It requires Terminal API POS, optionally online payments, and describes standard webhooks and Terminal API **payment responses** as the two insight collection routes. Card acquisition is mentioned only as a possible PAR response context. This page does not deliver a report, prove identity or authorization, list BIN fields, or establish universal cross-channel matching. 2. **Which fields and setup cautions matter?** The named fields are card alias, funding source, issuer country and PAR. Alias cannot make payments; issuer country is an indicator, not verified residence; the dated guide names Visa/MasterCard PAR only when available. Adyen recommends common-format standard webhooks across channels and says to select wanted identifiers; Terminal API payment responses also need some fields enabled.
