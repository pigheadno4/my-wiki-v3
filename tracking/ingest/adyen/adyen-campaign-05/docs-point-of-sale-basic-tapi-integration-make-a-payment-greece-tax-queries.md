# Adyen C05 — Greece tax signature flow fixed answers

1. **Purpose/scope; what not to infer.** This Adyen page, last modified 2024-11-28 and captured 2026-09-15, describes its Greek in-person Terminal API payment flow with an e-invoicing provider and AADE, plus a fallback for provider disconnection (`raw/adyen/docs/point-of-sale/basic-tapi-integration/make-a-payment/greece-tax/2026-09-15.md:15-24`, `:27-55`). Its December 2024 obligation and standalone-terminal prohibition are dated source statements, not a current legal determination (`:19`, `:31-38`). The page does not prove a merchant is configured, an AADE-listed provider is currently available, tax reporting completed, or capture/settlement occurred. Both illustrative success payloads request EUR 10 but show EUR 8 authorized (`:129`, `:178`, `:277`, `:323`).

2. **Central capability/prerequisites/warnings and route.** The documented normal route requires Terminal API terminal software 1.109.10+, Support-set Greece/Europe-Athens merchant settings, and a merchant POS integrated with a chosen e-invoicing provider; autonomous fallback needs 1.124+ (`:27-38`). The POS obtains a signature for the terminal and purchase amount, sends provider ID/signature/verification data in Base64 `SaleToPOIData`, and limits `RequestedAmount` to the signed amount; signature is transaction-unique, its verification timestamp must be neither future-dated nor older than 24 hours, and signature-data `TID` matches the terminal `POIID` (`:45-55`, `:68-109`, `:392-408`). The terminal verifies it; in the successful signed flow, `AdditionalResponse` supplies `aadeTransactionID` and the returned signature for the POS-to-provider handoff (`:146-149`, `:208-225`). The autonomous Success example does not show those identifiers (`:353-355`). The page says not to send the provider signature in a request other than the payment request, yet later instructs the POS to send the returned signature to the e-invoicing system; it does not reconcile the two statements (`:74-76`, `:225`). If provider connection is lost, `unbound_pos` is a conditional unsigned route; AADE connection failure returns `Failure` (`:227-249`, `:369-373`). Referenced refund uses the linked reversal route; unreferenced refund needs a fresh signature or autonomous fallback (`:376-386`).
