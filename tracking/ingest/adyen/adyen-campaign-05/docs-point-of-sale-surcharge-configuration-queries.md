# Fixed retrieval checks — Adyen POS configuration-based surcharge

1. **What is this page for, and what must it not be used to infer?** The 2026-09-15 snapshot describes Adyen's in-person configuration-based surcharge through Management API terminal settings, with automatic calculation on eligible terminals or Tap to Pay mobile devices. It is distinct from the online API-only surcharge pilot and dynamic per-payment surcharge. The guide says rules must meet applicable compliance requirements; it is not current legal advice, current merchant/terminal enablement proof, or evidence of final payment settlement. See `# Configuration-based surcharge`, `## Requirements`, and `## How it works` in [[raw/adyen/docs/point-of-sale/surcharge/configuration/2026-09-15|pinned raw]].

2. **What conditions govern configuration, calculation and disclosure, and where is the route?** An API key needs Management API Terminal settings read and read/write roles; GET/PATCH `/terminalSettings` can target company, merchant, store or terminal. SFO1/NYC1 are excluded, and terminal firmware gates specific features. Ordered `configurations` stop at the first matching brand/funding/issuer-country/currency rule; fixed/cap values use minor units. Commercial-only checks are unsupported on Mobile and offline terminals. Tap to Pay lacks the confirmation screen, needs another disclosure route and Support-enabled single tap. From v1.117, rules include MOTO/MKE and can double-charge if the merchant's custom surcharge also runs, so Adyen offers an opt-out. See `## Requirements`, `## Configure surcharges`, and `## Opting out for MOTO and MKE`.
