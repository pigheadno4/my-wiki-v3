Customer Area, API and physical-terminal checks observe connectivity at a point in time; none proves a local POS-to-terminal link, payment request delivery or result, authorization, capture, or settlement. 2. **What routes, prerequisites, and status limits should a reader retrieve?** Enable WebSockets in Customer Area; its terminal-list status can lag, and the individual connection icon requires each new manual check (raw lines 19, 30–54). The recommended Cloud device API uses a key with the Cloud device API role: `GET /merchants/{merchantAccount}/devices/{deviceId}/status` returns `ONLINE`/`OFFLINE` for a device ID or IPP Mobile installation ID, and `GET /merchants/{merchantAccount}/connectedDevices` lists currently connected IDs with optional store filter, excluding offline devices (lines 56–137). The older `/connectedTerminals` uses test/live Terminal API endpoints and Terminal API credentials; an empty array may mean no connection or disabled WebSockets (lines 141–214). The terminal-side test and restore steps are at lines 216–234.
