# C25 Marketplace multi pay-in allocation — retrieval checks

**Q1. What is this page for and what is required before allocation?** It allocates payments processed by third-party pay-in partners after their proceeds are in the multi pay-in account, using separate splits into user and platform balance accounts (raw lines 15–25). It calls for Checkout API credentials, Transfer and/or Transaction webhook subscription, and the ability to allocate **each individual payment within 24 hours after settlement in the multi pay-in account** (lines 27–36). One POST `/payments` per partner payment supplies the source BA and explicit split instructions (lines 38–69). **Q2. Which money-flow or evidence boundary matters?** The source multi pay-in BA is debited separately from the user BA credit, liable commission credit and selected/default liable fee debit; absent fee instructions, all fees default to liable (raw lines 58–69, 426–450, 731–744, 1037–1050, 1360–1372). A TEST `Authorised` Checkout response (lines 406–424) does not prove these movements. Follow each leg's Transfer and Transaction events and the accounting report (lines 453–1669); sample user-account IDs and commission transaction sign conflict (lines 918–920 versus 1024–1029; 1212–1239 versus 1319–1350). Payout is only routed after user-balance settlement, and this page shows no beneficiary-bank receipt (lines 1688–1690).
