# docs-marketplaces-payout-descriptions — worker retrieval checks

Q1. How do Marketplace payout descriptions work, and which fields can be configured?
A. `description` and `referenceForBeneficiary` are supplied through Transfers API or Customer Area, pass through a clearing network, then are displayed only to the extent the beneficiary bank chooses (raw lines 21–27). Scheduled managed/custom payouts may use static text or placeholders; `$shortTransferReference` is only for custom scheduled payouts, and balance-account settings override balance-platform settings (lines 37–69). On-demand Transfers API and Cashout requests require static strings, without placeholders (lines 71–76). Q2. Why can submitted text fail to appear on a statement, and what source conflict matters?
A. Network capabilities and bank display decisions separate accepted characters from visible characters (raw lines 23–27, 78–84). The route tables show PLN regular fields, SEPA EUR instant beneficiary reference, and SGD wire fields accepted with zero statement visibility (lines 131–138, 149–158, 246–255). Australia AUD fast lists 280 visible characters; its description row states an accepted maximum of 140, but its beneficiary-reference row says 80 in the maximum-character column while the visibility parenthetical says “Adyen accepts a maximum of 140.” Preserve that conflict without selecting a settled beneficiary-reference limit (lines 223–224). The zero-visibility rows qualify the broad recommendation that `$shortTransferReference` is supplied by all banks (lines 62–67). Descriptor submission or display proves neither payout execution nor receipt.
