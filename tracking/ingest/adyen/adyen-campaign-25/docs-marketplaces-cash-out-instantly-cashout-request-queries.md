# Retrieval checks — docs-marketplaces-cash-out-instantly-cashout-request

Q1. What does a cashout request do and what is required? Answer: It makes a user's pending funds instantly available in that user's balance account; optional `counterparty.transferInstrumentId` additionally requests a payout, while omission leaves the funds in the account. The Marketplace needs a Platforms integration, Transfers/Configuration API roles, Transfer webhooks, Support enablement and sales-day settlement; user accounts need receive/send balance-account capabilities, with send-to-instrument capability conditional on payout. Request amount must fit pending available balance; optional fee must share currency and fit the sum limit. Raw lines 19, 21–35, 99–122.

Q2. What boundaries/failures/conflicts matter? Answer: Created IDs start asynchronous processing; track Transfer and Transaction webhooks. A failed instrument payout after successful cashout reverses amount and user fee to pending available, with no marketplace charge; retry needs a new POST. This snapshot lists EUR/USD/GBP/AUD and unit-one minimum. The curl puts transferInstrumentId at top level contrary to the counterparty field table, and the response fee value conflicts with request/prose and fee-transfer value, so the example is not reliable schema or fee-math authority. Raw lines 117–124, 128–146, 149–219, 221–231, 276–322.
