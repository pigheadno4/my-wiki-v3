## Q1. What does this Marketplace payments guide require, and where do payment funds go?

It covers **online payments on behalf of marketplace users**, split between user balance accounts and the marketplace liable balance (raw line 19). Requirements include an online Checkout UI/integration, Checkout and Transfers API credentials, webhook handling, and a **valid** `receiveFromPlatformPayments` capability for user allocation; Sessions and Advanced are the named Checkout server flows (raw lines 21–35). The guide calls for split instructions on payment, capture and refund requests or a split profile (raw lines 37–43). It illustrates USD 400 pay-in, USD 396 user credit, USD 4 liable commission, USD 2 liable fee and later user/marketplace payouts (raw lines 51–69). ## Q2. What sends the full payment to the liable account, and does the example prove settlement or bank receipt?

If the holder’s `receiveFromPlatformPayments` capability is not valid, the user balance account cannot receive its allocation and the **full amount** books to liable (raw lines 32–33). If both profile and API split instructions are absent, the **whole transaction amount and fees** book to liable (raw lines 37–41). These are separate conditions. The diagram’s USD booking/payout numbers are illustrative (raw lines 51–69), not proof of payment authorization/capture, settlement, payout execution or beneficiary-bank receipt. Webhook subscription wording differs between “any” in requirements (raw lines 30–31) and “Transfer and Transaction” later (raw line 73), so this page alone does not settle full event coverage.
