# C25 Marketplace on-demand payout review — retrieval checks

**Q1. What does this page enable and what setup is needed?** An additional `review` object on a POST `/transfers` payout request makes it pending until an eligible reviewer approves or cancels it (raw lines 15–21, 32–50). The review API key needs TransferService Approval role and Transfer Webhooks subscription (lines 23–30). Approve and cancel requests use `transferIds` arrays of one to 500 IDs (lines 52–60, 261–269). **Q2. What state boundary matters before treating a review as payout success?** Approval merely authorizes continued processing; cancellation or no action for 30 days fails that request (raw lines 42–48). HTTP 200 on a review endpoint is a review response (lines 259, 468). Webhook examples distinguish pending `received`/`pending`, approved `authorised`/`approved`, and canceled `cancelled`/`unknown`; no expiry sample or beneficiary-bank receipt is shown (lines 470–736).
