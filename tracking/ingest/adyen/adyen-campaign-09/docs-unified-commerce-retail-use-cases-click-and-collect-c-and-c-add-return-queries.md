# Retrieval checks: click and collect with returns or add-on purchases

## Q1 — What is this guide for, and what must it not imply?

This is an Adyen retail use case for an online-paid order collected at a physical store. The shopper can drop items and receive a referenced refund of the online payment, or add items and pay for them separately through a Terminal API payment. The guide assumes both ecommerce and POS integrations plus a consolidated order/inventory or ERP system, or a webhook-consuming orchestration layer connecting those systems. It does not imply that card acquisition charges the shopper, that alias/PAR is a payment credential, that an issuer/payment response alone updates merchant inventory, or that the examples prove payment/refund completion. Canonical route: https://docs.adyen.com/unified-commerce/retail-use-cases/click-and-collect/c-and-c-add-return

## Q2 — How are pickup identification and item changes handled, with key prerequisites and warnings?

After Checkout API authorization, offer identification by the original payment card or by saved profile details. The page says to implement both because card recognition cannot identify purchases made with QR wallets, BNPL, or other alternative methods. Obtain explicit permission before first saving shopper details; enable identifying data in responses and webhooks for card recognition. Card alias recognizes a PAN but is not chargeable and is unavailable for NFC wallet transactions; PAR recognizes the linked payment account. The merchant looks up the shopper/order through its own systems using the data and online `AUTHORISATION` webhook. A dropped item gets a referenced refund: Terminal `ReversalRequest` uses `.pspReference` with a leading dot and `ReversedAmount` outside minor units, while Checkout `/payments/{paymentPspReference}/refunds` uses an amount whose value cannot exceed the captured amount (USD 12.50 appears as `1250` in the example). Added store items use a separate Terminal `PaymentRequest`. The guide recommends immediate online capture because delayed authorization may expire before pickup.
