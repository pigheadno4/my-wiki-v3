# C09 retrieval probes — Classic recurring payment capture

Q1. What does this page do, and what prior payment state and integration scope does it assume?
Expected: This 2026-09-15 snapshot covers capture of an already authorized recurring payment using the inactive Classic Payment API `/capture` modification. Some payment methods, including the page's card example, need a separate capture to collect reserved funds. The options named are automatic capture, manual capture in Customer Area, or a server-side `/capture` call. New integrations are directed to Checkout API and existing users to migration. This page is not a new `/authorise` call or a stored-detail update. Q2. What references and amount does the Classic `/capture` request use, and when is its outcome known?
Expected: The request supplies merchant account, full or partial `modificationAmount`, and the earlier authorization payment's `pspReference` as `originalReference`; examples also include a merchant modification reference. The illustrated response has its own `pspReference` and `[capture-received]`, which only acknowledges a syntactically valid received capture request. The final capture result arrives in a separate webhook, and this page does not define that event's fields or prove capture or settlement for a merchant.
