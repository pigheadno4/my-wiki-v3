# Retrieval checks: Classic API browser-based 3DS2

## Q1 — What is this page for, and what should it not be used to infer?

This is Adyen's website guide for a **full payment** using browser-based native 3D Secure 2 with an existing Classic Payment API `/authorise` integration. It covers frictionless and challenge authentication paths before payment authorization, with merchant-owned browser and server steps. It is distinct from the linked authentication-only route, where authorization occurs later. Adyen says it no longer accepts new Classic API integrations and recommends the Checkout API migration. Do not infer that a successful authentication step, issuer callback, or test example alone is an authorized payment, that a new Classic integration is accepted, or that 3DS2 always runs: the page notes possible 3DS1 fallback and direct `Authorised` responses for exempt transactions. Raw locators: `How it works` lines 19–43, `Step 1: Submit a payment request` lines 70–82 and 560–575. Canonical route: https://docs.adyen.com/online-payments/classic-integrations/classic-api-integration/3d-secure-authentication/native-3ds2/browser-based-integration

## Q2 — What is the central capability, with prerequisites and consequential warnings?

Merchant server starts with `/authorise` and `threeDS2RequestData`/`browserInfo`, then uses `resultCode`: `IdentifyShopper` leads to a hidden browser iframe posting method data, a method notification callback (or 10-second wait), and `/authorise3ds2` with `threeDSCompInd` `Y` or `N`; `ChallengeShopper` leads to an issuer ACS iframe, a challenge notification callback, and server-side `/authorise3ds2` with the resulting `transStatus`. A missing challenge callback after 10 minutes must be represented as `transStatus: U` under this guide. The merchant needs a test account, API key, API library, and two absolute notification URLs. This dated guide makes the helper functions optional for the merchant-built browser/server flow, says they replace the Web 3D Secure 2 SDK implementation, and directs existing Web SDK users needing assistance to Adyen Support. Optional fingerprint-key prefetch requires Support enablement and a fresh per-BIN cache; stale keys can cause refusals.
