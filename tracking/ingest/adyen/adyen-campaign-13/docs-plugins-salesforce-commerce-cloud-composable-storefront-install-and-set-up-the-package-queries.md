## Q2 — central capability, prerequisites, and warnings

**Question:** What platform versions, site setup, credentials, webhook handling and qualifications must be preserved?

**Expected answer:** The snapshot lists PWA Kit v3.12+, Node v22+, npm v11+, Salesforce sandbox/site/locale/inventory/WebDAV setup, MRT enablement/Admin rights and hooks. Import site-specific cartridge metadata; place Adyen SSR routes before Salesforce/custom routes. Configure checkout props, Adyen API/client keys, merchant account, test/live environment, webhook Basic/HMAC credentials, Commerce API identifiers/scopes and conditional live prefix; protect secrets. Standard webhook setup uses the site-ID URL, JSON/TLSv1.3, Basic/HMAC and OFFER_CLOSED, with AUTHORISATION implemented by default; SFCC Process/Clean jobs handle stored notifications and localhost webhook testing is unavailable. Optional redirect-back recovery can fail pending Salesforce orders and rebuild baskets. The guide states a one-site MRT connection while a later options example describes multi-site hosting; this remains unresolved. Optional Level 2/3 and Giving need package v4.3.0, but not all businesses can submit Level 2/3 data. Giving also needs a matching-currency campaign, a donation-token-capable non-gift-card method, and the standard webhook subscribed to DONATION for settlement notifications. In-person terminals need v4.4.0 plus their own site/store conditions.
