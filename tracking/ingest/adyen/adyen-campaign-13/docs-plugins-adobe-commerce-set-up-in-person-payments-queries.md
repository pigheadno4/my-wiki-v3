## Q2. What is the central capability, prerequisites, and material warnings?

Configure a separate POS merchant account, generate and securely retain a company-scope API key, and obtain **Merchant PAL webservice role** before live use (raw lines 23–53). Card payments can use immediate, timed or manual capture where separate authorization/capture is supported; Alipay, WeChatPay and some wallets are one-step exceptions. Two hours is only recommended; manual capture uses a Commerce invoice, and **partial capture automatically cancels the remaining authorization** (lines 55–86). A user with **Merchant POS Terminal Management Admin role** enables Terminal API and WebSockets in Customer Area (lines 88–99). Commerce POS settings distinguish merchant account, optional Terminal Store ID, test/live API keys, capture delay, installments and order creation **After payment** by default versus **Before payment** prior to request (lines 101–122). Optional tokenization selects a recurring model (lines 124–139) but does not prove consent or token creation. None of these settings establishes a terminal/network result, Commerce payment success, capture completion or bank receipt.
