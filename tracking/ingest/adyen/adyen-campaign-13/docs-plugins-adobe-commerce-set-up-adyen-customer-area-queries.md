## Q2 — Which credentials, webhooks and capture settings are required, and where do version boundaries apply?

Both setup tabs generate an API key for server authentication and a client key; the guide explicitly instructs secure storage of the API key, while it only says to generate the client key. Manual setup also configures allowed origins (raw lines 34–46, 70–83). The manual tab configures a Standard webhook and `OFFER_CLOSED` event, with merchant-account selection, JSON/TLSv1.2, Basic authentication and HMAC key; v9+ uses `/adyen/webhook`, while v8 uses `/adyen/process/json` (lines 85–136). Its CSP caveat concerns only the webhook response header and Adyen's 8192-byte limit, not all storefront CSP (line 96). Merchant-account capture delay is `manual` or `immediate` (default), but selecting it does not prove capture; authorization and capture remain separate (lines 48–68, 138–158). The page sends the reader onward to plugin and payment-method setup (lines 160–176). Use the concept→source→raw route for exact steps and keep test Customer Area instructions separate from live enablement.
