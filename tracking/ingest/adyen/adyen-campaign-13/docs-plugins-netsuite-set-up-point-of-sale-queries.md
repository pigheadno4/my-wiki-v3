## Q2. What is the central capability, prerequisites, and material warnings?

The guide requires Chargeback Workflow and SuitePayments bundles and POS-app/terminal connectivity (raw lines 19–24), then recommends a POS merchant account and allows multiple stores identified by `storeID` (line 28). A company-account user configures a Webservice credential, separate API key and Basic-auth password, three named roles including Support-enabled **API PCI Payments Role**, and associated merchant accounts (lines 30–65). NetSuite needs an EMV SCIS method, separate POS profile with subsidiary/currency/bank-account/merchant ID and request types, plus terminal IDs of model-and-serial format (lines 67–146). **TEST MODE** overrides the production-prefix setting, whose raw example is a test-looking URL; verify the actual live prefix (lines 112–123). NetSuite's postback URL is configured both as a merchant-scoped Standard webhook using JSON/TLSv1.2 and as a Terminal API Event URL with Public/Local scope; Support is asked to enable WebSockets and settings apply per device (lines 148–192). These are configuration and routing prerequisites, not payment, event-delivery, capture or bank-credit proof.
