# Independent retrieval checks — Adyen 3DS2 API reference

1. **Purpose, scope, and inference boundary.** This is the 2026-09-15 snapshot of Adyen's parameter and object reference for Checkout API v41+ 3DS2 requests on `/payments`, `/payments/details`, and `/sessions`; classic integrations have a separate reference (candidate lines 6–14; raw lines 19–36). It classifies required, conditional, recommended, and optional data and covers challenge objects and third-party MPI values (candidate lines 18–31; raw lines 38–69, 260–379, 444–460). It does not establish current merchant or card eligibility, a successful 3DS authentication, Adyen authorization, or liability shift. The high-level merchant guide separately routes native integrations on Checkout API v46 or earlier to an earlier-version integration guide (concept lines 14–18); this parameter reference does not supersede that routing.

2. **Index → concept → source → raw route.** `wiki/index.md` routes to `wiki/adyen-index.md` (index line 10), which routes to `[[adyen-3d-secure]]` (Adyen index line 99). The approved concept update links `[[source-adyen-docs-online-payments-3d-secure-api-reference]]` under Related; the candidate then links the immutable raw snapshot in Raw Sources (candidate lines 33–43). For a Web request, inspect the object table for `channel`, `paymentMethod`, `returnUrl`, `origin`, and scheme-dependent contact/IP data (raw lines 44–69), then the Web-specific `browserInfo` rule (raw lines 172–188). The reference warns that a missing or wrong Web `origin` prevents proper 3DS2 action handling (raw lines 57–58), `attemptAuthentication=never` can cause decline where authentication is regulated and overrides Dynamic 3D Secure settings (raw lines 143–145), `scaExemption` overrides Adyen's exemption logic (raw lines 62–65), and a preferred native flow can still redirect (raw lines 151–153). Standalone authentication ends before authorization (raw line 143); third-party data requires `mpiData` for a later Adyen authorization (raw line 262). Exact field formats, scheme combinations, and statuses remain in the linked raw tables.
