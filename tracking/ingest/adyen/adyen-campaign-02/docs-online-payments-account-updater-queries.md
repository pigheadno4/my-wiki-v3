# Account Updater retrieval checks

1. **Purpose and scope.** This 2026-09-15 Adyen webpage overview introduces Account Updater as an extension of Adyen tokenization. Visa, Mastercard and Cartes Bancaires provide card-account change notices; Adyen presents synchronous Real Time processing and asynchronous merchant-file Batch processing (`raw/adyen/docs/online-payments/account-updater/2026-09-15.md:15-34`). It does not establish a merchant's current enablement, eligibility, a successful update, or that every notice replaces card details. The listed notices include loss/theft and withdrawal of authorization for automatic charges (`:25-30`).

2. **Route and consequential detail.** `wiki/index.md` → `wiki/adyen-index.md` → `wiki/concepts/adyen-tokenization.md` → proposed `wiki/sources/adyen/source-adyen-docs-online-payments-account-updater.md` → `raw/adyen/docs/online-payments/account-updater/2026-09-15.md`. The reciprocal source link is the submitted concept suggestion; source/index promotion is pending the coordinator. For Real Time, Adyen recommends an integration-free route, asks for updates during payment processing, and describes a decline-triggered update request and immediate retry; automatic stored-token update is conditional on using Adyen tokenization (`:36-40`). For Batch, the merchant sends request files, receives result files, then needs a `/payments` request to update card details (`:42-44`). Card-selection/timing benefits are at `:46-50`; further guide routes are at `:52-60`.

3. **Concrete gaps.** This overview gives no merchant-specific enablement or eligibility check, Batch file schema, `/payments` payload, or full Real Time decline/retry outcome handling. The linked Real Time and Batch guides at `:38,44,54-60` are navigation targets and require their own evidence before those questions are answered.
