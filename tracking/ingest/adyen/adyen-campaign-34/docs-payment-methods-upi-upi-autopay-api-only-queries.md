# Retrieval checks — UPI Autopay API-only

Q1. How does the guide create a UPI Autopay billing plan, then charge later cycles?

A1. It assumes existing API-only Advanced integration (raw lines 21–26). Shopper approval in a UPI app is needed to create a mandate and store payment details (raw line 34). Initial server `/payments` includes UPI method and conditional VPA/appId, `storePaymentMethod`, Ecommerce interaction, recurring model, shopper reference, INR initial amount and mandate cap/rule/frequency/end date (raw lines 36–58); Intent/QR/Collect have distinct actions and final webhook handling (raw lines 60–248). For later cycles, send `/notifyShopper` at least 24 hours before charge through Adyen to UPI network/issuer, retain `shopperNotificationReference`, then send a ContAuth recurring `/payments` call tied to the stored method and corresponding sequence where adhoc (raw lines 324–417). The recurring `Received` response is initiation; use AUTHORISATION webhook for outcome (raw lines 447–471). Q2. Which lifecycle/limits and contradictions prevent treating the examples as live mandate or payment proof?

A2. The page gives recurring failed-authorization retries up to three with at least one hour between, then a new notification (raw line 470); merchant token delete and shopper app cancellation have `recurring.token.disabled` confirmation (raw lines 473–484). It describes a November 2025 plan to stop new UPI Collect integrations despite retaining Collect examples (raw lines 187–248). The amount-rule table compares `max`/`exact` to `amount.value`, but `/notifyShopper` compares to `mandate.amount` (raw lines 48–50, 354); merchant alphanumeric warning conflicts with allowed remarks spaces and example values (raw lines 28–30, 54, 373–375, 436–439); sample JSON and recurring mandate-created webhook wording are unreliable (raw lines 114–126, 175–185, 447–471). TEST requires Implementation Manager setup and LIVE Account Manager onboarding (raw lines 486–503). These, app actions, notification success and `Received` do not prove current eligibility, final authorization, capture or settlement.
