Q1. How do API-only UPI Intent, QR and Collect differ in request/action and shopper interface?
Answer: For India/INR on an existing API-only integration (raw lines 14–23), Intent uses upi_intent plus third-party appId and returns Pending/action.url for a mobile app redirect (lines 25–99). QR uses upi_qr and action.qrCodeData for a checkout QR, recommended on desktop/tablet (lines 141–212). Collect uses shopper VPA with upi_collect and an await action, but is no longer offered to new merchant integrations per the November 2025 body notice (lines 253–260, 327–360). Illustrative TEST requests are v72 Intent and v68 QR/Collect; no common minimum API version is stated. Q2. Can Pending, QR/app redirect, VPA validation or simulator selection be treated as a successful payment?
Answer: No. Pending is explicitly non-final (raw lines 90–95, 223–229, 358–360). The guide waits for AUTHORISATION webhook success/failure for Intent, QR and Collect (lines 104–117, 206–221, 374–387); optional Collect validation does not guarantee debit and applies only on Adyen Direct, while technical failures should not block (lines 262–325). TEST checklist calls the eventCode AUTHORISED (lines 134–137, 246–249, 412–415), conflicting with the outcome tables. The recommended five-minute countdown is a reminder, not stated expiry (lines 106, 210, 376).
