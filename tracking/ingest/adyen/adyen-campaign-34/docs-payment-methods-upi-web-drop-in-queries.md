# UPI Web Drop-in retrieval check

Q1. What prerequisites and request additions differ between Sessions and Advanced Web Drop-in for UPI?

Sessions requires existing Web Drop-in, Checkout API v68+, and UPI in Customer Area; this page specifies no extra UPI `/sessions` fields or configuration (raw lines 23–57). Advanced requires existing Web Drop-in, an additional action labelled `await`, and Customer Area setup; the `/payments` table conditionally requires `paymentMethod.appId` for `upi_intent` despite no extra UPI configuration (raw lines 83–121). Its Integration type URL at raw line 91 retains an encoded platform template, while action/import links at lines 92/99 use Web; do not treat the templated link as resolved. The TEST v72 request is an example (raw lines 123–143). Q2. Does this Drop-in page establish Collect migration, live UPI eligibility or a final payment from its simulator checklist?
