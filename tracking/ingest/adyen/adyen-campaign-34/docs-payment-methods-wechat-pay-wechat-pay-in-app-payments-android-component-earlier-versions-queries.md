# WeChat Pay Android Component earlier-version retrieval check

Q1. What is this guide's version and flow scope, and which systems act before the WeChat app switch?

It is titled Component v4.x.x but states support from Android Components 3.5.0 onward. It requires an existing **Advanced** Android Components integration, Adyen Customer Area method setup, a WeChat Open Platform developer account and registered mobile app. The integration selects `wechatpaySDK` from `/paymentMethods`, and the merchant server calls `/payments`; the Android module checks device availability and handles the returned `action` for the app switch. The `WeChatPayProvider` code is availability-only, while v72 and CN/CNY in examples are not universal minima or limits (raw lines 15–70, 72–93, 377–421). Q2. Does a TEST example, returned Intent, or Pending result prove a completed WeChat Pay payment?

No. The page says WeChat Pay had no test platform despite TEST-configured examples, suggests cancellation at verification or a low-value live test, and requires a live Customer Area request before accepting live payments (raw lines 79–80, 414–416, 466–475). The returned Intent supplies `actionComponentData` for server `/payments/details`; Pending/Received waits for a final AUTHORISATION webhook, not payment success (raw lines 423–464). The requirements link targets Advanced, while the See also Android Components link targets Sessions (raw lines 29, 481). No actual test or live operation is evidenced.
