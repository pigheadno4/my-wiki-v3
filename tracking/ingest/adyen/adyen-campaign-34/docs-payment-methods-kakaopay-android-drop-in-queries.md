Q1. How do base Android Drop-in requirements differ from the recurring token route?
A1. Sessions needs existing Android Drop-in, Checkout API v68+ and KakaoPay Customer Area setup, with no extra base /sessions or config fields (raw lines 25–46). Advanced needs existing Advanced Drop-in, explicit redirect handling and Customer Area setup, with no extra base /payments or config fields (raw lines 300–320). Recurring token creation separately adds storePaymentMethod and shopperReference in /payments, with shopper Kakao login/confirmation; later charges use storedPaymentMethodId, shopperReference, ContAuth and recurringProcessingModel (raw lines 48–87, 322–361).
