## Q1 — What is this page for, where does it apply, and what must it not imply?

The page explains onboarding versioning and the stated v2-to-v4 update path for Adyen Platforms' LEM API, Hosted onboarding, and KYC checks (raw lines 19–31, 69–89). It distinguishes Hosted from API-only migration (lines 91–149). The snapshot says v4 is latest stable at line 19 and in its v4 update steps (73–74), but calls v3 latest stable at line 67, so current version status must not be inferred from that contradictory sentence. It is historical integration guidance, not proof that any account has completed migration, verification, compliance approval, capability activation, transfer, or go-live. ## Q2 — What capabilities, prerequisites, and warnings are central?

The stated route contacts Adyen, updates the server to LEM v4, reviews features, tests, and goes live (raw lines 69–77). Hosted stays on LEM v2 until integration update and then uses v4 (91–93); API-only has additional support-contact and transfer-instrument `type` work (119–139). Both tabs require review of deadlines, data reviews, country/region rules, changed error and webhook structures, resource-level `sendToTransferInstrument`, business-line `service`, and source-of-funds conditions (95–117, 121–149). Older users' verification deadlines, PCI, and ToS differ from new users, and upgrading alone does not trigger checks (79–89). Test features must be enabled through Adyen contact and unsuccessful-verification handling tested (151–153). Older API versions may sunset after notice (51–67); release candidates are API-only previews (55–57). No specific credential/role is named. Do not infer that the recommended components guarantee an individual bank-account status, that integration migration itself verifies an entity, or that this 2025-modified page proves today's supported version.
