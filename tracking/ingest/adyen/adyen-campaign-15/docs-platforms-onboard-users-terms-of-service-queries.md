## Q1 — Purpose, scope, and what not to infer

**Question:** Whose acceptance does this Platforms guide require, and what does the page prove?

**Answer:** This 2026-09-15 Adyen guide says a platform user must accept required Adyen Terms before particular platform actions. Hosted onboarding includes the step; a platform-built UI must generate, show and obtain acceptance of the document (raw lines 15–21). The accepter is an **individual legal entity** representing a person; for an organization, it must be an authorized signatory, and the main user legal entity remains distinct from that person (lines 23–42). The guide is a workflow reference, not evidence that any specific person accepted current terms, that the accepted document matches a live account's current requirements, or that a payment, payout or capability succeeded. ## Q2 — Central procedure, prerequisites, and warnings

**Question:** How does an own-UI integration determine, present and record the right Terms document?

**Answer:** The guide requires Adyen for Platforms, Legal Entity Management API credentials, legal entities for the contractual platform user and accepting individual, plus standard-webhook receipt and Configuration-webhook subscription (raw lines 30–42). Listen for Terms-related `verificationErrors` in `balancePlatform.accountHolder.updated`; its `sendToTransferInstrument` blocked example is illustrative, not universal (lines 55–107). GET required document types for the **main** legal entity, or owner ID for a sole proprietorship; multiple types may be required. Test always returns `adyenForPlatformsAdvanced`, while live returns actual required types (lines 109–127). Generate document(s) with required type/language and optional format, present decoded Base64 content, and retain each `termsOfServiceDocumentId` (lines 129–383). Only after the person accepts, PATCH using main entity and document ID in the path with required `acceptedBy` individual ID; for an organization that ID is the authorized signatory. `ipAddress` is optional. A separate GET can retrieve acceptance information with `acceptedBy` and `acceptedFor` (lines 385–396, 596–622, 766–790). Code samples and sample responses do not prove real acceptance; the page gives no universal Terms revision identifier or re-acceptance rule. No provider operation was performed for this entry.
