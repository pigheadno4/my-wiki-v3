# Fixed retrieval checks — Platforms in-person Giving donations

Q1. What is this source's purpose and transaction scope, and what must not be inferred?
- Expected: This 2026-09-15 Adyen for Platforms guide describes a terminal or standalone, platform-model Giving flow after an account-holder donation campaign is set up. A shopper's opted-in donation to a nonprofit is a separate transaction from the in-store purchase. The guide says Adyen covers donation fees and transfers the whole donation to the nonprofit; sale amounts and fees may be split on the original purchase, but the donation itself cannot carry those splits. This is not the Platforms API-only online Giving implementation and does not identify merchant-of-record/legal seller, prove current nonprofit or merchant eligibility, confirm a particular donation, or prove settlement/bank receipt.

Q2. What prerequisites, method/channel limits, receipt path and outcome evidence govern the flow?
- Expected: The guide limits integration to platform-model merchants using Terminal API payment terminals or standalone; terminals need software v1.109 or later, with some devices/features needing v1.110 or later. Configure and start an account-holder campaign for a nonprofit; options appear after the next scheduled terminal reboot for supported payments. The page links supported terminal, payment-method, region and currency lists without reproducing them, and says gift-card purchases do not trigger a prompt. Subscribe to the Adyen Giving merchant webhook. Only a two-step Terminal API flow permits the full donation response for receipt generation: a transaction-status request sets `TransactionStatusRequest.MessageReference.SaleID` to `AdyenGiving` while outer `MessageHeader.SaleID` remains the POS system's ID, and uses receipt reprint and `DocumentQualifier`; the returned receipt is at `TransactionStatusResponse.RepeatedMessageResponse.RepeatedResponseMessageBody.PaymentResponse.PaymentReceipt`; use the original payment response's `adyen_giving_service_id` for a specific donation, while omitting it selects the latest donation on that terminal. The merchant `DONATION` webhook supplies the donation outcome, with `success` and `originalReference` linking the sale; shopper email/mobile notice requires contact details. Receipt data and the sample success webhook are not independently a live settlement or delivery proof.
