Q2. What are the central capabilities, prerequisites, and warnings?
- Route: [[source-adyen-docs-platforms-online-payments-checkout-components]] → [[adyen-platforms]]; follow its raw locators for field and environment detail.
- Answer: Payment server creates a session with merchant account, amount/currency in minor units, return URL and reference; country/currency filter available methods. The website initializes `AdyenCheckout`, checks available methods, mounts per-method Components and handles redirects. The webhook server receives the asynchronous authorization outcome for order updates. Prerequisites include stated Customer Area/API roles and credentials, client key, Standard webhook, test setup and then separate live-account/payment-method/HTTPS/PCI/endpoint work. Return URLs must omit PII; iframe/WebView/SSR/CSP and redirect constraints apply. Session-result status is fixed and must not be polled for updates; client events/status displays are not later financial proof. Use one live endpoint region per session and matching Component environment. This page supplies no split-instruction or user-balance-account booking procedure; checkout setup or an `AUTHORISATION` event does not prove a user split was booked. For split and liable-account allocation conditions, route to [[source-adyen-docs-platforms-online-payments]] and its pinned raw.
