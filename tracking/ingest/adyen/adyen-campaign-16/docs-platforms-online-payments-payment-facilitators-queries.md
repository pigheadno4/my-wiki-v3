Q1. What does this page establish about payment-facilitator users and Merchant of Record?
A. For Adyen Platforms online payments facilitated by the platform, this dated guide says card schemes require data about the user, who is considered Merchant of Record for that transaction. The platform needs an online payments integration with checkout UI and Checkout API credentials. Q2. What data, configuration, and statement handling does an online facilitator need?
A. On each `/sessions` or `/payments` authorization, send the user's unique ID, accurate statement name (Mastercard aggregator prefix), and transaction location using `AdditionalDataSubMerchant` under `additionalData.subMerchant.subSeller1.*`, with `numberOfSubSellers=1`. The table lists address, email and phone details and makes postal code specific to Canada/US; sample payloads omit email and phone, so check the current API contract. Adyen says later cancellations, captures and refunds reuse the initial payment's user data. Confirm platform `paymentFacilitatorIds`, `aggregatorPrefix`, and `amexCapnSubmitterId` before live use. If there are no stores, configure the shopper-statement description; depending on configuration, a request can add `shopperStatement`. Most, not all, methods may use an aggregated MID. The Checkout v72/test and SDK split examples show request shape only, with a Node JavaScript EUR versus other USD sample discrepancy.
