Q1. What is this document's purpose and scope, and what must not be inferred?
A1. It is a 2026-09-15 Adyen Platforms online-payment guide for a limited-availability currency-conversion pilot. It fixes the customer's amount in the processing currency while calculating a variable amount for the user in the settlement currency; the latter depends on the exchange rate and Adyen markup (raw lines 15–24, 44–50). It does not prove current pilot access, account eligibility, a live FX quote, successful payment booking, final user credit, payout, or merchant-of-record identity. The PLN/CZK values and the test Checkout v72 response are examples, with different illustrative figures across the rate calculation, field table and request sample (raw lines 87–142, 150–200, 799–820). Q2. What is the central capability, what prerequisites and consequential warnings apply?
A2. For a fixed processing-currency customer amount, the platform calls FX API `POST /rates/calculate` with `type=splitPayment`, processing-currency `sourceAmount`, settlement `targetCurrency`, and `exchangeSide=sell`; `targetAmount.value` gives the calculated settlement-currency user amount and `appliedExchangeRate` includes markup (raw lines 52–83). It then supplies customer processing amount/currency in Checkout `amount` and user settlement amount/currency in `splits.amount` via `/payments`, `/sessions`, or `/payments/{paymentPspReference}/captures` (raw lines 144–156). With multiple splits, the sum of settlement-currency split amounts must equal the calculated goods amount; mismatches or miscalculations book to the balance account named by `Remainder`, so that destination and actual accounting records matter (raw lines 154–156, 820). The pilot lists an online checkout integration, Checkout and Balance Platform FX API credentials, the FX `Read FX rates role`, standard plus transfer or transaction webhooks, account-holder capabilities, and Support enablement of FX API and required merchant-account currencies (raw lines 19–42). The page's split-guarantee statement does not remove the separate general split guide's invalid/closed-destination fallback, and an illustrative `Authorised` response is not final accounting proof (raw lines 799–820; [[source-adyen-docs-platforms-online-payments-split-transactions-split-payments-at-authorization]]).
