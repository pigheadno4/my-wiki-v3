Q2. What are the central capability, prerequisites and warnings? For ordinary Sessions, the guide adds no MoMo-specific `/sessions` fields or configuration (`raw/adyen/docs/payment-methods/momo-wallet/ios-drop-in/2026-09-15.md:38-46`); for Advanced, it adds no base `/payments` fields or configuration but requires redirect handling for `action.type: redirect` (`raw/adyen/docs/payment-methods/momo-wallet/ios-drop-in/2026-09-15.md:307-321`). Optional recurring requires `storePaymentMethod: true` and `shopperReference` on token-creation `/payments`; the token arrives through `recurring.token.created` after settlement, and later `/payments` uses stored method ID, same shopper, `ContAuth` and fixed/non-fixed recurring model (`raw/adyen/docs/payment-methods/momo-wallet/ios-drop-in/2026-09-15.md:57-85`, repeated `raw/adyen/docs/payment-methods/momo-wallet/ios-drop-in/2026-09-15.md:332-360`). Test uses MoMo's test app and credentials, while live use requires a live request (`raw/adyen/docs/payment-methods/momo-wallet/ios-drop-in/2026-09-15.md:288-297`). The Java sample uses `setRecurringDetailReference`, whereas prose/JSON use `storedPaymentMethodId` (`raw/adyen/docs/payment-methods/momo-wallet/ios-drop-in/2026-09-15.md:77`, `raw/adyen/docs/payment-methods/momo-wallet/ios-drop-in/2026-09-15.md:99-100`, `raw/adyen/docs/payment-methods/momo-wallet/ios-drop-in/2026-09-15.md:128-130`); preserve API-versus-SDK representation.
