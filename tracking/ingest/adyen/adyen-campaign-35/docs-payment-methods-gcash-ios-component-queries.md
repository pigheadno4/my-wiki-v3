## Q2 — What are the central capability, prerequisites and warnings?

Sessions requires an existing iOS Components integration, Checkout API v68+, redirect handling and GCash Customer Area setup; no extra GCash `/sessions` parameters or Component configuration are stated (raw lines 33–48). Advanced similarly requires the existing integration, redirect handling and Customer Area setup, with no extra GCash configuration or `/payments` parameters stated (raw lines 328–363). Both sections describe recurring payments: `/payments` token creation uses `storePaymentMethod: true` and a shopper reference of at least three characters; `recurring.token.created` arrives **when the payment has been settled**, and a server must receive token lifecycle webhooks (raw lines 76–95, 369–388). Subsequent token payments use stored ID, shopper reference, `ContAuth` and schedule-appropriate recurring model (raw lines 99–109, 392–402). A live Customer Area request is required before live GCash acceptance, while successful live-payment testing needs a registered real GCash mobile number (raw lines 310–318, 603–611).
