# api-explorer-balanceplatform-latest-delete-registereddevices-id — original Q1/Q2 answers

## Q1

The 2026-11-03 captured Balance Platform API reference shows `DELETE /registeredDevices/{id}` on the v2 TEST `/bcl/v2` server. Its purpose is deleting an SCA device from a specific payment instrument's registered-device list. The required path `id` is the SCA-device ID, while the required query `paymentInstrumentId` identifies the linked payment instrument; they are different resource identities. No request body, defaults, numeric limits, conditional fields or success response-body fields are shown. The caller must be authenticated and have permission according to the 401/403 entries, but this endpoint page specifies no credential role or LIVE server. The success entry is 204 with no body schema. ## Q2

A returned 204 reports success for the scoped registered-device deletion request. The page does not say when the device disappears from other associations, whether a global SCA device record is removed, or how future SCA/authentication behaves; it is not proof of card status, payment authorization, capture, booking or settlement. The route is distinct from the separately documented `/scaDevices/{deviceId}` operation. Listed failures are 400, 401, 403, 422 and 500; no 404, idempotency/retry guarantee, version-conflict contract, reversal, approval or asynchronous completion timing is specified. Its generic 422/500 examples describe payment-instrument operations and do not establish this endpoint's own error conditions. The displayed TEST base and 2026-11-03 snapshot establish neither live access nor account-specific eligibility or compliance.
