# api-explorer-legalentity-latest-patch-legalentities-id-termsofservice-termsofservicedocumentid — original query answers

## Q1

The 2026-11-03 Legal Entity Management API Explorer capture documents `PATCH /legalEntities/{id}/termsOfService/{termsofservicedocumentid}` for accepting a Terms document. Its listed server is TEST `https://kyc-test.adyen.com/lem/v4`. Required path strings are `termsofservicedocumentid` for the document and `id` for the legal entity: the owner individual for a sole proprietorship, the organization for an organization, or the individual for a legal representative of an individual. The body requires `acceptedBy`, the accepting user's individual legal-entity ID: authorized organizational signatory, sole-proprietor owner, or the individual/parent/guardian in the individual case. `ipAddress` is optional. The page names no request default, numeric input limit, idempotency key, credential role or query parameter. A 200 body lists optional acceptance `id`, `acceptedBy`, `ipAddress`, document `termsOfServiceDocumentId`, `language` (`en` or conditionally `fr`) and Terms `type`; the acceptance ID and document ID are different references. It states rate limits of 700 requests per five seconds in live, 200 per five seconds in test and five failures per ten seconds. ## Q2

A 200 says this Terms-acceptance request succeeded and may return an acceptance record; all listed response fields are optional in the schema, so the example's ID/type/language combination is not a universal response guarantee. This is acceptance of the specified document by the specified legal-entity signer, not evidence that a different document or revision was accepted, that legal-entity verification finished, or that a capability was allowed or activated. The reference lists 400 request, 401 authentication, 403 permission, 422 validation and 500 server errors, but no named credential role, idempotency or conflict rule. It does not describe document generation, later review, deletion/reversal or propagation timing. The optional generic error `pspReference` is described as a payment reference but does not indicate a payment outcome. The live rate limit appears without a live endpoint; the captured TEST `/lem/v4` server and `latest` URL do not establish current live availability, legal compliance, payment authorization, booking, settlement or bank receipt.
