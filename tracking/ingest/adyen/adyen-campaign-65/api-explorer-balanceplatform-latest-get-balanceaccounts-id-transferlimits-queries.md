# api-explorer-balanceplatform-latest-get-balanceaccounts-id-transferlimits — original query answers (attempt 1)

Q1: The 2026-11-03-captured Balance Platform API Explorer `latest` page documents `GET /balanceAccounts/{id}/transferLimits` to filter and view limits configured for a balance account. Its only listed server is TEST `https://balanceplatform-api-test.adyen.com/bcl/v2`, identifying the visible server version as v2. Required string path `id` is the balance-account ID. Optional query parameters filter by `status` (active, inactive, pendingSCA, scheduled), `transferType` (instant or all priorities) and `scope` (perTransaction or perDay); no query defaults, request body, pagination or list limit are specified. The page does not name a caller role. A 200 requires a `transferLimits` array; each entry requires `amount.currency` (three-character ISO code), `amount.value` (minor units), transfer-limit `id`, `limitStatus`, `scope`, `startsAt` and `transferType`. `endsAt`, `reference` and `scaInformation` are optional. `startsAt`/optional `endsAt` describe activation timing, and `scaInformation.status` is required within an included SCA object. Q2: A 200 and returned list establish readback of configured transfer-limit records under the supplied balance account and optional filters, not a changed limit, completed SCA, approved or executed transfer, booking, settlement or bank receipt. `limitStatus` distinguishes active, inactive, pendingSCA and scheduled; the separate SCA status can be notPerformed, pending or performed, and notPerformed may reflect an exemption. The example's active limits with `initialLimit` exemption and `notPerformed` SCA are illustrative only. This GET reference provides no idempotency key, mutation or deletion operation, propagation timing, approval event, effective-limit resolution across other configuration, or failure/reversal outcome for a transfer. The page documents 404 for a missing limit and 422 for request validation; it does not give a route-specific authentication or permissions error listing or state-conflict/retry contract. Its dated TEST v2 capture does not prove current live availability, account eligibility or compliance.
