# Original Q1/Q2 — api-explorer-legalentity-latest-patch-transferinstruments-id

## Q1

The 2026-11-03-captured Adyen Legal Entity Management API `/lem/v4` reference documents `PATCH /transferInstruments/{id}` to update a transfer instrument, with a listed TEST server `https://kyc-test.adyen.com/lem/v4`. It names no caller role or live server URL, although it states live and test rate limits. The required path `id` is the transfer-instrument ID. The request body marks `bankAccount`, owning `legalEntityId`, and `type=bankAccount` required; the listed `bankAccount` children are optional. The IBAN in the sample is an example, not a stated universal requirement. The optional `x-requested-verification-code` header uses `0_0001` to resolve suberrors and is TEST-only. Limits are 700 live or 200 test requests per 5 seconds, plus 5 failed requests per 10 seconds. The `200` response requires bank account, instrument ID, legal-entity ID and type, and can include `trustedSource`, supporting-entity `capabilities`, `documentDetails` and `problems`. The reference lists no query parameter, endpoint-specific idempotency key, or default. Evidence: [[source-adyen-api-explorer-legalentity-latest-patch-transferinstruments-id]], [captured API URL](https://docs.adyen.com/api-explorer/legalentity/latest/patch/transferInstruments/(id)), raw lines 5–105.

## Q2

A `200` establishes that this update request succeeded and returns a transfer-instrument representation; it does not alone establish that bank-account data passed verification, a capability was approved, or any payout was created or delivered. Optional `capabilities` distinguish supporting-entity `requested`, `allowed` and `verificationStatus` (`pending`, `invalid`, `valid`, `rejected`); the schema says an allowed supporting entity may be used even when the parent legal entity is not allowed because other supporting entities failed verification. Optional `problems` can carry capability verification errors. The optional TEST-only verification-code header is for resolving suberrors, not proof of general approval. `400`, `401`, `403`, `422`, and `500` error classes are listed; the page specifies no idempotency, reversal, propagation timing, or version/conflict behavior. The `latest` path and TEST server are snapshot evidence and not current live eligibility or proof of a transfer, booking, settlement, or bank receipt. Evidence: [[source-adyen-api-explorer-legalentity-latest-patch-transferinstruments-id]], [captured API URL](https://docs.adyen.com/api-explorer/legalentity/latest/patch/transferInstruments/(id)), raw lines 9–18, 28–43, 60–105, and 108–189.
