## Q1

The 2026-11-03 Legal Entity Management API v4 TEST `GET /transferInstruments/{id}` returns details of one transfer instrument from `https://kyc-test.adyen.com/lem/v4`. The required path string `id` names the transfer instrument, while response `legalEntityId` names its owner; the page names no particular caller or role and shows no query parameter or request body. The rate limits are 700 requests per five seconds live, 200 per five seconds test, and five failed requests per ten seconds. No default or idempotency key is listed. A `200` response requires `bankAccount`, instrument `id`, owner `legalEntityId`, and `type` (`bankAccount`). Within `bankAccount`, identification, account type, bank name, country code and `trustedSource` are optional. `capabilities`, `documentDetails`, and `problems` are optional; capability entries can include requested/allowed flags and verification status (`pending`, `invalid`, `valid`, `rejected`), while problems can include verification errors and remediating actions. The sample IBAN is illustrative. ## Q2

`200` establishes a successful read of a transfer-instrument resource and whatever verification data is returned, not completion of legal-entity or capability review. `trustedSource` denotes creation through instant bank verification; it is not a blanket payout permission. Supporting-entity `allowed` is distinct from its parent legal entity's status, and `verificationStatus` can be pending, invalid, valid or rejected. The page documents 400 request problem, 401 authentication required, 403 insufficient permissions, 422 validation error and 500 server failure, but no named role, idempotency rule, readback propagation timing, deletion/reversal path, or version/conflict behavior. Generic error `pspReference` wording is not payment proof. The TEST capture and `latest` URL do not prove live eligibility, compliant onboarding, an approved transfer instrument, payout initiation, booking, settlement, or bank receipt.
