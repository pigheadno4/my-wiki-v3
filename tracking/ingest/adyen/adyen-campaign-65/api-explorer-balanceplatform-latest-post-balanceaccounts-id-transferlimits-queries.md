# api-explorer-balanceplatform-latest-post-balanceaccounts-id-transferlimits — original query answers

## Q1

The 2026-11-03 Balance Platform API Explorer capture says `POST /balanceAccounts/{id}/transferLimits` creates a limit for the balance account identified by required path string `id`. It lists `https://balanceplatform-api-test.adyen.com/bcl/v2` as its test server; no live endpoint or named caller credential role appears. The optional header-table entry is `WWW-Authenticate` for SCA. The body requires `amount` with ISO currency and integer minor-unit value, `scope` (`perTransaction` or `perDay`) and `transferType` (`instant` or `all`). It optionally accepts `reference`, ISO-8601 `startsAt`/`endsAt`, and `scaInformation` with an exemption value or `scaOnApproval`. The latter defaults to `false` (initiate SCA immediately); `true` allows SCA during later approval of pending limits. A future start schedules a limit, and omitted end date means it remains active until override. The 200 response requires limit `id`, `amount`, `limitStatus`, `scope`, `startsAt`, and `transferType`; optional SCA information has a required `status` when present. No numeric maximum, idempotency key or count limit is specified. ## Q2

A 200 response says creation succeeded but its `limitStatus` can be `pendingSCA`, `scheduled`, `active` or `inactive`. The illustrated 200 result reports `pendingSCA` and SCA `pending`, so successful creation alone does not establish completed SCA or active enforcement. The SCA status enum also distinguishes `notPerformed` (failed authentication or exemption), `pending`, and `performed`. A 400 can mean invalid input or no registered SCA device; 401 requires resolving a provided SCA challenge; 422 is a request validation error. The page describes deferring SCA to approval but does not specify the approval endpoint's outcome or broader deletion, propagation, effective-limit precedence, reversal, or transfer lifecycle. Its exemption labels are request categories, not proof of regulatory qualification. No idempotency behavior or live server is given, and the `latest` URL cannot prove current version or eligibility. A configured limit does not establish any transfer booking, settlement or bank receipt.
