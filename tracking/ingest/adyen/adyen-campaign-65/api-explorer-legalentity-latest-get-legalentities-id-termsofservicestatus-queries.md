# api-explorer-legalentity-latest-get-legalentities-id-termsofservicestatus — original Q1/Q2 answers

## Q1

The 2026-11-03 Legal Entity Management API v4 reference shows `GET /legalEntities/{id}/termsOfServiceStatus` on the TEST `https://kyc-test.adyen.com/lem/v4` server. Its purpose is to return the Terms of Service types the addressed legal entity still needs to accept. Required path `id` is the owner individual's legal-entity ID for a sole proprietorship or the organization ID for an organization. No query, body, conditional input, default or idempotency parameter appears. The 200 schema has optional `termsOfServiceTypes`, an array of required acceptance types. An empty returned array means none needs acceptance; absence of the optional field is not defined as equivalent. The `adyenIssuing` sample is illustrative, not an exhaustive enum. Rate limits are 700 requests/5 seconds LIVE, 200 requests/5 seconds TEST, and five failed requests/10 seconds; no credential role or LIVE server URL is given. ## Q2

A 200 returns a status lookup of types still requiring acceptance. It does not itself record legal consent, prove a document was signed, trigger approval, establish completed verification, grant a capability, or show a payment or funds outcome. The page lists 400, 401, 403, 422 and 500 errors but gives no acceptance execution, asynchronous review/activation, propagation, deletion, reversal, retry/idempotency or version-conflict contract. Its generic error `pspReference` label concerns payments but does not change the operation's legal-entity lookup purpose. The only displayed base is TEST; stated LIVE rate limits, an illustrative `adyenIssuing` type and the dated `latest` snapshot do not prove current account-specific eligibility, compliance or accepted terms.
