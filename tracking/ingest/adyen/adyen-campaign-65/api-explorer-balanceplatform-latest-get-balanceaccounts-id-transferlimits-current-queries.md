The captured server is TEST `https://balanceplatform-api-test.adyen.com/bcl/v2`; `latest` is the URL segment and v2 is the server-path version. The required string path `id` is the balance-account identifier, distinct from each returned transfer-limit `id`. Two optional query filters are `transferType` (`instant` priority or `all` priorities) and `scope` (`perTransaction` or `perDay`). The page gives no caller-role name, request body, query defaults, pagination, list limit or GET idempotency rule. A 200 requires a `transferLimits` array. Each returned limit requires an `amount` object with ISO three-character currency and integer minor-unit value, its own limit `id`, `limitStatus`, `scope`, `startsAt` and `transferType`; `endsAt`, reference and `scaInformation` are optional, while `scaInformation.status` is required if that object is included. The maximum amount applies per transaction or per day according to `scope`. [Raw: lines 5–47]
