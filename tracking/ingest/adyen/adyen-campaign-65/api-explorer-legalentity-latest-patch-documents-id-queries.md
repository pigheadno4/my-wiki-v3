# Original query answers: PATCH /documents/{id}

## Q1

The 2026-11-03 capture describes Legal Entity Management API v4 TEST `PATCH /documents/{id}` to update the existing document selected by required string path `id`; the listed server is `https://kyc-test.adyen.com/lem/v4`. The request requires `description` and a document `type` whose allowed values depend on the legal-entity category; `bankStatement` is named for transfer-instrument documents. Singular `attachment` and plural `attachments` are optional parents, but each supplied object requires Base64 `content`; formats, filenames, page names and `pageType` are optional except that `driversLicense` and `identityCard` require front/back `pageType` and both sides in one API request. Photo IDs have a 15-page maximum. Optional `owner`, if supplied, requires nested `id` and `type`: `legalEntity` points to a legal-entity ID and `bankAccount` to a transfer-instrument ID, separate from the document path ID. Expiry date, file name, issuer country/state and number are optional. The optional `x-requested-verification-code` header uses `0_0001` for document suberrors in TEST only. The page states live 700 requests/five seconds, test 200/five seconds and failed requests five/ten seconds. A `200` body requires `description` and `type`, while response `id`, owner, attachments and other fields are optional. It states no idempotency key or version condition.
