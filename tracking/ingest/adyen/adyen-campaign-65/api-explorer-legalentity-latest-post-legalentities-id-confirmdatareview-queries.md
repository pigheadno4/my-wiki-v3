# api-explorer-legalentity-latest-post-legalentities-id-confirmdatareview — original Q1/Q2 answers

## Q1

The 2026-11-03 captured Legal Entity Management API v4 reference describes `POST /legalEntities/{id}/confirmDataReview` at the TEST `https://kyc-test.adyen.com/lem/v4` server. Its purpose is to tell Adyen that the platform's user reviewed and verified that the addressed legal entity's data is up to date. The required path `id` is that legal entity's unique ID; no request body, query parameter, conditional field, default or other resource reference is listed. The endpoint says 401 requires authentication and 403 reports insufficient permissions but specifies no credential role or user-authentication flow. Stated rate limits are 700 requests/5 seconds LIVE, 200 requests/5 seconds TEST, and five failed requests/10 seconds. A 200 response has optional `dataReviewedAt`, described as the confirmation date and introduced as when Adyen received the request. ## Q2

HTTP 200 establishes that the confirmation request succeeded; `dataReviewedAt`, when present, reports Adyen's receipt/confirmation timestamp. The response alone cannot establish that the platform user actually performed the review, that Adyen later accepted the data as valid, or that verification, capability approval, account activation, payment or funds movement occurred. The page lists 400, 401, 403, 422 and 500 errors; its generic error body's optional `pspReference` is labeled a payment reference but does not make this a payment endpoint. It states no idempotency, retry, reversal, asynchronous downstream review timing, deletion/propagation or version-conflict behavior. Although the text supplies LIVE rate limits, the only server URL shown is TEST; this snapshot does not prove current LIVE access, eligibility or compliance.
