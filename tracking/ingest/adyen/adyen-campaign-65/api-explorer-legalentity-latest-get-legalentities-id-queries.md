## Q1

The 2026-11-03 Legal Entity Management API v4 snapshot documents `GET /legalEntities/{id}` on TEST `https://kyc-test.adyen.com/lem/v4`. Required path `id` identifies the legal entity; no caller role, query, request body or conditional GET input is documented. The page states rate limits of 700 requests per 5 seconds for Live, 200 per 5 seconds for Test, and 5 failed requests per 10 seconds. A 200 response requires root `id`, can include optional `reference` (150-character maximum), entity-type branches, associations, documents, transfer instruments, problems, deadlines and keyed capabilities. Branch-specific required fields are response-schema descriptions, not GET inputs. The root `type` list omits `unincorporatedPartnership` despite a separately documented conditional branch. ## Q2

A 200 returns a snapshot of the legal entity and reported capability state. `requested` does not mean `allowed`; `verificationStatus` separately reports pending, invalid, valid or rejected, and transfer-instrument supporting-entity permission can differ from the parent entity. The example's requested-but-disallowed, pending capabilities are illustrative. Verification problems and deadlines may be returned, but readback does not create an entity, resolve review, approve a capability, activate an instrument or move funds. The page lists 400, 401, 403, 422 and 500 errors without specifying this GET's credential role, idempotency/update, reversal, approval timing, version/conflict behavior or payment outcome. The TEST snapshot and `latest` route do not establish current live eligibility.
