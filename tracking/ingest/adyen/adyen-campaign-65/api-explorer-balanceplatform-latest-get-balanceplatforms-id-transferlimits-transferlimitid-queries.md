# Original Q1/Q2 — api-explorer-balanceplatform-latest-get-balanceplatforms-id-transferlimits-transferlimitid

## Q1

The 2026-11-03-captured Adyen Balance Platform API `/bcl/v2` GET reference lists the TEST server `https://balanceplatform-api-test.adyen.com/bcl/v2` and retrieves one transfer limit under a balance platform. Both string path parameters are required: `id` is the balance-platform ID, and `transferLimitId` is the limit ID. The page names no specific caller role, query parameter, request body, idempotency key, or request default. The required `200` fields are `amount` with currency and integer minor-unit value, limit `id`, `limitStatus`, `scope`, `startsAt`, and `transferType`; optional fields are `endsAt`, `reference`, and `scaInformation`. The maximum amount is per transfer or per day according to `scope=perTransaction|perDay`; `transferType=instant|all` selects instant-priority or all transfers. The response supplies no actual transfer record. ## Q2

A `200` means this detail lookup succeeded and reports a limit configuration/state. `limitStatus` may be `active`, `inactive`, `pendingSCA`, or `scheduled`; `startsAt` can be future-dated and `endsAt` marks inactivity if provided. The raw says that with no end date, the limit stays active until overridden. Optional `scaInformation` has optional `exemption` and a required nested `status`; `notPerformed` can mean failed authentication **or exemption**, while `pending` and `performed` represent pending and successful SCA authentication. Thus an exemption or readback status must not be turned into a completed user challenge, actual enforcement, transfer approval, booking, settlement, or bank receipt. The endpoint is a GET, with `404` not-found and `422` validation errors listed; it does not document creation, approval, deletion, propagation timing, reversal, idempotency, version/conflict behavior, or an authentication/permission error contract. The `latest` path and listed TEST server are snapshot evidence, not current live availability or user eligibility.
