# api-explorer-balanceplatform-latest-delete-balanceplatforms-id-transferlimits-transferlimitid — original query answers

## Q1

The 2026-11-03 Balance Platform API Explorer capture documents `DELETE /balancePlatforms/{id}/transferLimits/{transferLimitId}` to delete a scheduled or pending **platform-level** transfer limit. It lists the Balance Platform API test base `https://balanceplatform-api-test.adyen.com/bcl/v2`. Required path strings are `id`, identifying the balance platform, and `transferLimitId`, identifying the transfer limit. The reference names no request body, query parameter, header, caller credential role, default, quantitative limit or idempotency key. Success is HTTP 204 with no response-body schema. It cannot be used to delete an active limit. ## Q2

A 204 establishes that the delete request succeeded for the identified pending or scheduled limit under this captured endpoint contract. It does not show deletion of an active limit, retroactive reversal of transfers, effective-limit precedence or propagation timing across accounts. The page lists 404 when a transfer limit could not be found and 422 for request validation, without mapping specific invalid states to either error. It documents no SCA/authentication challenge, idempotency behavior, approval or activation process, or replacement operation. This is a dated test-server snapshot; the `latest` URL does not prove a current live version, eligibility, or that any transfer was approved, booked, settled or received by a bank.
