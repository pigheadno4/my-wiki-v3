## Q1

The 2026-11-03 Balance Platform API v2 TEST `GET /balancePlatforms/{id}/transferLimits` filters and views limits configured for a balance platform, using `https://balanceplatform-api-test.adyen.com/bcl/v2`. The required path string `id` identifies the balance platform; the page does not name a particular caller or role. Optional query filters are `status` (`active`, `inactive`, `pendingSCA`, `scheduled`), `transferType` (`instant`, `all`), and `scope` (`perTransaction`, `perDay`). No request body, conditional input, default, query limit, pagination, or idempotency key is listed. The `200` body requires `transferLimits`; each returned object requires `amount` with ISO three-character `currency` and integer `value` in minor units, plus limit `id`, `limitStatus`, `scope`, `startsAt`, and `transferType`. `endsAt`, `reference`, and `scaInformation` are optional; `scaInformation.status` is required if that parent is present, while its `exemption` is optional. The API reference requires `transferLimits` and shows that key (API raw lines 29–35, 88–131), but the separate [[source-adyen-docs-business-accounts-use-transfer-limits-balance-platform|Business Accounts balance-platform guide]] shows `transfer` for the same GET route (guide raw lines 119–123, 154–197). These response shapes conflict; verify the actual contract before client parsing. ## Q2

The `200` response is a readback of configured transfer-limit records and their reported states, not creation, approval, deletion, or evidence that a transfer ran. `pendingSCA` awaits user SCA and `scheduled` denotes a future active date; `scaInformation.status: notPerformed` also covers an exemption, so it does not alone prove authentication failure. An `active` limit or `performed` SCA is not transfer authorization, booking, settlement, or bank receipt. The page lists 404 when one limit cannot be found and 422 validation failure, with no 401/403 contract, named role, idempotency rule, approval timing, reversal, or version/conflict behavior; absence of those details does not establish no authentication is needed. Its example limits do not prove actual or current platform capacity. The TEST snapshot and `latest` URL do not establish live availability, account eligibility, or compliance.
