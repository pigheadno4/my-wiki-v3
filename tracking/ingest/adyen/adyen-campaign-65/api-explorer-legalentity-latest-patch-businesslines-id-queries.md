# api-explorer-legalentity-latest-patch-businesslines-id — original Q1/Q2 answers

## Q1

The 2026-11-03 Legal Entity Management API v4 reference describes `PATCH /businessLines/{id}` on the TEST `https://kyc-test.adyen.com/lem/v4` server to update the business line identified by required path `id`; the 200 response separately identifies its owning `legalEntityId`. The request table has optional top-level `industryCode`, `salesChannels`, `sourceOfFunds`, `webData` and `webDataExemption`, with no request `service` field or stated whole-body rule. Sales channels are conditionally required with payment processing; source of funds is required for banking/issuing. Within that object, `adyenProcessedFunds` is required and false requires `type`; amount, financiers, dates, originator legal-entity ID and other fields have type-specific conditions. The 200 response requires `id`, `industryCode`, `legalEntityId` and `service`, with optional `problems` and other data. Rate limits are 700 requests/5 seconds LIVE, 200 requests/5 seconds TEST, and five failed requests/10 seconds. The table requires `amount` for business source of funds, but the sample banking/business response omits it, so the sample cannot waive the condition. No credential role is specified here. ## Q2

HTTP 200 means the business-line update request succeeded and returns a resource representation with possible verification `problems`; it does not establish that Adyen completed review, granted capabilities, activated a product or executed a payment or transfer. The captured reference states 400 request, 401 authentication, 403 permission, 422 validation and 500 server failures, but no idempotency, omitted-field PATCH semantics, deletion/propagation timing, reversal, asynchronous verification outcome or version-conflict behavior. The request/response tables' business-type `sourceOfFunds.amount` requirement conflicts with its banking/business 200 sample, and the `originatorLegalEntityId` row's example prose uses a different name; neither example is a safe basis for relaxing the table. The generic error `pspReference` label refers to payments but does not make this an actual payment outcome. The only displayed base is TEST; stated LIVE rate limits and the `latest` snapshot do not prove current live access, eligibility or compliance.
