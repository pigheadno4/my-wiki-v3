# Retrieval probes — docs-standard-integration-hosted-checkout

Q1. How does Standard Hosted Checkout start, and what setup/version gates does this guide state?
A1. It is the Standard online-payment redirect to an Adyen-hosted page (raw lines 15–19). The merchant payment server creates a session and the webhook server receives outcome events; the guide specifies Checkout API v72+ and a server-side library released March 30, 2026 or later (raw lines 21–54). Theme creation requires a named Customer Area role; the documented session fields and return-URL PII restriction are at raw lines 287–328. Q2. Can a return-page `completed` result be polled or treated as final order/settlement proof?
A2. No. The merchant server retrieves `sessionId`/`sessionResult` after redirect (raw lines 642–665); the result can be completed, paymentPending or expired, and that response status does not change (raw lines 811–848). The guide directs the order system to the AUTHORISATION webhook keyed by merchantReference and success (raw lines 850–890); repeated payment attempts can emit multiple webhooks with the same sessionId (raw lines 953–959). These events do not themselves prove capture or settlement. The request/response/webhook examples use differing amounts and IDs, so they are not one transaction trace (raw lines 330–353, 618–631, 856–921).
