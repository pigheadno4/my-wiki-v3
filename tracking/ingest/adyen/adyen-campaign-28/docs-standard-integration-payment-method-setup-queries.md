# Query proposal — docs-standard-integration-payment-method-setup

Q1. Which Standard integration payment methods need extra setup, and what are representative prerequisites?
Answer: The page says most methods need no additional setup but names exceptions (raw lines 19-49). Apple Pay needs IP allowance and either Adyen's or the merchant's certificate, with HTTPS/domain/merchant-identity steps depending on path (lines 50-143). PayPal needs developer/sandbox accounts, Customer Area addition and an activation permission link (lines 195-202); Bizum needs a local acquirer agreement and identifiers (lines 152-158), while named methods route through Support (lines 160-233). Q2. Does the listed method family or setup step prove availability for a particular store/session or successful payment?
Answer: No. The page is a dated setup checklist (raw lines 15-49), with merchant-account/shop-website conditions for one Apple Pay path (lines 69-77), method-specific sandbox activation for PayPal (lines 195-202), and pricing/contract gates for others (lines 212-225). It does not specify store-scoped enablement, `/sessions` filtering or an authorization/capture/settlement outcome. The MobilePay section says **payouts** (lines 176-181), so that wording cannot be broadened to checkout acceptance.
