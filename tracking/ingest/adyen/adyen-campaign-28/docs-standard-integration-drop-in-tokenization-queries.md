Q1. How does Standard Drop-in create and reuse a shopper payment token, and what gates apply?
A1. This is the bounded Standard Sessions/Drop-in path, requiring Checkout webservice and Merchant Recurring roles, a recurring-token lifecycle webhook and a recurring-capable payment method (raw lines 28–38). Ask shopper consent before storage; `askForConsent` displays a checkbox while `enabled` hides it, and zero-value authorization is method-limited (raw lines 105–126). A successful authorization produces the token via `recurring.token.created`; store `storedPaymentMethodId` with `shopperReference` (raw lines 154–178). Returning-shoppper one-click is a new CardOnFile session and separate payment-outcome webhook (raw lines 180–220).
