## Q1 — What does this Payout Service-path Balance Platform Accounting Report cover, and how is it generated?

It is a daily report of changes across all balance-platform accounts, including liable and user accounts, with scheduled or manual generation for a day; a manual interactive version adds date-range and account/event filters (raw lines 15–29). The guide routes processed payments, internal transfers, payouts, fees and invoice deductions to report reconciliation, while recommending API responses/webhooks for the latest transaction status (31–40). It covers a CET midnight-to-midnight Booking Date window and omits accounts with no transactions (132–146). ## Q2 — What separates pending transfers, booked transactions and external bank receipt?

A Transfer Id links pending initiated/authorized/refused events without booked money movement; refunds get a new transfer flow/ID (raw lines 50–54). A Transaction Id identifies a booked balance-account debit or credit (line 55), with bank-category booked/returned/rejected rows distinguished at lines 71–79. Booking Date and Value Date have different meanings, and value date can be on or before booking date (116–126); the selected-day report is CET scoped (136). These report rows are balance-platform evidence, not independent proof that an external beneficiary bank received a payout.
