Q1. What can a Standard Web Drop-in merchant configure here, and what is the ordering choice?
A. This page covers checkout order and localization plus text direction/CSS (raw lines 15–22, 50–52, 157–169). Dynamic payment-method ordering is enabled by default and can prioritize cost or conversion by country/region in Customer Area; manual country-specific configuration disables dynamic ordering and is not recommended (lines 24–48). It documents a UI configuration choice, not merchant payment-method enablement. Q2. Which localization and styling limits or example conflict matter?
A. Global `locale` wins; otherwise Drop-in uses session `shopperLocale`, with `en-US` when unmatched. `translations` and a matching locale customize or create text, with missing custom-locale keys falling back to en-US (raw lines 54–155). RTL needs the parent HTML `dir` attribute independent of locale, and CSS overrides cover elements outside an iframe only (lines 157–188). The sample defines `globalConfiguration` but invokes `AdyenCheckout(configuration)` (lines 147–155), so that snippet is not copy-ready without resolution.
