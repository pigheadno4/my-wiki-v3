Q1. What is this hosted-MPI procedure and what scope gate applies? It is the historical Classic SOAP `/authorise` custom 3DS1 procedure, followed conditionally by `/authorise3d`; Adyen says new Classic integrations are no longer accepted and points to migration (raw lines 14–26). Initial inputs include a constrained `returnUrl`, shopper IP and browser headers (lines 27–37). Q2. Does `RedirectShopper` mean authorization, and how is the payment completed? No. Initial `Refused` is a normal refused response; `RedirectShopper` supplies issuer URL, `md` and MPI-prefixed fields (raw lines 131–143). The merchant posts de-prefixed fields to the issuer, retains `md`, then after the issuer POST return calls `/authorise3d` using the same merchant account and required return data (lines 145–152, 219–234). The displayed `Authorised` SOAP payload is illustrative only (lines 281–318); this legacy snapshot does not prove current support or any real outcome.
