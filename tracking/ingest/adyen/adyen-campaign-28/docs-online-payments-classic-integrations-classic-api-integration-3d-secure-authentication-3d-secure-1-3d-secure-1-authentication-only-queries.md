# Q1 — What is this historical integration for and what is required?

It is a Classic Payment API 3DS1 authentication-only fallback, using `/authorise` and then `/authorise3d` with `authenticationData.authenticationOnly: true`, an issuer redirect, and returned `MD`/`PaRes` (pinned raw lines 25–45, 85–121). The guide calls for an Adyen test account, API key and Classic 3DS1 guide, but says new Classic integrations are no longer accepted and directs Checkout API migration (lines 19–39). # Q2 — Does AuthenticationFinished authorize payment, and are the examples copy-ready?

No. `AuthenticationFinished` marks a finished authentication process, and `threeDAuthenticatedResponse: Y` marks successful authentication in the guide; authorization with Adyen is a separate optional server-side `/authorise3d` branch using `authenticationOnly: false` (pinned raw lines 342–377). Another PSP/acquirer can use the authentication data for its own authorization (lines 25–27). The initial curl JSON lacks a colon after `authenticationData`, and several SDK snippets omit the prose-required true flag, so do not copy them as verified authentication-only requests (lines 60, 115–121, 145–340).
