# C23 query checks — docs-classic-platforms-fund-transfer

Q1. What money movement does this Classic guide cover, and what must be set up?

It covers a Classic Adyen for Platforms **account-to-account** transfer: `sourceAccountCode` is debited and `destinationAccountCode` credited, through POST `/transferFunds` or Customer Area; a previous transfer can be reversed fully or partly via POST `/refundFundsTransfer` (pinned raw lines 19–28, 38–48, 111–121). Adyen Support must enable the feature and preconfigure reason `transferCode` values; configure `TRANSFER_FUNDS` and `REFUND_FUNDS_TRANSFER` webhooks because processing is asynchronous (30–36). The transfer source account holder must be Active/payout-enabled; destination Active/processing-enabled. Customer Area requires its fund-transfer role and a positive source-account balance (44–47, 83–103). This is Classic, not the newer Balance Platform model. Q2. Which response, status and reversal boundaries matter?

An API `resultCode: Received` with `pspReference` acknowledges receipt; `TRANSFER_FUNDS` gives the result, and a successful transfer appears as `FundTransfer` in Marketplace Payment Accounting Report (raw 68–81). Customer Area Transactions and the webhook give transfer status (105–109). A reversal uses the original transfer `pspReference` as `originalReference` plus full/partial amount and is expressly allowed regardless of account-holder status, even no longer Active (111–121). Its initial `Received` response is also only acknowledgement; `REFUND_FUNDS_TRANSFER` reports the result and successful reversal has `FundTransferReversed` journal entry (139–151). These example TEST responses establish no completed transfer, external payout or bank receipt.
