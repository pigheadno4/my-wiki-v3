# C23 Classic Platforms Hosted Onboarding Page retrieval checks

## Q1 — What must a Classic platform do to start and complete the hosted onboarding flow?

Have Adyen Support enable HOP and set a default return URL, then choose upfront or staggered information collection (raw lines 47–57). Create the account holder, keep its `accountHolderCode`, request a one-time URL with `/getOnboardingUrl` when they start, and redirect within 15 seconds; the resulting session lasts 30 minutes (raw lines 31–41, 59–69, 87–105). Track account updates and verification results through `ACCOUNT_HOLDER_UPDATED` and `ACCOUNT_HOLDER_VERIFICATION` respectively (raw lines 113–122). ## Q2 — What expires or fails, and what does a redirect or sample response fail to prove?

The URL is single-use and must be used within 15 seconds; a late redirect or a reload after the session starts returns HTTP 401, and the platform must request a fresh URL. The session lasts 30 minutes; an incomplete or expired session can resume with a new URL because information is saved per section (raw lines 87–90, 103–116). The prose spells the response field `redirectURL` but the JSON example has `redirectUrl`; verify the actual API key before parsing (raw lines 87–100). Separately, the HOP request prose and example use `returnUrl` (HOP raw lines 69, 81), while its customization companion says `returnURL` (customization raw line 113); verify that request-field spelling before sending it. A URL response, return redirect, sample `pspReference`, or immediate payment processing after holder creation does not prove verification approval or payout completion; results come by verification webhook (raw lines 59–63, 87–100, 114–122).
