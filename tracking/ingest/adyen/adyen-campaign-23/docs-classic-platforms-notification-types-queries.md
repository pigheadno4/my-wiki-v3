# C23 query check: Classic notification types

Q1. What is this catalog for, and what setup does it assume? The 2026-09-15 snapshot is for Classic Adyen for Platforms and points new implementations elsewhere (raw line 19). Adyen sends event-specific notifications to endpoints the platform specifies when configuring notifications, and message fields vary by event (raw lines 21–23). The table maps event names to purposes across account holders, funds, payouts and reports (raw lines 25–45); the separate [[source-adyen-docs-classic-platforms-configure-notifications]] gives configuration and acceptance detail. Which event labels can mislead an outcome check? `ACCOUNT_HOLDER_CREATED` can mean creation or an error during creation (raw line 30). `ACCOUNT_HOLDER_PAYOUT` gives `Initiated` on process start or `Failed` on error, so Initiated is not bank credit (raw line 31). `TRANSFER_FUNDS`, `REFUND_FUNDS_TRANSFER` and `SCHEDULED_REFUNDS` are described as request-triggered, not completion proof (raw lines 42, 44–45). `COMPENSATE_NEGATIVE_BALANCE` conditionally describes a month-old negative balance being covered from the liable platform account at an end-of-month check (raw line 39), not a particular account's observed debit.
