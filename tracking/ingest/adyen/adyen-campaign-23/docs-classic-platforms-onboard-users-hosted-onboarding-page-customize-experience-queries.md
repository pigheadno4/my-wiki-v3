# C23 query checks — docs-classic-platforms-onboard-users-hosted-onboarding-page-customize-experience

Q1. What can this Classic HOP page customize, and what baseline flow does it assume?

It describes optional `/getOnboardingUrl` controls for the Classic Hosted Onboarding Page: `collectInformation` selects applicable verification checks, `showPages` controls welcome/summary pages, `shopperLocale` sets a language, `editMode` changes verified-data editing, `platformName` changes the welcome name, and a return parameter overrides the post-completion/timeout redirect (pinned raw 19–34, 36–62, 64–114). HOP otherwise collects all checks applicable to the legal-entity type (38–40). The companion Classic HOP guide owns platform enablement, one-time URL/session timing and later verification webhooks; this customization page does not itself establish verification or payout approval. Q2. What defaults, edit effects and source conflict matter?

The welcome page is hidden by default (raw 62), browser language is used by default with `en-US` fallback, and unsupported `shopperLocale` falls back to browser language (66–73). Already verified data cannot be edited by default; `editMode` allows editing, but is not proof that updated data passed verification (98–102). Completion or timeout redirects to the platform default URL unless overridden; this guide says `returnURL` object and a 500-character maximum (109–114), whereas the companion Classic HOP raw says optional `returnUrl` at line 69. Confirm the field spelling against the API contract; neither redirect nor a generated page proves approval. Keep Classic distinct from newer Platforms hosted onboarding (19).
