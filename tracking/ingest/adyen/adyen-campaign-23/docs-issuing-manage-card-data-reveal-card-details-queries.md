# C23 query check: reveal Issuing card details

Q1. What is the purpose and prerequisite for this reveal flow? The page covers displaying an Adyen-issued card's PAN, CVC and expiry to its cardholder in an app or website (raw lines 17–25). It requires Configuration API credentials with the **Bank Issuing PaymentInstrument Reveal Webservice** role (raw lines 41–46). GET `/publicKey` requests `purpose=panReveal`; a 256-bit AES key is encrypted with Adyen's RSA public key to make the session key sent with the card's `paymentInstrumentId` to POST `/paymentInstruments/reveal` (raw lines 48–54, 230–252). Q2. Where does sensitive plaintext appear, and what example conflict matters? The API returns `encryptedData`; the guide passes it to the client and decrypts it with the AES key in CBC mode with PKCS 5 padding before rendering PAN/CVC/expiry (raw lines 453–491). The client therefore handles plaintext after decryption; the page is not evidence of any implementation's compliance or that a specific user saw the data. The GET curl/prose specify `purpose=panReveal`, but several SDK snippets show placeholder `purpose: string` values (raw lines 54, 61, 98, 124, 173, 193). Use the stated purpose rather than treating placeholders as operational values.
