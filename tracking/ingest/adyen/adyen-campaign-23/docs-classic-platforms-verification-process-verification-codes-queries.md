# C23 query checks — docs-classic-platforms-verification-process-verification-codes

Q1. What does this catalog cover, and how does a Classic integration encounter it?

It is a 2019-modified, 2026-09-15-captured **Classic Adyen for Platforms** account-holder verification-error catalog for **version 5 and later**; v4 and earlier have a separate catalog, and new implementations are routed to the newer integration guide (pinned raw lines 15–25). Adyen delivers codes and descriptions through Classic notification webhooks or API responses (21). The categories are identity, document, bank-account and company verification (27–29, 40–42, 77–79, 112–114). The page is a failure interpretation reference, not a current product-eligibility or onboarding-approval proof. Q2. What handling, retry and funds boundaries matter?

Adyen says these descriptions are for the platform and should not be shared with account holders; communicate general failure and request details re-upload instead (raw 23). Codes `1304`, `1107`, `3110`, and `2102` explicitly say max retries exceeded/do not retry (36, 52, 90, 119). Code `8000` says a technical issue has an already scheduled retry, without authorizing the platform to initiate another (96). Manual-review codes include `1320`, `1120`, `3120`, and `2120` (37, 63, 95, 120). Bank code `3114` identifies an institution ineligible for Platforms payouts; it does not prove any other account or payout outcome (94). Keep these Classic v5+ codes distinct from modern Platforms verification (19,25).
