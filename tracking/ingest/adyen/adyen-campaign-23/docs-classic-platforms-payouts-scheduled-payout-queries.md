Q1. What is the Classic Platforms default scheduled-payout behavior and how is one account's schedule changed?
Answer: The page says the default is DAILY to account holders with positive balances, with available funds paid out; newer Classic integrations may use country-optimized daily timing, while others remain at 00:00 CET unless enabled (raw lines 21–40). A specific account uses Classic Account API POST /updateAccount with payoutSchedule.schedule (raw lines 42–59). Q2. What does HOLD do, and does HTTP 200/202 or SAME_DAY prove a payout arrived?
Answer: HOLD stops Adyen scheduled payouts for that account, requires a reason, and means payouts must be manually triggered (raw line 59). For schedule updates, HTTP 200 or queued HTTP 202 still needs ACCOUNT_UPDATED confirmation of the resource update (raw lines 90–93). SAME_DAY is a conditional faster processing option in AU/UK/US, subject to express-method availability and bank cutoff; update response also awaits ACCOUNT_UPDATED (raw lines 95–125). None proves a payout was sent or received by a bank.
