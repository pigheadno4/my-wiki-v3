Q1. What does the Classic Platforms guide require before combining reports for full reconciliation?
Answer: Understand the payment lifecycle, Classic account structure/funds flow, relevant report types and fees (raw lines 21–27); configure time zones and optional columns according to the use case (raw lines 29–50); obtain reports manually or automatically (raw lines 52–54). Combine report entries by Psp Reference ↔ Payment Psp Reference, optionally Merchant Reference ↔ Payment Merchant Reference (raw lines 56–67). Q2. What can make a report join misleading, and do illustrative rows or report setup prove live financial outcomes?
Answer: Reports must use the same reporting period and time zone; mismatch is a common reconciliation failure (raw lines 69–74). Merchant reference is not required by the API to be unique, so it is not a guaranteed unique join key (raw line 65). The common use-case examples show selected rows/columns, so the guide recommends testing with complete reports before live reconciliation (raw lines 76–83). This workflow does not itself prove an individual settlement or bank receipt.
