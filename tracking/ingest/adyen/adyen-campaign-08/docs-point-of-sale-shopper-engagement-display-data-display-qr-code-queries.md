# Fixed retrieval checks: QR code display

1. **Q:** What payload does Adyen's terminal QR-display request use, and is it a QR wallet payment or Base64 receipt XML? **A:** It is a nonfinancial Terminal API Device/Display request. A `DisplayOutput` array item uses `CustomerDisplay`, `InfoQualify=Display`, `OutputFormat=BarCode`, `OutputBarcode.BarcodeType=QRCode` and `BarcodeValue`. A URL alone can be plain text; richer content is URL-encoded. Optional Text-format array items form a header, then footer. This is different from Base64 XML virtual receipts and gives no wallet authorization, currency or expiry rule, shopper-scan proof or consent. 2. **Q:** How long does the QR stay visible, and how should the POS read success when QR, header and footer were requested? **A:** `MinimumDisplayTime` sets the stated QR-screen duration; without a timeout the page says it remains until another request, such as payment or standby display, replaces it. `ResponseRequiredFlag` defaults to true for the QR and optional text items. The `DisplayResponse.OutputResult` array tracks `DisplayOutput` by position: in the sample, indices 0, 1 and 2 correspond to QR, header and footer, each with `Response.Result=Success`. Check the relevant item; showing content is not evidence it was scanned, opened, enrolled or paid.
