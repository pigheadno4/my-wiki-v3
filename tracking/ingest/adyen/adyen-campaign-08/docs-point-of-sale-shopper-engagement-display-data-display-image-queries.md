# Fixed retrieval checks: image display

1. **Q:** How does a POS send an image to an Adyen terminal display, and what file or device constraints does this page establish? **A:** The guide says to Base64-encode a PNG, JPEG, GIF or BMP file and place the resulting string in the one-item `DisplayRequest.DisplayOutput` array under `OutputContent.OutputText[0].Text`, with `OutputFormat=MessageRef` and `PredefinedContent.ReferenceID=Image`. The item targets `CustomerDisplay`/`InfoQualify=Display`; the header is Device/Display. The sample uses a V400m ID and a shortened Base64 string, but gives no supported-model list, Data URI prefix, resolution, dimensions or payload-size rule. 2. **Q:** When does the image leave the screen, and does `Success` prove payment or a valid receipt? **A:** `MinimumDisplayTime` is described as the displayed seconds; with no timeout, the image stays until another request such as payment, another image or standby replaces it. A decoding error prevents display. In the shown one-item response, `DisplayResponse.OutputResult[0].Response.Result=Success` is success of that display item only. It does not prove a shopper saw or accepted the message, a payment occurred, a receipt was printed, or legal/tax content is correct.
