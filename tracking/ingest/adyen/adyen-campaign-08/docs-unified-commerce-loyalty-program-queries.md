# C08 shopper loyalty overview — fixed query answers

1. **Who stores the loyalty profile and decides the reward when payment-linked loyalty uses Adyen response identifiers?** The 2026-09-15 overview says the merchant needs its own backend customer-profile system containing card/shopper identifiers and relevant data such as purchase history. The merchant uses identifiers returned in Adyen API responses to look up the shopper in its loyalty program and decides the discount or reward. It presents this and product recommendations as examples; it does not show automatic Adyen profile creation, reward application or a successful payment. Evidence: `raw/adyen/docs/unified-commerce/loyalty-program/2026-09-15.md`, `# Shopper loyalty` lines 19–25 and `## Requirements` lines 27–31; proposed `[[source-adyen-docs-unified-commerce-loyalty-program]]`.

2. **Does a card alias identify a person across cards, and what permission does the overview call for before storing data?** The page says a card alias recognizes the shopper's **card**; merchant-created identifiers can be returned in API responses and associated with an individual through the merchant's profile system. It does not define a verified civil identity or automatic cross-card match. Before storing customer or payment data, the guide advises considering regional privacy rules, asking for **explicit permission**, and explaining intended use. The linked Data Protection API is described for data stored with Adyen, not as proof that the merchant's CRM data was deleted. Profile creation and online/in-person recognition details are delegated to the two linked next-step guides. Evidence: same raw, `# Shopper loyalty` line 25, `## Data privacy` lines 33–40 and `## Next steps` lines 42–54; proposed `[[source-adyen-docs-unified-commerce-loyalty-program]]`.
