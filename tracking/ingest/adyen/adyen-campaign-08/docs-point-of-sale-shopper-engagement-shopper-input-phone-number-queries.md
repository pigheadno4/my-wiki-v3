# C08 POS phone-number input — fixed retrieval checks

1. **Q: What does a successful GetPhoneNumber input response establish about the phone number?**
   **A:** The Terminal API `Device` / `Input` request shows a `GetPhoneNumber` prompt, accepts `DigitString`, and returns the entered `InputResult.Input.DigitInput`. The country code is prefilled from terminal location but can be changed. The guide explicitly says the input is not format-validated and directs the merchant to validate it in its own system. A `Success` input response therefore does not verify phone ownership, identity, consent, reachability or a payment. 2. **Q: What do placeholder, masking, timeout, Cancel and a concurrent payment request do in this guide?**
   **A:** `DefaultInputString` is a placeholder for the expected format; `MaskCharactersFlag` appears in the JSON example to mask input, while the parameter table misspells its name. `MaxInputTime` is an integer number of seconds, with 40 only in the example. Timeout returns `Failure` / `Cancel` with a screen-timeout message; pressing Cancel returns `Failure` / `Cancel` and empty `DigitInput`. A payment request overrides pending input and returns `Failure` / `Busy` for the input request. Evidence: `raw/adyen/docs/point-of-sale/shopper-engagement/shopper-input/phone-number/2026-09-15.md:29-36,87-100,125-133,205-211`; canonical URL: https://docs.adyen.com/point-of-sale/shopper-engagement/shopper-input/phone-number. These input outcomes do not state whether the payment succeeded.
