# C08 standby display — fixed retrieval checks

1. **Q: How does the pinned guide recommend making a terminal show its standby screen, and what does that screen contain?**
   **A:** The guide recommends a Terminal API Device/Display request with one CustomerDisplay `DisplayOutput`, `OutputFormat: MessageRef`, and `PredefinedContent.ReferenceID: Idle`. It says this works regardless of terminal model. The standby screen shows the merchant's configured branded logo as it normally does when no other process is running. Evidence: `raw/adyen/docs/point-of-sale/shopper-engagement/display-data/idle-display/2026-09-15.md:15-23,29-53`; canonical URL: https://docs.adyen.com/point-of-sale/shopper-engagement/display-data/idle-display. This dated guide does not prove a particular account's logo setup or current terminal eligibility.

2. **Q: What is different about the XHTML standby route, and what does a Success result prove?**
   **A:** The alternative uses `OutputFormat: XHTML` and an XML string encoded as Base64 in `OutputXHTML`; the guide limits it to M400, P400 Plus and V400m terminals that accept XHTML. The documented success check is `DisplayResponse.OutputResult.Response.Result: Success`, a display-request result. The page does not specify how long the standby screen remains, whether later terminal operations preempt it, or a financial outcome.
