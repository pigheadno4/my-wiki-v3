# C08 shopper-input overview — fixed retrieval checks

1. **Q: What input types does Adyen's POS shopper-input overview route to, and which distinctions does it itself state?**
   **A:** It routes to confirmation, signature, single-answer menu, multiple-answer menu, digit, amount, phone number, rating and text. The page distinguishes one versus multiple choices, digit as whole-number entry, amount as currency display with two decimals, phone number as a location-prefilled but editable country code, and rating as 0–10. It says predefined terminal display elements combine with merchant text and users respond through a keypad or on-screen controls. Those are the overview's descriptions; child guides own request fields and behavior. Evidence: `raw/adyen/docs/point-of-sale/shopper-engagement/shopper-input/2026-09-15.md:31-45,47-101`; canonical URL: https://docs.adyen.com/point-of-sale/shopper-engagement/shopper-input.

2. **Q: Does this overview say who processes collected input or prove payment, consent, timeout and cancellation behavior?**
   **A:** It says the communication flow is between the POS app and terminal, without the Adyen backend, and the merchant processes collected input using its own business logic. Terminal API integration is the stated requirement. It links to a cancel-in-progress guide and a session guide for a waiting screen, but does not specify response codes, timeouts, session duration, legal consent validity or payment outcomes. The overview gives no supported terminal-model table or Device-versus-Service message class; those details require operation-specific evidence.
