# C08 bespoke terminal interaction — fixed query answers

1. **What does the merchant need to collect a shopper response on an Adyen terminal, and does Adyen store or process it for the merchant?** The captured page requires a Terminal API integration using **cloud or local** communications and merchant **backend logic** for Input responses. It describes confirmation, signature, menu, digit, amount, phone, rating and text input. The page states that this interaction is between the POS app and terminal and that the merchant processes the collected input with its own business logic; it does not describe Adyen backend processing of that input. Before storing customer/payment data, the page advises explicit customer permission and intended-use disclosure. A prompt alone does not prove a saved profile, valid consent record or a payment. Evidence: `raw/adyen/docs/unified-commerce/terminal-interaction/2026-09-15.md`, `## Requirements` lines 24–30, `### Data privacy` lines 32–39 and `## Collect information` lines 41–59; proposed `[[source-adyen-docs-unified-commerce-terminal-interaction]]`.

2. **Is the guide's virtual receipt proof that a payment completed, and what can the Display request show?** No. The virtual receipt is an **overview of the purchase before payment**. The guide also gives image and URL QR-code displays outside a payment flow. It does not show a payment result, a final paid receipt, a QR scan or Checkout API action. Exact display request fields and device behavior are delegated to linked Display guides. Evidence: same raw, `## Show information` lines 73–91; proposed `[[source-adyen-docs-unified-commerce-terminal-interaction]]`.
