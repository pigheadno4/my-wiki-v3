# C08 print data on terminal — fixed query answers

1. **Can a POS print a QR code and bill text together, and does that mean payment occurred?** The guide calls for two consecutive Terminal API Device/Print requests, one for text and one for the QR code; it says there is no tear-off prompt after a print request, so they can form one slip. Printing is outside the payment flow. The sample `PrintResponse.Result: Success` concerns printing, not an authorized or settled payment. Evidence: `raw/adyen/docs/point-of-sale/shopper-engagement/print-data/2026-09-15.md`, opening lines 15–28, `## Print text` lines 40–76 and `## Print a QR code` lines 315–363; proposed source `[[source-adyen-docs-point-of-sale-shopper-engagement-print-data]]`.

2. **What hardware and encoding does image printing require, and how are printer faults reported?** The dated guide limits the feature to terminals with built-in printers. To print a PNG, Base64-encode the image, embed it in the supplied XML `<img>` template with the required space after `base64,`, then Base64-encode the whole XML into `OutputXHTML` with `OutputFormat: XHTML`. It states a 256000-byte image limit and recommends 1-bit grayscale up to 384 pixels wide. A printer failure returns `PrintResponse` with `Result: Failure`, `ErrorCondition: DeviceOut` and a descriptive `AdditionalResponse`; the example includes no paper. Evidence: `raw/adyen/docs/point-of-sale/shopper-engagement/print-data/2026-09-15.md`, `## Requirements` lines 30–38, `## Print an image` lines 458–500 and `## Handle print errors` lines 559–605; proposed source `[[source-adyen-docs-point-of-sale-shopper-engagement-print-data]]`.
