# Fixed retrieval checks: GetRating input

1. **Q:** How does a POS ask for a 0–10 terminal rating, and can it trust the returned `DigitInput` as a valid score? **A:** The guide uses a Terminal API `InputRequest` with a Device/Input header, `DisplayOutput` containing `PredefinedContent.ReferenceID=GetRating` and merchant text, plus `InputData` targeting `CustomerInput` with `InputCommand=DigitString` and `MaxInputTime` in seconds. An input response can carry `InputResult.Input.DigitInput` such as string `"9"`. The page explicitly says input is not validated against a format and tells the merchant to validate it; its sample score labels cover only 0–9 despite the stated 0–10 purpose. A successful InputResult is not payment success or consent. 2. **Q:** How should the POS distinguish timeout, a new payment request and terminal Cancel while GetRating waits? **A:** The prompt ends on input, the configured maximum time, terminal Cancel, a cancel-input request or another POS request. Timeout returns `InputResult.Response` Failure with `ErrorCondition=Cancel` and `message=Screen%20timeout`. A new payment request overrides the input prompt and yields Failure/Busy with a higher-priority-request message; the payment must be evaluated separately. Terminal Cancel gives an empty `DigitInput` plus Failure/Cancel, which is not a zero rating. The guide does not describe an automatic survey skip or payment cancellation.
