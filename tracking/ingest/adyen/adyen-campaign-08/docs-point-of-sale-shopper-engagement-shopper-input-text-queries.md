# C08 GetText terminal input — fixed retrieval checks

1. **Q: How does Adyen's terminal GetText guide collect an email-like text value, and does the terminal validate it?**
   **A:** A merchant POS app sends a Terminal API Device/Input `GetText` request with `DisplayOutput` text and `InputData.InputCommand=TextString`; the terminal returns the entered value in `Input.TextInput`. `DefaultInputString` is only a format hint. The guide explicitly says terminal input is not format-validated and instructs the merchant to pass `TextInput` to its own system for validation and further use. The guide does not prove email ownership, identity or consent. Evidence: `raw/adyen/docs/point-of-sale/shopper-engagement/shopper-input/text/2026-09-15.md:19-36,48-85,166-211`; canonical URL: https://docs.adyen.com/point-of-sale/shopper-engagement/shopper-input/text.

2. **Q: What masking, timeout and cancellation behavior is documented, and are a length limit or Confirm flag stated?**
   **A:** `MaxInputTime` sets seconds; the example chooses 120. The field table describes Boolean masking but misspells `MaskChararctersFlag`, while the JSON sample uses `MaskCharactersFlag`. Timeout returns Failure/`Cancel` with a screen-timeout message. A payment request overrides pending input with Failure/`Busy`; terminal Cancel returns Failure/`Cancel`. The page states no text-length bound or Confirm-flag behavior, so those need a separate contract rather than inference.
