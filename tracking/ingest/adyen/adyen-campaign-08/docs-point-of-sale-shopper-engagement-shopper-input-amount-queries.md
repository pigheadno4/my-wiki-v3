# C08 GetAmount input — fixed retrieval checks

1. **Q: What does the GetAmount Terminal API request collect, and does its Success response authorize a payment?**
   **A:** It is a `MessageClass: Device`, `MessageCategory: Input` request with `GetAmount` display content and `DecimalString` customer input. The terminal returns the entered amount in `InputResult.Input.DigitInput`; the merchant passes that value to its system for validation and further use. A successful input response reports completion of the input interaction, not payment authorization or a completed split bill. 2. **Q: How do timeout, terminal Cancel and a new payment request affect a waiting GetAmount input, and where does the displayed currency come from?**
   **A:** Timeout returns input Failure/`ErrorCondition: Cancel` with `message=Screen%20timeout`; user Cancel returns an empty `DigitInput` with Failure/Cancel. A payment request overrides the waiting input and yields input Failure/`ErrorCondition: Busy` with the higher-priority-request message. The displayed currency defaults to the first currency configured for the store, or the merchant account when it represents the physical store. The guide's EUR 36.59 right-to-left entry is an example, not a charge.
