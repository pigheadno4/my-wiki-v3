# C08 shopper signature input — fixed query answers

1. **Which fields ask for a signature, and what does a confirmed response contain?** The Terminal API request uses `PredefinedContent.ReferenceID: GetSignature` on the customer display but `InputCommand: GetConfirmation` for customer input. It sends two text items; the second must still be present as empty on M400, e280 and e285 even though those models ignore additional text. The guide says `InputResult.Response.AdditionalResponse` carries the shopper-provided signature and `Input.ConfirmedFlag: true` indicates Confirm was selected. The raw input still requires merchant-side validation and does not by itself establish legal consent or payment authorization. Evidence: `raw/adyen/docs/point-of-sale/shopper-engagement/shopper-input/signature/2026-09-15.md`, request fields lines 48–84 and response lines 170–215; proposed source `[[source-adyen-docs-point-of-sale-shopper-engagement-shopper-input-signature]]`.

2. **What happens to signature input when it times out or a payment request arrives?** Timeout returns `InputResult.Response` `Failure`/`Cancel` with `message=Screen%20timeout`. A payment request arriving while the input prompt waits overrides it, returning `Failure`/`Busy` with a higher-priority-request message. The payment operation needs its own result check. The page's Java example also adds undefined `declineAnswer` and `agreeAnswer` items despite its two-text instruction, so that sample should not be treated as a complete implementation. Evidence: `raw/adyen/docs/point-of-sale/shopper-engagement/shopper-input/signature/2026-09-15.md`, Java sample lines 149–157 and response branches lines 211–215; proposed source `[[source-adyen-docs-point-of-sale-shopper-engagement-shopper-input-signature]]`.
