# C08 single-key rating — fixed query answers

1. **Does a shopper need to confirm a `GetOneKeyRating` answer?** The guide says a single key press both answers and sends the response, unlike the default `GetRating` request. The POS sends a Terminal API Device/Input request with `PredefinedContent.ReferenceID: GetOneKeyRating`, `InputCommand: DigitString` and a `MaxInputTime` in seconds. The page does not validate the rating format; the merchant system must validate the returned `DigitInput`. This input is not a payment or a consent record. Evidence: `raw/adyen/docs/point-of-sale/shopper-engagement/shopper-input/rating/rating-single-press/2026-09-15.md`, opening lines 19–21, request fields lines 49–87 and response handling lines 183–228; proposed source `[[source-adyen-docs-point-of-sale-shopper-engagement-shopper-input-rating-rating-single-press]]`.

2. **What happens if the shopper skips, times out, or a payment request arrives while the rating is shown?** Cancel or Skip returns an empty `DigitInput` with `Failure`/`Cancel`. Timeout returns `Failure`/`Cancel` and `message=Screen%20timeout`. A payment request overrides the pending input, which returns `Failure`/`Busy` and a higher-priority-request message; the payment's own result must be checked separately. The dated page lists specific terminal models and does not prove present merchant/device eligibility.
