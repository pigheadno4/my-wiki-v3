# Fixed-query answers: Adyen POS card application selection

Evidence: `raw/adyen/docs/point-of-sale/aid-selection-rules/2026-09-15.md`, SHA-256 `198640eba1b4b778e5123e782593ec5d9d294f4c09d1d37f0881ca7f60bb88b9`. Page last modified 2025 and captured 2026-09-15.

1. **How does the terminal choose among applications on a co-badged or combo card?** In Terminal API or standalone scope, the guide says automatic selection checks whether the terminal supports the application and transaction type and whether that network is available. Payment-request conditions, scheme-compliance rules and least-cost priorities then affect the choice; an installment request with a combo card is its example of selecting the credit application. Some non-compliance priorities can be changed through Adyen Support/account management, while compliance and supported-feature rules cannot. The USD fee figures are illustrations, not current merchant pricing or a guaranteed network choice. Locators: raw lines 19–25, 27–49, 51–74.

2. **How can a shopper override the default application, and what is the EEA qualifier?** The guide says the shopper selects **Card options** before presenting the card, chooses a brand, and may need to present the card again. Presenting without Card options uses the default brand. It states a choice requirement for EEA-issued co-badged cards when both brands are supported and recommends terminal software 1.109 or later for that compliance path. The existing generic [[co-badged-cards]] concept summarizes in-person applicability as France/Germany; its narrower line and this dated Adyen wording need separate authoritative legal reconciliation. Neither alone proves current legal duties, scheme availability, merchant enablement, or a successful payment. This page describes physical terminals/standalone use, not a Mobile POS or online-checkout selection API. Locators: raw lines 31–33, 76–96.
