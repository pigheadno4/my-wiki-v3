## Q2 — What capabilities, prerequisites and warnings matter most?

Collect shopper information, then send server `/payments` with `paymentMethod.type=affirm`, required shopper name/phone/email, and `countryCode` for Canada/UK despite the blank requiredness cell; omission defaults to US (`:33-62`). `stateOrProvince` is required for Canadian/US addresses and optional for UK; missing delivery address falls back to billing (`:60-61`). The introduction says to provide purchased-item detail (`:21-24`), yet the endpoint table calls `lineItems` optional and recommends them for approval rates (`:62`); the form's address collection list (`:35-44`) likewise should not be substituted for the endpoint table's outer requiredness cells (`:60-61`). Follow returned `action.url`, then after return POST `/payments/details` with URL-decoded `redirectResult` (`:802-843`). `Pending` needs the AUTHORISATION webhook for a final outcome (`:865-870`). Capture after dispatch within 28 days or authorisation expires; an uncaptured payment can be cancelled, while a captured one needs a refund to return funds (`:872-886`). For lesser fulfillment, this guide says full capture then refund (`:876`), while the Affirm overview marks partial/multiple-partial captures supported (`raw/adyen/docs/payment-methods/affirm/2026-09-15.md:27-29`); do not promise one unqualified partial-capture workflow. Affirm test/live credentials and live Customer Area request are separate gates (`:888-894`). The Go example's v10.4.0 label conflicts with `/v9/` imports (`:481-490`).
