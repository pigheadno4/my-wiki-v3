**Q2. What are the central capability, prerequisites and warnings?**
Use an existing Web Drop-in and add Bancontact mobile in test Customer Area. Enable **3DS2 Additional Fields** under **Developers > Additional data** only to receive `bcmcmobile.urlIntent` in the payment response. Base `/sessions` (default for Drop-in v5+) or conditional `/payments` needs no extra method fields or Drop-in configuration (raw/adyen/docs/payment-methods/bancontact/bancontact-mobile/web-drop-in/2026-09-15.md:27-48). Recurring is WIP-gated by signup, eligibility, Support and amount limits: request token storage plus shopper reference; the token ID comes via lifecycle webhook after settlement, then later `/payments` uses the ID, same reference, `ContAuth` and a recurring model (raw lines 50-107). With no Bancontact mobile test platform, the page recommends a EUR 0.01 *live* penny test; this is not proof of execution (raw lines 446-450).
