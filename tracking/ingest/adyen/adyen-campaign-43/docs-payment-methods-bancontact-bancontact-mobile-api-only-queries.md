## Q1 — What is this page for, and what cannot be inferred?

[[source-adyen-docs-payment-methods-bancontact-bancontact-mobile-api-only]] is the Web API-only Bancontact Mobile guide for QR on desktop and app switch on mobile, with separate return/details and conditional WIP recurring instructions (raw/adyen/docs/payment-methods/bancontact/bancontact-mobile/api-only/2026-09-15.md:15–60, 370–405, 718–754, 1013–1070). `Pending` is not a completed payment; desktop waits for `AUTHORISATION`, while mobile can use `/payments/details` after return and still needs the asynchronous outcome for Pending/Received (raw lines 370–405, 985–1011). This historical source, its `Authorised` sample, test-endpoint examples and recommendation of a live penny test do not prove current eligibility or a successful live transaction; it explicitly says there is no Bancontact Mobile test platform (raw lines 1–11, 990–1011, 1409–1414).

## Q2 — What central capability, prerequisites, and warnings are stated?

The page requires an existing Web API-only integration at minimum version 53, Bancontact setup, and a 3DS2 Additional Fields Customer Area setting to receive `bcmcmobile.urlIntent`; `/paymentMethods` examples use BE/EUR and `bcmc_mobile` (raw/adyen/docs/payment-methods/bancontact/bancontact-mobile/api-only/2026-09-15.md:21–46). Desktop uses `action.qrCodeData`; mobile should open `additionalData.bcmcmobile.urlIntent`; tablet can offer either/both, with 15 minutes for completion (raw lines 48–56, 370–395, 718–754). Both flow descriptions spell the return field `returnURL` (raw lines 65, 413), but the `/payments` JSON examples use `returnUrl` (raw lines 85, 433); verify the Checkout API field before implementing instead of treating those spellings as interchangeable. Mobile return posts URL-decoded `redirectResult` to `/payments/details`; `Pending`/`Received` await `AUTHORISATION` webhook finality (raw lines 752–754, 985–1011). WIP recurring requires signup, eligibility, Support enablement, amount limits and an initial consent/SCA transaction; token creation after settlement and later `ContAuth` requests are separate steps (raw lines 1013–1070). The guide says no Bancontact Mobile test platform even though it includes `checkout-test` samples and test-area setup, so do not claim these examples validate live operation (raw lines 25–31, 71–87, 1409–1414).
