Q2. What is the central capability, what prerequisites and consequential warnings apply?
A2. With an Adyen for Platforms integration, **Balance platform base role** allows Customer Area viewing and **TransferService Webservice Retrieve role** is listed for API retrieval (raw lines 35–43). Customer Area **Balances > Transfers** shows one balance platform at a time, supports date/status/reference filters and PSP payment-reference filtering, and can search a specific transfer by ID or description (raw lines 45–69, 476–493). Transfers API `GET /transfers` returns matching `data` and pagination `_links`; `GET /transfers/{id}` exposes amount, direction, events, reference and current status (raw lines 71–83, 264–269, 495–497, 643–651). The page states a less-than-six-month date interval and at least one unique identifier, yet its example prose spans May 2025–May 2026 and its curl uses only a May 12–13, 2026 date interval; verify the current API schema before implementation (raw lines 77–100). Its list mixes bank/internal records, the detail example is internal, and the bank-list example has booked status with `counterpartyAccountNotFound`; those samples cannot prove beneficiary-bank receipt or form a canonical join (raw lines 271–474, 653–737).
