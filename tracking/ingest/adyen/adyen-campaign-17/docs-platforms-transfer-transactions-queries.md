# Fixed retrieval checks — docs-platforms-transfer-transactions

Q1. What can this tracking hub tell a platform about fund movement?
A. This 2026-09-15 Adyen for Platforms page says each balance-platform fund movement results in a transaction and routes readers to Transfers/Transactions webhooks for real-time updates or Transfers API requests on demand. Its table is a transfer-lifecycle orientation: `authorised` reserves funds, `booked` deducts from the source balance account, `failed` cannot initiate, `refused` is network/bank rejection, and `returned` means sent funds returned. A `booked` source debit does not prove beneficiary bank receipt. Raw locators: lines 15–47; source `## Overview` and `## Key takeaways`. Q2. How should failed, refused, and returned transfers be handled in this source?
A. For `failed` or `refused`, the page says no balance-account deduction occurred and advises notifying the user and checking bank details or balance; it gives no automatic retry rule. A bank return can arrive days after initiation; a `balancePlatform.transfer.updated` webhook marks `returned`, funds are credited to the original balance account, and a separate Balance Platform Accounting Report entry records the return. Follow linked method and reconciliation guides for identifiers and later outcome details. Raw locators: lines 49–66; source `## Key takeaways` and `## Detail locators`.
