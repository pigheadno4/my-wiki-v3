Q2. Which reconciliation grain and amount-basis choices apply to each payout type?
- Expected: Payout report provides one payout-transfer-to-constituent-payments/refunds/adjustments breakdown for **managed and custom scheduled payouts**. The availability matrix excludes this transaction breakdown for **custom on-demand payouts and cashout**, which are outside automated batch cycles; use a unique request reference and filter the Accounting report to the final `Booked` status and value date. The Accounting report supplies the full balance-account credit/debit ledger, the Statement report a period activity summary, and payout transfer webhooks real-time status changes across all four listed payout types. By default payout uses **available balance**, including pending-risk effects, so totals may differ from recently settled sales. The page says choosing **current balance** uses the settled-funds sum with a reserve account covering risk, aligning the Payout report total; that relationship does not prove reserve sufficiency, account configuration or bank receipt. Webhook success/return and booked ledger status are evidence at their respective stages, not a beneficiary bank statement.
