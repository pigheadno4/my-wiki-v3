# Fixed retrieval checks — Transfers API transaction tracking

## Q1. How can a platform retrieve transactions and page the result?

The 2026-09-15 guide covers Transfers API GET /transactions for a balance platform, account holder or balance account and GET /transactions/{id} for one transaction. The integration may be Platforms, Issuing or Payouts; the guide requires the TransferService Webservice Retrieve role and source-balance-account transfer enablement. A list request includes at least one of balancePlatform, accountHolderId or balanceAccountId, plus ISO 8601 createdSince and createdUntil; optional limit, sortOrder, cursor and paymentInstrumentId refine it. The response data array is paginated with _links; follow the returned cursor. The TEST curl/SDK examples contain malformed or mismatched details and should not be copied as operational proof. ## Q2. What do sign, status and dates establish for internal or external rows?

The amount sign is relative to the named balance account: positive adds funds, negative deducts them. Pending incoming is not yet added; pending outgoing is reserved, while booked denotes account-side addition or deduction. Both internal and external movements can have either sign, so inspect transfer category, account and transfer fields. bookingDate records reserved/pending accounting and valueDate when funds are deducted or made available; the guide says outgoing funds are deducted at booked stage. Its sample list pairs EUR-suffixed IDs with USD amounts, and the separate internal-leg examples reuse IDs and the same balance-account description with different transfer IDs. These snippets do not give a reliable counterpart join or currency rule. A booked external payout debit is still not proof of beneficiary bank receipt.
