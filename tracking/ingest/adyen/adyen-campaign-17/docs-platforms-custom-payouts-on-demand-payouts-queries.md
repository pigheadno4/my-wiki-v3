# Fixed queries — docs-platforms-custom-payouts-on-demand-payouts

## Q1 — purpose, scope, and non-inference

**Query:** What is this on-demand payout path, and what does request acceptance or booking prove?

**Answer:** The guide covers an off-schedule Adyen for Platforms payout from a user's source balance account to that user's verified bank-account transfer instrument through Customer Area or Transfers API `POST /transfers` (raw lines 15–27, 73–95, 126–139). The opening routes third-party bank transfers to a separate business-accounts product with additional verification (lines 19–23). HTTP 2XX with transfer ID is request creation; capability/review, authorization and booking are later stages, and booking deducts the user balance and sends to the instrument (lines 46–71, 463). None of these or the examples prove beneficiary bank receipt, legal ownership or current eligibility. ## Q2 — central capability, prerequisites, and warnings

**Query:** Which roles, route, priority, review, future-date and return conditions govern this payout?

**Answer:** Requires Platforms integration, Transfers API initiation role or Customer Area payout role, Transfer webhooks, allowed `sendToTransferInstrument` capability (per instrument from LEM v3), Support enablement for the source balance and default transfer description (raw lines 29–44). The bank-category request supplies source balance account, amount/currency, linked target transfer instrument and priority; route availability and regional cutoff influence speed and fees (lines 25, 87–101, 128–139, 467–473). A `priorities` list retries the next available route within the same request; it is not permission to resubmit a pending payout (lines 467–565). Optional additional review permits one approval; future-dated payouts stay received/pending until execution, then Adyen checks funds and approval and attempts processing only once, with failure sent by webhook (lines 569–577, 942–963). A prior bank return can block new transfers; final return reasons must not be retried, and a bank-detail update precedes the guide's retry route for the block (lines 1032–1066). Reference/description limits depend on region, currency and priority; the short Customer Area reference limit conflicts with later 80-character tables, so inspect current route details before building payloads (lines 99–101, 1068–1245).
