# Fixed retrieval checks — balance-account top-up webhooks

Q1. What is this source's purpose and scope, and what must not be inferred?
- Expected: A 2026-09-15 Adyen for Platforms webhook guide for **scheduled and on-demand top-ups of user balance accounts**. It distinguishes Standard merchant-account `AUTHORISATION` when a top-up triggers direct debit or payment authorization from balance-platform Transfer and Transaction webhooks for incoming credits and, for an on-demand payment, a separate outgoing transaction-fee debit. It is event interpretation, not direct-debit mandate or bank-source setup, account-specific capability approval, completed external debit, payout, beneficiary bank receipt, or irrevocability. The introduction says webhooks inform failure but gives no concrete rejected/returned sequence in this snapshot.

Q2. How do scheduled credit, on-demand credit and fee legs differ across event states and identifiers?
- Expected: A scheduled pull-sweep example for the user's first balance account uses `category: platformPayment`, `direction: incoming`, `type: capture`; Transfer `received` → `authorised` → `captured` adds `transactionId`, then Transaction `booked` records the credit. On-demand payment/split examples credit EUR 1,000 to the user's first balance account using `category: topUp`, `direction: incoming`, `type: capture`, `platformPaymentType: TopUp`, with the same transfer-stage versus booked-transaction distinction. A separate EUR 3.44 fee leg debits the user's **second** balance account with `category: platformPayment`, `direction: outgoing`, `type: capture`, `platformPaymentType: PaymentFee`; positive transfer `amount.value` coexists with stage mutation signs and a negative booked-transaction amount. Match environment, balance account, transfer, transaction, payment/capture references, direction, currency and status by leg. Do not copy the fee example as reconciliation proof: its booked Transaction names the **first** balance account, reuses the top-up-credit transaction ID and has a value date before its creation date. A received or authorised transfer is not a booked credit/debit, and a booked balance movement does not prove external debit finality or bank receipt.
