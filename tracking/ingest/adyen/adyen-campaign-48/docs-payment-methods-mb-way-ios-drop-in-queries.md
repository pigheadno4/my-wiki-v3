## Q2 — Sessions, Advanced standard, App2App and test distinctions

**Query:** How do the MB WAY iOS Drop-in fields and shopper action differ across Sessions, Advanced standard, and optional App2App?

**Expected answer:** Sessions requires existing iOS Drop-in, Checkout API v68+, Customer Area setup and `shopperStatement` in `/sessions`; no extra method configuration (child `raw/adyen/docs/payment-methods/mb-way/ios-drop-in/2026-09-15.md`, lines 25–44, 67–71). Advanced requires existing iOS Drop-in, `await` action handling, Customer Area setup and standard `/payments` fields `paymentMethod.type: mbway` and `telephoneNumber`; `shopperStatement` is unmarked. Standard response is `Pending`/`await` while shopper completes payment in MB WAY app, not final success (child lines 96–167).
