# C07 iOS Mobile build overview — fixed query answers

1. **Can one merchant-built iOS POS app offer both Tap to Pay on iPhone and a card-reader path, and do they use different SDKs?** The 2026-09-15 build overview says both solutions use the **same iOS Mobile SDK** and can coexist **if the POS app allows selecting the payment interface**. It does not claim that every app has implemented that choice. This self-build section is skipped when using a ready-made partner solution. Evidence: `raw/adyen/docs/point-of-sale/mobile-ios/build/2026-09-15.md`, `# Build your iOS Mobile solution` lines 15–23; proposed `[[source-adyen-docs-point-of-sale-mobile-ios-build]]`.

2. **What development does the iOS Mobile build overview require, and does it establish current device or Apple eligibility?** It calls for a server-to-server request that establishes a secure session between the SDK and Adyen, plus Terminal API integration in the POS app. It says the app **must** support `PaymentRequest` and **preferably** support `ReversalRequest`. The overview points to separate Tap to Pay and card-reader build guides and does not itself state device/OS or SDK-version floors, region support, Apple entitlement, reader model, live approval or a demonstrated payment. Its no-cross-platform-wrapper statement is a dated snapshot claim. Evidence: same raw, `## Integration effort` lines 25–37 and `## Choose a solution` lines 47–57; proposed `[[source-adyen-docs-point-of-sale-mobile-ios-build]]`.
