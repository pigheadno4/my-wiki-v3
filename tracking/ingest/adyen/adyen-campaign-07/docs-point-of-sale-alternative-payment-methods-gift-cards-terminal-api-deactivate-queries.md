# C07 POS gift-card cashback and deactivation — fixed retrieval checks

1. **Q: Does a gift-card cashback request disable the card, and can it return only part of the balance?**
   **A:** Cashback takes value off the card and gives it back to the shopper; cashing out the full remaining balance makes the card inactive. Whether cashback is allowed depends on provider, scheme rules and law. The guide says full-balance cashout is usual and some Givex cases allow a partial amount. The Terminal API path is a `PaymentRequest` with `redemptionType=cashback`, requested amount and currency, and a gift-card `StoredValue` instrument. Giving cash is separate from transferring funds to a credit/debit card through the linked unreferenced-refund route. Check `PaymentResponse.Response.Result` for `Success`. The cashback `SaleReferenceID` row conflicts on whether the field is required, so this snapshot does not settle omission. 2. **Q: Can the deactivation example be used for SVS or valuelink, and is it a normal refund or void?**
   **A:** No. The guide explicitly limits deactivation to Givex, even though a later account-detail table lists other providers. It specifies a Terminal API `StoredValueRequest`, `MessageCategory=StoredValue`, `StoredValueTransactionType=Unload`, `ItemAmount=0` and card currency. A successful deactivation is checked through `StoredValueResponse` with `Unload`, `Response.Result=Success` and `CurrentBalance=0`; this disables the card without cashing it out. The response bullet's “funds were loaded” phrase conflicts with the deactivation explanation and zero-balance example and should not define the action.
