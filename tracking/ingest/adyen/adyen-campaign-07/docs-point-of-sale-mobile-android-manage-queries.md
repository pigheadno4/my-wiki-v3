# C07 Android Mobile management — fixed retrieval checks

1. **Q: For a merchant-built Android Mobile SDK app, is Google Play upload required, and what happens if the app is not registered for live use?**
   **A:** Google Play upload is optional for the Android Tap to Pay and Card reader paths. The merchant-built SDK app must be registered in the live Customer Area with the package name and signing-certificate SHA-256 fingerprint; Adyen says it blocks all live transactions when the app is unregistered or a registered app is detected as tampered. These instructions exclude the Android Payments app. Evidence: `raw/adyen/docs/point-of-sale/mobile-android/manage/2026-09-15.md:21-31,65-82`; canonical URL: https://docs.adyen.com/point-of-sale/mobile-android/manage. Deleting a registered fingerprint can take up to ten minutes to take effect and then blocks transactions with the linked app (`raw/adyen/docs/point-of-sale/mobile-android/manage/2026-09-15.md:117-119`).

2. **Q: What transaction restrictions does the dated guide state for an expired or removed Android Mobile SDK version, and is the Android Payments app governed by that same removal rule?**
   **A:** The guide says a Mobile SDK version expires six months after release: Tap to Pay on Android and card-reader PIN transactions are blocked, while card-reader transactions without PIN remain possible. Twelve months after expiry, the SDK version is removed and all transactions are blocked. The Android Payments app has a separate six-month version expiry rule; this page gives no app-removal deadline. Evidence: `raw/adyen/docs/point-of-sale/mobile-android/manage/2026-09-15.md:121-150,170-184`; canonical URL: https://docs.adyen.com/point-of-sale/mobile-android/manage. Version-specific expiry dates require Customer Area or release-note lookup (`raw/adyen/docs/point-of-sale/mobile-android/manage/2026-09-15.md:162-168`).
