# Fixed retrieval checks: BLIK one-time numeric code

1. **Q:** What changes between merchant-initiated and shopper-initiated BLIK on an Adyen payment terminal? **A:** Both are Poland-only in this 2026-09-15 guide and require BLIK added to the Adyen account. For merchant initiation, POS staff select BLIK and the Terminal API payment request specifies `PaymentTransaction.TransactionConditions.AllowedPaymentBrand` as an array containing `blik_pos`; the shopper then enters the banking-app six-digit code at the terminal. For shopper initiation, the POS sends a normal payment request and the shopper selects Scan then BLIK/BLIK Code on the terminal; the guide says this path requires no POS integration change and is the only standalone-terminal path. The app separately prompts the shopper to confirm. The request's PLN 10.99 amount and IDs are examples, not fixed requirements. 2. **Q:** Does a BLIK code payment use ordinary card refund and test assumptions? **A:** The guide says its result arrives as a card-payment result would and places BLIK's reference in the shopper receipt `Transaction ref`; that does not turn code entry and banking-app confirmation into card tap/insert/swipe. It permits full or partial **referenced** refunds through `ReversalRequest`; it does not establish an unreferenced-refund route. It lists `999000` as a test BLIK code, which is not proof of live eligibility or a successful payment.
