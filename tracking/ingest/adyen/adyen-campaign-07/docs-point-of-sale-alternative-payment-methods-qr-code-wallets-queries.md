1. **Who presents the QR code in each POS wallet flow?** In the terminal-menu path, staff or shopper selects the terminal QR icon and wallet after a standard payment request; the terminal displays the code for the shopper to scan. In the POS-app path, the request supplies `AllowedPaymentBrand` so the terminal directly displays that wallet's code. In the barcode-scanner path, the shopper shows a wallet code on their phone and the POS scans and converts it to a numeric `StoredValueID` in a Terminal API payment request. The scanner path needs QR-reading hardware and excludes Affirm, Atome, IRIS, PayMe, PayNow, PayPay, PIX, Rakuten Pay, TWINT, and Zip in this snapshot. 2. **When is a QR wallet payment approved, and how can it be refunded?** This guide describes automatic `Approved` results only for its test scenarios: terminal/POS generated codes after 15 seconds, except IRIS test results depend on amount; scanned codes immediately. A real flow sends the transaction to Adyen and returns a payment result, so showing or scanning a QR code alone is not proof of payment. The page provides no general QR expiry, cancellation, notification, or final-status timer. It says QR wallet payments support referenced full or partial refunds through `ReversalRequest`.
