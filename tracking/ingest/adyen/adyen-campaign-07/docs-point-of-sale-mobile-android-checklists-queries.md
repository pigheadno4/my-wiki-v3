# C07 Android Mobile checklists — fixed retrieval checks

1. **Q: What must a merchant check before building and testing an Android Mobile POS solution, and are all three routes interchangeable?**
   **A:** The captured checklist asks the merchant to choose an SDK-enabled Android POS app for Tap to Pay, a card reader, or both, versus Tap to Pay through the separate Adyen Payments app. It calls for country/region, payment-method, feature, hardware and software checks; a test account enabled for Mobile by Adyen Support; a test card; a test NYC1 only for the reader route; a supported Android mobile device; a Terminal API-integrated mobile POS app; and testing. SDK `warmUp` is recommended only for an SDK integration. Adyen says Mobile solutions have not reached traditional-terminal feature parity and geographic availability differs by route. Evidence: `raw/adyen/docs/point-of-sale/mobile-android/checklists/2026-09-15.md:19-51`; canonical URL: https://docs.adyen.com/point-of-sale/mobile-android/checklists. The checklist links away for exact current OS, device, region, method and feature support; it does not prove eligibility or a test result.

2. **Q: What separate live gates apply to SDK-in-POS-app versus Android Payments app, and does listing penny tests prove a live transaction?**
   **A:** Both routes are under live-account, Mobile contract/pricing, Support live-configuration, maintenance/update, personnel-training and live penny-test checklist steps. The SDK branch calls for a live SDK-download-role credential, live SDK package, a separate live API-key/client-key credential with **Checkout webservice**, live session endpoint/key, and Adyen app registration; Google Play upload is optional. The Payments-app branch lists a live SDK-download-role credential, Adyen Payments app from Google Play, live App Link URLs, and live Management API base URL. The checklist says each SDK version expires after six months and that Android minimum-version requirements may change; reader firmware duties apply where relevant. It also gives an optional NYC1-dock checklist with an Adyen-specific adapter and SDK/reader-firmware prerequisites. A penny test here is an instruction to perform and verify, not evidence that authorization, capture, settlement or reconciliation occurred. Evidence: `raw/adyen/docs/point-of-sale/mobile-android/checklists/2026-09-15.md:53-101,103-126`; canonical URL: https://docs.adyen.com/point-of-sale/mobile-android/checklists.
