# C07 POS gift-card load — fixed retrieval checks

1. **Q: Can a load request activate a new gift card, and which Terminal API action and financial amount does this guide specify?**
   **A:** The card must already be activated. The guide says a load request can add the initial funded amount or increase an existing balance. It uses a `StoredValueRequest` with `MessageCategory=StoredValue`, `StoredValueTransactionType=Load`, `StoredValueData.ItemAmount` for the amount being added, `Currency`, and gift-card account details. This is distinct from a gift-card purchase `PaymentRequest`; the guide does not describe how the shopper pays for the added value. This 2019-modified guide does not prove current provider or merchant eligibility.

2. **Q: What confirms a gift-card load in this guide, and can the sample request or `ServiceID` be treated as an idempotent retry or balance proof?**
   **A:** Check the `StoredValueResponse` for `StoredValueResult.StoredValueTransactionType=Load`, `Response.Result=Success`, response amount/currency and POI transaction ID. The request's `ServiceID` must be unique for that terminal over 48 hours, but the page states no idempotent-retry guarantee. The response's load amount should not be read as the card's total post-load balance without a separate inquiry. Its JSON/prose example uses GBP 15 while the Java example sets 10, so the samples are not one verified transaction.
