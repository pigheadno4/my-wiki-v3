# C07 Menus and passcodes — fixed retrieval checks

1. **Q: Where can an operator manage Adyen terminal passcodes, who is authorized, and when does a changed passcode take effect?**
   **A:** The captured guide covers Customer Area and Management API `/terminalSettings` GET/PATCH at company, merchant, store, and terminal levels. Lower-level values override inherited higher-level ones. Customer Area passcode management calls for **Merchant POS Terminal Management Admin**; API management calls for **Management API—Terminal Advanced settings read and write**. The guide says automatic maintenance downloads happen every 180 minutes and a restart makes the new passcodes effective, usually at a configured 6:00 AM restart hour. Its immediate route uses the **old** code in **Settings > Configuration > Update**. The passcodes serve Admin & Settings, Transactions, standalone Refunds, and Android Screen lock. For unattended Android terminals, screen lock must be disabled even if a higher-level setting propagates. 2. **Q: What terminal-menu actions and qualifications make the page unsafe to treat as generic current access or payment proof?**
   **A:** The guide says airplane mode needs Support enablement; its protected Network toggle disables Wi-Fi, Bluetooth, and cellular connections, and turning it off restores previous connections. Android Settings > Apps can force quit, clear cache, or clear storage; clearing storage deletes all data associated with the app and resets it, and opening the Apps listing can carry out scheduled installs/removals. Its Requirements table gates Apps to S1U2/S1E2L on software 1.103+, although its general menu table and the separate S1E4Pro manual show broader Apps entries, so the device/model scope needs verification. From software 1.90 it describes shared menu structure; earlier non-Android versions use legacy menus, with an enablement route for 1.85–1.90. Transactions and Refunds passcodes protect specified standalone special transactions, but menu text does not prove MOTO, refund, manual entry, bypass, or payment eligibility or execution.
