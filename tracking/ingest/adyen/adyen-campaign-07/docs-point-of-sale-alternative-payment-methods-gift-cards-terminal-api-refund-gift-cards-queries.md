# C07 POS gift-card refunds — fixed retrieval checks

1. **Q: How does the guide distinguish referenced and unreferenced refunds to a gift card, including partial refunds?**
   **A:** A referenced refund uses a `ReversalRequest` tied to the original gift-card payment transaction identifier; the guide says card details need not be supplied again and multiple partial referenced refunds are possible. An unreferenced refund, when that original payment link is unavailable, uses a `PaymentRequest` with `PaymentType=Refund` and explicit gift-card details. This page details the unreferenced path and links elsewhere for referenced steps. The partial statement is scoped to referenced refunds; the snapshot does not define a general unreferenced-partial rule or idempotent retries.

2. **Q: Is an unreferenced refund to a gift card the same as cashing out its balance, and what result should be checked?**
   **A:** No. The unreferenced request returns a specified `RequestedAmount` and `Currency` to the card using a stored-value gift-card instrument; the guide directs cash payout of a card balance to a separate cashback request. Scan supplies card number and expiry in the request, while swipe/manual entry prompts on the terminal. Check the `PaymentResponse` transaction ID, receipt data and `Response.Result=Success` for the refund response; request submission alone is not a confirmed outcome.
