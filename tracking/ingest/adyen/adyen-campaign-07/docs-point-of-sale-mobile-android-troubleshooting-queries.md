# C07 Android Mobile troubleshooting — fixed query answers

1. **Is `INVALID_NYC1_FIRMWARE_VERSION` a handset security error, and what does the guide direct the operator to do?** It is listed in the Android Mobile SDK **device error messages** table, but its description specifically says the **card reader firmware** is invalid. The dated guide directs updating the card reader to the latest software version and trying again; the row marks internet as needed to resolve. This is an NYC1 reader-specific entry, not evidence that the Android handset OS or online-checkout SDK needs an update. Evidence: `raw/adyen/docs/point-of-sale/mobile-android/troubleshooting/2026-09-15.md`, `## Device error messages` lines 29–40, specifically line 38; proposed `[[source-adyen-docs-point-of-sale-mobile-android-troubleshooting]]`.

2. **If the Android Payments app returns `05_009` after a payment, can the POS app assume no charge happened and send another payment?** No such outcome follows from this error table. `05_009` is an **after-payment** App Link error: the system cannot extract the transaction ID from the Terminal API response, possibly because a required response parameter is missing. The raw says to try again and contact Support if needed, but it does not establish the financial state or that a new payment request is safe. Check the actual payment state before another charge attempt. This error belongs to the separate Android Payments app route, not Android Mobile SDK attestation or the native online-checkout SDK. Evidence: same raw, opening lines 19–23, `## Error messages for the Android Payments app` lines 49–53 and 86–89, specifically line 88; proposed `[[source-adyen-docs-point-of-sale-mobile-android-troubleshooting]]`.
