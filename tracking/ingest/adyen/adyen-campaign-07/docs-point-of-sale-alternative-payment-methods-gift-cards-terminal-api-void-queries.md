# C07 Terminal API gift-card load undo — fixed retrieval checks

1. **Q: Which gift-card transaction can this undo request reverse, and can it cancel a gift-card payment or refund to the card?**
   **A:** It reverses only the **most recent load** on the gift card, and that load must have occurred within the past 24 hours; the loaded amount is taken off the balance. The guide expressly excludes canceling a gift-card payment and making a refund to a gift card. It requires a Terminal API/payment-terminal integration, the method added to the Adyen account, and provider onboarding. Evidence: `raw/adyen/docs/point-of-sale/alternative-payment-methods/gift-cards-terminal-api/void/2026-09-15.md:15-34`; canonical URL: https://docs.adyen.com/point-of-sale/alternative-payment-methods/gift-cards-terminal-api/void.

2. **Q: How does the request identify the original load, and what response fields indicate that it was reversed?**
   **A:** Supply the original `POITransactionID.TimeStamp` and `POITransactionID.TransactionID` in a StoredValue Service request with `StoredValueTransactionType: Reverse`. The recommended ID format is `tenderReference.pspReference`; `pspReference` alone needs a leading dot, and `tenderReference` alone is allowed only on the original terminal. In the response, `StoredValueTransactionType: Reverse` with `Response.Result: Success` indicates reversal; `StoredValueAccountStatus.CurrentBalance` gives the remaining card balance. Evidence: `raw/adyen/docs/point-of-sale/alternative-payment-methods/gift-cards-terminal-api/void/2026-09-15.md:36-76,154-162`; canonical URL: https://docs.adyen.com/point-of-sale/alternative-payment-methods/gift-cards-terminal-api/void. The `ServiceID` uniqueness rule is terminal-scoped for 48 hours; this page gives no general retry/idempotency guarantee (`raw/adyen/docs/point-of-sale/alternative-payment-methods/gift-cards-terminal-api/void/2026-09-15.md:47-55`).
