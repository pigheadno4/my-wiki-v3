# C07 Android Card reader build guide — fixed retrieval checks

1. **Q: For Adyen Card reader on Android, which device presents the payment interface, and what builds the request?**
   **A:** The merchant's Android POS app integrates with Terminal API and uses the Mobile SDK; the SDK starts the transaction on the NYC1 card reader, where the shopper taps, inserts or swipes a card or presents a wallet. The Android device is a commercial off-the-shelf device, not an Adyen payment terminal, and the reader can connect by Bluetooth or USB. 2. **Q: Can the SDK download key or an immediate refund response be treated as proof that a live card-reader integration is ready and a refund succeeded?**
   **A:** No. The SDK download credential is restricted to the download role; session establishment uses a different API credential with an API key, client key and Checkout webservice role, with separate test/live artifacts and live setup. Refund responses usually confirm receipt only; Standard webhooks report referenced or unreferenced refund outcomes, subject to the guide's limited synchronous unreferenced-refund exception. The guide also requires Android 12+ runtime, reader/store preparation, firmware maintenance and live registration steps.
