1. **Can Stored Value API replace Terminal API for a POS gift-card payment?** No. The overview says Stored Value API can replace Terminal API requests in the `StoredValue` message category, such as activation via `/changeStatus`, but cannot make payments. It frames Terminal API as the payment route, including cash-outs and refunds, even if management operations across POS and ecommerce use Stored Value API. A Terminal API integration, method addition to the account, and provider onboarding are stated setup steps. This does not establish a shared online payment flow. Locators: raw lines 21–40.

2. **Which POS gift-card operations and security/onboarding conditions does this snapshot describe?** Its matrix lists Givex, SVS, Fiserv/ValueLink and Intersolve across activation, payment, balance, load, load reversal, refund and cash-out, while deactivation is checked only for Givex. Local-provider cards in Denmark, France, the Netherlands, Norway, Sweden and the UK are payment-only in this table. Card capture may be POS-scanned or terminal-swiped/keyed. For cards with a PIN or security code, the terminal prompts the shopper; optional Support-enabled controls include prompt override and a 25-second to 30-minute PIN cache that clears sooner when another payment/card is presented. Co-badged mall cards require issuer onboarding of store- and scheme-specific MIDs; viewing those MIDs in the live Customer Area requires **View Acquiring Details**. These are dated documentation claims, not current provider/account eligibility or proof of acceptance. Locators: raw lines 42–103.
