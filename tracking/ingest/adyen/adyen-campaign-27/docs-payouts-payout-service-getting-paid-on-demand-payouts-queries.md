# C27 Q1–Q2: Payout Service on-demand payouts

**Q1. What flow is this, and what must be in place to initiate it?**
Follow [[index]] → [[adyen-index]] → [[adyen-financial-products]] → [[source-adyen-docs-payouts-payout-service-getting-paid-on-demand-payouts]] → [[raw/adyen/docs/payouts/payout-service/getting-paid/on-demand-payouts/2026-09-15]]. This Payout Service guide describes an unscheduled bank-directed payout from a balance-platform source balance account toward a transfer instrument, such as the account holder's verified payout account, using Customer Area or Transfers API `POST /transfers` (raw lines 15-19, 27, 34-52, 87-97). The Customer Area requirements table lists **Configure scheduled payouts** and **Initiate payouts to transfer instruments** roles; it also requires webhook receipt, says to contact Support for a default transfer description, and recommends calculating available routes before submitting while considering regional bank cutoffs (raw lines 27-32). The API table marks `amount`, `balanceAccountId`, `category: bank`, `counterparty.transferInstrumentId` linked to the holder's legal entity, and `priority` required; the optional references differ in whether they reach the beneficiary (raw lines 89-100). This is separate from the legacy Online Payout API and from internal balance-account transfer.

**Q2. What review, outcome and retry boundaries apply?**
At the same route, Customer Area confirmation creates a payout request, and the Transfers tab can later show whether it was booked (raw lines 64-66); API HTTP 2XX returns a transfer-request ID, not proof of bank credit (raw line 424). An optional `review.numberOfApprovalsRequired: 1` adds one team approval before Adyen proceeds, and its 2XX response does not mean approval occurred (raw lines 428-436, 801-807). Track later statuses through Transfer created/updated and balance-deduction Transaction created webhooks, acknowledging them (raw lines 809-831); a source debit is distinct from beneficiary-bank receipt. The sample 422/`1063_101` block follows a previous bank return; the guide says not to retry final return reasons, and only to retry codes recommended for retry (raw lines 839-861). Its subsequent suggestion to update bank details through Adyen and make a new request must be read under that return-reason restriction (raw lines 864-867). Customer Area EUR 150 “Instant” and TEST API v4 EUR `amount.value: 60000` `fast` are separate examples, not an arrival guarantee (raw lines 70-85, 106-126).
