Q1. What prerequisites and scope does the dated Payout Service guide give for balance-platform web service API credentials?
Answer: It assumes a Payout Service integration and a Customer Area user with Manage API credentials or Merchant admin role. Setup includes default credentials; additional web service credentials are configured at the company-account level and authenticate named Configuration, Transfers and Session authentication API routes according to enabled roles. LEM users are separate. Test credentials do not carry over: the page instructs creation of new live credentials and keys in the live Customer Area (raw lines 36–93). Q2. What are the material secret-rotation and deactivation boundaries?
Answer: The page says a new API key is active immediately while the previous key remains active 24 hours, with a control to reset its expiry to 24 hours or expire it immediately. A new basic-authentication password deactivates the predecessor immediately, so overlapping migration uses another credential. At least one role must be enabled. A credential cannot be deleted but can be deactivated to block its API keys. This is historical documentation and does not prove any credential or role was changed or any API/payout request succeeded (raw lines 95–199).
