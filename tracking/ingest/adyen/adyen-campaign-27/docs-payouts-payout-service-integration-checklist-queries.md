A1. Work with an Adyen contact on credentials, design, balance-platform resources and a settlement model, with distinct company/merchant/platform/legal-entity/account-holder/balance-account/transfer-instrument resources (raw lines 27–51). Test a Transfers API credential with GET /transfers, configure payout webhooks, choose own/third-party payout paths and reports, then apply for and separately configure LIVE (raw lines 53–77, 241–294). Q2. What does the TEST credential check prove, and what must be repeated for LIVE?
A2. A TEST GET /transfers HTTP 200 returns data/links for a read check, not payout completion (raw lines 77–89, 239). HMAC verification and fallback are recommended (249–254). TEST setup is not replicated to LIVE; obtain the live account/credentials, switch endpoint and test request, payouts and webhook acceptance separately (278–294). Versioned Java and Go snippets have sample discrepancies (105, 181–182), so do not treat code as validated execution.
