# Retrieval checks — docs-payouts-payout-service-getting-paid-payout-webhooks

Q1. Which Payout Service webhooks and identifiers track an outgoing bank payout? Answer: With a Payout Service integration and Transfer/Transaction webhook subscriptions, identify `category: bank`, `direction: outgoing`, `type: bankTransfer`. Transfer.created received reports the request; Transfer.updated authorised reserves source-account funds; booked with accounting transactionId records source debit. Insufficient funds can refuse with notEnoughBalance and require funding plus a new request. Raw lines 19–59, 60–230, 325–334.

Q2. Which signals distinguish bank progress, failure and retry limits? Answer: Booked is not final. Internal-review tracking can be pending or failed despite top-level booked/approved; the failed-review TEST payload also mismatches amount 1000 with -10000 first mutation. Local ETA may differ from actual bank arrival and excludes instant/cross-border; UK FPS/US ACH tracing identifies network progress, not credit. Instant completed `tracking.status: credited` is provider credit confirmation; external-bank failure or return has reasons and balance mutations. Permanent reasons can block the instrument so new requests return 422 even though the reason table generically says retry for closed/blocked accounts. Raw lines 325–334, 434–704, 706–836, 950–1113, 1111–1233, 1349–1547.
