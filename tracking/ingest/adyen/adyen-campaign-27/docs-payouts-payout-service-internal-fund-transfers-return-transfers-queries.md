# Query proposal — docs-payouts-payout-service-internal-fund-transfers-return-transfers

Q1. How does the Payout Service guide return an internal transfer, and what must be in place?
Answer: Only an original internal **push** transfer can be returned this way, using its incoming transfer ID in POST `/transfers/{transferId}/returns`; the amount currency/value match the original (raw lines 17-21, 39-50). Transfer webhook reception, Support enablement on the balance account returning funds, Transfers API access/role and conditional cross-holder send/receive capabilities are listed prerequisites (lines 23-38). Q2. Does an authorised response establish a completed return, and how are IDs/failures distinguished?
Answer: No. The response's `id` is the return-request ID; `transferId` is the original incoming transfer ID. `Declined` can indicate a wrong URL transfer ID (raw lines 293-307). The guide directs status and failure tracking to Transfer webhooks and also offers Customer Area viewing (lines 310-314); an authorised response is not booking evidence.
