**Q1 — Purpose, scope, and limits.** The 2026-09-15 MobilePay overview at canonical stem `https://docs.adyen.com/payment-methods/mobilepay` introduces online acceptance (raw lines 15–17), a DK/FI redirect-wallet matrix in DKK/EUR (lines 29–31), and routes to Web, iOS, Android, React Native, Flutter, API-only and Pay by Link guides (lines 68–110). Its payout section is a separate experimental linked-card payout route (lines 33–66). This snapshot and its capability marks do not prove current availability, a merchant's approval, a working child integration, or a completed payment. **Q2 — Central capability, prerequisites, and warnings.** The shopper must have the MobilePay app and a linked Visa, Mastercard or Dankort card (raw lines 23–25). In-app payments switch to that app for authentication; website payments redirect first to a hosted phone-number page and then prompt the app (line 27). The dated matrix marks recurring X but refunds, captures and chargebacks with checkmarks (lines 29–31); these marks are not outcome proof. Payouts require Adyen approval, balance platform setup and Transfers API, and do not work with the deprecated Payout API (lines 33–41). The `enablePayOut` /payments token arrives via recurring lifecycle webhook but is payout-only, never recurring or card-on-file (lines 43–56). Experimental payout limitations include Visa/Mastercard only, separate merchant accounts for concurrent payout types, and token creation only on /payments (lines 58–66).
