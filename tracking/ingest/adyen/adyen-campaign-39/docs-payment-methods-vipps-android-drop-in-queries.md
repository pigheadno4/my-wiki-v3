# Vipps Android Drop-in retrieval checks

**Q1 — Purpose, scope, and what cannot be inferred.** [[source-adyen-docs-payment-methods-vipps-android-drop-in]] is a 2026-09-15 method-specific add-on for existing Android Drop-in Sessions and Advanced flows (pinned raw lines 15–23, 25–34, 104–112). It covers request additions, an Advanced redirect action, TEST-app and LIVE setup guidance (lines 38–45, 122–172, 174–200). The NOK/NO/Android values in the examples (lines 47–66, 133–156) are not a full availability matrix, current merchant approval, Android SDK version or completed payment. **Q2 — Central capability, prerequisites, and warnings.** [[source-adyen-docs-payment-methods-vipps-android-drop-in]] requires existing Sessions Drop-in with Checkout API v68+ and Customer Area addition, or existing Advanced Drop-in with redirect handling and Customer Area addition (raw lines 25–34, 104–112). Both request tables state a 100-minor-unit (1.00 NOK) minimum and optional `shopperStatement` with `reference` fallback (lines 42–45, 126–131); Advanced also describes phone prefill and relevant `channel` (lines 128–130). The `RedirectShopper` action is a redirect handoff (lines 158–172). TEST uses the Vipps test app and app authorization (lines 78–92, 176–190), while LIVE requires a separate Customer Area request and webhook/Payment list checks (lines 94–102, 192–200). The Advanced `channel` row links a `/paymentMethods` reference although it describes `/payments` (line 130).
