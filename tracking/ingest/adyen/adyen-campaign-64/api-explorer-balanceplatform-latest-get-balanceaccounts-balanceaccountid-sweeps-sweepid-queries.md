# C64 sweep GET: original fixed-query answers

## Q1

The 2026-11-02-captured Balance Platform API v2 TEST `GET /balanceAccounts/{balanceAccountId}/sweeps/{sweepId}` reads one sweep configuration, using two required path IDs for the balance account and sweep and the listed server `https://balanceplatform-api-test.adyen.com/bcl/v2`. It has no request body or query parameters in the pinned reference. Required 200 fields are sweep `id`, `counterparty`, uppercase ISO `currency`, and `schedule`; counterparty prose requires one balance-account ID, transfer-instrument ID, or merchant account. The merchant account is limited to pull sweeps when processing with Adyen. Optional fields include category, priorities, description, status, direction, reference, disable reason/detail, `sweepAmount` or mutually exclusive `targetAmount`, and `triggerAmount`. Nested amount currency and minor-unit value are required if an amount object appears. Response descriptions say `triggerAmount` defaults to zero, direction to push, status to active; schedule type is required and may be cron, daily, weekly, monthly, or balance. Cron needs a five-part expression in the balance-account time zone; daily/weekly/monthly describe 07:00 CET. Pull triggers at balance ≤ threshold; push at balance ≥ threshold. Bank-transfer priorities are ordered preferences, with acceptance described if at least one is supported and activated for the platform. [[source-adyen-api-explorer-balanceplatform-latest-get-balanceaccounts-balanceaccountid-sweeps-sweepid]]; https://docs.adyen.com/api-explorer/balanceplatform/latest/get/balanceAccounts/(balanceAccountId)/sweeps/(sweepId); verified raw lines 5–54.

## Q2

A 200 establishes successful retrieval of a sweep configuration, not that a threshold was reached or a transfer was initiated, booked, settled or received by a bank. The sample is an active daily push configuration with zero target and trigger amounts; it is not an outcome report. The priority description's acceptance rule concerns configuration and still requires a supported/activated option; GET readback does not prove current transfer-route availability. `inactive` means a sweep cannot trigger; optional reason fields explain disablement when present. The raw lists 400/401/403/422/500 error classes but no operation-specific idempotency, execution history, deletion/reversal, propagation timing, live-server or caller-grant contract. Its generic 422/500 examples refer to payment instruments, not sweep outcomes. The `latest` URL and TEST snapshot are not proof of present live availability or account eligibility.
