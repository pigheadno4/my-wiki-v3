# C64 fixed answers — api-explorer-balanceplatform-latest-get-balanceaccounts-balanceaccountid-sweeps-sweepid-executions

## Q1

The 2026-11-02-captured Balance Platform API v2 `GET /balanceAccounts/{balanceAccountId}/sweeps/{sweepId}/executions` returns a paginated list of custom payout schedule executions for the required balance-account and sweep-configuration IDs. Only the TEST `https://balanceplatform-api-test.adyen.com/bcl/v2` server is displayed; no caller role or request body is specified. Optional `cursor` uses a prior next/previous link; optional `limit` defaults to 10 items per page; optional comma-separated `results` filters succeeded, failed or skipped. The 200 schema requires `link` and `sweepExecutions`; pagination-link children and each execution's `id`, `triggeredAt`, `result` and `resultDetails` are optional. Optional details include reason, reason code, whether the sweep configuration was disabled, and the ID of a transfer created by that execution if applicable. The sweep path ID, execution ID and transfer ID are distinct. ## Q2

A 200 establishes a successful paginated read of execution records. The API describes `succeeded` as a completed sweep payout, `failed` as error, and `skipped` as not triggered; these are execution-level results, and the companion custom-payout guide routes a resulting transfer ID to later Transfer webhooks, including possible bank return. Thus a succeeded item or optional `transferId` does not prove final booked transfer or beneficiary bank receipt. The illustrated success item and next link are examples, not required payloads for every execution. This GET does not create, activate, delete or execute a sweep; no propagation, retry, idempotency, reversal or asynchronous completion guarantee is specified here. The page lists 401 authentication required, 404 not found, 422 validation and 500 server errors, but no credential method/role. The TEST base and `latest` URL cannot prove live eligibility or current version.
