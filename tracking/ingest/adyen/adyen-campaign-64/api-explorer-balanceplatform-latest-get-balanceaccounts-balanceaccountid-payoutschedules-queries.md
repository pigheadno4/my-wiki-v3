## Q1

The 2026-11-02 Balance Platform API `GET /balanceAccounts/{balanceAccountId}/payoutSchedules` reference lists managed payout schedules configured on a balance account, through the captured TEST `https://balanceplatform-api-test.adyen.com/bcl/v2` server. The required path ID is the balance account, not a schedule or transfer ID. Optional query inputs are `limit` (10 per page by default, maximum 100), a cursor from previous response links, and a three-character ISO currency filter; no request body is listed. The 200 schema requires the `balanceAccountPayoutSchedules` array and `link` object. Within each schedule, `balanceAccountId`, `balancePlatformPayoutScheduleId`, `createdAt`, and payout-destination `transferInstrumentId` are required; the account-level schedule `id` is optional in this table. Optional settings include enabled state, currency, frequency, allowed monthly/weekly frequency values, amount bounds, retained amount, description and beneficiary/merchant references. The table documents inherited defaults from the platform schedule, zero defaults for the minimum/maximum/retained amounts, description and reference limits, month-end/weekend handling, and a retained-funds execution gate. The schema lists only a-z, A-Z and 0-9 for `referenceForBeneficiary` (raw line 48), but the response example uses hyphens in `PAYOUT-REF-001` (line 157). That example does not prove hyphens are accepted; this snapshot leaves their validation unresolved. It names no specific caller role or GET idempotency key. ## Q2

A 200 establishes that this read succeeded and returned a page of configured schedules and pagination links. It does not establish that a schedule execution occurred, its transfer succeeded, funds were booked or settled, or the beneficiary bank received a payout. Even an `enabled` schedule and a transfer-instrument ID are configuration/reference state. The schema says an execution is not initiated when funds are below the retained amount, but this GET gives no specific execution or failure result. Listed errors are 401 authentication required, 404 resource not found, 422 request validation, and 500 server failure.
