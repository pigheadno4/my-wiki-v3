## api-explorer-balanceplatform-latest-get-balanceplatforms-balanceplatformid-webhooks-webhookid-settings

Q1. The 2026-11-02 Balance Platform API capture documents `GET /balancePlatforms/{balancePlatformId}/webhooks/{webhookId}/settings` on `https://balanceplatform-api-test.adyen.com/bcl/v2`. It reads all balance webhook settings for the specified webhook under a specified balance platform. Both `balancePlatformId` and `webhookId` are required string path IDs; this page lists no query or request-body fields, defaults, pagination or result-count limits. The 200 schema marks `webhookSettings` optional, but marks each returned setting's `currency`, setting `id`, `status`, `target` and `type` required, with `target.id` and `target.type` required inside `target`. Targets can be a whole balance platform, an account holder or one balance account. The two setting objects in the single named 200 response example show `conditions`, but the response schema does not define that field or its requiredness. Q2. A 200 response establishes successful readback of configured settings; an `active` value describes a notification rule, not proof that Adyen delivered a webhook or that a balance changed. The status row says any condition may trigger, while the separate captured configuration guide says all conditions must match; the condition logic is unresolved across the captures. The 404 row anomalously says “The payment was not found,” which does not change this endpoint into a payment lookup or establish what missing webhook resource returns 404. This GET has documented 400, 401 authentication, 403 permission, 404, 422 and 500 errors, but no idempotency header, mutation/deletion, propagation timing, asynchronous delivery/retry or reversal contract. The `latest` path and TEST v2 host do not prove current version, LIVE availability, subscription or account eligibility; settings readback is not payment, payout or bank-receipt evidence.
