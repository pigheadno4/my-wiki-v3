# C64 fixed answers — api-explorer-balanceplatform-latest-post-balanceaccounts-balanceaccountid-recurringtopups

## Q1

The 2026-11-02-captured Balance Platform API v2 `POST /balanceAccounts/{balanceAccountId}/recurringTopUps` creates a recurring top-up configuration on the balance account identified by the required path ID. Only `https://balanceplatform-api-test.adyen.com/bcl/v2` is shown; this reference does not name the caller's credential role. The request table requires `counterparty.transferInstrumentId`, `description` (140-character cap with truncation), `topUpAmount` and `trigger`. Fixed and target amount children are individually optional in the API table, but each supplied child requires currency and minor-unit value; the companion Issuing guide says choose one. `trigger.threshold` and its currency/value are required; `trigger.schedule` is optional, with required nested type if supplied. Weekdays/weekly/monthly run at 07:00 local balance-account time; null/default is continuous monitoring. Status defaults active; inactive cannot trigger. The 200 schema requires an `id` for the new configuration, along with required configuration fields; response status is optional. ## Q2

A 200 and returned ID establish request success with a reported configuration ID, but do not alone confirm asynchronous creation. The Issuing top-up-webhooks guide says a successful Top-up API response does not necessarily mean creation succeeded (guide raw line 19); the `balancePlatform.balanceAccount.recurringTopUp.created` Configuration webhook is its documented successful-creation signal (guide raw lines 35–41). Even confirmed creation is separate from a triggered direct-debit request, successful debit, booked balance credit or card payment. The API says triggering occurs when balance is below the threshold (raw line 40), while the companion guide's Customer Area wording says less than or equal to (guide raw line 242); equality behavior is unresolved. The page lists 400, 401, 403 and 422 errors, with 422 examples for currency mismatch, disabled DirectDebitTopUp property, inactive holder, invalid transfer instrument, missing receive capability and unavailable route; examples do not prove a complete eligibility rule. It specifies no idempotency, retry, deletion, propagation or asynchronous financial-outcome guarantee. The TEST server and `latest` URL do not establish live version, access or eligibility.
