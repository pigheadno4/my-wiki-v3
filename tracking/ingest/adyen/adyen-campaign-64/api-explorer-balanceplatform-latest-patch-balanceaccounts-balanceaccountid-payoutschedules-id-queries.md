# Fixed query answers — api-explorer-balanceplatform-latest-patch-balanceaccounts-balanceaccountid-payoutschedules-id

## Q1

The 2026-11-02 capture is Balance Platform API v2 on TEST `https://balanceplatform-api-test.adyen.com/bcl/v2`. `PATCH /balanceAccounts/{balanceAccountId}/payoutSchedules/{id}` updates an applied managed payout schedule: both path IDs are required, with `balanceAccountId` selecting the balance account and `id` the applied schedule. The body table marks all settings optional and says omitted optional parameters remain unchanged. Fields cover description (140-character maximum, possible truncation), enabled, frequency (daily/weekdays/weekly/monthly), conditional `frequencyValue` (weekly 1–5, monthly 1–31, with stated weekend/nonexistent-date handling), min/max payout amounts and retained amount (each default 0), references, sales-day closing time (00:00–07:00 in HH:mm:ss and account time zone), and destination `transferInstrumentId`. The response marks account ID, platform schedule ID, createdAt and transferInstrumentId required; account-applied schedule ID, enabled, settings, currency and updatedAt are optional. The raw does not state amount units. See [[source-adyen-api-explorer-balanceplatform-latest-patch-balanceaccounts-balanceaccountid-payoutschedules-id]] and [the captured API reference](https://docs.adyen.com/api-explorer/balanceplatform/latest/patch/balanceAccounts/(balanceAccountId)/payoutSchedules/(id)), raw lines 5–34 and 46–70.

## Q2

A 200 establishes successful schedule update, not payout initiation, transfer booking, settlement or bank receipt. The `enabled` field reports schedule activation state; the response example's `enabled: false` and amounts are illustrative. If available funds are below `retainedAmount`, the page says schedule execution is not initiated. The listed failures are 401 authentication, 404 resource not found, 422 validation and 500 server error; no idempotency, deletion, propagation timing, asynchronous execution outcome or reversal contract appears here. Request and response descriptions disagree on supported `referenceForBeneficiary` characters: request allows hyphen and space, response lists only alphanumerics, so accepted or bank-visible characters cannot be inferred from this snapshot. The `latest` URL and TEST v2 server do not prove current access or live payout eligibility. See [[source-adyen-api-explorer-balanceplatform-latest-patch-balanceaccounts-balanceaccountid-payoutschedules-id]] and [the captured API reference](https://docs.adyen.com/api-explorer/balanceplatform/latest/patch/balanceAccounts/(balanceAccountId)/payoutSchedules/(id)), raw lines 7, 25–34, 46–70, 73–146 and 148–171.
