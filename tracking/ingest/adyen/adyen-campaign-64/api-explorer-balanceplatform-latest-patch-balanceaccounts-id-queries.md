# Fixed query answers — api-explorer-balanceplatform-latest-patch-balanceaccounts-id

## Q1

The 2026-11-02 capture is Balance Platform API v2 on TEST `https://balanceplatform-api-test.adyen.com/bcl/v2`. `PATCH /balanceAccounts/{id}` updates the balance account named by required path `id`; it is not an account-holder ID. The request table marks `accountHolderId`, description, metadata, reference, status, time zone, and optional `platformPaymentConfiguration` children all **No**, and states no whole-body requiredness. Metadata replacement deletes omitted existing pairs. Status values are `active`, `closed`, `suspended`, and linked payment instruments are usable only when active. Closing-time configuration allows whole hours 00–07 (default 00:00); settlement delay allows 1–20 business days or null (default null) with Custom Sales Day Payout enablement. Time zone defaults to the holder's time zone if unset. A 200 returns required account-holder and balance-account IDs plus optional balance, status, configuration and descriptive fields; the response states EUR default/immutable currency, 300-character description and 150-character reference maxima. See [[source-adyen-api-explorer-balanceplatform-latest-patch-balanceaccounts-id]] and [the captured API reference](https://docs.adyen.com/api-explorer/balanceplatform/latest/patch/balanceAccounts/(id)), raw lines 5–31 and 41–67.

## Q2

A 200 says the balance-account update request succeeded and returns resource state; the example's active status and zero balances do not prove actual funds, payment, payout or bank receipt. The endpoint lists 401 authentication, 403 permission, 400 request-reading, 422 validation and 500 server errors; its generic 422/500 examples concern payment instruments, not demonstrated PATCH-specific failure conditions. The request enum permits `closed`; the separate [[source-adyen-docs-platforms-manage-balance-accounts|Platforms guide]] says permanent closure requires an empty balance account (its raw lines 473–482), while this endpoint table gives no closure prerequisite, propagation time, idempotency, asynchronous outcome or reversal contract. The `latest` URL and TEST v2 server do not prove current live access or eligibility. See [[source-adyen-api-explorer-balanceplatform-latest-patch-balanceaccounts-id]] and [the captured API reference](https://docs.adyen.com/api-explorer/balanceplatform/latest/patch/balanceAccounts/(id)), raw lines 5–10, 23–31, 41–67, 70–167 and 169–256.
