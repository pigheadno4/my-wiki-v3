## api-explorer-balanceplatform-latest-get-balanceaccounts-id

- Q1: `GET /balanceAccounts/{id}` reads a balance-account resource and, per the purpose line, its default-currency balance plus other currencies with non-zero balances. The captured Balance Platform API Explorer server is TEST `https://balanceplatform-api-test.adyen.com/bcl/v2` (v2 despite `latest` in the URL). The only documented input is required string path `id`, the balance-account ID; no request body, query parameter or input limit is listed. A 200 response requires the balance-account `id` and associated `accountHolderId`. The optional `balances` array has required `available`, settled `balance`, `currency` and `reserved` fields within each included object, and optional `pending` and `pendingAvailable`. Other optional resource fields include default currency (EUR default and immutable after creation), status (active by default), description/reference length limits, metadata, migration code, platform payment configuration and time zone. The optional configuration gives a 00:00 sales-day close default and nullable 1–20-business-day settlement delay conditional on Custom Sales Day Payout enablement. - Q2: A 200 means this GET request succeeded and reports the resource and any included balances at readback; the EUR zero-balance example is illustrative. `available`, settled `balance`, `pending`, `pendingAvailable` and `reserved` have distinct meanings. The GET response-field lower-of formula for `pendingAvailable` [raw line 33] conflicts with Example 2 in [[source-adyen-docs-platforms-balance-types]] [that guide's raw lines 72–84]: Pending EUR -70 and Available EUR -20 would calculate to EUR -90, while the table says Pending available EUR -70. These snapshots do not provide a reliable executable formula. Neither the returned account ID nor optional status/balance values establish creation, verification, authorization, new booking, payout or bank receipt. The page lists 401 authentication and 403 permission errors alongside 400, 422 and 500, but gives no authentication scheme or role, idempotency behavior, mutation lifecycle, deletion, propagation timing, asynchronous outcome or reversal contract for this GET. Its generic 422/500 examples concern payment instruments rather than a balance-account GET. The `latest` URL and 2026-11-02 TEST v2 snapshot do not prove current live availability or eligibility; the optional settlement-delay field's enablement condition must be respected.
