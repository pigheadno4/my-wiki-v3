## Q1 — Captured endpoint and inputs

`GET /balancePlatforms/{id}/accountHolders` is the 2026-11-02-captured Balance Platform API v2 reference for a paginated list of account holders belonging to one balance platform. Its only listed server is TEST, `https://balanceplatform-api-test.adyen.com/bcl/v2`; the `latest` documentation path does not independently verify current live availability. The caller supplies the required balance-platform `id` in the path and may supply `limit` and `offset` as query parameters. `limit` defaults to 10 items per page and has a maximum of 100; `offset` skips items. No request body, extra selector, or idempotency parameter is documented for this GET. A 200 response has an `accountHolders` array and `hasNext`/`hasPrevious` booleans. Each returned holder's response schema requires its account-holder `id` and associated `legalEntityId`; optional fields include the balance-platform ID, reference, status, primary balance-account ID, capability map and verification deadlines. The legal entity and balance account are distinct referenced resources. ## Q2 — Meaning and boundaries of a returned list

HTTP 200 means this list request succeeded and reports a page of resource and status data, with `hasNext`/`hasPrevious` indicating whether adjacent pages exist; it does not create an account holder, approve a capability, move funds or prove payment, payout, settlement or bank receipt. Capability `requested` is separate from `allowed`, which indicates permission after successful verification, while `enabled: false` marks temporary disablement; verification may be pending, invalid, valid or rejected. The account-holder status description says suspended blocks payouts and closed is final. Authentication and permission failures are separately documented as 401 and 403; 400, 422 and 500 are also listed. This GET defines no idempotency, modification, deletion, propagation or asynchronous outcome contract. The response table's optional `balancePlatform` field oddly says it is required in a request when credentials span multiple platforms, although this GET's request parameters list only path `id` and query `limit`/`offset`; that wording cannot establish an extra input. The 422 and 500 examples concern payment instruments, so they cannot be used as endpoint-specific error or reversal evidence. The page is a dated TEST-server capture, not proof of current live eligibility or any holder's present state.
