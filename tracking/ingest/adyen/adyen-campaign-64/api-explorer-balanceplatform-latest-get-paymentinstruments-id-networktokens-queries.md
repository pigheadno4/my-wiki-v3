## Q1

The 2026-11-02 Balance Platform API `GET /paymentInstruments/{id}/networkTokens` reference lists network tokens connected to a payment instrument on the captured TEST `https://balanceplatform-api-test.adyen.com/bcl/v2` server. The required string path `id` identifies that payment instrument, distinct from each optional returned network-token `id` and its optional `paymentInstrumentId` link. No request body, query filter, count, pagination, ordering, default, or limit is documented. The 200 schema marks the `networkTokens` array optional; each listed token field is optional, including brand variant, creation date, device, IDs, status (`active`, `inactive`, `suspended`, `closed`), last four token-ID digits, token requestor and type examples `wallet`/`cof`. Nested device phone is conditional, available for up to 24 hours after provisioning request, and requires a specific user role whose name is not given. ## Q2

A 200 establishes success of this listing request and may return token metadata/status; it does not create or mutate a token or grant the phone-field role. The separate dated [[source-adyen-docs-issuing-network-tokens|Issuing lifecycle guide]] defines `active` as usable for payments after approval or reactivation from suspension (its raw lines 51–68 and 74–81). Wallet and card-on-file tokens remain distinct; this GET does not establish the particular path that produced a token's active status, or prove a card authorization, capture, booking, settlement, or receipt. The token `status` is distinct from the payment-instrument or payment status. Errors listed are 400, 401 authentication, 403 permission, 422 validation and 500 server failure. The generic 422 and 500 JSON examples concern payment-instrument update/creation, not network-token-listing-specific failure conditions. This page specifies no GET idempotency key, token deletion/lifecycle transition mechanism, propagation timing, reversal, version/conflict rule, or later asynchronous outcome. The dated TEST snapshot and `latest` URL do not prove current eligibility or live API access.
