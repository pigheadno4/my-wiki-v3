## Q1

The 2026-11-02 capture is Balance Platform API v2 on TEST `https://balanceplatform-api-test.adyen.com/bcl/v2`. `PATCH /balanceAccounts/{balanceAccountId}/recurringTopUps/{topUpId}` updates an existing recurring top-up configuration; the two required path IDs identify the balance account and its recurring top-up, not a transfer or funding instrument. The request table marks description (140-character truncation), beneficiary reference, status, top-up amount and trigger optional; amount may be fixed or target, while trigger may be scheduled or threshold-based, with values in minor units. Status allows active/inactive and is described as defaulting to active if omitted, but the paired description-only example returns inactive, leaving PATCH omission semantics unresolved. The 200 response requires top-up `id`, counterparty with funding `transferInstrumentId`, description, amount and trigger; status and beneficiary reference are optional, while nested amount currency/value, schedule type and threshold currency/value have their own required markers when their parents are present. The schedule description gives weekdays/weekly/monthly 07:00 local pulls and null-default continuous monitoring. ## Q2

A 200 says the configuration update request succeeded and returns top-up settings; it does not establish that a direct-debit pull began, funds were booked, or a payout/bank receipt occurred. `Inactive` is described as disabling triggers, but the example's inactive status after a description-only request cannot prove a status change because the same table says omitted status defaults active. The page lists 401 authentication and 403 permission errors, plus 400 request-reading and 422 validation; its 422 examples illustrate currency mismatch, disabled DirectDebitTopUp, inactive holder, invalid transfer instrument, missing `receiveFromTransferInstrument` capability and missing routes without making each a universal prerequisite. It gives no idempotency, deletion, propagation timing, asynchronous transfer outcome, reversal or bank-credit contract. The `latest` URL and TEST v2 host do not prove current live access or eligibility.
