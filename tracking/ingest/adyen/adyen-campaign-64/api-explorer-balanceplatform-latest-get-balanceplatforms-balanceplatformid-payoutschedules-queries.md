## Q1 — Captured endpoint, inputs and response

The 2026-11-02 Balance Platform API v2 `GET /balancePlatforms/{balancePlatformId}/payoutSchedules` reference lists managed payout schedules configured for one balance platform. The only displayed server is TEST, `https://balanceplatform-api-test.adyen.com/bcl/v2`; `latest` in the documentation URL does not verify a current live endpoint. The caller supplies required `balancePlatformId` in the path. Optional `currency` and `countryCode` query fields filter the list; no body, pagination parameters or default filters are documented. A 200 response requires `balancePlatformPayoutSchedules`, an array of schedule configurations. For each schedule, the response table marks `balancePlatformId`, `createdAt`, `payoutScheduleDescription`, `userSettlementDelay`, `userSettlementTime` and `userSettlementTimeZone` required; `id` is marked optional. Other optional fields include automatic application to new balance accounts, enabled state, country/currency, default frequency and references, amount thresholds, retained amount and update time. `defaultFrequencyValue` is conditional on monthly or weekly frequency, with ranges 1–31 or 1–5. `maxPayoutAmount` defaults to zero for no maximum; `minPayoutAmount` and `retainedAmount` default to zero, and the retained amount can prevent execution initiation when account funds are below it. Source: [[source-adyen-api-explorer-balanceplatform-latest-get-balanceplatforms-balanceplatformid-payoutschedules]]; https://docs.adyen.com/api-explorer/balanceplatform/latest/get/balancePlatforms/(balancePlatformId)/payoutSchedules; verified pinned raw lines 5–24 and 26–54.

## Q2 — What the list does and does not establish

HTTP 200 establishes a successful read of configured platform-level schedules. The array and its optional `automaticApplication`, `enabled`, frequency, timing and amount fields report configuration. They do not prove a schedule has been applied to a particular balance account, an execution was initiated or succeeded, a transfer booked, funds settled or a beneficiary bank received money. The `payoutScheduleDescription` field describes Standard and Accelerated timing relative to settlement, but this list is not outcome evidence. A reported `retainedAmount` is an execution gate: if account funds are below it, execution is not initiated. The GET has no documented idempotency, creation, update, deletion, propagation, asynchronous outcome, failure reversal or payment authorization/capture contract. Its errors are 401 for authentication, 404 for missing resource, 422 for validation and 500 for processing failure; no specific caller role or response example is provided. This dated TEST-server snapshot does not prove current live access or account eligibility.
