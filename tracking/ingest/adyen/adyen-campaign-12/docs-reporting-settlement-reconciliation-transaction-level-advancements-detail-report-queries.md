Q1 — What is this source for, what scope does it cover, and what must it not establish? The Advancements Detail Report shows installments Adyen used to determine an amount advanced, generated per merchant account and advancement code where the Advancement Product is offered. A code can cover multiple merchant accounts under one legal-entity number, so one report is not the whole operation. Bulk entries cannot be tied to individual installments. This reporting evidence alone does not establish settlement finality or verify a bank deposit. Raw lines 17–21, 39, 55–59, 121–127, 205–207. Q2 — What are the central capability, prerequisites and warnings? Transaction rows show installment advances and cancellations; bulk rows cover unidentified installments; the last Advancement row carries merchant-account/code totals. Separate GC payment-currency and NC settlement-currency debit/credit columns, advancement costs, estimated commission and rounding correction must be read by journal type. Markup, scheme-fee and interchange columns are empty because events are not settlement; account settings can alter columns and order. Generation/download requires the See installments reports role per merchant account, the report is currently CET/CEST only, and a nonexistent manual code may produce an empty report.
