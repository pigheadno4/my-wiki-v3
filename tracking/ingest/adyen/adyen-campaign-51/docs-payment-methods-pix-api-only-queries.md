**Expected answer:** `https://docs.adyen.com/payment-methods/pix/api-only` is a 2026-09-15-captured add-on for an existing API-only Advanced flow handling `action.type: qrCode`, with Pix enabled in Customer Area. ## Q2 — expiration, asynchronous result, amount and refund warnings

**Query:** What is the Pix payment expiration by Checkout API version, when is payment final, and what do the amount and refund examples establish?

**Expected answer:** The `sessionValidity` table describes **payment expiration** with a default of **1 hour at Checkout API v71 or earlier** and **24 hours at v72 or later**; it does not specify a separate QR-display countdown (pinned `raw/adyen/docs/payment-methods/pix/api-only/2026-09-15.md`, raw line 361). The `/payments` example returns `Pending` with a `qrCode` action, `qrCodeData`, and `pix.expirationDate` (raw lines 853–873), while a separate example `AUTHORISATION` webhook has `success: true` (lines 875–940). The webhook sample amount/`pix.originalAmountValue` is **100000**, versus **10000** in the payment request example (lines 377–380, 885–900); no overpayment or reconciliation behavior is defined by that mismatch. The guide permits refund within **90 days after payment** via Customer Area or Refund API (lines 958–960), describes test-only promotion of a pending offer and requires a live Customer Area Pix request before live acceptance (lines 962–975). The generic “capture the payment” step (lines 31–37) does not override the overview matrix's crossed-out separate/partial capture variants. Pending QR issuance and test promotion do not prove live/final payment.
