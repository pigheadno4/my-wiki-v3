## Q1: What does recurring top-up do, and what must be in place to configure it?

The captured Issuing guide configures a balance-account schedule that initiates outgoing direct debit requests to a bank-account source; Adyen then books top-up funds to the balance account (raw lines 19–21). The guide requires Issuing integration, a funded top-up source, account-holder `receiveFromTransferInstrument` active with valid `verificationStatus`, and Configuration/Transfer/Transaction webhooks. API setup additionally lists BankAPI Advanced Webservice role and prior Terms of Service acceptance; Customer Area lists two roles and handles acceptance in its wizard (raw lines 23–38, 250–252). ## Q2: What limits, failure boundaries, or source conflicts affect interpretation?

The page limits recurring top-ups to EUR/USD and excludes on-demand top-ups (raw lines 35–36). The API table calls for one of fixed or target amount (lines 78–83), but the later payload uses `fixedAmount` and an outer `currency` field (lines 203–225). API threshold prose says balance **below** threshold (line 99), while Customer Area says **less than or equal to** (line 242). Triggered top-ups create transfer records to track; examples and the report/status routes do not prove a particular debit settled (lines 254–275). Creation errors include capability, ToS, currency, routing, instrument and direct-debit-limit failures (lines 277–304).
