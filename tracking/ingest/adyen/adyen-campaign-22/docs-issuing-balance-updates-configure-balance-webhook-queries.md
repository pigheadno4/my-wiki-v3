# C22 balance webhook retrieval checks

Q1. What is the setup sequence and which roles and limits does the captured guide state? The pilot guide requires subscribing to the Balance webhook in Customer Area, saving its webhook ID, then configuring conditions through the Configuration API. The API credential needs the Balance Platform BCL role; Customer Area access needs Merchant technical integrator or Merchant admin. It states at most 20 settings per webhook and 20 condition sets per setting. Raw lines 19–20, 26, 32–39, 41–75. Q2. When does a setting notify, and what implementation conflicts need checking? The status row says an `active` setting notifies when *any* condition is met and `inactive` suppresses notification; the conditions row says *all* conditions must be met. The multi-condition trigger rule is therefore unresolved in this snapshot; check the linked API reference or verified behavior. With no conditions, the guide says updates for all balance changes in the specified account(s). Its prose names POST `/balancePlatforms/{id}/webhooks/{id}/settings`, while its curl example posts to `/bcl/v2/balancePlatforms`; the latter should not be copied as a verified settings endpoint. Troubleshooting lists duplicate conditions, account-not-found and invalid-currency examples. Raw lines 73–103, 151–244.
