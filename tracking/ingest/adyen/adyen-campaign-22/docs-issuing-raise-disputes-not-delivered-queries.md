# C22 query checks — docs-issuing-raise-disputes-not-delivered

Q1. When can a platform raise an Issuing non-delivery dispute, and what is the creation route?
Answer: A cardholder reports undelivered goods/services after unsuccessfully contacting the merchant, and the platform checks that the merchant has not already refunded the transaction (raw lines 19–21). Find the transaction ID through the accounting report, Customer Area or Transfer webhooks, then `POST /disputes` with `type=notDelivered`, `transactionId` and required `notDeliveredInfo` fields (raw lines 27–57). General prerequisites and limits are in the parent Raise disputes guide, linked at line 25. Q2. Does draft creation or submission establish a successful chargeback, and what changes after submission?
Answer: Creation returns a draft dispute ID and draft webhook (raw lines 86–94, 124). Cardholder review precedes submission; after submission no dispute edits, attachment upload/deletion or closure are allowed (raw lines 197–200, 240–260). A submitted status is not a win; follow `balancePlatform.dispute.updated`, and for `chargeback`/`secondPresentment` match transfer webhooks by ARN and reconcile the cardholder balance account (raw lines 286–293). The printed response example has malformed JSON and a `whatWasNotDelivered` shape mismatch with the request table (raw lines 54, 79, 109–117).
