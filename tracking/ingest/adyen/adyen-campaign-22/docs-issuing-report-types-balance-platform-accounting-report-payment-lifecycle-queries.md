# C22 Issuing Accounting Report payment-lifecycle retrieval checks

## Q1 — How does this guide identify and date issued-card lifecycle rows?

Given Balance Platform Accounting Report rows for payments to the platform, it points to `Category`, `Type`, `Status`, and `Booking Date`. `issuedCard` denotes an issued-card activity; events appear on the report day when each status update took place, so authorization and later capture can appear on different days (raw lines 19–27). The GBP purchase against a EUR default balance account illustrates separate original and account-currency amounts (raw lines 31–44). This page states no access or generation prerequisites; the parent [[source-adyen-docs-issuing-report-types-balance-platform-accounting-report]] owns report scope. ## Q2 — Which examples have important interpretation limits or conflicts?

The partial-capture table shows a later `expired` row for the outstanding amount after the prose's seven-day interval (raw lines 46–55). The cancellation prose says the cafe cancels instead of partially capturing, but the same example includes `cancelled` and `captured` rows for one Transfer Id (raw lines 57–66); do not derive a general cancellation/capture guarantee. The Booking Date sentence also has duplicated received-status wording (raw line 25), and refund sample signs differ across original GBP and EUR report columns (raw lines 79–89). These are illustrative rows, not proof of a live payment, refund, or settlement.
