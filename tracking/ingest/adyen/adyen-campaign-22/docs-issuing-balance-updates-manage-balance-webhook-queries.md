# C22 docs-issuing-balance-updates-manage-balance-webhook retrieval checks

Q1. How can an Issuing platform inspect and update a balance webhook setting, and which scope and threshold fields matter?

Answer: The 2026-09-15 source marks balance webhooks **limited availability / pilot** (raw lines 19–20). Configuration API GET on `/balancePlatforms/{balancePlatformId}/webhooks/{webhookId}/settings` lists settings; GET with `/{settingId}` reads one (26–28, 81–87). PATCH on the setting route changes it; `type: balance` is required in the guide's body table (121–133). Optional target scope is `balancePlatform`, `accountHolder` or `balanceAccount`, identified by `target.id`; currency and conditions define balance type and threshold comparison (134–147). This is setting configuration, not proof of webhook delivery. Q2. What happens when conditions are added or removed, and how do inactive and DELETE differ?

Answer: To add a condition, send both existing and new condition sets in PATCH; to remove one, omit it but send all conditions to keep (raw lines 155–157, 191–195). Removing the **only** existing condition makes the setting send updates for **all balance changes in the specified balance account(s)** (243–245), a widened trigger. `status: active` sends when any condition matches; `inactive` suppresses the configured notifications (139–141), and the guide uses it for a temporary stop (224–226). DELETE of the setting is its permanent stop for those specified conditions (247–253). These are source-stated pilot behaviors, not evidence of current live eligibility or delivery.
