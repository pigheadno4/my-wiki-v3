Q1. What do the Issuing-path transaction components show, and what is needed to integrate them?
Answer: Transactions Overview shows balance-account transaction records, balances and insights, and Transaction Details shows a selected record; the page explicitly requires an Adyen for Platforms integration (raw lines 27, 50, 60–76, 154–164). The server creates an account-holder-scoped Session Authentication API session with the View role and `product=platform`; the client installs and initializes the Platform Experience library (raw lines 230–247, 288–306, 331–346). Q2. Can the UI refund any payment or export the full ledger, and does a displayed refund status prove shopper receipt?
Answer: The Manage Refunds role is needed on both API credential and session; full/partial support depends on payment method, and described repeated partial refunds may total no more than the original amount (raw lines 180–191). Export is CSV-only, capped at 100 rows, with the overview specifying the first 100 filtered transactions (raw lines 53–54, 70). A component request and displayed status are UI/request evidence, not independent proof of final settlement or shopper receipt (raw lines 182, 191, 211).
