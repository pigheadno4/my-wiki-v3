# C22 query checks — docs-issuing-raise-disputes-duplicate

Q1. How does a platform identify and draft an Issuing duplicate-charge dispute?
Answer: The guide covers a charge on one card or two Adyen-issued cards (raw lines 15–19). Find both transaction IDs from the accounting report, Customer Area or Transfer webhooks; POST a `duplicate` dispute with the disputed `transactionId`, `duplicateInfo.duplicateTransactionId` and `sameCard`. Both charges must have the same amount (raw lines 25–44). The parent Raise disputes guide owns overarching requirements (raw line 23). Q2. Does submission win the chargeback, and which field examples need caution?
Answer: The created dispute is draft (raw lines 65–93). The cardholder reviews it; after submission to the scheme, edits, attachment changes and closure are unavailable (raw lines 162–200). Submitted status is a process state; later updated-dispute webhooks and, for chargeback/secondPresentment, ARN-matched transfer webhooks support balance reconciliation (raw lines 216, 238–245). The examples quote boolean `sameCard`/`sameIssuer` (raw lines 41–42, 57–58, 85–86), and the PATCH table incorrectly types `duplicateTransactionId` as boolean versus the POST string table and example (raw lines 40, 56, 190).
