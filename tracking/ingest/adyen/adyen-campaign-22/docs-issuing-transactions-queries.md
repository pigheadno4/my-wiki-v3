# C22 query checks — docs-issuing-transactions

Q1. What does this page let an integration query, and what prerequisites or filters does it state?

The 2020-modified, 2026-09-15-captured Issuing-path page uses Transfers API `GET /transactions` for on-demand balance-platform transaction records across the whole platform, an account holder or a balance account, and `GET /transactions/{id}` for one ID (raw lines 15–19, 347). Its requirements table names Adyen for Platforms, Issuing or Payouts integration, **TransferService Webservice Retrieve role**, and transfers enabled for the source balance account (21–27; the table formatting is broken). The list table requires at least one of `balancePlatform`, `accountHolderId`, or `balanceAccountId`, and marks `createdSince`/`createdUntil` required ISO 8601 date-time filters; it offers `paymentInstrumentId`, pagination and sort parameters (31–47). `data` carries matches and `_links` supports cursor paging (219–223). Q2. How do the returned records indicate money direction and completion, and what must not be inferred?

Positive `amount.value` adds funds to the balance account; negative deducts (raw 349–356). `pending` means incoming not yet added or outgoing reserved; `booked` means incoming added or outgoing deducted, with outgoing deduction at booked stage (357–370). `bookingDate` records reserved/pending funds; `valueDate` marks deduction or availability (361–368). The sample response contains a bank category and internal transfers, so this is broader than card payment tracking (224–345). The curl example has a stray `accountHolder` query item and the Java example has invalid punctuation (54,75), so sample calls are not a validated integration; test `booked` records prove no real settlement or beneficiary receipt.
