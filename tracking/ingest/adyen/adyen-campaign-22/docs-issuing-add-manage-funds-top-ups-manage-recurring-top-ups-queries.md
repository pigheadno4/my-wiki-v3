# C22 retrieval probes — manage recurring top-ups

Q1. How can an Issuing integrator view or manage an existing recurring balance-account top-up, and what access prerequisites apply?

Answer: The 2026-09-15 raw guide says the Configuration API or Customer Area can view, change and delete settings (line 21). It lists the BankAPI Advanced Webservice API role, Balance platform base and Configure scheduled payouts Customer Area roles, Configuration/Transfer/Transaction webhook subscriptions, and an active `receiveFromTransferInstrument` with valid `verificationStatus` when topping up from a transfer instrument; the source must have enough balance (Requirements, lines 23–36). The schedule sets when the available balance is checked (`null` means continuous monitoring), and a top-up triggers only if that balance is below the threshold (lines 94–99). GET lists by balance account, PATCH changes listed settings and DELETE removes the schedule (lines 38–62, 303–334, 413–451). Q2. Can the funding source be changed or a top-up triggered on demand, and how does deletion differ from deactivation?

Answer: No on-demand top-up is supported by this feature (Requirements > Limitations, line 35). A weekly schedule checks available balance on Monday, and a top-up triggers only if it is below the threshold; `null` means continuous monitoring (lines 94–99). The `transferInstrumentId` cannot be PATCHed; changing funds source requires deactivating the current recurring top-up and creating a new one (Update > API, lines 309–313). PATCH can set status `inactive` (lines 331–332), while DELETE removes the schedule and returns 204 No Content only if successful (Delete > API, lines 413–445). These describe schedule management, not a guarantee that a transfer succeeds or funds settle.
