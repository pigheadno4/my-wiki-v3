# C22 query checks — docs-issuing-raise-disputes-attach-supporting-information

Q1. How does a card-issuing platform attach evidence to a raised dispute, and what prerequisites or limits are stated?

Adyen recommends attaching receipts, merchant correspondence or other reviewable evidence **before** dispute submission; the parent Raise disputes guide owns the general requirements (pinned raw 15–23). Base64-encode each cardholder file and make a separate POST `/disputes/{disputeId}/attachments` per attachment with `attachmentType`, `fileName`, and `content` (25–45). Supported file types are JPEG/PDF/TIFF, photos should be clear, filename length is 4–17 characters including `jpeg`/`pdf`/`tiff` extension, and attachment type is receipt/correspondence/other (29–45). Save the response `attachmentId` for later operations (61–73). The example is a TEST endpoint, not evidence of a real submission. Q2. How are attachments retrieved or deleted, and what does deletion or upload not prove?

GET with both `disputeId` and `attachmentId` returns the file metadata and Base64 content for decoding; GET with just `disputeId` lists the dispute's attachments (raw 75–118). DELETE with both IDs is successful on HTTP 204; a recently deleted file needs a unique filename if reuploaded (139–161). Adyen may still retain attached files for audit/compliance after deletion (141–143). This page recommends pre-submission attachments but does not establish post-submission mutation permission, card-scheme acceptance, winning the dispute or returned funds (19, 139–161).
