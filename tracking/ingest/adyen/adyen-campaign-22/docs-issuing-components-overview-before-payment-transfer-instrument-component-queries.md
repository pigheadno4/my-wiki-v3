# C22 Issuing Transfer Instrument component query checks

Q1 — What are these components for, and what must the platform prepare? The Configuration component collects users' bank-account information through an instant-verification permission path or document upload; Management displays added accounts, verification statuses and errors and offers account actions (pinned raw lines 57–75). The guide limits compatibility to LEM API v3/v4 entities (line 23), requires an Adyen for Platforms integration and LEM API key (lines 43–53), and still requires other API-only onboarding calls (line 27). The platform server creates a Session Authentication API session scoped to the bank-account-owning contractual legal entity (individual owner for sole proprietorship), `product=onboarding`, the required component role(s), and an allowed origin with live HTTPS (lines 98–113). Component-library version can change feature guidance (lines 35–37). Q2 — Does `complete`, an immediate management change, or a displayed verification status prove a verified bank account or completed payout? No. `complete` reports successful submission and component completion (raw line 186); management events report user actions (lines 562–572). The management prose says changes apply immediately for payout direction (line 75), but the component also displays verification statuses/errors (line 73), and the illustrative `complete` payload has null verification fields (lines 578–601). Read actual verification and payout evidence separately; this guide alone establishes neither payout eligibility nor bank receipt.
