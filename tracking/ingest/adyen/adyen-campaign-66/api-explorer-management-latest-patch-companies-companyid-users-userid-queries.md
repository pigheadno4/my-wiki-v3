## Q2

The documented 200 means the user-details update request succeeded and returns a user representation. It does not establish that a user logged in, that SSO is configured or working, that assigned roles grant any particular account or payment access, or that payments or payouts occurred. The `active` flag is a user property, not company or merchant-account activation. The captured reference gives no idempotency, deletion/reversal, propagation timing, asynchronous approval, or financial outcome semantics for this PATCH. Its listed failures are 400 request, 401 authentication, 403 permission, 422 validation, and 500 server processing.
