# api-explorer-legalentity-latest-post-legalentities-id-onboardinglinks — original query answers

## Q1

`POST /legalEntities/{id}/onboardingLinks` returns a link to an Adyen-hosted onboarding page to which the caller redirects its user. The November 3 capture lists the Legal Entity Management v4 TEST base `https://kyc-test.adyen.com/lem/v4`; the path `id` is a required legal-entity ID. The request-body table marks `locale`, `redirectUrl`, `settings`, and `themeId` optional and does not state whole-body requiredness. `locale` falls back to browser language, then `en-US`; `redirectUrl` is the destination after completion. `settings` contains optional controls, including `acceptedCountries` (empty by default, so all supported countries/regions), payout-account format choice, debug UI, entity type/country edits, age enforcement, onboarding introductions, instant bank verification, PCI signing prompts, and `transferInstrumentLimit`. The `200` response lists optional `url`, which expires after four minutes and is single-use. Captured limits are 700 requests per five seconds live, 200 per five seconds test, and five failed requests per ten seconds. ## Q2

The `200` result establishes only that the request succeeded and supplies an optional hosted-onboarding URL; the endpoint directs the caller to redirect the user. It does not report user completion, verification review/approval, capability activation, PCI compliance, payment authorization, payout, settlement or bank receipt. The link expires after four minutes, can be used and clicked only once, and must be regenerated after expiry. The capture lists authentication-required `401`, permission `403`, request/validation `400`/`422`, and server `500` errors, plus separate failed-request rate limits. It does not specify idempotency, deletion/reversal, propagation or asynchronous outcome semantics; the `latest` path and sample TEST URL do not prove current version or live eligibility.
