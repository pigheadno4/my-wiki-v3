# Original C66 query answers: api-explorer-management-latest-delete-merchants-merchantid-payoutsettings-payoutsettingsid

## Q1

The captured Management API v3 TEST reference describes `DELETE /merchants/{merchantId}/payoutSettings/{payoutSettingsId}` at `https://management-test.adyen.com/v3`. It deletes the payout setting named by required `payoutSettingsId` under the merchant account named by required `merchantId`. The page says use is integration-dependent, such as Adyen for Platforms Manage, and an Adyen contact sets up access; the API credential needs `Management API—Payout account settings read and write`. No query fields, request body, conditional inputs, defaults, numeric limits or success-response fields are documented. Success is `204`, with the actual response code giving request status. ## Q2

A documented `204` means the delete request succeeded according to its actual response code; it returns no payout-setting state. The page does not specify deletion propagation timing, whether deletion can be reversed, what happens to pending or future payouts, or any booking, settlement or recipient-bank receipt. It also gives no idempotency, asynchronous review/approval/activation or version-conflict rule. Access is contact-set and requires the stated credential role; `401` is authentication required and `403` is insufficient permission, alongside `400` request, `422` validation and `500` server errors. The captured `latest` page lists only the TEST `/v3` server, so it is not current live eligibility or financial-outcome proof.
