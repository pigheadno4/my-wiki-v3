# api-explorer-management-latest-post-merchants-merchantid-payoutsettings — original query answers

## Q1

The captured Management API `POST /merchants/{merchantId}/payoutSettings` sends a request to add a payout setting to the merchant account identified by required path `merchantId`; the setting links it to a Legal Entity API transfer instrument holding payout-bank details. The page documents the TEST `https://management-test.adyen.com/v3` server, role **Management API—Payout account settings read and write**, and Adyen-contact setup for integrations that require this endpoint, such as Adyen for Platforms Manage. The request-body table requires `transferInstrumentId`; `enabled` is optional with default `true`; `enabledFromDate` is optional ISO 8601 and changes the effective enablement as specified. It gives no query parameters or other limits, and does not separately mark the body container required. A 200 body requires payout-setting `id` and `transferInstrumentId`; optional fields are `allowed`, `enabled`, `enabledFromDate`, `priority` and `verificationStatus`. A 204 has no additional content. ## Q2

A 200 says the setting request succeeded and can return its `id`; a 204 says processing succeeded without additional content. Neither is a payout or bank-receipt record. Adyen verifies the bank account before allowing and enabling the setting. `allowed` is automatic and `true` only when `verificationStatus=valid`; `pending`, `invalid` and `rejected` make it `false`. Payouts into the bank account require both `allowed` and `enabled` true. `enabledFromDate` can defer enablement: with `enabled=false`, the field says it becomes true on that date and the date resets to null; with `enabled=true`, payouts are enabled starting then. Access needs Adyen-contact setup and the stated credential role; the documented errors are 400, 401, 403, 422 and 500. The reference states no idempotency contract, duplicate behavior, deletion or reversal, propagation timing, or separate asynchronous approval outcome beyond verification status. Its priority timing descriptions depend on payout frequency, currencies and banks and do not prove financial completion. This 2026-11-03 TEST snapshot and “latest” documentation route do not establish current LIVE eligibility or compliance.
