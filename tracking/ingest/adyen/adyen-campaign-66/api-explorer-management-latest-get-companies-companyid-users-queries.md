## Q1

The 2026-11-03 Management API v3 snapshot says `GET /companies/{companyId}/users` lists user records under the company account identified by the required string path `companyId`. The listed server is `https://management-test.adyen.com/v3`. The caller is an API credential requiring **Management API—Users read and write**; that role is separate from roles on returned human user records. Optional queries are partial-or-complete `username`, `pageSize` (default 10, maximum 100), and `pageNumber` (no default stated); there is no request body. The `200` response has optional pagination `_links` and optional `data`, required `itemsTotal`/`pagesTotal`, and per-user email, ID, roles, time-zone code, and username marked required within returned items. Other user fields include active status, apps, account groups, associated merchant accounts, and name. See [[source-adyen-api-explorer-management-latest-get-companies-companyid-users]] and the [pinned API reference](https://docs.adyen.com/api-explorer/Management/latest/get/companies/(companyId)/users), raw lines 5–66.

## Q2

A successful `200` is a paginated read of company-user records and their listed fields. It does not create or modify users, prove a user's successful login or effective current access, confirm SSO/MFA enrollment, or authorize a payment. `401` means authentication is required and `403` insufficient permissions; `400`, `422`, and `500` cover request, validation, and server failures. The page does not specify idempotency, user lifecycle/deletion effects, propagation timing, asynchronous review/activation, reversal, or version-conflict behavior; those cannot be inferred from a list response. The TEST v3 endpoint and 2026-11-03 capture do not establish present live availability or financial outcome. See [[source-adyen-api-explorer-management-latest-get-companies-companyid-users]] and the [pinned API reference](https://docs.adyen.com/api-explorer/Management/latest/get/companies/(companyId)/users), raw lines 9–14, 31–66, and 69–166.
