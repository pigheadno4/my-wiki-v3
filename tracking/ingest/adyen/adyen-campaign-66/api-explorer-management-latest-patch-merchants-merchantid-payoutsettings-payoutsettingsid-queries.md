# Original retrieval answers: api-explorer-management-latest-patch-merchants-merchantid-payoutsettings-payoutsettingsid

- Q1: The 2026-11-03 Management API v3 TEST `PATCH /merchants/{merchantId}/payoutSettings/{payoutSettingsId}` enables or disables the payout setting identified by required string path IDs for the merchant account and its payout setting. It is for integrations that require it, such as Adyen for Platforms Manage, with access set up by an Adyen contact and an API credential bearing `Management API—Payout account settings read and write`. Its sole request-body field is optional boolean `enabled`, default `true`; the page does not separately require the whole body or specify conditional input or a rate limit. The 200 response requires payout-setting `id` and bank-account `transferInstrumentId`, and optionally reports verification-derived `allowed`, `enabled`, `enabledFromDate`, `priority`, and `verificationStatus`; 204 has no content. These response-only fields are not documented as PATCH inputs. [[source-adyen-api-explorer-management-latest-patch-merchants-merchantid-payoutsettings-payoutsettingsid]] — https://docs.adyen.com/api-explorer/Management/latest/patch/merchants/(merchantId)/payoutSettings/(payoutSettingsId) ; pinned raw lines 5–16, 18–50.
- Q2: 200 establishes request success with a setting representation, and 204 establishes successful processing without content. For payouts to the bank account, both `enabled` and verification-derived `allowed` must be true; `allowed` is true only when `verificationStatus` is `valid`. The 200 response describes optional future `enabledFromDate` and priority/arrival timing, but this PATCH does not document setting those fields or guarantee a bank transfer or receipt. The page lists 401 authentication-required and 403 insufficient-permission failures, plus 400, 422, and 500. It states no idempotency, deletion/reversal, asynchronous approval, propagation-time, or financial outcome contract. Its `latest` URL and TEST snapshot do not prove current eligibility or live availability, and generic error `requestId`/`pspReference` wording is not payment evidence.
