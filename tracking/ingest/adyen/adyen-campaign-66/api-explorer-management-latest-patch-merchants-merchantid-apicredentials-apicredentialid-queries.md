## Q1

The 2026-11-03-captured `PATCH /merchants/{merchantId}/apiCredentials/{apiCredentialId}` updates an API credential under a merchant account through the Adyen Management API. Its listed server is TEST `/v3`; both path IDs are required, and the calling credential needs `Management API—API credentials read and write`. The request table marks `active`, a new string list of `allowedOrigins`, `description`, `roles`, and `subjectDN` optional and does not separately declare whole-body requiredness. Assignable roles are limited to roles assigned to `ws@Company.<CompanyName>`. A `200` can return the full credential, with required active state, allowed-IP list, client key, credential ID, roles and username; optional allowed-origin objects and links are distinct from the request's string list. `active: true` is required to use a credential, and an empty allowed-IP list permits any source IP per the response description. A separate `204` has no additional content. This page gives no live URL, numeric rate limit, default for omitted PATCH fields or idempotency rule.
