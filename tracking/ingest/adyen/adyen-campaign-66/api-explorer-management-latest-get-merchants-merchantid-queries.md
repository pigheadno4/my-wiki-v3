## Q1

`GET /merchants/{merchantId}` is the 2026-11-03-captured Adyen Management API v3 lookup of one merchant account on the shown `https://management-test.adyen.com/v3` server. The API credential must have access to that merchant and the `Management API—Account read` role. The required path string `merchantId` identifies the merchant account; no query parameter or request body is documented. A `200` can return optional `_links` (with `self` required within that object and optional API-credential, user and webhook links), merchant `id` and parent `companyId`, legal-entity name/city, reference, status, capture delay, shopper interaction, description, data centers, pricing plan for partner-managed accounts, settlement currency and shop URL. The description maximum is 300 characters; documented capture delay is Immediate, Manual or 1–29 days. Test responses have an empty live prefix and `default` data-center name. There is no request default or rate limit stated here. See [[source-adyen-api-explorer-management-latest-get-merchants-merchantid]] and https://docs.adyen.com/api-explorer/Management/latest/get/merchants/(merchantId) (verified raw lines 5–54).

## Q2

A `200` says the read succeeded and reports captured merchant-account settings/status; `204` is also listed as success without content. `PreActive` cannot process payments; `Active` permits Customer Area access, while payment processing and payouts additionally require an Active company account. `InactiveWithModifications` blocks new payments but allows modifications such as refunds and payouts; `Inactive` disables processing/payouts; `Closed` is irreversible and disables login, processing and payouts. The page gives `400`, `401`, `403`, `422` and `500` errors, but no GET-side activation, deletion, idempotency, propagation, review or reversal operation, and no proof of any particular authorization, capture, payout, settlement or bank receipt. The captured server is `/v3`, yet the example's resource links use `/v1`; `Manual` in the response table appears as `manual` in the example. The snapshot does not reconcile those values, and `latest` does not establish current live credential access or account eligibility. See [[source-adyen-api-explorer-management-latest-get-merchants-merchantid]] and https://docs.adyen.com/api-explorer/Management/latest/get/merchants/(merchantId) (verified raw lines 23–58, 61–190).
