## Q1

The 2026-11-03 Management API v3 TEST reference describes `POST /companies/{companyId}/apiCredentials/{apiCredentialId}/allowedOrigins` as adding an allowed origin to the selected API credential's list. Required path IDs identify the company account and its API credential; the caller needs **Management API—API credentials read and write**. The listed server is `https://management-test.adyen.com/v3`. In the request-body table, `domain` is required, `id` and `_links` optional, and `_links.self` required if the parent appears; the page does not independently mark whole-body requiredness or specify defaults/limits. `200` returns a body with required `domain` and optional origin `id` and links. ## Q2

A `200` says the allowed-origin creation request succeeded and can return a domain, optional ID and link. It does not show a later client-side authentication, live origin acceptance, API/client-key generation, payment or financial state. The capture requires the caller's credential role and lists `401` authentication, `403` permissions, `400` request, `422` validation and `500` server failures; it gives no idempotency, deletion, propagation, asynchronous approval or reversal guarantee. The sample self-link is `/v1` even though the listed TEST server is `/v3`, so the sample cannot settle the v3 link path. The dated snapshot does not prove current live permission or account eligibility.
