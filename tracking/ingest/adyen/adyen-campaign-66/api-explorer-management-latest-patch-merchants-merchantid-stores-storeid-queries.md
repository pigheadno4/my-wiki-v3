## Q1

The 2026-11-03-captured `PATCH /merchants/{merchantId}/stores/{storeId}` updates selected store parameters under an Adyen merchant account using the Management API's listed TEST `/v3` server. The API credential needs the `Management API—Stores read and write` role. Both merchant-account `merchantId` and Adyen store `storeId` are required path IDs. The request table marks the top-level update fields optional and does not declare whole-body requiredness; country cannot be changed. The conditional address `stateOrProvince` rule applies to Australia, Brazil, Canada, India, Mexico, New Zealand and the US; `externalReferenceId` has country/payment-method-specific CNPJ, SIRET and Zip rules. If optional `subMerchantData` is supplied, its four children are marked required, with stated ID/name/MCC limits. Optional split configuration holds distinct balance-account and split-profile IDs. A `200` can return a store object with optional IDs, address, business lines, status, split configuration and sub-merchant data; `204` has no additional content. Live rate limits are linked but not quantified here. ## Q2

`200` means the store update request succeeded with a store response; `204` means processing succeeded without additional content. Status `active` is assigned at creation; the PATCH permits active-to-inactive and inactive-to-active-or-closed, while closed cannot reopen. Inactive blocks new transactions but allows outstanding captures; closing reassigns terminals to merchant inventory so they cannot process payments. This reference does not define propagation timing or prove a terminal is assigned/boarded, a payment was authorized, a capture settled, or funds reached a bank. The credential role is required, and `400`, `401`, `403`, `422` and `500` errors are listed. No idempotency, retry, reversal, asynchronous approval or conflict-version contract is stated. The listed server is TEST `/v3`, while each response example's `_links.self.href` is `/v1/stores/`; the page does not reconcile that mismatch. The dated raw and `latest` URL do not establish current live eligibility or behavior.
