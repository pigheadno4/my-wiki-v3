# Original retrieval answers: api-explorer-management-latest-post-merchants-merchantid-activate

- Q1: The 2026-11-03 Management API v3 TEST `POST /merchants/{merchantId}/activate` requests activation of the merchant account named by the required string path `merchantId`; an Adyen contact sets up access for integrations that require it, such as Adyen for Platforms Manage. The API credential needs `Management API—Accounts read and write`. The page gives no request body, conditional input, default, or rate limit. A 200 can optionally return the company-account `companyId` and requested `merchantId`; a 204 has no additional content. The captured server is `https://management-test.adyen.com/v3`. [[source-adyen-api-explorer-management-latest-post-merchants-merchantid-activate]] — https://docs.adyen.com/api-explorer/Management/latest/post/merchants/(merchantId)/activate ; pinned raw lines 5–18, 20–40.
- Q2: A 200 says the activation request succeeded, and a 204 says it was processed without content; neither confirms activation. The activation result arrives asynchronously through `merchant.updated`. Only once the account is activated does the page say it can start accepting payments and payouts; it gives no proof of a particular authorization, payout, settlement, or bank receipt. It lists 401 authentication-required and 403 permission errors along with 400, 422, and 500, but no idempotency, deletion/reversal, propagation-time, or further review/approval contract. The `latest` URL and 2026-11-03 TEST snapshot do not prove current eligibility or live availability; the generic error `requestId`/`pspReference` description is not a payment outcome.
