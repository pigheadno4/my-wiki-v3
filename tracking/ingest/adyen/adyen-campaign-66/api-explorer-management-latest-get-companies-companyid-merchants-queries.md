# api-explorer-management-latest-get-companies-companyid-merchants — original query answers

## Q1

`GET /companies/{companyId}/merchants` in the captured Management API reference lists merchant accounts under the required company-account `companyId`, restricted to those accessible to the calling API credential. The page names the Management API—Account read role and the test server `https://management-test.adyen.com/v3`; its “latest” route is a documentation label, not proof of current live availability. There is no request body. Optional integer `pageSize` defaults to 10 and has maximum 100; optional integer `pageNumber` has no stated default. A 200 response has required `itemsTotal` and `pagesTotal`, optional pagination `_links` and optional `data` merchant objects. Merchant `id`, parent `companyId`, and merchant `reference` are distinct optional response fields. Other optional fields include status, capture delay, default shopper interaction, legal-entity name/city, primary settlement currency, website, partner-only pricing plan, data-center values, and links to the merchant resource, credentials, users and webhooks. The raw schema says the test `livePrefix` is empty and test `dataCenters.name` is `default`. [[source-adyen-api-explorer-management-latest-get-companies-companyid-merchants]]; https://docs.adyen.com/api-explorer/Management/latest/get/companies/(companyId)/merchants; verified raw lines 5–71.

## Q2

A 200 establishes only that this credential-scoped list request succeeded; it does not create, approve, activate, change or delete a merchant account, or establish payment/payout/bank receipt. `PreActive` cannot process payments. For a merchant `Active`, the reference says processing and payouts are enabled **if its company is also Active**. `InactiveWithModifications` blocks new payments but allows payment modifications such as refunds and still allows payouts; `Inactive` disables processing and payouts; `Closed` is irreversible. Authentication and permissions remain relevant: the page requires the Account read role and documents 401 authentication and 403 permission errors, along with 400, 422 and 500. This GET reference documents no idempotency, asynchronous review/approval/activation, propagation, failure reversal, or lifecycle mutation contract. Its test `/v3` server conflicts with `/v1` links in the illustrative 200 payload, so the example cannot establish a current link version. The 2026-11-03 snapshot and “latest” documentation path do not prove present live eligibility, compliance, actual financial outcomes or account-specific access. [[source-adyen-api-explorer-management-latest-get-companies-companyid-merchants]]; https://docs.adyen.com/api-explorer/Management/latest/get/companies/(companyId)/merchants; verified raw lines 7–14, 32–71, 74–171 and 173–433.
