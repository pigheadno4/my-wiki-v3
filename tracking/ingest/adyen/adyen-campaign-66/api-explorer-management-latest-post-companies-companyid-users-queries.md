## Q1

The 2026-11-03-captured `POST /companies/{companyId}/users` creates a user under the company account named by required path `companyId`. It is a Management API reference with listed TEST `/v3` server and a required calling-credential role of `Management API—Users read and write`; it lists no live server. The request-body table requires `email`, a 1–80-character `name` with `firstName` and `lastName`, and `username`, which it says must equal `email`; it does not separately state whole-body requiredness. Optional account-group IDs, merchant-account IDs, roles, time-zone database name and `Email`/`SSO` login method are listed. SSO must already be configured with Adyen before creating an SSO user. A `200` returns a user schema with required email, user ID, roles, time-zone code and username, plus optional `active`, apps, account associations and name. The page states no rate limit or input default. [[source-adyen-api-explorer-management-latest-post-companies-companyid-users]] [Endpoint reference](https://docs.adyen.com/api-explorer/Management/latest/post/companies/(companyId)/users) (verified raw lines 5–36, 101–123).

## Q2

`200` establishes that the creation request succeeded and reports a user resource; the sample's `active: true` does not prove all new users are active, able to log in, SSO provisioned, or granted any particular account/role access. `400`, `401`, `403`, `422` and `500` cases are documented. The page states no idempotency, retry, deletion, propagation, notification, asynchronous review/approval, reversal or version-conflict contract. Its required `username = email` rule conflicts with all three request examples (`johnsmith` versus `john.smith@example.com`), so the samples should not be treated as validation proof. The TEST server is `/v3`, while the response example's self link is `/v1`, with no reconciliation. The 2026-11-03 snapshot and `latest` URL do not prove current live availability, credential eligibility or financial outcomes. [[source-adyen-api-explorer-management-latest-post-companies-companyid-users]] [Endpoint reference](https://docs.adyen.com/api-explorer/Management/latest/post/companies/(companyId)/users) (verified raw lines 1–14, 29–36, 40–100, 101–123, 126–253).
