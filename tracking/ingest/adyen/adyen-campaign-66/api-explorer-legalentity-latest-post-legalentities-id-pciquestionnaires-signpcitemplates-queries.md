# Original retrieval answers: api-explorer-legalentity-latest-post-legalentities-id-pciquestionnaires-signpcitemplates

- Q1: The 2026-11-03 snapshot documents the Legal Entity Management API v4 TEST `POST /legalEntities/{id}/pciQuestionnaires/signPciTemplates` for signing required PCI questionnaires. The path `id` is the legal entity of the user with a contractual relationship to the platform; the required request-table fields are `pciTemplateReferences` (Adyen-generated questionnaire template identifiers) and `signedBy` (the signing individual's legal entity ID). Whole-body requiredness is not separately stated. The captured page gives no conditional input or default. Limits are 700 requests per five seconds live, 200 per five seconds test, and five failures per ten seconds. A 200 response optionally contains `pciQuestionnaireIds` for signed documents and `signedBy`; the example contains only IDs. - Q2: The 200 description establishes request success and the optional returned IDs identify signed PCI documents, not PCI DSS compliance, current eligibility, verification or onboarding approval, payment authorization, settlement, or bank receipt. The page lists 401 authentication-required and 403 insufficient-permission errors, plus 400, 422, and 500; it states no credential/role, idempotency, deletion/reversal, status propagation, asynchronous review/approval/activation, or financial outcome contract. The `latest` URL is a captured reference, not proof of the present version or availability; the generic error schema's `pspReference` does not make signing a payment.
