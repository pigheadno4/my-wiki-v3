## Q1

`GET /merchants/{merchantId}/payoutSettings` is the 2026-11-03-captured Adyen Management API v3 read of payout settings for the merchant account identified by the required string path `merchantId`, on the shown `https://management-test.adyen.com/v3` server. Adyen for Platforms Manage is one example use; an Adyen contact sets up access, and the credential needs `Management API—Payout account settings read`. No query parameter or body is documented. A `200` has an optional `data` array of payout accounts; each item requires its payout-setting `id` and bank-account `transferInstrumentId`, while `allowed`, `enabled`, `enabledFromDate`, `priority` and `verificationStatus` are optional fields. `enabled` defaults to true, but payouts to that bank account require it and `allowed` both true. `allowed` is true for valid bank verification and false otherwise. `enabledFromDate` controls future enablement; priority values are `first` (same day), `urgent` (next day) and `normal` (one to three days), qualified by payout frequency, currencies and banks. No request default, count limit or rate limit is stated. See [[source-adyen-api-explorer-management-latest-get-merchants-merchantid-payoutsettings]] and https://docs.adyen.com/api-explorer/Management/latest/get/merchants/(merchantId)/payoutSettings (verified raw lines 5–40).

## Q2

A `200` establishes successful settings readback, while the separately listed `204` has no content. A returned `enabled: true` alone is insufficient for payouts to the bank account: `allowed` must also be true, which the reference ties to `verificationStatus: valid`. If an `enabledFromDate` is specified with `enabled: false`, the page says the switch becomes true on that date and the date field resets to null; this is documented configuration timing, not evidence of a transfer. The page lists `400`, `401`, `403`, `422` and `500` errors but no GET-side idempotency, mutation/deletion, propagation, asynchronous approval outcome, activation, reversal or payout state. No example response or actual transaction is supplied. The `latest` URL and captured test server do not establish present live entitlement; returned settings, even valid verification and a priority label, do not prove an actual payout, settlement or bank receipt. See [[source-adyen-api-explorer-management-latest-get-merchants-merchantid-payoutsettings]] and https://docs.adyen.com/api-explorer/Management/latest/get/merchants/(merchantId)/payoutSettings (verified raw lines 25–44, 47–144).
