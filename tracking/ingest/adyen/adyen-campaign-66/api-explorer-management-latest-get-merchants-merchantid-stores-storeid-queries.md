## Q1

The 2026-11-03 Management API v3 snapshot says `GET /merchants/{merchantId}/stores/{storeId}` returns one merchant-scoped store's details. Its listed server is `https://management-test.adyen.com/v3`, and the caller's API credential must have **Management API—Stores read** or **Management API—Stores read and write**. The required string path IDs identify the merchant account and store; the page specifies no request body, query parameters, or defaults. It notes live rate limits without numbers. The optional top-level `200` fields include the Adyen-generated store `id`, owning `merchantId`, reference, address, business-line IDs, shopper statements, split configuration, status, and `subMerchantData`. Some nested fields are marked required only within their optional parent object. `204` has no content. See [[source-adyen-api-explorer-management-latest-get-merchants-merchantid-stores-storeid]] and the [pinned API reference](https://docs.adyen.com/api-explorer/Management/latest/get/merchants/(merchantId)/stores/(storeId)), raw lines 5–71.

## Q2

A `200` reads a store representation; `204` reports successful processing without one. The `active`, `inactive`, and irreversible `closed` status descriptions distinguish a store state from terminal assignment/boarding, payment-method availability, payment authorization, capture, or settlement; `inactive` blocks new terminal transactions while outstanding captures remain possible, and closing reassigns terminals to merchant inventory. Authentication and permission failures are `401`/`403`; `400`, `422`, and `500` cover request, validation, and server failures. This GET page specifies no idempotency, update propagation timing, asynchronous activation/review, reversal, or version-conflict handling. Its v3 TEST server conflicts with a v1 self link in the `200` example, and the example reference includes a space excluded by the field rule; neither example settles the contract. A 2026-11-03 snapshot and a live rate-limit mention do not establish current live eligibility or a financial outcome. See [[source-adyen-api-explorer-management-latest-get-merchants-merchantid-stores-storeid]] and the [pinned API reference](https://docs.adyen.com/api-explorer/Management/latest/get/merchants/(merchantId)/stores/(storeId)), raw lines 9–18, 28–71, and 74–200.
