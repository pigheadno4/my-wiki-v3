# Fixed retrieval checks — Capital dynamic financing offers

Q1. What is this guide's scope and eligibility/financial evidence boundary?
- Expected: A 2026-09-15 Capital guide for limited-availability pilot dynamic financing offers with variable 90/180/360-day terms. A Capital-supporting Platforms integration, appropriate Balance Platform API key roles and the holder's `getGrantOffers` capability are listed; pilot access requires an Adyen contact. It gives no country list and cannot establish current account-holder qualification, a live offer, accepted Terms, approved grant, disbursement or repayment. A preliminary calculation is informational; a static formal offer is still distinct from grant initiation/funding.

Q2. How do range, preliminary calculation and static-offer stages differ in data, limits and outcomes?
- Expected: GET `/dynamicOffers` for an accountHolderId can return up to three holder-specific ranges/terms, with `businessFinancing`, start/expiry and estimated/maximum term fields; selected amount must be in that holder's range, and higher amounts are only *typically* associated with longer terms. A dynamic offer lasts seven days, with a replacement generated only if the holder still qualifies and the range may change. POST `/{id}/calculate` with matching currency/in-range minor-unit amount gives preliminary amount, fee, daily basis points, 30-day threshold and term/validity data; it cannot initiate a grant and has a captured 120/min Test/Live limit counting failures. POST `/{id}/grantOffer` gives a static definitive offer and distinct static ID needed for later grant request, at 30/min including failures. Dynamic/static creation use distinct webhook types. The static request example's 500000 amount conflicts with response 250000, so the sample pair is not a reliable amount mapping.
