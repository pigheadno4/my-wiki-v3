Q1. What do the Issuing-path Onboarding components cover, and what must exist before using them?
Answer: This page covers Transfer Instrument Configuration/Management for user bank-account information, resource creation, status/error display, and management actions (raw lines 21–35, 57–75). They work only with legal entities created by LEM API v3/v4, require Adyen for Platforms and a LEM API key, and still leave other API-only onboarding calls to the platform (raw lines 19, 23, 43–53). Q2. How is the component session scoped, and does a completion event prove bank verification or a payout?
Answer: The platform server creates a session via POST /sessions with LEM credentials, an allowed origin (HTTPS on live), onboarding product, a legalEntity policy resource for the contractual bank-account owner, and the applicable Transfer Instrument role(s) (raw lines 98–113). Configuration's complete event reports successful submission/component completion (raw lines 180–189, 562–567); the sample payload has null verification fields (raw lines 578–601). Neither that event nor a displayed status proves verification approval, payout eligibility, or bank receipt.
