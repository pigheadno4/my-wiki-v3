Q1. How does the first Issuing platform admin become active, and what can the Customer Area be used to navigate or manage?
Answer: Adyen says it creates the admin user at signup, emails it for verification, and activates it when verification completes (raw line 19). Customer Area lists resource views, transaction rules, webhook configuration, card status, reports, organization users and API credentials; the linked child guides contain operation detail (raw lines 21–32). Q2. Does this page settle which user type people should receive for interactive Customer Area access?
Answer: It says roles control access to specific Customer Area sections and calls accounts created for people “web service users” (raw lines 34–36). The linked [[source-adyen-docs-issuing-manage-access-api-credentials-web-service]] instead defines web-service users as API-request authentication credentials (that source's raw lines 19–25, 42–52). Treat the wording as unresolved here and consult dedicated user/role guidance before deciding an interactive-login user type.
