Q1. What is an Issuing account holder, and what must precede creation?
Answer: It is the user API resource associated with the user's legal entities, balance accounts and capabilities (pinned raw line 19). Create a legal entity first, then POST the holder with that legal-entity ID; for a sole proprietorship, the guide uses the owner's individual legal-entity ID (lines 27–30). The returned account-holder ID supports webhook matching, later updates and creation of a separate balance account (lines 246–290). Creation's active status is not verified capability access: the example has allowed false and pending verification (lines 250–290). Q2. What limits prevent treating suspend, reactivation, closure, or capability request as completed Issuing access?
Answer: The holder cannot be deleted (line 23). API suspension disables payout capabilities but leaves linked balance accounts and payment instruments active (line 752). API reactivation is limited to a currently suspended holder and cannot reverse an Adyen-initiated suspension (line 983). Permanent closure requires zero balances, then non-primary balance accounts, then the primary and holder (lines 1213–1223). A capability request goes to Adyen for approval (line 1281); its example response is requested true, allowed false, pending (lines 1543–1566). The raw enable/disable request names sendToTransferInstrument but its displayed response names withdrawFromAtm (lines 1602–1615, 1844–1866), so that response does not verify the requested capability.
