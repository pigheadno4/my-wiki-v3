## Findings for ingest

1. **MB WAY and Bizum:** release notes announce PaymentSheet support. The
   retained enum adds `mb_way` and `bizum`; next-action decoding adds
   `mb_way_await_authorization` and `await_authorization`. The handler routes
   these to PaymentSheet polling for MB WAY and Bizum respectively. Both paths
   require `PaymentSheetAuthenticationContext` and PaymentIntent action params;
   they reject non-PaymentSheet contexts and SetupIntent use. This does not
   establish merchant eligibility, form fields, polling duration, or settlement.
2. **Standalone Link private preview:** `LinkController.present` now returns
   an error received from native Link selection before considering cancellation
   or creating a PaymentMethod. Release notes identify the no-funding-sources
   case. Internal `collectPaymentMethod` and FlowController selection callbacks
   discard the added error argument; do not generalize the preview error
   contract to every Link consumer. The internal detection implementation is
   excluded from this capsule.
3. **Crypto Onramp alpha:** `deleteWalletAddress(walletId:)` is added to the
   coordinator and its protocol. It uses the wallet ID, requires Link account
   information, awaits the API operation, logs success afterward, and maps
   errors through the coordinator's existing error path. Error analytics now
   include available request IDs. The excluded API implementation prevents
   claims about endpoint details, idempotency, or deletion persistence.
4. **Checkout confirmation separation:** the old
   `PaymentSheet+CheckoutSessionAPI.swift` is removed. New
   `Checkout+Confirm.swift` and `Checkout+Confirm+Link.swift` own confirmation.
   `PaymentSheet.confirm` explicitly rejects Checkout intents and directs them
   to `Checkout.confirm`. Shared Bacs mandate and saved-card CVC preconfirmation
   actions are factored into an async result. Native and web Link controllers
   accept injected confirmation handlers. Ordinary Intent-based PaymentSheet
   flows must not be confused with this Checkout SPI change.
5. **Unfinished Checkout SPI, not a production integration recommendation:**
   at this SHA, `Checkout.confirm` commits a returned session response but
   discards the internal payment result and returns `.canceled`, with an
   explicit result-mapping TODO. Its internal Apple Pay branch also returns
   canceled with a TODO. Express Checkout renders Apple Pay/Link controls but
   their tap handlers are empty TODOs; Shipping Address completion is also
   unfinished. A canceled result from this unfinished SPI is not evidence that
   no server-side payment occurred. These are observed 26.6.0 implementation
   limits, not all proven newly introduced regressions.
6. **Newly retained session evidence:** `noPaymentRequired` is defined by
   `paymentStatus == .noPaymentRequired`, not merely a zero amount. Billing
   tax-region updates require automatic tax to use billing; a missing country
   in supplied billing details produces a no-op. The session exposes status,
   totals, currency options, customer, saved methods, and address operations.
   Record these as an expanded 26.6.0 evidence baseline; the prior capsule did
   not retain enough code to date every behavior's introduction.
7. **Confirmation response timing:** the prior helper committed the session
   before handling the returned Intent's next action. The new internal helper
   returns the response with its result, and the outer Checkout confirmation
   commits afterward. SetupIntent dispatch still precedes PaymentIntent, and
   `noPaymentRequired` still suppresses `save_payment_method`.
8. **Form-spec removal:** Package.swift stops processing Resources/JSON, and
   CustomerSheet removes local/Elements Session form-spec loading. Upstream
   inventory records form-spec provider/resource deletions, but replacement
   form-factory implementation is excluded. Do not claim full UI parity or
   describe unretained factory internals. Existing task-cancellation defers are
   not a new 26.6.0 behavior.
9. **Other bounded changes:** appearance defaults reference helper constants;
   helper implementation is excluded, so do not claim numerical equivalence
   from the caller alone. FPX bank brands gain SPI CaseIterable conformance.
   The eight retained podspecs only bump versions; no deployment-floor or
   standalone Apple Pay integration change is established by those bumps.

## Ingest guidance and limitations

Full mode is warranted by the capsule-policy expansion and confirmation
architecture change, not by a rule that every minor release requires full mode.
Append a version-qualified baseline to the stable source and a separate release
entry to its changelog; preserve 26.5.0, 26.4.1, and legacy knowledge. Existing
general Checkout wording should gain a version/SPI qualification rather than
silently suggesting that all current PaymentSheet shapes confirm Checkout.

The 26.5.0 evidence-gap statements remain valid for that historical capsule.
Explain which session/billing details become available at 26.6.0 without
retroactively filling the earlier immutable capsule. Continue to distinguish
session completion, SDK completion, authorization, and actual payment success.

Excluded implementation still includes Link UI funding-source detection,
PaymentSheet method availability/form factory/polling view model, Crypto Onramp
API requests, appearance helpers, and parts of saved-method UI. Tests are
excluded. No SDK build, simulator, payment execution, or eligibility check was
performed. Deeper questions about those internals require exact-SHA evidence.
