### Verified findings

Evidence below refers to `files/` in the immutable snapshot
`raw/github/stripe/stripe-ios/snapshots/2026-09-30-62c2070/`, compared with
`2026-09-30-3410ff0` (26.6.0).

- **Financial Connections Lite dependency:** `Package.swift` registers the new
  product/target and adds it to PaymentSheet dependencies;
  `StripePaymentSheet.podspec` adds the corresponding dependency. `MIGRATING.md`
  and the release notes require manual/Carthage PaymentSheet users to embed
  `StripeFinancialConnectionsLite.xcframework`; CocoaPods/SPM need no additional
  action according to those instructions. The actual Lite implementation is
  not retained, so this verifies packaging/migration, not bank-flow execution.
- **Hide Link's button without disabling Link:**
  `StripePaymentSheet/StripePaymentSheet/Source/PaymentSheet/PaymentSheetConfiguration.swift`
  adds `walletButtonHidden`: "Link remains enabled" while its button/row is
  hidden. `shouldDisplay` returns true for this mode, while `shouldShowButton`
  returns false. The two Embedded Payment Element implementations now call
  `PaymentSheet.shouldShowLinkButton` for row construction and preservation of
  the previous Link selection. That helper's definition is not retained;
  the verified evidence is the configuration contract and these call sites,
  not runtime proof of every Link surface.
- **Autocomplete configuration:** the `useAutocompleteEndpoints` STP SPI
  setting is removed from PaymentSheet, Embedded and CustomerSheet
  configuration and the shared configuration protocol. CustomerSheet now
  passes `elementsSession.shouldUseAutocompleteProxyEndpoints` directly rather
  than combining it with a merchant-side configuration flag. The add-payment
  controller passes the flag directly to the autocomplete initializer. The
  release notes say "Address autocomplete results sourced from internal
  service." The service implementation and flag decoder are not retained;
  this does not prove every request unconditionally uses that service.
- **Vipps typed support:** retained PaymentMethod enum, decoder, parameters,
  and the new `STPPaymentMethodVipps`/`STPPaymentMethodVippsParams` types add
  the `vipps` API identifier and typed construction/serialization. In
  `StripePayments/StripePayments/Source/PaymentHandler/STPPaymentHandler.swift`,
  `.vipps` joins the synchronous group: `_isProcessingIntentSuccess` returns
  false, so `processing` alone is not treated as a completed flow for it.
  This is not evidence of merchant eligibility, general availability, or a
  fully verified PaymentSheet/Checkout Vipps integration.
- **Historical annotations:** the new cumulative changelog inserts a
  `vipps_preview=v1` beta-header note under 26.6.0 and AddressElement dismissal
  notes under 26.5.0. Record these as retrospective upstream annotations, not
  newly introduced 26.7.0 behavior. Vipps typed additions above are observed
  between the actual retained SHAs, independently of those heading dates.
