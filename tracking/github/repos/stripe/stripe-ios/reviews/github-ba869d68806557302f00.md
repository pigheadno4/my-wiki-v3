2. PaymentIntent automatic mandate inference removes `krCard` and `naverPay`; `kakaoPay` remains. Explicit mandate data still takes precedence. SetupIntent confirmation code is unchanged, so this is not a general removal of mandate requirements across both intent types.
3. The new Financial Connections branding helper returns explicit Onelink, otherwise account Onelink, otherwise nil. This narrow helper does not replace the general `resolvedLinkBrand` precedence or establish downstream rendering behavior.
4. Identity adds an SPI biometric-consent branding-header configuration and forwards the configuration object to the flow controller. This is not consent suppression or verification bypass; the actual controller/UI implementation is outside this capsule.
5. Embedded initial selected-row restoration adds the change button and sublabel without animation. Interactive callers retain the default animated path. No device-rendering verification was performed.
6. Checkout Apple Pay confirmation parameters gain `shippingAddressRequired`; the retained Payment Element caller supplies false and delegates through a session-aware confirmation helper. Do not generalize this to all Checkout shipping requirements or Express Checkout behavior.
7. README/release notes add Arabic (Saudi Arabia). Alpha CryptoOnramp notes announce Canada SIN, Colombia NIT and Philippines TIN plus `KycInfo.idType`; implementation is excluded. The eight retained podspec changes are version-only, not new platform requirements.
